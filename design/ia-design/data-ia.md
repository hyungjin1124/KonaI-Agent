## 2. 데이터 메뉴 단일 화면

### 2.1 목적

에이전트가 참조하는 뷰테이블을 탐색하고, 스키마·데이터·접근 권한을 하나의 화면에서 확인·관리한다. "이 뷰테이블에 어떤 데이터가 있고, 누가 볼 수 있는가?"에 답하는 화면이다.

### 2.2 레이아웃: 테이블 + 슬라이드 패널 (하이브리드)

```
┌──────────────────────────────────────────────────────────────────────────┐
│  데이터                                                      [+ 등록]    │
├────────────────────────────────────┬─────────────────────────────────────┤
│                                    │                                     │
│  🔍 검색    도메인: [전체 ▾]         │  v_bom_master               [↗ 확장]│
│  소스 유형: [전체 ▾]                │                                     │
│                                    │  [개요] [스키마] [데이터] [접근 권한] │
│  ┌────────────┬────┬────┬────────┐│  ──────────────────────────────────  │
│  │뷰테이블 이름│소스 │도메인│허용 대상 ││  (선택된 탭의 내용)                   │
│  ├────────────┼────┼────┼────────┤│                                     │
│  │v_bom_master│ERP │생산 │부서 2·   ││                                     │

│  │ status     │    │    │        ││                                     │
│  │v_sales_    │Excel│영업│전체 허용 ││                                     │
│  │ targets    │    │    │        ││                                     │

└────────────────────────────────────┴─────────────────────────────────────┘
```

**예시 행 설계 의도**: ERP 소스 4개 + 비ERP 소스 3개(Jira, Excel, API)를 혼합하여, 허용 대상의 다양한 조합(부서+그룹+사용자 오버라이드, 그룹+사용자, 그룹만, 부서+사용자, 전체 허용, 사용자만, 미설정)이 모두 보이도록 구성했다. 비ERP 소스 행 클릭 시 패널 탭이 [개요][접근 권한]으로 줄어드는 것을 개발자가 인지할 수 있도록, 소스 컬럼에서 ERP/비ERP가 명확히 구분된다.

기본은 슬라이드 패널에서 정보를 확인하고, 데이터 미리보기 등 넓은 공간이 필요할 때 패널 헤더의 **[↗ 확장]** 버튼으로 전체 페이지로 전환한다. 스킬 메뉴의 패널 전체 확장과 동일한 패턴이다.

### 2.3 좌측: 뷰테이블 목록 테이블

| 요소 | 설명 |
|------|------|
| **검색** | 뷰테이블 이름, 설명 텍스트 검색 |
| **필터** | 도메인 드롭다운 (전체 / 생산 / 회계 / 인사 / ...) + 소스 유형 드롭다운 (전체 / ERP / Jira / Excel / ...) |
| **테이블 컬럼** | 뷰테이블 이름, 소스, 도메인, 허용 대상 |
| **정렬** | 이름순(기본), 도메인순, 수정일순 |
| **행 클릭** | 우측 슬라이드 패널 열림. ERP 뷰는 4탭, 비ERP 소스는 2탭 패널이 열린다 |
| **[+ 등록]** | 페이지 헤더 우측. 비ERP 데이터 소스 등록 다이얼로그 열기. ERP 뷰테이블은 백엔드 마이그레이션으로 등록되며, UI에서는 비ERP 데이터 소스만 등록 가능하다. |

#### 허용 대상 컬럼

허용 대상 컬럼은 "이 뷰테이블이 얼마나 열려 있고, 어떤 구조로 권한이 구성되어 있는가"를 테이블 수준에서 바로 파악할 수 있게 한다. 기존 "접근 대상 수"(단일 숫자)에서 **허용 대상 유형별 요약**으로 변경했다.

*[설계 변경 (v2): 접근 대상 수(숫자 1개) → 허용 대상 요약. 단일 숫자는 "12명이 많은가 적은가", "부서 단위인가 개인 단위인가"를 알 수 없어 관리자의 다음 판단으로 연결되지 않았음. 접근 구조(부서·그룹·사용자)를 요약하면 패널을 열지 않고도 권한 배치의 적절성을 가늠할 수 있음]*

**표시 규칙**:

| 케이스 | 표시 예시 | 설명 |
|--------|----------|------|
| 부서 + 그룹 + 사용자 | `부서 2 · 그룹 1 · 1명` | ERP 뷰에서 부서권한·그룹권한·사용자 오버라이드가 모두 있는 경우 |
| 그룹 + 사용자 | `그룹 1 · 1명` | 부서 권한 없이 그룹과 사용자 오버라이드만 있는 경우 |
| 그룹만 | `그룹 1` | 그룹 단위로만 접근이 허용된 경우 |
| 부서 + 사용자 (비ERP) | `부서 1 · 2명` | 비ERP 소스에서 부서와 개별 사용자 직접 지정 |
| 사용자만 | `3명` | 개별 사용자에게만 직접 부여된 경우 |
| 전체 허용 | `전체 허용` | 접근 제한이 없는 경우 |
| 없음 | `—` | 아직 접근 권한이 설정되지 않은 경우 |

- 유형별 카운트를 `·`(가운뎃점)으로 구분하여 나열한다
- 표시 순서: 부서 → 그룹 → 사용자 (상위 → 하위 단위 순)
- "N명"은 항상 개별 사용자 직접 지정(ERP의 `_tcausersecu` 오버라이드 또는 비ERP의 관리자 직접 설정)을 의미한다

### 2.4 우측: 슬라이드 패널

패널 상단에 **뷰테이블 이름**과 [↗ 확장] 버튼을 표시하고, 그 아래에 소스 유형에 따라 탭을 배치한다.

**ERP 뷰** (auth_type이 erp_pgm 또는 erp_derived):
```
[개요] [스키마] [데이터] [접근 권한]
```

**비ERP 소스** (Jira, Excel, API, 기타):
```
[개요] [접근 권한]
```

*[설계 변경 (v2): 비ERP 소스는 [스키마][데이터] 탭을 제거. 비ERP 소스는 스키마가 고정되지 않거나(Jira 이슈 필드 변동), 데이터 미리보기를 바로 제공하기 어려운 경우(API, Excel 파일)가 있어, 현 단계에서는 개요와 접근 권한만 제공한다. 소스 연동이 성숙해진 후 스키마·데이터 탭 추가를 검토한다.]*

패널을 열 때 기본 선택 탭은 **[개요]**이다.

### 2.5 [개요] 탭

뷰테이블의 메타데이터를 표시한다. 등록/수정 다이얼로그에서 입력한 정보의 읽기 전용 뷰.

#### ERP 뷰 (auth_type이 erp_pgm 또는 erp_derived)

| 필드 | 설명 |
|------|------|
| 뷰테이블 ID | `v_bom_master` |
| 표시명 | `BOM 마스터 조회` |
| 설명 | 뷰테이블 용도 설명 |
| 도메인 | `생산` |
| auth_type | `erp_pgm` 또는 `erp_derived` |
| 원천 ERP 화면 | pgmseq + `_tcamenu`에서 조회한 ERP 화면명 (예: `[1234] BOM 조회`) |
| rls_type | `code_secu` 또는 `NULL` |
| 활성 여부 | ✓ 활성 |

- **원천 ERP 화면** 필드는 `agent_view_source` 테이블과 `_tcamenu` 테이블을 조인하여 pgmseq에 해당하는 ERP 화면 명칭을 함께 표시한다. erp_derived의 경우 복수 행으로 표시.
- 모든 필드는 읽기 전용이다.
- **[편집] 버튼**: 제거. ERP에서 관리되는 데이터이므로 이 화면에서 수정할 수 없다.

**하단 액션**: 액션 없음

```
  도메인         생산

```

### 2.6 [스키마] 탭 (ERP 뷰 전용)

뷰테이블의 컬럼 목록을 테이블 형태로 표시한다. 탭 선택 시 전체 내용이 바로 보인다 (아코디언 접힘 없음). **비ERP 소스에서는 이 탭이 노출되지 않는다.**

|--------|-----------|------|
| item_seq | int | 품목 ID |
| item_name | varchar | 품목명 |
| dept_seq | int | 부서 ID |
| ... | ... | ... |

탭 헤더에 컬럼 수를 인라인 표시: `스키마 (14)`

### 2.7 [데이터] 탭 (ERP 뷰 전용)

뷰테이블의 실제 데이터를 미리보기한다. **비ERP 소스에서는 이 탭이 노출되지 않는다.**

- **지연 로드**: 탭을 선택하는 순간 쿼리를 실행. 다른 탭에서는 로드하지 않음
- **최대 50행**: 가로·세로 스크롤 지원
- **읽기 전용**: 데이터 수정 불가
- **RLS 미적용**: 관리자가 전체 데이터를 확인하는 목적이므로, 미리보기에서는 RLS 필터를 적용하지 않음
- **패널 확장 권장**: 컬럼이 많은 뷰테이블은 패널 너비로 부족할 수 있음. 탭 내 상단에 "전체 화면에서 보기" 힌트 표시

### 2.8 [접근 권한] 탭

"이 뷰테이블에 접근 가능한 사람이 누구인가?"를 표시하고, RLS 설정을 확인한다.

#### ERP 뷰 접근 가능 부서/그룹/사용자

ERP 권한 테이블(`_TCAOrgDeptSecu`, `_tcagroupsecu`, `_tcausersecu`)에서 자동 계산한 현황을 테이블로 표시한다. 부서 → 그룹 → 사용자 오버라이드 순서로 표시한다.

| 대상 | 유형 | 인원 | 권한 근거 |
|------|------|------|----------|
| ▸ 부서명 (DeptSeq) | 부서 | N명 | `_TCAOrgDeptSecu` secu='1' |
| ▸ 그룹명 | 그룹 | N명 | `_tcagroupsecu` secu='1' |
| 사용자명 | 사용자 | — | `_tcausersecu` secu='1' (오버라이드) |

**행 펼침**: 부서/그룹 행의 ▸ 를 클릭하면 소속 사용자 목록이 인라인으로 펼쳐진다.

- 소속 구성원이 많은 경우 기본 5명까지 표시 + "...외 N명" 접힘. 클릭 시 전체 펼침
- 각 구성원 행에 이름과 부서를 표시하여 "결국 누가 볼 수 있는가?"에 바로 답할 수 있다
- erp_derived 뷰의 경우, ALL 로직 적용 결과를 표시: "원천 pgmseq [1234, 2345] 모두에 허용된 대상만 표시"
- **하단 안내 문구**: "ⓘ ERP 연동 뷰의 접근 권한은 ERP 부서별권한등록·그룹별권한등록·사용자별권한등록에서 관리됩니다. 위 현황은 ERP 권한 기준으로 자동 계산되었습니다."
- **[편집] 버튼**: 제거 (ERP에서 관리)
- **[그룹 상세 보기 →] 링크**: 제거

#### RLS 설정 (데이터 범위 제한)

접근 가능 부서/그룹/사용자 영역 아래에, 이 뷰테이블에 적용된 행 수준 보안(RLS) 규칙을 표시한다. RLS는 접근이 허용된 사용자가 "전체 데이터 중 어디까지 볼 수 있는가?"를 결정한다. *[근거: data-access-policy.md 5.6절]*

rls_type에 따라 표시 형식이 달라진다. 아래 세 가지 유형별 표시 예시를 기술한다.

**① code_secu — ERP 코드권한 기반 필터**

ERP 코드권한 체계에서 전체 자동 해석되므로 관리자가 설정할 값이 없다. 적용 현황만 표시한다.

```
RLS 설정
──────────────────────────────────────────────
유형: ERP 코드권한 기반 필터

  코드권한그룹    부서
  필터 대상 컬럼   DeptSeq
  해석 방식       사용자에게 허용된 부서(DeptSeq)만
                 조회 가능

  예시) 김영수 (생산기술팀)
        → WHERE DeptSeq IN (150, 200)
        → 생산기술팀(150), 품질관리팀(200) 데이터만 조회

ⓘ ERP 코드권한 테이블(_TCACodeSecu)에서 자동 해석됩니다.
  설정을 변경하려면 ERP 코드권한 관리에서 수정하세요.
──────────────────────────────────────────────
```

표시 항목:
- **코드권한그룹**: `_TCACodeSecuType`에서 조회한 그룹명 (예: "부서", "급여작업군", "사원")
- **필터 대상 컬럼**: 코드권한그룹의 CodeSeq가 의미하는 컬럼 (예: "부서" → DeptSeq)
- **해석 방식**: 사용자에게 허용된 CodeSeq 값만 조회 가능하다는 설명
- **예시**: 대표적인 사용자 한 명을 기준으로, 실제 적용되는 WHERE 조건과 그 의미를 보여준다. 접근 가능 그룹/사용자 목록에서 첫 번째 사용자를 자동 선택하여 표시
- **안내 문구**: ERP에서 관리되는 설정임을 명시

**② mapping_table — 전용 매핑 테이블 참조**

rls_config에 저장된 매핑 정보를 표시한다.

```
RLS 설정
──────────────────────────────────────────────
유형: 전용 매핑 테이블 참조

  매핑 테이블     _tpdbomdeptauthority
  뷰 조인 키     item_seq
  매핑 조인 키    itemseq
  매핑 부서 키    deptseq
  전체 허용 값    0 (deptseq=0이면 전 부서 조회 가능)

  예시) 김영수 (생산기술팀, DeptSeq=150)
        → _tpdbomdeptauthority에서
          deptseq=150 또는 deptseq=0인 itemseq 목록 조회
        → 뷰의 item_seq IN (해당 목록) 필터 적용
        → 생산기술팀에 배정된 BOM 품목만 조회

ⓘ 매핑 테이블의 데이터가 변경되면 조회 범위도 자동 변경됩니다.
──────────────────────────────────────────────
```

표시 항목:
- **매핑 테이블**: rls_config.table 값
- **뷰 조인 키**: rls_config.view_join_key — 뷰테이블에서 매핑에 사용하는 컬럼
- **매핑 조인 키**: rls_config.mapping_join_key — 매핑 테이블의 조인 컬럼
- **매핑 부서 키**: rls_config.mapping_dept_key — 매핑 테이블에서 부서를 식별하는 컬럼
- **전체 허용 값**: rls_config.allow_all_value — 이 값이면 전 부서 조회 가능
- **예시**: code_secu와 동일하게 대표 사용자 기준 적용 결과

**③ NULL — RLS 미적용**

```
RLS 설정
──────────────────────────────────────────────
유형: 미적용

  이 뷰테이블은 행 수준 보안이 적용되지 않습니다.
  접근이 허용된 사용자는 전체 데이터를 조회할 수 있습니다.
──────────────────────────────────────────────
```

## 3. 비ERP 데이터 소스 등록/수정 다이얼로그

비ERP 데이터 소스 등록과 수정은 **모달 다이얼로그**로 수행한다. 등록은 페이지 헤더의 [+ 등록] 버튼에서, 수정은 패널의 [편집] 버튼에서 트리거한다. 등록과 수정은 동일한 폼을 사용하되, 등록 시에는 view_id 입력이 가능하고, 수정 시에는 view_id가 읽기 전용이다.

**주의**: ERP 뷰테이블은 백엔드 마이그레이션으로만 등록되며, UI에서는 비ERP 데이터 소스만 등록 가능하다.

### 3.1 폼 필드

| 필드 | 타입 | 필수 | 설명 |
|------|------|------|------|
| view_id | text input | ✓ | 뷰테이블 식별자 (등록 시 입력, 수정 시 읽기 전용) |
| view_name | text input | ✓ | 표시명 |
| description | textarea | | 뷰테이블 설명. 에이전트가 질의에 적합한 뷰를 선택할 때 참조 |
| source_type | select | ✓ | 데이터 소스 유형 (Jira / Excel / API / 기타) |
| source_config | 동적 폼 | | source_type에 따라 동적으로 폼 변경. API 엔드포인트, 인증 정보, 쿼리 설정 등 |
| domain | select | ✓ | 도메인 (생산, 회계, 인사, ...) |
| is_active | toggle | ✓ | 활성 여부 (기본: 활성) |

**주의**: auth_type은 source_type에서 자동 결정되며, ERP 관련 필드(pgmseq 매핑, rls_type, rls_config)는 비ERP 소스에서 사용되지 않는다.

### 3.2 source_config 동적 폼

source_type 선택에 따라 source_config 입력 영역이 변경된다.

**Jira 선택 시:**

| 필드 | 설명 |
|------|------|
| Jira URL | Jira 인스턴스 URL (예: `https://jira.example.com`) |
| 프로젝트 키 | 조회할 프로젝트 키 (예: `PROJ`) |
| JQL 쿼리 | 이슈 필터링 JQL (예: `status = "Done"`) |
| 인증 방식 | API Token / OAuth |
| 인증 정보 | API Token 또는 OAuth 인증 세부 정보 |

**Excel 선택 시:**

| 필드 | 설명 |
|------|------|
| 파일 업로드 | Excel 파일 선택 (.xlsx, .xls) |
| 시트명 | 사용할 시트 이름 |
| 헤더 행 | 헤더가 있는 행 번호 (기본: 1) |

**API 선택 시:**

| 필드 | 설명 |
|------|------|
| API 엔드포인트 | REST API URL |
| HTTP 메서드 | GET / POST |
| 인증 방식 | Bearer Token / Basic Auth / 기타 |
| 인증 정보 | 선택한 인증 방식의 세부 정보 |
| 요청 본문 (선택) | POST 요청 시 전송할 JSON 본문 |
| 응답 매핑 | 응답 JSON 경로에서 데이터 배열을 추출하는 설정 |

**기타 선택 시:**

| 필드 | 설명 |
|------|------|
| 설명 | 데이터 소스에 대한 설명 |
| 담당자 | 이 소스를 관리하는 담당자 |

### 3.3 등록/수정 플로우

```
[+ 등록] 또는 [편집] 클릭
  → 다이얼로그 열림
  → 폼 입력/수정 (source_type에 따라 동적 폼 변경)
  → [저장] 클릭
  → 유효성 검증 (view_id 중복, 필수 필드, source_config 유효성)
  → 성공 시: agent_view_registry 저장 (비ERP 전용)
            다이얼로그 닫힘, 목록 갱신
  → 실패 시: 인라인 에러 메시지 표시
```

## 4. 관리자 > 사용자 관리 확장

> 이 섹션은 데이터 접근 권한과 관련하여 관리자 > 사용자 관리 메뉴에 추가되는 내용만을 다룬다. 사용자 관리의 전체 IA는 관리자 IA 설계 문서(05-admin-ia.md)를 참조한다.

사용자 관리 메뉴에 **(1) 테이블에 권한 그룹 컬럼 추가**, **(2) 패널에 사용자 정보(접힘) + 뷰테이블 접근 현황(펼침) 배치**한다. 사용자별 데이터 접근 구조를 테이블 수준에서 빠르게 파악하고, 패널에서 상세를 확인할 수 있다.

*[설계 변경 (v2): (1) 테이블에 "권한 그룹" 컬럼 추가 — "팀" 컬럼이 이미 부서(부서 기반 접근의 한 축)를 보여주므로, 테이블에서 보이지 않는 정보인 ERP 그룹 소속을 추가. 패널을 열지 않아도 "이 사람이 어떤 경로로 권한을 갖는가"를 파악 가능. (2) 패널 정보 위계 변경 — 뷰테이블 접근 현황을 기본 펼침, 사용자 정보를 기본 접힘으로. 테이블 행에 이미 보이는 정보(이름, 팀, 역할)를 패널에서 또 펼쳐둘 이유가 없고, 관리자가 패널을 여는 주된 이유가 접근 현황 확인이므로.]*

*[설계 변경 (v4): 패널 배치 순서 변경 — 사용자 정보(접힘)를 상단, 뷰테이블 접근 현황(펼침)을 하단으로. v2에서는 접근 현황을 먼저 배치했으나, 접근 현황 목록이 길어질 경우(뷰테이블 20개 이상) 사용자 정보가 패널 하단으로 밀려 접근하기 어려워지는 문제. 사용자 정보를 접힘 상태로 상단에 고정하면 필요할 때 즉시 펼칠 수 있고, 접근 현황은 그 아래에서 자유롭게 늘어나도 무방.]*

### 4.1 단일 화면 구조

사용자 관리는 단일 화면으로 구성된다. 사용자 목록 (권한 그룹 컬럼 포함) + 슬라이드 패널 (사용자 정보 접힘 + 뷰테이블 접근 현황 펼침).

### 4.2 테이블 권한 그룹 컬럼

기존 사용자 관리 테이블(05-admin-ia.md 4.1절)에 **권한 그룹** 컬럼을 추가한다. 이메일 컬럼과 역할 컬럼 사이에 배치한다.

```
┌──────────────────────────────────────────────────────────────────────────────────────┐
│  사용자 관리                                                                          │
│  검색 [___________]   팀▼   역할▼                                                      │
├──────────────────────────────────────────────────────────────────────────────────────┤
│  │ 이름    │ 팀        │ 이메일            │ 권한 그룹          │ 역할 ▼  │ 최근 활동일 │
│  │ 김영수  │ 생산기술팀 │ kim@kona.com      │ 생산관리, 기본권한  │ [일반 ▼]│ 2026.03.24 │
│  │ 박지은  │ 회계팀    │ park@kona.com     │ 기본권한           │ [일반 ▼]│ 2026.03.20 │
│  │ 이대표  │ 대표실    │ lee@kona.com      │ 임원(사장단)       │ [관리자▼]│ 2026.03.25 │
│  │ 최민호  │ 영업1팀   │ choi@kona.com     │ —                 │ [일반 ▼]│ 2026.03.28 │
│  │ 정수진  │ 구매팀    │ jung@kona.com     │ 기본권한, 구매관리  │ [일반 ▼]│ 2026.03.22 │
│  ...                                                                                  │
└──────────────────────────────────────────────────────────────────────────────────────┘
```

**예시 행 설계 의도**: 그룹이 2개(김영수, 정수진), 1개(박지은, 이대표), 0개(최민호)인 케이스를 모두 포함하여, 권한 그룹 컬럼의 다양한 표시 상태를 보여준다. 최민호처럼 "—"(그룹 없음)인 사용자는 부서 권한만으로 접근하거나, 아직 그룹 할당이 안 된 상태를 나타낸다.

| 컬럼 | 설명 | 정렬 |
|------|------|------|
| 권한 그룹 | ERP 그룹(`_tcagroupsecu`) 소속 목록. 최대 2개 표시, 초과 시 `+N` truncation (예: `생산관리, 기본권한 +1`). 그룹 없으면 `—` | — |

- "팀" 컬럼이 부서를 이미 보여주므로, 권한 그룹 컬럼은 ERP 그룹만 표시한다
- 관리자는 "팀(=부서) + 권한 그룹" 조합으로 해당 사용자의 접근 경로를 테이블 수준에서 추론할 수 있다

**예시 패널 설계 의도 (김영수 기준)**: 접근 현황 테이블에서 다양한 허용/차단 케이스를 보여준다.

| 뷰테이블 | 접근 | 허용 근거 | 커버하는 케이스 |
|----------|------|----------|---------------|
| v_bom_master | ✅ | 생산기술팀(부서) + 생산관리(그룹) | ERP 부서+그룹 복합 허용 |
| v_bom_cost | ❌ | secu='2' 차단 | ERP 명시적 차단 (secu 값으로 차단) |
| v_slip_summary | ❌ | 그룹 권한 없음 | ERP 그룹 미소속으로 인한 차단 |
| v_payroll_summary | ❌ | 임원(사장단) 그룹 아님 | 민감 데이터 그룹 불일치 차단 |
| v_jira_status | ❌ | 미설정 | 비ERP 소스에서 권한 미부여 |
| v_sales_targets | ✅ | 전체 허용 | 비ERP 소스 전체 허용 |
| v_hr_override | ✅ | 사용자 직접 부여 (오버라이드) | ERP 사용자만 직접 부여 케이스 |
| v_api_metrics | ❌ | 미설정 | 비ERP 소스 등록 직후 권한 미설정 |

#### 뷰테이블 접근 현황 테이블

| 컬럼 | 설명 |
|------|------|
| 뷰테이블 이름 | view_id |
| 접근 | ✅ 허용 / ❌ 차단 |
| 허용 근거 | **ERP 뷰**: 어떤 부서/그룹의 어떤 secu 값인지, 사용자 오버라이드인지, erp_derived의 ALL 로직 결과 / **비ERP 뷰**: 직접 설정된 부서/사용자 권한 |
| RLS 범위 | 허용된 뷰의 경우, 적용되는 RLS 필터 요약 (예: `dept_seq = 150`) |

**필터**: 접근 상태 드롭다운 (전체 / 허용만 / 차단만). 관리자가 "이 사용자가 왜 이걸 못 보지?"를 추적할 때 차단 필터가 유용하다.

**행 상세**: erp_derived 뷰테이블의 경우, 허용 근거에 원천 pgmseq별 판단 결과를 표시한다.

```
v_cost_purchase_trend (erp_derived)
├─ pgmseq 1234 (BOM 조회): ✅ 생산기술팀(부서) + 생산관리(그룹) 허용
└─ pgmseq 2345 (구매단가조회): ✅ 생산기술팀(부서) + 생산관리(그룹) 허용
→ ALL 로직: 모두 허용 → ✅
→ RLS: dept_seq = 150 (생산기술팀)
```

#### 사용자 정보 섹션 (기본 접힘)

패널 상단의 접힘 섹션. 펼치면 테이블 행에서 확인하기 어려운 상세 정보를 표시한다.

| 필드 | 설명 |
|------|------|
| 이메일 | 사용자 이메일 주소 |
| 그룹 소속 | ERP 그룹 전체 목록 (테이블에서 truncation된 경우 여기서 전체 확인) |
| 최근 활동일 | 마지막 로그인 또는 활동 날짜 |

### 5.1 데이터 메뉴 단일 화면

| 사용자 행동 | 시스템 반응 |
|------------|-----------|

| 비ERP 소스 행 클릭 | 슬라이드 패널 열림 — 2탭 ([개요] [접근 권한]), [개요] 기본 선택 |
| [스키마] 탭 클릭 (ERP 뷰만) | 컬럼 목록 표시 |
| [데이터] 탭 클릭 (ERP 뷰만) | 쿼리 실행 → 최대 50행 로드 |
| [접근 권한] 탭 클릭 | 접근 가능 부서/그룹/사용자 + RLS 설정 표시 |

| [↗ 확장] 클릭 | 패널이 전체 페이지로 전환 (탭 구조 유지: ERP 4탭, 비ERP 2탭) |
| [← 목록으로] 클릭 | 전체 확장 해제, 목록 + 패널 레이아웃 복귀 |
| [+ 등록] 클릭 | 비ERP 데이터 소스 등록 다이얼로그 열림 |
| [편집] 클릭 (개요 또는 접근 권한 탭, **비ERP 뷰만**) | 뷰테이블 수정 다이얼로그 열림 |
