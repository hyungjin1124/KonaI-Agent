### 2. AI 채팅

> 단일 화면(2.0) 안에서 좌측 사이드바·중앙 채팅·우측 사이드바가 영역으로 구성됨.
> 각 영역은 별도 화면이 아니라 하나의 화면 내 패널로 동작한다.

| 화면 ID | Depth | 화면명 | 화면 설명 | 화면 유형 | 접근 권한 |
|---------|-------|--------|----------|----------|----------|
| 2.0 | 1depth | AI 채팅 | AI 에이전트와의 대화 기반 업무 수행 인터페이스 | 채팅 (3영역 레이아웃) | 전체 사용자 |
| — | 영역 | 좌측 사이드바: 대화 목록 | 이전 채팅 이력 목록 및 검색. 탭 전환으로 파일 시스템 이동 | 사이드바 탭 | 전체 사용자 |
| — | 영역 | 좌측 사이드바: 파일 시스템 | 클라우드 기반 유저별 파일 시스템. 유저 업로드 문서 및 AI 에이전트 생성 문서 저장 | 사이드바 탭 | 전체 사용자 |
| — | 영역 | 중앙: 대화 화면 | AI 에이전트와의 실시간 대화 영역 | 채팅 | 전체 사용자 |
| — | 영역 | 중앙: Artifact 패널 | 에이전트 생성 결과물(차트, 테이블, 스킬 정의 등) 표시·편집 | 오버레이 패널 | 전체 사용자 |
| — | 영역 | 우측 사이드바: 진행 상황 | AI 에이전트의 작업 계획과 진행 상태 표시 | 사이드바 탭 | 전체 사용자 |
| — | 영역 | 우측 사이드바: 작업 폴더 | AI 에이전트가 현재 세션에서 생성한 파일 목록 | 사이드바 탭 | 전체 사용자 |
| — | 영역 | 우측 사이드바: 컨텍스트 | AI 에이전트가 사용한 스킬, 조회한 뷰 테이블 표시 | 사이드바 탭 | 전체 사용자 |

### 3. 스킬

> 스킬 메인 화면(3.0)이 곧 스킬 목록이므로 별도 목록 화면을 두지 않는다.

| 화면 ID | Depth | 화면명 | 화면 설명 | 화면 유형 | 접근 권한 |
|---------|-------|--------|----------|----------|----------|
| 3.0 | 1depth | 스킬 | AI 에이전트가 호출하는 업무 자동화 도구 목록. 내 스킬 / 전체 필터 전환, 활성 사용자 수 표시 | 목록 (카드) + 필터 | 전체 사용자 |
| 3.1 | 2depth | 스킬 상세 | 개별 스킬의 설명, 사용 현황, 버전 이력, 편집·공유·삭제 기능 제공 | 상세 (탭 구성) | 전체 사용자 |

### 5. 관리자

> **5.2 권한 관리**는 메뉴/기능 접근 권한(RBAC)만 담당한다.
> 테이블/행/컬럼 수준의 데이터 접근 정책은 **4.3 데이터 접근 정책**에서만 설정한다.

| 화면 ID | Depth | 화면명 | 화면 설명 | 화면 유형 | 접근 권한 |
|---------|-------|--------|----------|----------|----------|
| 5.0 | 1depth | 관리자 | 사용자·권한·감사·사용량을 통한 엔터프라이즈급 통제 관리 허브 | 좌측 네비게이션 + 콘텐츠 | 관리자 |
| **5.A** | **카테고리** | **접근 제어** | *누가 어떤 메뉴/기능에 접근하는가* | — | — |
| 5.1 | 2depth | 사용자 관리 | 사용자 계정 생성, 역할 할당, 비활성화 | 목록 + 폼 | 관리자 |
| 5.1.1 | 3depth | 사용자 상세 | 개별 사용자 정보 조회·편집, 역할 할당 | 상세 + 폼 | 관리자 |
| 5.2 | 2depth | 권한 관리 | 역할 정의, 메뉴별·기능별 접근 권한 매트릭스 (데이터 접근 정책은 4.3에서 관리) | 매트릭스 + 폼 | 관리자 |
| 5.2.1 | 3depth | 역할 상세 | 개별 역할의 메뉴/기능 접근 권한 편집 | 폼 | 관리자 |
| 5.2.2 | 3depth | 메뉴 접근 권한 설정 | 역할별 메뉴·화면 접근 허용/차단 설정 | 매트릭스 | 관리자 |
| **5.B** | **카테고리** | **모니터링** | *무슨 일이 일어났는가* | — | — |
| 5.3 | 2depth | 감사 로그 (플랫폼) | 플랫폼 전체 활동 로그 (로그인, 권한 변경, AI 사용 등) | 목록 (로그) | 관리자 |
| 5.4 | 2depth | 사용량 | AI 사용량, API 호출, 토큰 소비, 비용 추적 | 대시보드 (차트 + 테이블) | 관리자 |
| 5.5 | 2depth | AI 거버넌스 | AI 가드레일 설정, 콘텐츠 필터, 모델 접근 제어, 데이터 정책 적용 현황 모니터링 | 대시보드 + 폼 | 관리자 |
| 5.5.1 | 3depth | 가드레일 설정 | AI 행동 제약 규칙 편집 | 폼 | 관리자 |
| **5.C** | **카테고리** | **플랫폼 관리** | *플랫폼 관리자 역할에만 노출* | — | — |
| 5.6 | 2depth | 테넌트 관리 | 고객사(테넌트) 생성, 설정, 격리 관리. Phase 1에서는 단일 테넌트 기본 설정만 제공 | 목록 + 폼 | 플랫폼 관리자 |
| 5.7 | 2depth | 시스템 설정 | 모델 배포, API 키 관리, 시스템 전역 설정. Phase 1에서는 모델 선택, API 키 관리만 제공 | 폼 | 플랫폼 관리자 |

## 접근 권한 체계

### 역할 정의

| 역할 | 설명 | 접근 가능 메뉴 |
|------|------|---------------|
| 전체 사용자 | 일반 직원 | 홈/대시보드, AI 채팅, 스킬 (조회) |
| 스킬 소유자 | 스킬을 생성한 사용자 | + 본인 스킬 편집/버전 관리/A/B 테스트 |
| 데이터 담당자 | 데이터 거버넌스 담당 | + 데이터 메뉴 전체 |
| 관리자 | 조직 관리자 | + 관리자 메뉴 (5.1~5.5) |
| 플랫폼 관리자 | 시스템 운영자 | + 플랫폼 관리 (5.6~5.7) |

### 권한 설정 위치

| 대상 | 설정 위치 | 설명 |
|------|----------|------|
| 메뉴/기능 접근 권한 | 5.2 권한 관리 | 역할별 메뉴·화면·기능 접근 허용/차단 (RBAC) |
| 데이터 접근 권한 | 4.3 데이터 접근 정책 | 역할별 테이블/컬럼/행 수준 세분화 정책 (RLS 등) |
| AI 행동 제약 | 5.5 AI 거버넌스 | 가드레일, 콘텐츠 필터, 모델 접근 제어 |

## 메뉴 간 연결점

### 핵심 연결 (프로토타입 필수)

| 연결 | 방향 | 설명 |
|------|------|------|
| 채팅 → 대시보드 | 단방향 | 채팅 결과를 대시보드 위젯으로 저장 ("대시보드에 저장" 버튼) |
| 대시보드 → 채팅 | 단방향 | KPI/인사이트 클릭 → 채팅에서 심층 분석 ("AI로 분석하기" 버튼) |
| 채팅 ↔ 스킬 | 양방향 | 채팅 중 스킬 자동 호출 + 스킬 결과가 채팅에 표시 (@멘션 또는 자동 트리거) |
| 스킬 → 채팅 | 단방향 | 스킬 상세에서 "채팅에서 실행" 버튼으로 스킬 테스트·실행 |
| 데이터 → 채팅 | 시스템 레벨 | 에이전트가 온톨로지+접근 정책을 참조해 자연어 질의 이해 |
| 관리자 → 전체 | 시스템 레벨 | RBAC 정책이 모든 메뉴의 접근 권한 제어 |

### 보조 연결 (프로토타입 선택)

| 연결 | 설명 | 프로토 포함 |
|------|------|:-----------:|
| 스킬 → 대시보드 | 스킬 실행 결과를 대시보드 위젯으로 추가 | 결정 필요 |
| 스킬 ↔ 데이터 | 스킬이 사용하는 데이터 소스 표시 / 데이터에서 관련 스킬 링크 | 결정 필요 |
| 데이터 → 대시보드 | 데이터 접근 정책(RLS)이 대시보드 위젯 표시에 자동 적용 | 포함 (시스템 레벨) |

## 거버넌스 계층 구조

```
플랫폼 관리자 (5.6~5.7: 시스템 전역 설정)
    ↓ 테넌트/시스템 정책
관리자 (5.1~5.5: RBAC + AI 거버넌스)
    ↓ 역할별 메뉴/기능 접근 권한 + AI 가드레일
데이터 담당자 (4.1~4.4: 데이터 접근 정책)
    ↓ 테이블/행/컬럼 수준 세분화된 정책
에이전트 실행 시 적용
    → 채팅, 스킬, 대시보드에서 데이터 조회 시 3단계 정책 순차 적용
```

### 1. 홈/대시보드 — 리서치 근거

**탭 통합 구조 (AI 인사이트 + KPI 대시보드 + 커스텀 대시보드)**

홈과 대시보드를 단일 페이지에 탭으로 통합한 결정은 feature-architecture.md에 기술된 ServiceNow AI Control Tower 패턴에 근거한다. 엔터프라이즈 AI 플랫폼에서는 "조직 상황 파악"이 단일 진입점에서 이뤄져야 하며, 분리 시 중복 네비게이션이 발생한다.

| 구성 요소 | 리서치 근거 | 벤치마크 서비스 |
|----------|-----------|---------------|
| AI 인사이트 탭 | AI가 자동 발견한 이상 신호를 우선순위순 표시 | ThoughtSpot AI Highlights, Datadog Watchdog Alerts Widget |
| KPI 대시보드 탭 | 상단 4~6개 KPI 카드 + 30일 트렌드 차트 패턴 | `ai-platform-admin-dashboard-patterns.md` — OpenAI Platform, Anthropic Console, AWS Bedrock, Helicone |
| 커스텀 대시보드 탭 | 채팅 분석 결과를 대시보드로 저장하는 도착점 | Databricks Genie→Dashboard, ThoughtSpot Pin to Liveboard |

**리서치 미반영 사항**: `ai-platform-admin-dashboard-patterns.md`에서 권장한 "모델별 비용 분리 차트"와 "에이전트 실행 성공률 KPI 카드"는 현재 IA에 명시되지 않았다. KPI 대시보드(1.2) 위젯 설계 시 반영 필요.

### 2. AI 채팅 — 리서치 근거

**3영역 레이아웃 (좌측 사이드바 + 중앙 채팅 + 우측 사이드바)**

AI 채팅의 레이아웃은 기존 개발 진행 중인 구조를 기반으로 하되, 우측 사이드바(진행 상황·작업 폴더·컨텍스트)를 추가하여 에이전트의 투명성을 확보했다.

| 구성 요소 | 리서치 근거 | 벤치마크 서비스 |
|----------|-----------|---------------|
| 대화 기반 스킬 생성 | 채팅 중 Artifact 패널에서 SKILL.md 실시간 수정 | `skill-creator-ux-workflow-patterns.md` — Claude Code, Coze Plugin Creator, Dify Tool Builder |
| Artifact 패널 | 에이전트 생성 결과물을 채팅 옆에 표시·편집 | Claude Code Artifact 패턴, Anthropic Cowork |
| 파일 시스템 (좌측) | 유저별 클라우드 파일 시스템으로 문서 관리 | v2 피드백에 의한 신규 추가 (자체 요구사항) |
| 우측 사이드바 | 에이전트 작업 계획·생성 파일·사용 컨텍스트 투명 공개 | v2 피드백에 의한 신규 추가 (자체 요구사항) |

**리서치 미반영 사항**: `skill-creator-ux-workflow-patterns.md`에서 언급한 "대화 이력이 사실상 버전 히스토리" 패턴은 스킬 버전 관리(3.1.2)와 채팅 이력 간 연결로 구현 가능하나, 현재 IA에 명시적 연결이 없다.

**리서치 미반영 사항**:

- `ai-platform-admin-dashboard-patterns.md`의 "에이전트 실행 트레이스"(LangSmith 패턴: 입력→추론→도구→출력 경로 시각화)는 현재 IA에 없다. AI 거버넌스(5.5) 또는 사용량(5.4) 하위에 추가 검토 필요
- `platform-admin-patterns.md`의 "Vercel 수준 다단계 알림 웹훅"은 사용량(5.4)의 상세 설계 시 반영 필요
- `tenant-lifecycle-ux-patterns.md`의 "해지 후 30~90일 데이터 보존 정책 안내"는 테넌트 관리(5.6) 상세 설계 시 반영 필요
