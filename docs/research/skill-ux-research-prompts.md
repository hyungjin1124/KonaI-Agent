`````
## 배경: 우리 제품의 현재 설계 (v7)

우리 제품 "KonaI-Agent"는 팀이 AI 에이전트 스킬을 공유하고 관리하는 화면을 만들고 있습니다. 핵심 구조는 다음과 같습니다:

### 화면 구조: 테이블 + 슬라이드 패널
- **전체 폭 테이블**: 팀 내 모든 스킬을 보여주는 테이블. "활성화 그룹"과 "비활성 그룹"으로 나뉨
- **행 클릭 시**: 우측에서 슬라이드 패널이 열리고, 테이블은 축약됨
- 테이블 컬럼: 이름, 한 줄 설명, 카테고리, 작성자, 수정일, 버전, 호출 수, 활성 멤버, 활성화 토글
- **패널 열릴 때 축약 규칙**: 이름 + 작성자 + 호출 수 + 활성화 토글만 유지, 나머지(설명, 카테고리, 수정일, 버전, 활성 멤버) 숨김
- 패널 내 구성: 헤더(메타 정보) → 버전 이력 + AI 변경 인사이트(최상단) → 스킬 콘텐츠(하단, 기본 접힘)
- [↗ 전체 확장] 버튼으로 전체 페이지 전환 가능

### 테이블 구성 (전체 폭 상태 ASCII 목업)

│  │ 매출 분석│ 월별 매출 추이│ 데이터  │ 홍길동│ 2026.03.20│ v3│   47│[홍][김]+3│ON│

### 탐색 규모 및 분류
- **타겟 규모**: 팀 내 10~50개 스킬 (대규모 마켓플레이스가 아닌 팀 카탈로그)
- **그룹핑**: 활성화/비활성 2그룹으로 분리 표시
- **기본 정렬**: 활성 그룹은 호출 수 많은 순, 비활성은 최근 수정일 순
- **필터**: 카테고리(4종), 작성자(팀원 목록), 활성 멤버(팀원 목록)
- **검색**: 이름, 설명, 작성자, 카테고리 기준 실시간 필터링
- **팀 모델**: 1인 1팀, 공유 드라이브 메타포 (올라간 건 모두에게 보임)

### 기존 리서치에서 이미 알려진 것
- Jira, Linear, Notion이 테이블+패널 구조를 사용한다는 것은 확인됨 (구체적 패턴 미분석)
- ChatGPT Enterprise 관리 뷰가 테이블 기반 + 사용 통계 컬럼 + 접근 권한 필터를 제공 (v7 테이블에 가장 유사)
- ChatGPT GPT Store의 카드 기반 + 카테고리 필터는 대규모 탐색용으로, 10~50개 팀 규모에는 과도
- Dify Marketplace의 카드 + 태그 필터 구조
`````

## 세션 B — R2: diff 뷰어 UX 패턴 심화 (P2)

`````
당신은 엔터프라이즈 AI 에이전트 플랫폼의 UX 리서처입니다. "텍스트 기반 diff 뷰어"의 UX 패턴을 심화 리서치해주세요.

## 배경: 우리 제품의 현재 설계 (v7)

우리 제품은 AI 에이전트 스킬의 버전 이력을 관리합니다. 스킬은 마크다운 기반 지시 문서(SKILL.md)이며, 사용자가 채팅으로 스킬을 수정하면 새 버전이 생기고, AI가 변경 요약을 자동 생성합니다.

### 원문 비교(diff) 설계
- **위치**: 슬라이드 패널(폭 약 400~500px) 내, AI 변경 요약 블록 하단의 [원문 비교 →] 링크 클릭 시 인라인으로 펼쳐짐
- **기본 방식**: Unified inline diff (한 컬럼)
  - 삭제: 빨간 배경 + 취소선
  - 추가: 녹색 배경
  - 변경 없는 영역: 전후 2줄 맥락만 유지, 나머지 "··· (변경 없음, N줄) ···"로 접힘
- **전체 확장([↗]) 시**: Unified (기본) + Side-by-side 토글 제공 (폭이 충분하므로)
- **특수 기능**:
  - AI 변경 요약의 태그 색상과 diff 색상 연동 ([추가] → 녹색, [삭제] → 빨간색)
  - AI 요약 항목 클릭 시 해당 변경 위치로 앵커 스크롤
  - 하단에 "추가 N건, 변경 N건, 삭제 N건" 카운트 요약

### 패널 내 diff 목업

```
┌─ 원문 비교: v2 → v3 ────────────────────────┐
│                                               │
│  ## 데이터 분석 프로세스                       │
│                                               │
│  1. 데이터를 수집합니다                        │
│  ██ 1-1. 빈 셀 발견 시 기본값(0)으로          │ ← 추가 (녹색)
│  ██      자동 채움                            │
│  2. ██ 표로 정리합니다 ██                      │ ← 삭제 (빨간 + 취소선)
│     ██ 차트로 시각화합니다 ██                  │ ← 추가 (녹색)
│  3. 결과를 리포트에 포함합니다                 │
│                                               │
│  ··· (변경 없음, 8줄) ···                     │ ← 접힌 영역
│                                               │
│  트리거: '매출 분석', '매출 보고서'            │
│  ██ , '분기 보고서' ██                        │ ← 추가 (녹색 인라인)
│                                               │
│  ─── 변경 요약: 추가 2건, 변경 1건 ──────     │
│                               [닫기]          │
└───────────────────────────────────────────────┘
```

### 설계 근거 (이미 결정된 사항)
- 패널 폭 400~500px에서 side-by-side는 한국어 문장 줄바꿈이 빈번해 비교 어려움
- AI 변경 요약이 "무엇이 바뀌었는지"를 이미 알려준 상태이므로, 원문 비교는 "정말 그런지 확인"하는 보조 용도
- 변경 없는 영역 접기로 긴 스킬에서도 변경 지점만 빠르게 파악 가능

### 기존 리서치에서 알려진 것
- Distill.io의 diff 인라인 패턴 분석 완료 (파란 배경 + 좌측 보더로 AI 콘텐츠 구분)
- AI 요약 블록 배치 패턴 5가지 분석 완료 (diff-inline, editor-inline, timeline bot comment, collapsible panel, content-bottom)
- 비개발자 대상 자연어 diff에 대한 구체적 사례는 미조사

### 핵심 질문
이 diff 뷰어의 사용자는 **비개발자(PM, 기획자, 운영 담당)**입니다. 코드 diff에 익숙하지 않은 사용자가 마크다운/자연어 변경을 쉽게 이해할 수 있는 패턴을 찾아야 합니다.

## 리서치 과제: diff 뷰어 UX 패턴 심화 (R2)

아래 5개 서비스의 diff/변경 비교 UX를 조사해주세요:
1. **GitHub** (코드 diff — unified/split 토글, PR 리뷰)
2. **Google Docs** (제안 모드 — 인라인 추적 변경)
3. **Notion** (페이지 히스토리 — 변경 하이라이트)
4. **WordPress** (포스트 리비전 비교)
5. **Confluence** (페이지 비교)

**각 서비스별로 조사할 항목:**
1. 삭제/추가/변경의 시각적 표현 방식 (색상 코드, 취소선, 배경, 인라인 vs 블록 수준)
2. 변경 없는 영역의 접힘/펼침 규칙 (전후 몇 줄 유지, 접힌 영역 표시 방식)
3. 비개발자 대상 diff에서의 단어 단위 vs 줄 단위 비교
4. 좁은 폭(400~500px)에서의 diff 표시 전략 (반응형 처리, 가로 스크롤 등)
5. 변경 요약↔원문 비교 간 연동 사례 (앵커 링크, 스크롤 연동, 하이라이트 동기화)
6. 마크다운 원문 diff vs 렌더링된(WYSIWYG) diff — 어떤 것을 보여주는가
`````

`````
3. **팀 표시**: 팀 드라이브에 새 행으로 추가
4. **자동 활성화**: 내 채팅에서 자동 활성화
`````
