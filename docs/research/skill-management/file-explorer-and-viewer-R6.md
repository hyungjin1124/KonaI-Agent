# 파일 탐색기 + 콘텐츠 뷰어 통합 UX 리서치 (R6)

> 조사 기준일: 2026-03-25
> 대상: GitHub, VS Code, Notion, GitBook, Storybook
> 목적: 스킬 콘텐츠 뷰어의 레이아웃 및 렌더링 규격 도출
> 핵심 제약: 400~500px 폭의 슬라이드 패널 내 파일 목록 + 콘텐츠 동시 표시

---

## 1. 서비스별 분석

### 1-1. GitHub 코드 뷰어

**파일 탐색 구조**

GitHub의 리포지토리 뷰는 좌측에 접이식(collapsible) 파일 트리 사이드바를 제공하며, 우측 메인 영역에 선택된 파일의 콘텐츠를 렌더링한다. 파일 트리는 계층적 들여쓰기 트리(indented tree) 구조로, 디렉토리는 화살표(▶/▼)로 펼침/접힘을 토글한다. 디렉토리 깊이에 제한은 없으나, 얕은 깊이(1~2단계)에서는 기본 펼침(auto-expand) 처리하여 클릭 수를 줄인다. 파일 아이콘은 확장자별로 컬러/형태가 달라 시각적 구분이 용이하다.

**기본 선택 파일 규칙**

리포지토리 루트에 진입하면 파일 목록 아래에 README.md를 자동으로 렌더링하여 보여준다. 이는 GitHub의 핵심 규칙으로, 하위 디렉토리에서도 해당 디렉토리의 README.md가 존재하면 파일 목록 아래에 렌더링된다. 특정 파일을 클릭하면 해당 파일의 콘텐츠로 전환된다.

**파일 타입별 렌더링**

- Markdown(.md): 렌더링된 HTML로 표시 (헤딩, 테이블, 코드블록 등). 상단에 "Code/Preview" 토글로 원문 전환 가능
- 코드 파일(.py, .js, .ts 등): 구문 강조(syntax highlighting) + 줄번호 표시. Shiki 기반 서버사이드 하이라이팅 적용
- 이미지(.png, .jpg, .svg 등): 인라인 렌더링 (실제 이미지 표시)
- CSV/TSV: 테이블 형태로 자동 렌더링
- PDF: 내장 PDF 뷰어로 표시

**좁은 폭 대응**

모바일 뷰에서 파일 트리 사이드바는 완전히 숨겨지고, 파일 목록은 메인 영역에서 전체 폭으로 표시된다. 파일을 탭하면 콘텐츠 뷰로 전환(페이지 네비게이션 방식)되며, 뒤로가기로 파일 목록으로 복귀한다. 데스크탑에서 사이드바 폭은 약 260px이며, 토글 버튼으로 숨길 수 있다. 2025년 9월 업데이트에서 파일 트리 내 브랜치 전환 UX가 개선되었다.

**줄바꿈 / 스크롤 처리**

코드 파일은 기본적으로 가로 스크롤(horizontal scroll)을 사용한다. 줄바꿈(word wrap)은 사용자가 토글할 수 있으나 기본값은 꺼짐이다. Markdown 렌더링 뷰에서는 콘텐츠 폭에 맞춰 자연스러운 줄바꿈이 적용된다.

**장점**: README.md 우선 렌더링으로 프로젝트 개요 즉시 파악 가능. 파일 타입별 최적화된 렌더링. 확장자 기반 아이콘으로 빠른 파일 식별.
**단점**: 좁은 패널에서 트리+콘텐츠 동시 표시가 어려움. 사이드바 최소 폭이 ~260px로 400px 패널에서는 콘텐츠 영역이 매우 좁아짐.

### 1-2. VS Code 탐색기 + 에디터

**파일 탐색 구조**

VS Code는 좌측 Primary Sidebar(기본 폭 ~300px)에 Explorer 뷰를 배치하고, 우측 Editor 영역에서 파일 콘텐츠를 표시하는 완전 분리형 레이아웃을 사용한다. Explorer의 파일 트리는 계층적 들여쓰기 트리로, 디렉토리 펼침/접힘을 지원한다. 사이드바는 드래그로 폭 조절이 가능하며, Activity Bar 아이콘 클릭으로 토글된다. 3~5개 뷰가 하나의 사이드바에 수직으로 쌓이는 구조(Explorer, Timeline, Outline 등)이다.

**기본 선택 파일 규칙**

VS Code는 마지막 세션 상태를 복원하는 방식으로, 이전에 열었던 파일을 다시 연다. 새 워크스페이스를 열면 아무 파일도 선택되지 않고 Welcome 탭이 표시된다. 파일 단일 클릭 시 "프리뷰 모드"(탭 제목 이탤릭)로 열리며, 더블 클릭 시 고정 탭으로 전환된다. 이는 빠른 파일 탐색 시 탭 과잉 생성을 방지하는 패턴이다.

**파일 타입별 렌더링**

- Markdown: 기본은 원문(raw) 표시이며, 별도 프리뷰 패널(Cmd+Shift+V)로 렌더링 뷰 확인 가능
- 코드: TextMate 문법 기반 구문 강조 + 줄번호. 모든 텍스트 파일에 동일한 에디터 뷰 적용
- 이미지: 내장 이미지 뷰어로 렌더링
- PDF: 확장(extension)을 통해 지원

**좁은 폭 대응**

사이드바는 사용자가 폭을 자유롭게 조절할 수 있다. 매우 좁게 줄이면 파일명이 말줄임표(…)로 잘린다. 사이드바를 완전히 숨길 수도 있으며, 숨긴 상태에서 호버 시 임시 표시하는 옵션은 없다(토글만 가능). 에디터 영역은 별도의 공간을 차지하므로, 400px 패널 내에서 사이드바+에디터를 동시 표시하는 것은 VS Code 패턴과는 맞지 않는다.

**줄바꿈 / 스크롤 처리**

`editor.wordWrap` 설정으로 제어한다. 옵션은 `off`(기본, 가로 스크롤), `on`(뷰포트 폭에 맞춤), `wordWrapColumn`(지정 컬럼), `bounded`(뷰포트 또는 컬럼 중 작은 쪽)이다. Markdown 파일에는 `bounded` 모드가 권장된다. 2020년 v1.42에서 가변폭 폰트 대응 `wrappingStrategy: advanced` 옵션이 추가되었다.

**장점**: 프리뷰 모드로 빠른 파일 훑어보기 가능. 폭 조절 자유도 높음. 줄바꿈 옵션이 세분화됨.
**단점**: 사이드바+에디터가 완전 분리되어 좁은 패널에 통합하기 어려움. 비개발자에게는 진입장벽이 높은 UI.

### 1-3. Notion 페이지 내 파일 뷰어

**파일 탐색 구조**

Notion은 전통적인 파일 트리를 사용하지 않는다. 대신 페이지 내에 블록 단위로 파일을 임베드하는 방식을 채택한다. `/file`, `/image`, `/pdf`, `/embed` 명령어로 각 블록을 삽입하며, 각 블록은 페이지 내 독립적 요소로 존재한다. 데이터베이스에서는 "Files & media" 프로퍼티로 파일을 관리하며, 셀에서 썸네일이나 아이콘으로 표시된다. 파일 간의 계층 관계나 디렉토리 구조 개념이 없다.

**기본 선택 파일 규칙**

파일 목록이라는 개념 자체가 없으며, 페이지의 콘텐츠 순서대로 블록이 표시된다. 첫 번째 임베드된 파일이 자연스럽게 먼저 보이는 구조이다.

**파일 타입별 렌더링**

- 이미지: 인라인 렌더링, 좌우 드래그로 리사이즈 가능
- PDF: 내장 PDF 뷰어(스크롤 가능한 임베드)로 표시. 폭 리사이즈 가능
- 코드: 코드 블록(/code)으로 구문 강조 표시. 약 100여 개 언어 지원
- 일반 파일: 파일명 + 다운로드 링크로 표시
- 비디오/오디오: 내장 플레이어로 재생

**좁은 폭 대응**

Notion은 반응형 설계로, 모바일에서는 각 블록이 전체 폭을 차지한다. 임베드 블록의 좌우 핸들로 폭을 수동 조절할 수 있어 좁은 공간에도 적응 가능하다. PDF 임베드의 경우 좁은 폭에서는 직접 보기보다 "탭하여 열기" 방식으로 전환된다(모바일).

**줄바꿈 / 스크롤 처리**

코드 블록은 기본적으로 줄바꿈을 적용하며, 긴 코드는 가로 스크롤로 처리한다. "Wrap code" 토글 옵션을 제공한다. 일반 텍스트는 항상 블록 폭에 맞춰 줄바꿈된다.

**장점**: 파일 수가 적을 때 매우 직관적. 비개발자도 이해하기 쉬운 블록 기반 UI. 파일별 리사이즈 가능.
**단점**: 여러 파일을 "목록"으로 탐색하는 경험이 없음. 파일 간 빠른 전환이 어려움. 패키지/디렉토리 구조 표현 불가.

### 1-4. GitBook 문서 사이드바 + 콘텐츠

**파일 탐색 구조**

GitBook은 좌측에 Table of Contents(TOC) 사이드바를 배치하고, 우측에 페이지 콘텐츠를 표시하는 2컬럼 레이아웃을 사용한다. TOC는 페이지와 페이지 그룹으로 구성된 계층적 트리이며, 최대 3단계 깊이가 권장된다. 각 페이지에 아이콘/이모지를 추가하여 시각적 구분이 가능하다. 2025년 5월 사이드바 리디자인에서 Linear에서 영감을 받은 "hover-to-show" 패턴을 도입하여, 사이드바를 접으면 화면 왼쪽 가장자리에 마우스를 가져갈 때만 나타나도록 했다. 사이드바 폭은 사용자가 드래그로 조절 가능하며, 콘텐츠가 30% 더 컴팩트해졌다.

**기본 선택 파일 규칙**

TOC의 첫 번째 페이지가 항상 스페이스의 랜딩 페이지로 기능한다. 숨겨진 페이지라도 TOC의 첫 항목이 랜딩 페이지다.

**파일 타입별 렌더링**

- Markdown: 완전 렌더링(WYSIWYG). 헤딩, 테이블, 코드 블록, 이미지, 임베드 등 모두 렌더링
- 코드 블록: 구문 강조 + 복사 버튼. "Wide" 레이아웃 선택 시 코드 블록이 전체 폭으로 확장
- 이미지: 인라인 렌더링 + 갤러리 뷰
- PDF: 임베드 또는 파일 링크
- OpenAPI: 전용 API 문서 블록으로 인터랙티브 표시

**좁은 폭 대응**

공개 문서 사이트에서 모바일 뷰는 사이드바를 햄버거 메뉴 뒤로 숨긴다. 에디터에서는 사이드바 숨기기 버튼 또는 화면 가장자리 호버로 토글한다. 페이지 레이아웃 옵션(Docs, Landing, Custom)으로 TOC, 페이지 아웃라인 등의 표시/숨김을 제어할 수 있다. 콘텐츠 영역은 `max-width`로 가독성을 유지하되, "Wide" 모드에서는 테이블과 코드 블록이 넓게 펼쳐진다.

**줄바꿈 / 스크롤 처리**

코드 블록은 가로 스크롤로 처리하되, 블록 자체의 폭을 "Wide"로 설정하면 더 많은 코드를 한 줄에 표시할 수 있다. 일반 텍스트는 콘텐츠 영역 폭에 맞춰 자동 줄바꿈된다.

**장점**: TOC가 문서 구조를 명확히 보여줌. 호버 기반 사이드바로 공간 효율 극대화. 페이지 그룹으로 논리적 분류 가능. 아이콘/이모지로 비개발자 친화적.
**단점**: "파일" 단위가 아닌 "페이지" 단위로 설계되어, 파일 패키지 뷰어에 직접 적용은 제한적. 코드 중심 콘텐츠에는 최적화되지 않음.

### 1-5. Storybook 컴포넌트 트리 + 프리뷰

**파일 탐색 구조**

Storybook은 좌측 사이드바에 컴포넌트 트리를, 우측에 Canvas(프리뷰) 및 Addon 패널을 배치한다. 사이드바 트리는 `/` 구분자 기반의 계층 구조로 "Root > Folder > Component > Story" 순이다. 기본 사이드바 폭은 300px이며, `navSize` 설정으로 조절 가능하다. 최상위 노드는 "roots"로 표시되어 확장 불가능한 섹션 헤더로 작동하고, 하위 그룹은 폴더로 표시된다. "Expand all" 기능으로 특정 루트 아래의 모든 폴더를 한 번에 펼칠 수 있다. 퍼지 매칭 기반 검색(finder) 기능과 "최근 열람" 히스토리도 제공한다.

**기본 선택 파일 규칙**

`storySort` 함수로 사이드바 정렬 순서를 커스터마이즈할 수 있다. 기본적으로는 import 순서대로 정렬된다. 단일 스토리 컴포넌트(형제 스토리 없이 이름이 컴포넌트명과 일치)는 자동으로 부모 컴포넌트 레벨로 "호이스팅"되어, 불필요한 한 단계 깊이를 제거한다.

**파일 타입별 렌더링**

Storybook의 프리뷰 영역은 컴포넌트를 실제 렌더링한다. 레이아웃 옵션으로 `centered`(중앙 정렬), `fullscreen`(전체 폭), `padded`(기본, 패딩 포함)을 제공한다. Docs 탭에서는 MDX 기반 문서를 렌더링하며, 인라인 코드 예제와 컴포넌트 프리뷰를 혼합 표시한다. Addon 패널(하단 또는 우측)에서 Controls, Actions, Accessibility 검사 등을 제공한다.

**좁은 폭 대응**

사이드바는 `showSidebar` 함수로 조건부 숨김/표시가 가능하다. 키보드 단축키로도 토글된다. 좁은 화면에서는 사이드바를 숨기고 프리뷰에 집중하는 패턴이 일반적이다. 사이드바와 Canvas는 리사이즈 불가한 고정 비율이 아닌, `navSize` 설정으로 제어된다.

**줄바꿈 / 스크롤 처리**

Docs 뷰의 코드 블록은 가로 스크롤 처리된다. Canvas 프리뷰는 `layout` 파라미터에 따라 컴포넌트가 배치되며, 컴포넌트 자체의 반응형 동작을 따른다.

**장점**: 단일 스토리 호이스팅으로 불필요한 깊이 제거. 검색+최근 열람으로 대규모 라이브러리 탐색 용이. 조건부 UI 커스터마이즈 가능.
**단점**: 컴포넌트 프리뷰 특화 설계로, 파일 콘텐츠 뷰어에 직접 적용하기 어려움. 비개발자에게 복잡한 트리 구조.

## 2. 패턴 비교

### 2.1 파일 탐색 구조 비교표

## 3. KonaI-Agent 적용 권장안

### 3.1 파일 목록 레이아웃 권장안

**핵심 결정: 적응형 하이브리드 (파일 수에 따라 전환)**

400~500px 폭에서 트리와 콘텐츠를 좌우 분할하면 양쪽 모두 가독성이 심각하게 저하된다. 조사된 모든 서비스가 좁은 폭에서는 트리와 콘텐츠를 동시 표시하지 않고, 숨기기/토글/전환 방식을 채택한다.

**권장 레이아웃: 세로 배치 (파일 목록 상단 → 콘텐츠 하단)**

```
┌─────────────────────────────────┐
│ ▼ 스킬 콘텐츠                    │  ← 접힘/펼침 토글
├─────────────────────────────────┤
│ ● SKILL.md                      │  ← 파일 목록 (컴팩트)
│   scripts/extract_data.py       │
│   references/report-template.md │
│   assets/logo.png               │
├─────────────────────────────────┤
│                                 │
│  [선택된 파일 콘텐츠]              │  ← 콘텐츠 영역
│                                 │
│                                 │
└─────────────────────────────────┘
```

**파일 수에 따른 적응형 표시:**

- **단일 파일 (SKILL.md만 있는 경우)**: 파일 목록 영역을 완전히 생략하고, 콘텐츠만 전체 표시. 파일명은 콘텐츠 상단 헤더로 표시. *근거: 대부분의 스킬이 단일 파일이므로, 불필요한 UI 요소를 제거하여 콘텐츠에 집중*
- **2~4개 파일**: 컴팩트 플랫 리스트 (위 목업 형태). 각 파일은 한 줄, 아이콘 + 파일명. 선택된 파일은 배경색 강조. *근거: 깊이가 1~2단계이고 파일이 적으면 트리보다 플랫 리스트가 더 간결*
- **5개 이상 파일**: 인덴트 트리 (디렉토리별 그룹화). scripts/, references/, assets/ 디렉토리를 접힘 가능하게 표시. SKILL.md는 트리 최상단에 고정. *근거: GitHub 패턴을 따라 디렉토리별 시각적 그룹화 제공*

**목록 위치: 상단 고정**

GitBook의 TOC 패턴에서 차용하여, 파일 목록을 콘텐츠 위에 고정 배치한다. 콘텐츠 영역만 스크롤되고, 파일 목록은 항상 보인다. 파일 수가 5개 이상일 때는 파일 목록 영역의 최대 높이를 제한(~120px)하고, 내부 스크롤을 적용한다.

---

### 3.2 콘텐츠 렌더링 규격

**SKILL.md 렌더링 방식: 렌더링된 마크다운 (기본) + 원문 토글**

- 기본값: GitHub 패턴을 따라 Markdown을 HTML로 렌더링하여 표시. 헤딩, 리스트, 코드 블록, 링크 등이 포맷팅된 상태로 표시됨
- 토글: 콘텐츠 상단에 "렌더링 / 원문" 토글 버튼 제공. 원문 모드에서는 YAML 프론트매터 포함 전체 텍스트를 코드 뷰 형태로 표시
- YAML 프론트매터 처리: 렌더링 모드에서는 프론트매터를 파싱하여 메타데이터 카드(이름, 설명 등)로 구조화 표시하거나, 비개발자를 위해 완전히 숨김 처리. 원문 모드에서만 전체 표시
- *근거: GitHub은 README를 렌더링하여 보여주며, GitBook도 WYSIWYG 렌더링을 기본으로 한다. 비개발자가 YAML 프론트매터 원문을 보면 혼란을 겪을 수 있음*

**코드 하이라이팅 범위:**

- .py, .js, .ts, .sh, .bash, .yaml, .yml, .json, .toml, .xml, .html, .css 등 주요 언어 지원
- 줄번호 표시 (GitHub 패턴)
- 복사 버튼 제공 (GitBook 패턴)
- 구문 강조 라이브러리: Prism.js 또는 Shiki 권장 (400~500px 폭에서 번들 크기 고려 시 Prism.js가 가벼움)

**이미지 프리뷰 규격:**

- 이미지는 콘텐츠 영역 폭에 맞춰 자동 리사이즈 (max-width: 100%)
- 클릭 시 원본 크기 모달 또는 새 탭으로 확대 (Notion 패턴)
- 지원 포맷: PNG, JPG, GIF, SVG, WebP
- 작은 아이콘/로고 이미지는 원본 크기 유지 (max-width 제한 내에서)

### 3.3 좁은 패널(400~500px) 최적화

**파일 목록 + 콘텐츠의 공간 배분:**

- 좌우 분할은 사용하지 않는다. 모든 조사 서비스가 400px 이하에서 좌우 분할을 포기함
- 파일 목록: 높이 고정(파일당 32px, 최대 4파일 표시 = ~128px). 5개 이상일 때 내부 스크롤
- 콘텐츠: 나머지 영역 전체. 세로 스크롤로 긴 콘텐츠 탐색
- 전체 "스킬 콘텐츠" 섹션은 접힘/펼침 토글로 필요 시 공간 확보

**줄바꿈 vs 가로 스크롤 규칙:**

| 콘텐츠 타입 | 처리 방식 | 근거 |
|------------|-----------|------|
| Markdown 렌더링 | 자동 줄바꿈 | 일반 텍스트는 폭에 맞춰야 가독성 유지 |
| 코드 파일 (.py, .js 등) | 가로 스크롤 (기본) | 코드 들여쓰기를 보존해야 의미 전달. GitHub, VS Code 모두 코드에는 가로 스크롤 기본 |
| YAML/JSON 설정 파일 | 가로 스크롤 | 구조적 들여쓰기 보존 필요 |
| CSV/TSV | 테이블 렌더링 + 가로 스크롤 | GitHub 패턴 차용 |
| 긴 파일 경로/URL | 줄바꿈 허용 (word-break: break-all) | 400px에서 긴 URL은 반드시 줄바꿈 |

코드 블록 가로 스크롤 시 스크롤바는 항상 표시(auto-hide 하지 않음)하여 스크롤 가능함을 시각적으로 암시한다.

**단일 파일 스킬 시 간소화:**

```
┌─────────────────────────────────┐
│ ▼ 스킬 콘텐츠                    │
├─────────────────────────────────┤
│  SKILL.md  [렌더링 ▾]           │  ← 파일명 + 뷰 모드 토글
├─────────────────────────────────┤
│                                 │
│  ## 스킬 이름                    │
│  이 스킬은 ...                   │  ← 콘텐츠 직접 표시
│                                 │
└─────────────────────────────────┘
```

단일 파일이면 파일 목록을 별도 영역으로 분리하지 않고, 콘텐츠 상단에 파일명만 표시한다. 이는 전체 패널 높이를 콘텐츠에 할당하여 가독성을 극대화한다.

### 3.4 비개발자 고려사항

**YAML 프론트매터 표시 전략:**

- 렌더링 모드(기본)에서는 YAML 프론트매터를 **숨기거나** 구조화된 메타데이터 카드로 변환하여 표시한다
- 메타데이터 카드 예시: "이름: XXX | 설명: YYY | 트리거: ZZZ" 형태의 라벨+값 쌍
- "원문 보기" 토글 시에만 YAML 전체가 코드 블록으로 표시됨
- *근거: Notion은 데이터베이스 프로퍼티를 사람이 읽기 쉬운 형태로 변환하여 보여줌. YAML 원문은 비개발자에게 `---` 구분자, 키-값 구문 등이 혼란스러움*

**기술적 파일(scripts/)의 표시 전략:**

- 파일 목록에서 scripts/ 디렉토리 파일은 코드 아이콘(🔧 또는 `</>`) + 파일명으로 표시
- 파일 타입 라벨을 작은 뱃지로 추가: `extract_data.py` → `extract_data.py` `Python`
- 코드 파일 선택 시 상단에 안내 메시지: "이 파일은 스킬이 실행할 때 사용하는 스크립트입니다"
- 읽기 전용이므로 "편집하려면 채팅에서 요청하세요"와 같은 행동 유도 문구(CTA) 제공
- *근거: GitBook은 페이지별 설명을 제공하고, Storybook은 Docs 뷰에서 컴포넌트 설명을 함께 보여줌. 맥락 없는 코드는 비개발자에게 불안감을 줄 수 있음*

**파일 아이콘 체계:**

| 파일 타입 | 아이콘 | 색상 제안 |
|-----------|--------|-----------|
| SKILL.md (핵심 파일) | 📄 또는 별표 강조 문서 | Primary 컬러 (강조) |
| .md, .txt | 📝 문서 | 기본 텍스트 컬러 |
| .py, .js, .sh | ⚙️ 또는 코드 괄호 | Blue/Purple 계열 |
| .png, .jpg, .svg | 🖼️ 이미지 | Green 계열 |
| .pdf | 📕 PDF | Red 계열 |
| .csv, .json, .yaml | 📊 데이터 | Orange 계열 |

SKILL.md는 "핵심 파일"임을 시각적으로 강조(볼드, Primary 컬러, 또는 스타 아이콘)하여, 비개발자가 어떤 파일이 가장 중요한지 즉시 인지할 수 있도록 한다.

## 5. 추가 고려사항

**접근성(Accessibility):**

파일 목록에 키보드 내비게이션(↑↓ 방향키로 파일 선택, Enter로 열기)을 지원하고, 선택된 파일에 `aria-selected` 속성을 적용한다. 콘텐츠 영역은 `role="region"`으로 랜드마크를 제공한다.

**성능:**

대용량 파일(수백 줄 이상의 코드)은 가상 스크롤(virtual scrolling)을 적용하여 초기 렌더링 성능을 확보한다. 이미지는 레이지 로딩을 적용한다.

**향후 확장:**

파일 비교(diff) 뷰, 파일 검색, 파일 다운로드 등의 기능은 현재 v7 스코프에서는 제외하되, 콘텐츠 영역 상단의 액션 바 공간을 확보해두어 향후 추가를 용이하게 한다.
