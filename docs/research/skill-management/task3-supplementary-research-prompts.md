## 보완이 필요한 5개 영역

### 영역 1: 스킬 데이터 모델 확장 — Eval/Benchmark 메타데이터 UI 표현

**부족한 이유**: 기존 리서치는 Eval/Benchmark 기능의 존재와 작동 원리를 설명했지만, 이 데이터를 스킬 관리 UI에 어떻게 표시할지에 대한 참조가 없다. 현재 코드의 Skill 인터페이스는 `{ id, title, description, isEnabled, type }` 5개 필드뿐이어서, 어떤 메타데이터를 추가하고 어떻게 시각화할지 결정하려면 실제 Eval 결과의 데이터 구조와 다른 도구들의 표현 방식을 알아야 한다.

---

### 영역 2: 멀티테넌트 스킬 계층 구조 — 3-tier를 우리 시스템에 매핑

**부족한 이유**: 기존 리서치에서 "개인 > 프로젝트 > 엔터프라이즈" 3계층 우선순위를 설명했지만, 우리 SaaS의 관리자 구조(플랫폼 관리자 → 테넌트 관리자 → 개인 사용자)와 어떻게 대응되는지 분석이 없다. 현재 SkillManagementView는 `type: 'my' | 'example'` 2분류뿐이어서, 조직 프로비저닝 스킬을 어디에 표시하고 누가 관리할 수 있는지 설계하려면 다른 멀티테넌트 SaaS의 확장/플러그인 관리 패턴을 참조해야 한다.

---

### 영역 3: 스킬 마켓플레이스/디렉토리 UX 패턴

**부족한 이유**: 기존 리서치에서 서드파티 마켓플레이스(SkillsMP, Tessl, Antigravity)를 나열했지만, 이들의 실제 UI/UX 패턴(검색, 카테고리, 설치 플로우, 리뷰/평점)을 분석하지 않았다. 현재 코드의 "스킬 탐색" 탭은 하드코딩된 6개 예시 스킬 목록이므로, 실제 마켓플레이스/디렉토리 경험을 구축하려면 참조 모델이 필요하다.

---

### 영역 4: P2P 스킬 공유 대안 및 팀 협업 패턴

**부족한 이유**: 기존 리서치에서 "P2P 스킬 공유는 현재 지원되지 않는다"고 밝혔지만, 이 공백을 우리 제품에서 어떻게 다룰지 방향이 없다. 우리 시스템의 사용자들(같은 테넌트 내 팀원들)이 자체 제작한 스킬을 공유하려면, Anthropic의 공식 지원을 기다릴지, 자체 공유 메커니즘을 만들지, 기존 서드파티 방식을 참조할지 결정해야 한다.

---

### 영역 5: 스킬 버전 관리 + Eval 연동 실무 패턴

**부족한 이유**: 기존 리서치에서 API 수준의 버전 관리와 Eval 반복별 스냅샷을 설명했지만, 이를 GUI에서 어떻게 표현할지(버전 목록, 비교 뷰, 롤백 UI)에 대한 참조가 없다. Tessl Registry가 버전+Eval 결과를 연결한다고 언급했지만, 구체적 UX 패턴이 빠져 있다.

## Claude Web 리서치 프롬프트

### 프롬프트 1: Eval/Benchmark 메타데이터의 UI 표현 패턴

```
Anthropic의 skill-creator Eval 시스템이 생성하는 평가 결과의 데이터 구조를 조사해줘.

구체적으로 알고 싶은 것:

1. Eval 실행 결과에 포함되는 필드들 (통과율, 실패 케이스, 실행 시간, 토큰 사용량 등)
2. Benchmark 스냅샷의 구체적 데이터 포맷
3. 이 데이터가 로컬에 어떤 디렉토리/파일 구조로 저장되는지
4. Comparator(A/B 비교)의 결과 포맷

그리고, 이런 테스트/품질 메타데이터를 플러그인이나 확장 프로그램의 관리 UI에서 시각화하는 사례를 조사해줘:
- VS Code Extension Marketplace의 품질 지표 (다운로드 수, 평점, 호환성 배지)
- Terraform Registry의 모듈 상세 페이지 (버전별 테스트 상태, 호환성 매트릭스)
- npm 패키지 상세 페이지 (번들 사이즈, 테스트 커버리지 배지, 주간 다운로드)
- Tessl Registry의 스킬 상세 페이지 (있다면)

각 사례에서 "품질/신뢰도 정보를 카드나 목록 아이템에 어떻게 요약 표시하는지"와 "상세 페이지에서 어떻게 펼쳐서 보여주는지" 두 가지 관점으로 정리해줘.

우리 시스템 컨텍스트:
- 스킬 관리 화면에서 각 스킬을 카드 형태로 보여주고 있음 (제목, 설명, on/off 토글)
- 여기에 Eval 통과율이나 마지막 벤치마크 점수 같은 메타데이터를 추가하려고 함
- 비개발자(도메인 전문가)도 쉽게 이해할 수 있는 표현이어야 함

결과를 마크다운으로 정리해서 다운로드할 수 있게 해줘.
파일명: skills-eval-ui-patterns.md
```

### 프롬프트 2: 멀티테넌트 SaaS의 확장/플러그인 계층 관리 패턴

```
멀티테넌트 SaaS 제품에서 확장(extension), 플러그인, 또는 앱을 3계층(플랫폼 → 테넌트 → 개인)으로 관리하는 UX 패턴을 조사해줘.

구체적으로 비교 분석할 제품들:

1. Slack — 워크스페이스 관리자가 앱을 승인/제한하고, 개인이 추가하는 2-tier 모델
2. Salesforce AppExchange — 조직 관리자가 설치하고, 사용자별 권한을 부여하는 모델
3. Shopify App Store — 스토어 오너가 설치하고, 스태프별 접근 권한을 설정하는 모델
4. Notion — 워크스페이스 관리자가 통합(integration)을 승인하는 모델
5. Microsoft Teams — 조직 관리자가 앱 정책을 설정하고, 팀/개인 수준에서 추가하는 3-tier 모델

각 제품에서 다음을 정리해줘:
- 관리 계층 구조 (누가 설치/활성화/비활성화/삭제할 수 있는가)
- 관리자가 "이 확장은 전체 조직에 기본 활성화" 또는 "이 확장은 특정 팀만 사용 가능" 같은 정책을 어떻게 설정하는지
- 개인 사용자가 관리자 정책과 별도로 자신의 확장을 커스터마이즈할 수 있는 범위
- "이 확장은 관리자가 설치한 것" vs "내가 직접 추가한 것"을 UI에서 어떻게 구분하는지 (배지, 라벨, 아이콘, 색상 등)
- 조직 전체에 배포된 확장을 개인이 끌 수 있는지 여부 (강제 vs 선택)

우리 시스템 컨텍스트:
- 멀티테넌트 AI 에이전트 플랫폼 (코나체인)
- 3계층 관리: 플랫폼 관리자(우리 팀) → 테넌트 관리자(고객사 IT관리자) → 개인 사용자
- 현재 스킬 관리 화면은 "내 스킬" / "스킬 탐색" 2분류만 있음
- Anthropic의 조직 프로비저닝 스킬(2025년 12월 출시)을 참고하되, 우리 3계층에 맞게 확장해야 함

비교표 형태로 정리하고, 우리 시스템에 가장 적합한 모델이 무엇인지 추천도 포함해줘.
파일명: multi-tenant-extension-management-patterns.md
```

### 프롬프트 3: 스킬 마켓플레이스/디렉토리 UX 상세 분석

```
AI 에이전트 스킬 또는 플러그인의 마켓플레이스/디렉토리 UI를 상세 분석해줘.

조사 대상:

1차 (AI 에이전트 스킬 전용):
- Anthropic Skills Directory (2025년 12월 출시, Notion/Figma/Atlassian/Canva 파트너 스킬 포함)
- SkillsMP.com (500,000+ 스킬 인덱싱)
- Antigravity awesome-skills (1,234+ 큐레이션, GitHub 22,000+ 스타)
- Claude Code 플러그인 마켓플레이스 (/plugin marketplace 명령어)

2차 (참조 마켓플레이스):
- VS Code Extension Marketplace
- Raycast Store
- Zapier App Directory
- ChatGPT GPT Store

각 마켓플레이스에서 다음을 분석해줘:

검색/탐색 UX:
- 카테고리 분류 체계 (depth, 항목 수)
- 검색 필터 (호환성, 인기도, 최신순, 평점)
- 추천/큐레이션 방식 (에디터 추천, 인기 목록, "이 스킬을 쓴 사람이 같이 쓴 스킬")

스킬 카드 UI:
- 카드에 표시되는 정보 (아이콘, 이름, 설명, 제작자, 다운로드 수, 평점, 호환성 배지)
- 카드 크기/레이아웃 (그리드 vs 리스트)

스킬 상세 페이지:
- 구성 요소 (설명, 스크린샷/데모, 설치 방법, 변경 로그, 리뷰/평점, 관련 스킬)
- "설치" 버튼의 동작 (원클릭 설치, 설정 필요, 관리자 승인 필요)

설치 후 관리:
- 설치된 확장 목록 UI
- 업데이트 알림 방식
- 활성화/비활성화 토글 UX

우리 시스템 컨텍스트:
- 현재 "스킬 탐색" 탭에 6개 하드코딩된 예시 스킬이 있음 (제목 + 설명 + on/off 토글)
- 이것을 실제 디렉토리/마켓플레이스 경험으로 확장하려 함
- 사용자는 한국 기업의 도메인 전문가 (비개발자 포함)
- 스킬 수는 초기 20-50개 → 장기적으로 수백 개 예상

분석 결과를 마크다운으로 정리해줘. 가능하면 UI 패턴별로 ASCII 와이어프레임 스케치도 포함해줘.
파일명: skill-marketplace-ux-analysis.md
```

### 프롬프트 4: 팀 내 스킬 공유 및 협업 워크플로우

```
AI 에이전트 스킬(또는 유사한 자동화 단위)을 팀 내에서 공유하고 협업하는 워크플로우 패턴을 조사해줘.

배경:
- Anthropic은 현재 P2P 스킬 공유를 공식 지원하지 않음
- 배포 경로는: 조직 프로비저닝, Git 커밋(.claude/skills/), 플러그인 마켓플레이스 3가지
- 우리는 같은 테넌트(고객사) 내 팀원들이 자체 제작 스킬을 편하게 공유하는 경험을 만들고 싶음

조사해줘:

1. 현재 Anthropic 생태계에서 스킬 공유가 실제로 어떻게 이루어지는지:
   - Git 기반 (.claude/skills/ 커밋 → 팀원 pull)
   - 플러그인 마켓플레이스 (marketplace.json 등록 → /plugin install)
   - 수동 공유 (파일 전달 → 개인 폴더에 복사)
   - 각 방법의 장단점, 실제 사용자 후기

2. 유사 제품의 팀 내 공유 패턴:
   - Zapier: 팀 내 Zap 공유/복사
   - Make(Integromat): 팀 시나리오 공유
   - Notion: 워크스페이스 내 템플릿 공유
   - Figma: 팀 라이브러리/컴포넌트 공유
   - 각 제품의 "공유 → 발견 → 설치 → 피드백" 사이클

3. 공유 UX에서 중요한 요소:
   - 공유할 때: 공유 범위 설정(전체 조직 / 특정 팀 / 특정 인원), 권한(보기만 / 수정 / 복제)
   - 발견할 때: 팀 내부 디렉토리, 추천, "최근 팀에서 인기" 같은 큐레이션
   - 설치 후: 원본 수정 시 알림, 포크/복제 관계 추적

우리 시스템 컨텍스트:
- 멀티테넌트 SaaS, 테넌트 내 사용자 수: 50-500명
- 스킬 제작자는 소수(5-10명), 소비자가 다수
- 비개발자도 스킬을 소비(활성화/비활성화)할 수 있어야 함
- 현재 스킬 업로드는 .zip/.skill 파일 드래그앤드롭 방식

파일명: team-skill-sharing-patterns.md
```

### 프롬프트 5: 스킬 버전 관리 + Eval 연동 GUI 패턴

```
소프트웨어 아티팩트의 버전 관리와 품질 테스트 결과를 연동하여 GUI로 보여주는 UX 패턴을 조사해줘.

조사 대상:

1. Terraform Registry 모듈 상세 페이지:
   - 버전 목록, 각 버전의 호환성 매트릭스, 변경 로그
   - 버전 간 전환 UI

2. Docker Hub 이미지 상세 페이지:
   - 태그별 보안 스캔 결과, 이미지 계층 정보
   - 취약점 요약을 태그 목록에 인라인으로 표시하는 방식

3. GitHub Actions Marketplace:
   - 액션 버전, 검증 배지, 사용 통계
   - 버전 선택과 워크플로우 통합 UX

4. TestRail / Allure Report:
   - 테스트 실행 결과의 시각화 (통과/실패/스킵 비율, 트렌드 차트)
   - 테스트 히스토리를 타임라인으로 보여주는 방식

5. Tessl Registry (AI 스킬 전용):
   - 버전 고정 평가 결과
   - CI/CD 통합으로 새 게시마다 자동 평가 실행
   - 있다면 구체적 UI 스크린샷이나 문서

각 사례에서:
- 버전 목록을 어떻게 표시하는가 (드롭다운, 타임라인, 테이블)
- 각 버전에 연결된 테스트/품질 결과를 어떻게 요약 표시하는가
- "이전 버전으로 롤백" 동작이 있는가, 어떻게 작동하는가
- 두 버전을 비교하는 diff/compare 뷰가 있는가

우리 시스템 컨텍스트:
- 에이전트 스킬의 버전을 관리하고, 각 버전의 Eval 통과율/벤치마크 점수를 연결해서 보여주려 함
- 스킬 관리자(IT관리자)가 "이 스킬 v2.0이 v1.5보다 성능이 좋은가?"를 판단할 수 있어야 함
- 문제 발생 시 이전 버전으로 롤백하는 동작이 필요
- 비개발자도 이해할 수 있는 직관적 UI가 필수

파일명: skill-versioning-eval-ui-patterns.md
```
