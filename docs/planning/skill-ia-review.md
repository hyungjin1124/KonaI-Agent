# 기획(03-skill-ia.md v4) vs 코드 불일치 리뷰

> **기획 문서**: `design/ia-design/03-skill-ia.md` (v4.1, 2026-03-24)
> **검토일**: 2026-03-24 (2차 리뷰)
> **목적**: 아래 항목을 순서대로 수정하여 기획 의도와 코드를 일치시킨다.

### 설계 전제 (리뷰 중 확인)

1. **저장 = 채팅 적용**: 수정본을 저장하면 내 채팅에서 원본 대신 수정본이 즉시 적용된다. 별도의 "테스트 시작" 동작 없음. 기존 `DraftStatus`의 `'testing'`이 이 상태를 표현한다.
2. **뱃지는 본인만**: 수정본 상태 뱃지(편집 중, 수정본 등)는 수정본 소유자 본인에게만 표시된다. 다른 팀원에게는 보이지 않는다.

---

## 1. 패널 상태별 액션 구조 — "..." 메뉴 미구현

**기획 의도 (§3.2 패널 상태별 액션):**
| 패널 상태 | 직접 노출 | "..." 메뉴 |
|-----------|----------|-----------|
| 수정본 없음 | [편집] | 채팅에서 편집, 삭제 |
| 수정본 있음 | [편집], [개선 제안 제출] | 채팅에서 편집, 수정본 폐기 |
| 편집 모드 | [저장] | 수정본 폐기 |

**현재 코드:**
- `SkillSlidePanelHeader.tsx`: [편집], [채팅에서 편집], [삭제/폐기 요청] 모두 플랫 버튼으로 노출. "..." DropdownMenu 없음.
- 편집 모드(`DraftEditContent.tsx`): [테스트], [저장], [개선 제안 제출], [수정본 폐기] 모두 하단 바에 플랫 노출. "..." 메뉴 없음.
- **[테스트] 버튼이 별도로 존재** — 저장 = 채팅 적용이므로 별도 테스트 버튼 불필요.

**수정 방향:**
- `SkillSlidePanelHeader.tsx`: 주요 액션만 직접 노출, 나머지를 Radix `DropdownMenu`의 "..." 버튼(`MoreHorizontal` 아이콘)으로 이동
  - 수정본 없음: [편집] 직접 노출 → "..." 메뉴에 [채팅에서 편집], [삭제]
  - 수정본 있음: [편집], [개선 제안 제출] 직접 노출 → "..." 메뉴에 [채팅에서 편집], [수정본 폐기]
- 편집 모드 상단 바(`DraftEditHeader`): [저장] 직접 노출 → "..." 메뉴에 [수정본 폐기]
- 하단 바의 [테스트] 버튼 제거

**파일:** `SkillSlidePanelHeader.tsx`, `DraftEditContent.tsx`, `SkillSlidePanel.tsx`

## 2. 패널이 "내 현재 버전"을 표시하지 않음

**기획 의도 (§3.2):**
> 패널은 항상 **"내 현재 버전"**을 표시한다. 수정본이 없으면 원본, **수정본이 있으면 수정본이 표시**된다.

**현재 코드 (`SkillSlidePanel.tsx`):**
- 패널을 열면 항상 **원본**을 읽기 전용으로 보여줌
- 수정본이 있으면 "수정본이 있습니다" 배너 + [수정본으로 전환] 버튼이 표시됨
- 사용자가 수동으로 전환해야 수정본을 볼 수 있음

**기획과의 차이:**
- 기획: 수정본이 있으면 **자동으로** 수정본 내용이 읽기 전용으로 표시됨 (내 채팅에 적용 중인 버전)
- 코드: 원본을 보여주고 배너로 전환 유도 → 기획 의도와 반대

**수정 방향:**
- `SkillSlidePanel.tsx`의 읽기 모드에서, `skill.myDraft`가 존재하면 수정본(draft)의 내용으로 콘텐츠 영역을 표시
  - `FileContentView`에 전달하는 데이터를 draft의 `instructionBody`, `attachments` 등으로 교체
- 헤더에 "수정본 적용 중" 라벨/뱃지로 수정본을 보고 있음을 명시
- [편집] 클릭 시 편집 모드 전환 (기존 로직 유지)
- 원본을 보려면 편집 모드의 [원본] 토글 사용

**파일:** `SkillSlidePanel.tsx`, `SkillSlidePanelHeader.tsx`

## 3. [저장] 후 편집 모드 종료 미구현

**기획 의도 (§3.3, §6.2):**
> [저장] 후 흐름: 저장 → 내 채팅에 즉시 적용 → **편집 모드 종료** → 수정본 내용이 읽기 전용으로 표시

**현재 코드 (`DraftEditContent.tsx`):**
- `handleSave()`는 `onSaveDraft()`만 호출하고 편집 모드를 종료하지 않음
- 저장 후에도 계속 편집 모드에 머무름

**수정 방향:**
- 저장 시 draft의 status를 `'testing'`으로 전환 (저장 = 채팅 적용)
- `SkillSlidePanel.tsx`에서 저장 후 `setIsInDraftMode(false)` 호출하여 읽기 전용 뷰로 복귀
- 읽기 전용 뷰에서 수정본 내용 표시 (#2와 연동)

**파일:** `SkillSlidePanel.tsx`, `DraftEditContent.tsx`

## 4. [개선 제안 제출] 위치 오류

**기획 의도 (§3.2):**
- 수정본 있음 (읽기 전용 상태): [편집]과 함께 **[개선 제안 제출]이 직접 노출**
- 편집 모드: [저장]만 직접 노출, [개선 제안 제출]은 없음

**현재 코드:**
- `DraftEditContent.tsx` (편집 모드 하단 바): [개선 제안 제출] 버튼 있음 (isDirty === false일 때만 활성)
- `SkillSlidePanelHeader.tsx` (읽기 모드): [개선 제안 제출] 버튼 **없음**

**기획과의 차이:**
- 기획: 저장 완료 후 읽기 전용 상태에서 [개선 제안 제출] 노출
- 코드: 편집 모드 안에서만 노출

**수정 방향:**
- #3 (저장 후 편집 모드 종료) 구현 후, `SkillSlidePanelHeader.tsx`의 수정본 읽기 상태에 [개선 제안 제출] 추가
- `DraftEditContent.tsx`에서 [개선 제안 제출] 제거 (편집 모드에서는 기획상 불필요)

**파일:** `SkillSlidePanelHeader.tsx`, `DraftEditContent.tsx`

## 5. 미저장 이탈 방지 모달 미구현

**기획 의도 (§3.2):**
> 미저장 이탈 방지: 편집 모드에서 패널 닫기 시도 시 "저장하지 않은 변경이 있습니다" 확인 모달

**현재 코드:**
- `TeamSkillsTab.tsx`의 `handleClosePanel`은 즉시 패널을 닫음
- 편집 모드에서 닫기를 눌러도 미저장 확인 없이 바로 닫힘
- `DraftEditContent`에서 `isDirty` 상태를 추적하고 `saveRef`로 상위에 노출하지만, 패널 닫기 시 활용되지 않음

**수정 방향:**
- `SkillSlidePanel.tsx`에서 `onClose` 래핑: `isInDraftMode && isDirty`이면 ConfirmDialog 표시
- 선택지: [저장 후 닫기] / [저장하지 않고 닫기] / [취소]
- 다른 행 클릭으로 패널이 교체되는 경우에도 동일하게 적용

**파일:** `SkillSlidePanel.tsx`

## 6. 관리자 리뷰 패널 — "신규" 타입에 파일 탐색기 미사용

**기획 의도 (§3.4 검토 시 상세 패널 연동):**
> | 신규 | 스킬 전체 내용 **(파일 탐색기 + 콘텐츠 뷰 — 팀 스킬 상세와 동일 구조)** | 확인 / 삭제 |

**현재 코드 (`AdminReviewPanel.tsx`):**
- `SkillContentView` 함수가 설명 + SKILL.md (코드블록) + 첨부 파일 리스트를 **플랫하게** 나열
- 팀 스킬 패널의 파일 탐색기(FileEntry 선택 → FileContentView) 패턴을 사용하지 않음

**수정 방향:**
- `SkillSlidePanel.tsx` 내부의 `FileContentView` + 파일 목록 로직을 별도 컴포넌트로 추출 (예: `SkillFileExplorer.tsx`)
- `AdminReviewPanel.tsx`의 신규 타입 뷰에서 해당 컴포넌트 재사용

**파일:** `AdminReviewPanel.tsx`, 신규 파일 `SkillFileExplorer.tsx` (선택)

## 7. 관리자 리뷰 패널 — "폐기" 타입에 스킬 전체 내용 누락

**기획 의도 (§3.4):**
> | 폐기 | **스킬 전체 내용** + 사용 현황 (활성화 팀원 수) | 승인 / 반려 |

**현재 코드 (`AdminReviewPanel.tsx`):**
- 폐기 타입: 폐기 사유 + 활성화 사용자 수만 표시
- **스킬 전체 내용이 표시되지 않음** — 관리자가 폐기 대상의 내용을 확인 불가

**수정 방향:**
- 폐기 타입 뷰에 스킬 전체 내용 영역 추가 (폐기 사유 + 사용 현황 아래에 파일 탐색기 + 콘텐츠 뷰)
- `DeprecationRequest` 타입 또는 `UnifiedQueueItem`에 스킬 참조 데이터 필요할 수 있음 (현재 payload에 TeamSkill 없음)

**파일:** `AdminReviewPanel.tsx`, `skill-management.types.ts` (DeprecationRequest에 skill 참조 추가), `skillMockData.ts`

## 8. 편집 모드 상단 바에 [저장] 미배치

**기획 의도 (§3.3, §6.2):**
> 상단 바: "편집 중" 라벨, [편집|원본|diff] 토글, **[저장] 직접 노출**, [...] 메뉴 (수정본 폐기)

**현재 코드:**
- `DraftEditHeader` (상단): "편집 중" 라벨 + [편집|원본|diff] 토글만 배치. [저장] 없음
- `DraftEditContent` (하단 바): [수정본 폐기], [테스트], [저장], [개선 제안 제출] 모두 하단에 배치

**수정 방향:**
- `DraftEditHeader`에 [저장] 버튼과 "..." 메뉴(수정본 폐기) 추가
- 하단 바 제거 (#1과 함께 처리)
- [저장]은 `isDirty` 상태에 따라 활성/비활성

**파일:** `SkillSlidePanel.tsx` (DraftEditHeader), `DraftEditContent.tsx`

## 9. 파일 목록이 파일 탐색기 형태가 아닌 가로 칩으로 구현

**기획 의도 (§3.2 본문 A. 파일 목록, 패널 열린 상태 와이어프레임):**
```
● SKILL.md  ← 기본 선택 (강조 표시)
  scripts/extract_data.py
  references/report-template.md
  assets/logo.png
```
세로 리스트 형태의 파일 탐색기. 선택된 파일에 ● 강조 표시.

**현재 코드 (`SkillSlidePanel.tsx` 432-453행):**
```tsx
<div className="flex gap-1.5 flex-wrap">
  {allFiles.map((file) => (
    <button className="flex items-center gap-1.5 px-2.5 py-1.5 rounded-md ...">
      {getFileIcon(...)} {file.name}
    </button>
  ))}
</div>
```
- `flex flex-wrap` → **가로로 나열**되는 pill/chip 탭 형태
- 파일이 많아지면 줄바꿈되어 탭 바처럼 보임
- 기획의 세로 파일 트리(탐색기) 패턴과 다름

**수정 방향:**
- `flex-wrap` → `flex-col` 세로 리스트로 변경
- 선택된 파일: 좌측 인디케이터(●) 또는 배경 강조
- 파일명 앞에 파일 타입 아이콘, 디렉토리 경로 구조 유지
- 콘텐츠 영역과의 레이아웃: 파일 목록을 좌측 사이드바로 배치하거나, 콘텐츠 영역 상단에 세로 리스트로 배치 (패널 폭 고려)

**파일:** `SkillSlidePanel.tsx`, `DraftEditContent.tsx` (편집 모드에서도 동일 패턴 적용)
