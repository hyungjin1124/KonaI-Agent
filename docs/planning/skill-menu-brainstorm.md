# 스킬 메뉴 구성 방안 — 브레인스토밍 결과

> **제품**: KonaI-Agent 채팅 내 스킬 메뉴
> **타겟 사용자**: 엔터프라이즈 직원 + PM/기획자
> **핵심 문제**: 여러 스킬을 조합해 복합 워크플로우를 실행하기 어려움
> **일자**: 2026-03-23

---

## 1. 현재 상태 분석

KonaI-Agent에는 이미 견고한 스킬 관리 인프라가 존재한다.

- **SkillManagementView**: 카탈로그, 활성 스킬, 팀, 관리자 4개 탭으로 스킬 CRUD 지원
- **스킬 타입 시스템**: category(document/data/content/automation), source(platform/org/personal), deploy policy(mandatory/recommended/allowed/blocked) 등 정교한 도메인 모델
- **채팅 인터페이스**: general-chat(일반 대화)과 agent-chat(시나리오 실행) 분리 구조
- **ScenarioContext**: `triggerScenario(mode, data)`로 PPT, 분석, 멀티에이전트 시나리오 트리거

**현재 빠져 있는 것**: 채팅 내에서 스킬을 **발견 → 조합 → 워크플로우 실행**하는 통합 경험

## 2. 관점별 아이디어 (각 5개)

### 2-A. Product Manager 관점 — 시장 적합성 · 가치 창출 · 차별화

| # | 아이디어 | 설명 |
|---|---------|------|
| PM-1 | **스킬 워크플로우 빌더** | 드래그 앤 드롭으로 여러 스킬을 순서대로 연결해 "나만의 워크플로우"를 만드는 비주얼 에디터. 예: "데이터 조회 → 차트 생성 → PPT 슬라이드 삽입"을 하나의 플로우로 저장·공유 |
| PM-2 | **스킬 번들 (레시피)** | 자주 쓰는 스킬 조합을 "레시피"로 패키징. 조직 내 베스트 프랙티스를 레시피로 공유하여 신규 직원 온보딩 가속. 예: "주간보고 레시피" = 데이터 집계 + 요약 + 문서 생성 |
| PM-3 | **역할 기반 스킬 프리셋** | PM, 마케터, 데이터 분석가 등 역할별로 큐레이션된 스킬셋을 제공. 사용자가 역할을 선택하면 해당 역할에 최적화된 스킬 메뉴가 자동 구성됨 |
| PM-4 | **스킬 마켓플레이스 + 사용 통계** | 조직 내부 마켓플레이스에서 팀이 만든 커스텀 스킬을 등록·검색. 사용 빈도, 평균 완료 시간, 만족도 등 통계로 스킬 품질을 투명하게 노출 |
| PM-5 | **조건부 분기 워크플로우** | "만약 데이터가 임계값 초과 → 알림 스킬 실행, 아니면 → 리포트만 생성" 같은 조건 분기를 지원해 자동화 수준을 높임. IFTTT/Zapier 스타일의 엔터프라이즈 버전 |

### 2-B. Product Designer 관점 — 사용자 경험 · 온보딩 · 인게이지먼트

| # | 아이디어 | 설명 |
|---|---------|------|
| DS-1 | **슬래시 커맨드 팔레트 (`/`)** | 채팅 입력창에서 `/`를 입력하면 스킬 목록이 팝업. 카테고리별 탭(문서/데이터/자동화)과 퍼지 검색을 지원하여 키보드만으로 빠르게 스킬 호출. VS Code의 Command Palette에서 영감 |
| DS-2 | **스킬 체이닝 캔버스** | 채팅 옆 사이드 패널에 미니 캔버스가 열려 ReactFlow 기반으로 스킬 노드를 연결. 각 노드는 입력·출력 슬롯이 있어 데이터 흐름이 시각적으로 보임. 실행 중에는 현재 진행 노드가 하이라이트 |
| DS-3 | **맥락 인식 스킬 서제스천** | 대화 맥락(파일 첨부, 키워드, 이전 스킬 결과)을 분석해 "다음에 이 스킬을 써보세요" 칩을 입력창 위에 자동 표시. 사용자가 탭을 누르면 바로 실행. 인텔리센스와 유사한 경험 |
| DS-4 | **스킬 실행 타임라인 뷰** | 워크플로우 실행 시 세로 타임라인 UI로 각 스킬 단계의 상태(대기/진행/완료/실패)를 표시. 각 단계를 펼쳐 중간 결과를 확인·수정(HITL)할 수 있음 |
| DS-5 | **퀵 액션 독 (Dock)** | 채팅 하단에 자주 쓰는 스킬 3-5개를 아이콘 바로 고정. 한 번 탭으로 즉시 실행. 사용자가 독 구성을 커스터마이즈 가능. 모바일 하단 네비게이션 바 패턴 차용 |

### 2-C. Software Engineer 관점 — 기술 혁신 · 확장성 · 플랫폼 역량

| # | 아이디어 | 설명 |
|---|---------|------|
| ENG-1 | **스킬 파이프라인 DSL + 런타임** | JSON/YAML 기반 워크플로우 정의 언어(DSL)를 설계. 스킬 간 데이터 매핑, 병렬 실행, 에러 핸들링을 선언적으로 정의. 기존 `useScenarioOrchestration` 훅을 확장해 파이프라인 런타임으로 활용 |
| ENG-2 | **스킬 호환성 그래프 엔진** | 각 스킬의 input/output 스키마를 등록하고, 호환 가능한 스킬 쌍을 자동으로 계산하는 그래프 엔진. UI에서 "이 스킬 뒤에 연결 가능한 스킬" 목록을 실시간 제안 |
| ENG-3 | **LangGraph 기반 멀티스텝 오케스트레이터** | LangGraph의 상태 머신 패턴을 활용해 스킬 워크플로우를 실행. 각 스킬을 노드로, 데이터 흐름을 엣지로 모델링. 중간 상태 저장으로 실패 시 재시도(resume) 및 HITL 인터럽트 지원 |
| ENG-4 | **스킬 샌드박스 실행 환경** | 각 스킬을 격리된 실행 컨텍스트에서 구동해 보안과 안정성 확보. Web Worker 또는 서버 사이드 격리로 한 스킬의 에러가 전체 워크플로우를 죽이지 않도록 설계 |
| ENG-5 | **실시간 스킬 이벤트 스트림** | SSE/WebSocket 기반으로 스킬 실행 이벤트(시작/진행/결과/에러)를 실시간 스트리밍. 채팅 UI에서 각 단계 진행률과 중간 결과를 라이브로 렌더링. streaming artifact preview와 통합 |

## 3. Top 5 우선순위 아이디어

핵심 가치 전달, 검증 속도, 차별화 잠재력 기준으로 선정:

### 1위: 슬래시 커맨드 팔레트 + 맥락 인식 서제스천 (DS-1 + DS-3)

**왜 1위인가**: 워크플로우 조합의 **진입점**이 되는 기능. 스킬을 쉽게 발견하고 호출하는 경험이 없으면 다른 모든 기능이 무용지물.

**구체적 형태**:
- 채팅 입력창에서 `/` 입력 시 커맨드 팔레트 팝업
- 카테고리 탭(문서 / 데이터 / 콘텐츠 / 자동화)과 퍼지 검색
- 현재 대화 맥락 기반으로 상단에 "추천 스킬" 섹션 자동 표시
- 기존 `PlusMenu` 컴포넌트를 확장해 스킬 팔레트 통합

**핵심 가설**:
- 가설 1: `/` 커맨드 방식이 메뉴 탐색보다 스킬 호출 속도를 50% 이상 단축한다
- 가설 2: 맥락 기반 추천이 스킬 발견율을 2배 이상 높인다

**검증 방법**: 프로토타입 A/B 테스트 — `/` 팔레트 vs 기존 사이드바 스킬 탐색 비교

---

### 2위: 스킬 체이닝 캔버스 (DS-2 + PM-1)

**왜 2위인가**: 핵심 문제인 "스킬 조합"을 직접 해결. ReactFlow 기반이므로 기존 codebase의 의존성을 활용 가능.

**구체적 형태**:
- 채팅 우측 아티팩트 패널에 캔버스 모드 추가
- 스킬 노드를 드래그하여 배치, 엣지로 연결
- 각 노드에 input/output 슬롯 — 호환되는 연결만 허용 (ENG-2 연계)
- 완성된 워크플로우를 "레시피"로 저장하여 재사용

**핵심 가설**:
- 가설 1: 비주얼 캔버스가 텍스트 기반 워크플로우 정의 대비 완료율을 40% 이상 높인다
- 가설 2: 저장된 레시피 재사용률이 월 3회 이상으로 반복 가치를 증명한다

**검증 방법**: 5명의 PM 대상 사용성 테스트 — 3단계 워크플로우 구성 태스크 수행 시간 측정

---

### 3위: 스킬 파이프라인 DSL + 런타임 (ENG-1 + ENG-3)

**왜 3위인가**: 2위 캔버스의 **백엔드 엔진**. 비주얼 캔버스가 프론트엔드라면 DSL/런타임은 실행 기반. 기존 `useScenarioOrchestration`을 확장해 빠르게 구현 가능.

**구체적 형태**:
```yaml
# 워크플로우 DSL 예시
workflow:
  name: "주간 보고 자동화"
  steps:
    - skill: data-query
      params: { source: "sales-db", period: "weekly" }
      output: $sales_data
    - skill: chart-generate
      params: { data: $sales_data, type: "bar" }
      output: $chart
    - skill: ppt-create
      params: { slides: [{ title: "주간 매출", chart: $chart }] }
```
- `useScenarioOrchestration`의 `progressTaskGroups` 확장
- `ScenarioContext`에 workflow trigger 모드 추가
- 스킬 간 `$variable` 참조로 데이터 파이프라인 구성

**핵심 가설**:
- 가설 1: DSL 기반 파이프라인이 수동 순차 실행 대비 평균 작업 시간을 60% 이상 단축한다
- 가설 2: 기존 오케스트레이션 훅 확장으로 2주 이내에 MVP 구현이 가능하다

**검증 방법**: 내부 도그푸딩 — "주간보고 생성" 워크플로우를 DSL로 구현하여 기존 대비 시간 측정

---

### 4위: 스킬 실행 타임라인 뷰 (DS-4 + ENG-5)

**왜 4위인가**: 멀티스텝 워크플로우가 실행될 때 사용자가 **통제감**을 느끼게 하는 핵심 UI. HITL과 결합하면 엔터프라이즈 신뢰성 요구를 충족.

**구체적 형태**:
- 채팅 메시지 내 인라인 타임라인 컴포넌트
- 각 스킬 단계: 아이콘 + 이름 + 상태 뱃지(⏳ 대기 / 🔄 실행 / ✅ 완료 / ❌ 실패)
- 단계 클릭 시 중간 결과물 프리뷰 + "수정 후 계속" HITL 인터랙션
- 기존 `renderSegments` 패턴 활용

**핵심 가설**:
- 가설 1: 타임라인 뷰가 "작업 진행 상황을 알 수 없다"는 사용자 불만을 80% 이상 해소한다
- 가설 2: HITL 개입 포인트가 최종 결과물 만족도를 유의미하게 향상시킨다

**검증 방법**: 3단계 이상 워크플로우 실행 시 타임라인 유/무에 따른 사용자 신뢰도 설문

---

### 5위: 스킬 번들 (레시피) + 역할 기반 프리셋 (PM-2 + PM-3)

**왜 5위인가**: 조직 단위 확산의 핵심. 개인이 만든 워크플로우를 팀에 공유하고, 역할별로 큐레이션하면 채택률이 비약적으로 올라감.

**구체적 형태**:
- 레시피 = 스킬 목록 + 실행 순서 + 기본 파라미터 + 설명
- "레시피 갤러리" 탭 — 조직 내 인기 레시피, 역할별 추천
- 관리자가 역할(PM, 마케터, 분석가)별 기본 레시피셋 지정
- 기존 `SkillManagementView`의 `team` 탭 확장

**핵심 가설**:
- 가설 1: 사전 구성된 레시피가 신규 사용자의 첫 워크플로우 실행까지 걸리는 시간을 70% 단축한다
- 가설 2: 팀 공유 레시피의 월간 사용률이 개인 스킬 대비 3배 이상 높다

**검증 방법**: 온보딩 A/B — 레시피 프리셋 제공 그룹 vs 빈 스킬 목록 그룹의 7일 리텐션 비교

## 4. 구현 로드맵 (권장)

```
Phase 1 (MVP — 4주)
├── 슬래시 커맨드 팔레트 (DS-1)
├── 맥락 인식 서제스천 기본형 (DS-3)
└── 스킬 파이프라인 DSL 기본형 (ENG-1)

Phase 2 (확장 — 4주)
├── 스킬 체이닝 캔버스 (DS-2)
├── 실행 타임라인 뷰 (DS-4)
└── 호환성 그래프 엔진 (ENG-2)

Phase 3 (조직 확산 — 4주)
├── 레시피 시스템 + 역할 프리셋 (PM-2, PM-3)
├── 레시피 갤러리 + 사용 통계 (PM-4)
└── 조건부 분기 워크플로우 (PM-5)
```
