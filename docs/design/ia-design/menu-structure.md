# KonaI-Agent 메뉴 구조 확정 문서

> 확정일: 2026-03-21
> 의사결정자: 형진 (에이전트 서비스 개발 담당)
> 근거: 15개 서비스 벤치마크 리서치 + 제품 전략 검토

---

## 확정된 메뉴 구조

### GNB 유형: 상단 네비게이션

Chat 화면이 이미 3-column 레이아웃(좌측 사이드바 + 채팅 + 우측 패널)으로 구성되어 있어,
좌측 GNB를 추가하면 UI 복잡성이 과도하게 증가한다.

리서치 참고: 15개 서비스 중 13개가 좌측 사이드바를 사용하지만,
이는 채팅 중심 서비스(Claude, ChatGPT)가 1-column 기본 레이아웃이기 때문에 가능한 구조이다.
KonaI-Agent처럼 채팅 화면 자체가 멀티 컬럼인 경우 상단 배치가 더 적합하다.

### 메뉴 목록 (5개, 프로토타입 기준)

```
홈/대시보드 | AI 채팅 | 스킬 | 데이터 | 관리자
```

| 순서 | 메뉴 | 목적 | 접근 대상 |
|------|------|------|----------|
| 1 | **홈/대시보드** | AI 인사이트 + KPI 위젯, 진입점 | 전사 직원 |
| 2 | **AI 채팅** | 자연어 대화, 분석, 문서 생성 (이미 개발 중) | 전사 직원 |
| 3 | **스킬** | 스킬 탐색·관리·생성, 스킬 마켓 | 전사 직원 (관리는 담당자) |
| 4 | **데이터** | 데이터 소스 + 온톨로지 + 접근 제어 관리 | 데이터 담당자 |
| 5 | **관리자** | 사용자·권한·감사로그·사용량·모니터링 | 고객사 관리자 |

### 플랫폼 관리: 동일 앱 내 역할 기반 분리

플랫폼 관리자 역할이 부여된 사용자에게만 "관리자" 메뉴 내에서 플랫폼 관리 탭/섹션이 추가로 노출된다.
현재 확정된 테넌트가 하나이고 RBAC이 미구축 상태이므로, 별도 URL 분리는 시기상조.
향후 멀티테넌트 확장 시 별도 포탈 분리를 검토한다.

### 예약 작업: 프로토 단계 제외

예약 작업은 부수 기능으로 판단. 프로토타입에서는 제외하고 추후 로드맵에서 추가한다.
추가 시 위치는 스킬 하위 또는 독립 메뉴로 재검토.

## 각 결정의 근거

### 결정 1: GNB — 상단 네비게이션

**선택**: 상단 네비게이션
**핵심 근거**: Chat의 3-column 레이아웃과 좌측 사이드바가 충돌
**리서치**: 좌측 사이드바가 업계 표준(13/15)이나, 채팅 화면이 멀티 컬럼인 KonaI-Agent에는 부적합

### 결정 2: 스킬 — 독립 최상위 메뉴

**선택**: 옵션 A (최상위 독립 메뉴)
**핵심 근거**: 스킬 활용이 제품 핵심 가치. 다중팀 협업 플랫폼으로 포지셔닝하므로 스킬 재사용/관리가 중요
**리서치**:
- 최상위 독립: Coze(Plugins), Dify(Tools), Datadog(Integrations), Genspark(Tools) — 4/15
- Claude Cowork: "사용자 지정" 메뉴에서 스킬 별도 관리 (리서치에서 누락되었으나 확인됨)
- 패턴: 스킬/도구가 핵심 가치인 서비스들이 최상위로 배치

**리서치 보정**: Claude Cowork의 사용자 지정 메뉴에서 스킬이 별도로 관리되는 구조가
리서치에서 충분히 반영되지 않았음. Claude Code CLI + claude.ai 소비자에 집중하여
Cowork 인터페이스의 스킬 관리 메뉴를 누락한 오류.

### 결정 3: 예약 작업 — 프로토 단계 제외

**선택**: 옵션 C (프로토 제외, 로드맵 후순)
**핵심 근거**: 부수 기능으로 판단. 핵심 기능에 집중
**리서치**:
- 독립 메뉴: n8n, Databricks, Datadog, ThoughtSpot — 4/15 (자동화 중심 플랫폼)
- 내부 기능: Coze, Dify, Copilot Studio — 3/15
- 없음: 8/15 (Claude, ChatGPT, Manus 등)
- 패턴: AI 채팅/에이전트 중심 플랫폼은 예약 작업을 독립 메뉴로 두지 않는 경향

**리서치 보정**: Claude Cowork에는 실제로 예약 작업 기능이 존재함
(scheduled-tasks MCP로 구현). 리서치에서 "Claude.ai 소비자에는 없음"으로
분류하면서 Cowork의 예약 작업을 사실상 누락. 다만, Cowork에서도 독립 메뉴가
아닌 MCP 기반 기능으로 제공되므로, "독립 메뉴 제외" 결정에는 영향 없음.

### 결정 4: 플랫폼 관리 — 역할 기반 분리 (옵션 B)

**선택**: 동일 앱 내 역할 기반 분리
**핵심 근거**:
- 확정 테넌트가 하나이므로 별도 URL 분리는 과도
- RBAC 미구축 상태에서 별도 시스템은 비현실적
- 프로토 단계에서 빠른 검증에 유리
**리서치**: Datadog, Snowflake, ThoughtSpot, Dify가 동일 앱 내 역할 기반 분리 사용 (4/15)

### 결정 5: 메뉴 개수 — 5개

예약 작업 제외 + 플랫폼 관리를 관리자 내 역할 분기로 처리하여 5개.
"중간(6-8개)" 범주의 하단에 위치하며, 프로토 단계에 적합한 간결함.

향후 추가 예정:
- 모니터링 / 감사 로그: 관리자 메뉴 내 탭으로 시작, 필요시 독립
- 지식베이스: Chat 화면 좌측 사이드바에 파일 시스템 형태로 제공 (별도 메뉴 불필요)
- 예약 작업: 로드맵에 따라 추가

### 결정 6: 메뉴 배열 순서

**선택**: 옵션 A 기반, 데이터 후순 배치

```
홈/대시보드 → AI 채팅 → 스킬 → 데이터 → 관리자
```

**배열 논리**:
- 홈/대시보드: 진입점, 전사 직원이 가장 먼저 보는 화면
- AI 채팅: 핵심 기능, 사용 빈도 최고
- 스킬: 채팅에서 사용하는 도구를 관리하는 메뉴 → 채팅 바로 뒤
- 데이터: 데이터 담당자만 접근하므로 뒤로 배치
- 관리자: 관리자 역할만 접근하므로 가장 뒤

이 순서는 리서치의 공통 패턴(생성→자산→운영→관리)과 일치하면서,
데이터가 특정 사용자 전용이라는 KonaI-Agent의 특성을 반영한다.

| 관리자 > 플랫폼 관리 | | | | ● |
