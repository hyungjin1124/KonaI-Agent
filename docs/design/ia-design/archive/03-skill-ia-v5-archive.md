## 1. 사이트맵

```
스킬 (GNB 3번째)
├─ [기본] 팀 스킬 ──────────── 단일 테이블 + 슬라이드 패널
│   ├─ 테이블 (활성화 그룹 / 비활성 그룹)
│   ├─ 슬라이드 패널 (스킬 상세, 전체 확장 가능)
│   └─ 개인 수정본 (편집 시 자동 생성, 테스트·제안용)
│
└─ [관리자 전용] 스킬 관리 ──── 관리자에게만 탭 표시
    ├─ 통합 대기열 (유형: 신규/제안/폐기, 승인/반려)
    ├─ 전체 스킬 관리
    └─ 카테고리 관리
```

## 2. 스코프 모델

### 팀 기반 강제 공유

| 항목 | 내용 |
|------|------|
| **공유 범위** | 팀 단위. 생성한 스킬은 즉시 팀 전체에 공유됨 (Draft 없음). "미검토" 뱃지 부착 → 관리자 확인 후 뱃지 제거 |
| **탐색 범위** | 내 팀 스킬만 열람 가능. 다른 팀 스킬은 볼 수 없음 |
| **팀 소속** | 1인 1팀. 다중 팀 소속 없음 |
| **관리 주체** | 팀 관리자가 공유 스킬을 관리 (신규 스킬 검토, 중복 정리, 개선 제안 승인, 폐기) |

### 활성화 모델

팀 스킬 중 **내가 사용할 스킬만 활성화**한다. 활성화해도 사본이 생기지 않고, 원본을 그대로 참조한다.

| 동작 | 설명 | 결과 |
|------|------|------|
| **활성화** | 팀 스킬을 내 채팅에서 사용하겠다고 선택 | 에이전트가 해당 스킬을 호출 가능 |
| **비활성화** | 내 채팅에서 더 이상 사용하지 않음 | 에이전트가 호출하지 않음. 팀에서 사라지지 않음 |

### 개인 수정본

팀 스킬을 수정하고 싶으면 **편집을 시작하는 순간 개인 수정본이 자동 생성**된다. 별도의 "포크" 버튼 없이, 편집 행위 자체가 수정본 생성을 트리거한다.

```
팀 스킬 (원본)
    │
    └─ [편집] 클릭 → 개인 수정본 자동 생성
                        │
                        ├─ 수정 (인라인 / 채팅)
                        ├─ [저장] → 수정본 저장 + 내 채팅에 즉시 적용 (원본 대신 수정본 사용)
                        │
                        ├─ 만족 → [개선 제안] → 관리자에게 전달
                        │                          ├─ 승인 → 원본에 병합 (새 버전)
                        │                          └─ 반려 → 코멘트와 함께 반환 (수정 후 재제안 가능)
                        │
                        └─ 불만족 → 계속 수정 또는 원본 복구 (수정본 폐기, 원본으로 복귀)
```

수정본은 **개인에게만 보인다**. 수정본 상태 뱃지(편집 중, 수정본 등)도 **본인에게만** 표시되며, 다른 팀원에게는 보이지 않는다. 저장된 수정본은 내 채팅에서 원본 대신 자동 적용되고, 다른 팀원에게는 원본이 그대로 유지된다.

### 삭제 권한 (작성자 기반)

삭제는 **원본 작성자에게만** 제공된다. 수정본 유무와 관계없이 작성자만 삭제/폐기 요청을 할 수 있으며, 비작성자는 패널에서 삭제 옵션이 노출되지 않는다.

| 조건 | 권한 | 근거 |
|------|------|------|
| 작성자 + 다른 활성화 사용자 **없음** | 자유롭게 삭제 | 테스트/미완성 스킬 정리 |
| 작성자 + 다른 활성화 사용자 **있음** | "폐기 요청"만 가능 → 관리자 승인 | 사용 중인 스킬이 갑자기 사라지는 것 방지 |
| 비작성자 | 삭제 불가 | 삭제 권한은 작성자에게만 부여 |
| 관리자 | 언제든 삭제/폐기 가능 | 중복 정리, 폐기 승인 |

수정본이 있는 상태에서 삭제 시, 수정본도 함께 삭제된다. 삭제 확인 모달에서 "수정본도 함께 삭제됩니다"를 안내한다.

*[설계 근거: (1) 즉시 공유는 단순하지만 미완성·저품질 스킬 노출 문제가 있음 → "미검토" 뱃지로 품질 신호를 제공하고, 관리자에게 알림으로 사후 검토 기회 보장. 사전 승인은 병목 위험이 있어 채택하지 않음. (2) 삭제 권한을 작성자로 한정하여 권한 모델 단순화. (3) 팀 기반 스코프는 스킬 수가 관리 가능한 범위로 제한되므로 관리자의 큐레이션이 현실적]*

## 3. 화면별 정보 구성

### 3.1 팀 스킬 — 테이블

팀 내 모든 스킬을 한 화면에서 관리하는 테이블. **활성화 그룹과 비활성 그룹**으로 나뉜다.

#### 테이블 컬럼

| 컬럼 | 설명 | 정렬 | 패널 열림 시 |
|------|------|------|------------|
| 이름 | 스킬 이름. 미검토 스킬은 "미검토" 뱃지 표시 | 가나다순 | 유지 |
| 한 줄 설명 | 스킬 용도 요약 | — | 숨김 |
| 카테고리 | 데이터 분석, 문서 생성, 업무 자동화, 커뮤니케이션 | — | 숨김 |
| 작성자 | 스킬 생성자 이름 | — | 유지 |
| 최종 수정일 | 마지막 수정 날짜 | 최근순 | 숨김 |
| 버전 | 현재 버전 번호 | — | 숨김 |
| 사용횟수 | 활성화한 팀원 수 | 많은순 | 유지 |
| 활성화 토글 | 내 채팅에서 사용 여부 | — | 유지 |

기본 정렬: 활성화 그룹 내에서 사용횟수 많은 순, 비활성 그룹 내에서 최근 수정일 순.

#### 필터

| 필터 | 옵션 |
|------|------|
| 카테고리 | 데이터 분석, 문서 생성, 업무 자동화, 커뮤니케이션 |
| 상태 | 활성화 / 비활성 / 미검토 / 수정본 있음 |
| 작성자 | 팀원 목록 |

### 3.2 스킬 상세 — 슬라이드 패널

테이블 행 클릭 시 우측에서 슬라이드로 열리는 상세 패널.

#### 헤더

| 요소 | 설명 |
|------|------|
| 스킬 이름 | 제목 |
| 설명 (Description) | 스킬이 무엇을 하는지 한 줄 설명 |
| 카테고리 | 태그 |
| 메타 정보 | 작성자, 버전, 사용횟수, 출처(직접 생성/외부 가져오기), 생성일, 최종 수정일 |
| 상태 표시 | "활성화 중" 또는 "비활성" (텍스트만, 토글은 테이블에서) |
| 액션 버튼 | 아래 참조 |
| 전체 확장 | [↗] 버튼 → 전체 페이지로 전환 (편집 작업 시 넓은 공간 확보) |

#### 패널 상태별 액션

패널은 항상 **"내 현재 버전"**을 표시한다. 수정본이 없으면 원본, 수정본이 있으면 수정본이 표시된다. 액션 구성은 **작성자 여부**에 따라 달라진다 (삭제는 작성자에게만 노출).

**읽기 모드 — 수정본 없음:**

| 사용자 유형 | 직접 노출 | "..." 메뉴 |
|------------|----------|-----------|
| 작성자 | [채팅에서 편집] | 직접 편집, 삭제 |
| 비작성자 | [채팅에서 편집] | 직접 편집 |

**읽기 모드 — 수정본 있음:**

| 사용자 유형 | 직접 노출 | "..." 메뉴 |
|------------|----------|-----------|
| 작성자 | [채팅에서 편집], [개선 제안 제출] | 직접 편집, 원본 복구, 삭제 |
| 비작성자 | [채팅에서 편집], [개선 제안 제출] | 직접 편집, 원본 복구 |

수정본이 있는 읽기 모드에서는 콘텐츠 영역 상단에 **[diff 보기]** 버튼을 제공한다. 클릭하면 원본과 수정본의 side-by-side diff로 전환되고, 다시 클릭하면 수정본 단독 뷰로 복귀한다.

**편집 모드:**

| 직접 노출 | "..." 메뉴 |
|----------|-----------|
| [취소], [저장] | — (없음) |

편집 모드에서도 콘텐츠 영역 상단에 **[diff 보기]** 버튼을 제공한다. 원본 대비 현재 편집 내용을 side-by-side로 확인하고 돌아와서 편집을 계속할 수 있다.

**액션 상세:**
- **[채팅에서 편집]**: 주 편집 경로. AI 채팅으로 이동하여 스킬 컨텍스트를 로드한 상태에서 대화형으로 편집. 구조적 변경에 적합
- **[개선 제안 제출]**: 저장된 수정본이 있을 때만 표시. 변경 요약 입력 → 관리자에게 전달
- **직접 편집** ("..." 내): 보조 편집 경로. 수정본이 없으면 자동 생성 후 편집 모드 진입, 있으면 기존 수정본 열기. 오타 수정, 파라미터 값 변경 등 경미한 수정에 적합
- **원본 복구** ("..." 내): 수정본을 폐기하고 원본으로 복귀. 내 채팅도 원본으로 자동 전환
- **삭제** ("..." 내, 작성자만): 사용 여부 기반 분기 — 2절 참조
- **[취소]**: 미저장 변경이 있으면 확인 모달("저장하지 않은 변경이 있습니다") 표시. 확인 시 편집 모드 종료, 이전 읽기 상태로 복귀
- **[저장]**: 편집 내용 저장 → 내 채팅에 즉시 적용 → 편집 모드 종료 → 수정본 읽기 전용 뷰로 복귀
- **미저장 이탈 방지**: 편집 모드에서 패널 닫기/다른 행 클릭 시도 시에도 확인 모달 표시

*[설계 변경 (v5): (1) [채팅에서 편집]을 주 편집 경로로 승격하고 [직접 편집]을 "..." 메뉴로 이동. 실제 사용에서 채팅 편집이 주가 될 것으로 판단. (2) 편집 모드에서 "..." 메뉴 제거하고 [취소] 버튼 추가. 편집 중 수정본 폐기는 [취소]로 읽기 모드 복귀 후 "..."에서 [원본 복구]로 접근. (3) 삭제를 작성자에게만 노출하여 권한 모델 단순화. (4) [편집|원본|diff] 3개 토글을 [diff 보기] 버튼으로 단순화. side-by-side diff에서 원본이 이미 보이므로 [원본] 토글 불필요.]*

#### 본문 (파일 탐색기 + 콘텐츠 뷰)

헤더 아래 본문은 **파일 목록 → 콘텐츠 영역 → 메타 섹션** 순으로 구성된다. 스킬은 파일 패키지이므로, 파일 목록에서 파일을 선택하면 해당 파일의 내용이 콘텐츠 영역에 표시되는 구조를 사용한다.

**A. 파일 목록**

```
● SKILL.md                        ← 기본 선택 (강조 표시)
  scripts/extract_data.py
  references/report-template.md
  assets/logo.png
```

- 스킬 패키지에 포함된 모든 파일을 목록으로 표시
- SKILL.md(메인 지시사항)가 기본 선택 상태. 패널을 열면 자동으로 SKILL.md 내용이 콘텐츠 영역에 표시
- 다른 파일 클릭 시 콘텐츠 영역이 해당 파일 내용으로 전환
- 단일 파일 스킬: SKILL.md만 표시 (파일 목록 영역이 최소화되어 공간 낭비 없음)

**B. 콘텐츠 영역**

파일 목록에서 선택한 파일의 내용을 표시하는 영역.

| 선택 파일 | 표시 내용 |
|-----------|----------|
| SKILL.md (기본) | 파일 내용 전문 (지시사항, 파라미터 등 모두 본문에 포함) |
| 텍스트 파일 (.md, .txt, .csv) | 파일 내용 전문 |
| 스크립트 (.py, .js, .sh) | 코드 하이라이팅 적용된 파일 내용 |
| 바이너리 (.png, .pdf 등) | 미리보기 (이미지: 렌더링, PDF: 뷰어) |

원본 상태에서는 **읽기 전용**. [편집] 버튼을 누르면 패널 전체가 편집 모드로 전환되며, 파일 타입에 따라 편집 방식이 달라진다:

| 파일 유형 | 편집 모드 동작 |
|-----------|--------------|
| 텍스트 (.md, .txt, .csv) | 콘텐츠 영역에서 바로 인라인 편집 |
| 스크립트 (.py, .js, .sh) | 콘텐츠 영역 상단에 [채팅에서 수정] 버튼 표시 |
| 바이너리 (.png, .pdf 등) | 콘텐츠 영역 상단에 [파일 교체] 버튼 표시 |

파일 간 이동: 편집 모드에서 파일 목록의 다른 파일을 클릭하면, 현재 파일의 편집 내용이 유지된 채 선택 파일로 전환. 각 파일의 편집 상태는 독립적으로 관리.

**C. 버전 이력** (기본 접힘)

| 항목 | 설명 |
|------|------|
| 버전 목록 | 수정일, 변경 요약, 수정자 (개선 제안 반영 시 제안자 표시) |
| 버전 비교 | 선택한 두 버전 간 side-by-side diff 표시. 패널 폭이 좁으면 unified diff로 폴백 |
| 버전 복원 | 이전 버전으로 되돌리기 (관리자만) |

**D. 개선 제안 이력** (기본 접힘)

| 항목 | 설명 |
|------|------|
| 제안 목록 | 이 스킬에 대한 모든 제안. 상태: 대기 중 / 승인됨 / 반려됨 |
| 제안 상세 | 제안자, 변경 diff, 원본 작성자 코멘트, 관리자 코멘트 |

버전 이력과 제안 이력은 스킬 전체에 대한 메타 정보이므로 콘텐츠 영역 아래에 접힘 상태로 배치. 파일 단위가 아닌 스킬 단위로 관리.

### 3.3 개인 수정본 — 편집·테스트·제안

[편집] 버튼을 누르면 **슬라이드 패널이 편집 모드로 전환**된다. 수정본이 없으면 자동 생성, 있으면 기존 수정본을 열기. 편집 모드에서는 상단에 "편집 중" 표시.

#### 수정본 상태

저장과 동시에 내 채팅에 적용되므로 "수정본 있음"과 "테스트 중"은 동일한 상태이다. 뱃지는 **수정본 소유자 본인에게만** 표시된다.

| 상태 | 설명 | 테이블 뱃지 (본인만) |
|------|------|-------------------|
| 편집 중 | 수정본을 편집하고 있는 단계 | 뱃지 (편집 중) |
| 수정본 적용 중 | 저장 완료. 내 채팅에서 원본 대신 수정본이 적용되는 상태 | 뱃지 (수정본) |
| 제안 완료 | 관리자에게 제안을 제출한 상태 | 뱃지 (제안 대기) |
| 승인됨 | 관리자가 승인하여 원본에 병합됨 | 제거 (원본이 새 버전) |
| 반려됨 | 관리자가 반려함 | 뱃지 (반려됨, 수정 후 재제안 가능) |

#### 편집 모드 패널 구성

| 영역 | 내용 |
|------|------|
| 상단 바 | "편집 중" 라벨, [diff 보기] 버튼, [취소] [저장] |
| 본문 | 파일 탐색기 + 콘텐츠 뷰 |

편집 모드에서는 "..." 메뉴가 없다. 수정본 폐기(원본 복구)가 필요하면 [취소]로 읽기 모드에 복귀한 후 "..." 메뉴에서 접근한다.

**콘텐츠 영역 동작:**
- **기본**: 파일 목록에서 선택한 파일을 인라인 편집/채팅에서 수정/파일 교체. 파일 간 이동 시 편집 상태 유지
- **[diff 보기]** 클릭 시: 원본 대비 현재 편집 내용을 side-by-side diff로 표시 (읽기 전용). 다시 클릭하면 편집 뷰로 복귀. 패널 폭이 좁으면 unified diff로 폴백

**[저장] 후 흐름**: 저장 → 편집 모드 종료 → 수정본 내용이 읽기 전용으로 표시. 패널을 닫고 다시 열어도 수정본이 그대로 보임. [개선 제안 제출]은 수정본 읽기 전용 상태에서 노출.

**[취소] 흐름**: 미저장 변경이 있으면 "저장하지 않은 변경이 있습니다" 확인 모달 → 확인 시 편집 모드 종료, 이전 읽기 상태로 복귀 (수정본이 있었으면 수정본 읽기 전용, 없었으면 원본 읽기 전용).

**저장 = 채팅 적용**: [저장] 시 수정본이 즉시 내 채팅에 적용된다. 별도의 "테스트 시작" 동작 없이, 저장된 수정본이 곧 내 채팅의 현재 버전이 된다. 수정본을 폐기하면 원본으로 자동 복귀한다.

### 3.4 관리자 뷰 — 스킬 관리 탭

팀 관리자에게만 표시되는 탭. 일반 사용자에게는 보이지 않는다.

#### 레이아웃

| 영역 | 구성 |
|------|------|
| 통합 대기열 | 관리자 처리가 필요한 모든 항목을 하나의 테이블로 표시 |
| 전체 스킬 관리 | 팀 전체 스킬 테이블 (관리자 액션 추가) |
| 카테고리 관리 | 카테고리 CRUD |

#### 통합 대기열

신규 스킬 검토, 개선 제안, 폐기 요청을 하나의 테이블로 통합한다. "유형" 컬럼으로 구분하고, 유형별 필터를 제공한다.

```
┌─────────────────────────────────────────────────────────────────────┐
│  처리 대기 (4)                   유형▼ [전체 / 신규 / 제안 / 폐기]    │
├─────────────────────────────────────────────────────────────────────┤
│  유형  │ 스킬 이름   │ 요청자  │ 요청일  │ 요약                │ 액션 │
│  신규  │ 이메일 초안 │ 최수진  │ 03-24  │ 회신 이메일 자동 작성 │[검토]│
│  제안  │ 매출 분석   │ 이민수  │ 03-22  │ 파라미터 기본값 변경  │[검토]│
│  제안  │ 재고 점검   │ 박영희  │ 03-21  │ 조건 분기 추가        │[검토]│
│  폐기  │ 주간 회의   │ 홍길동  │ 03-20  │ 사용 중단 요청        │[검토]│
└─────────────────────────────────────────────────────────────────────┘
```

#### 검토 시 상세 패널 연동

[검토] 클릭 시 **모든 유형에서 팀 스킬 상세와 동일한 패널 구조**(헤더 + 파일 목록 + 콘텐츠 영역 + 버전/제안 이력)가 열리되, **상단에 관리자 액션 바가 추가**된다. 패널 프레임은 통일하고, 콘텐츠 영역의 기본 뷰만 유형에 따라 다르다:

| 유형 | 콘텐츠 영역 기본 뷰 | 관리자 액션 |
|------|-------------------|-----------|
| 신규 | 스킬 전체 내용 (SKILL.md 기본 선택) | 확인 (미검토 뱃지 제거) / 삭제 |
| 제안 | 원본 대비 side-by-side diff (기본) + [diff 보기] 토글로 전체 내용과 전환 가능. 작성자 코멘트 표시 | 승인 (원본 병합, 새 버전) / 반려 (코멘트 필수) |
| 폐기 | 스킬 전체 내용 + 사용 현황 (활성화 팀원 수) | 승인 (폐기 처리) / 반려 (코멘트 필수) |

모든 유형에서 파일 목록 탐색, 버전 이력, 제안 이력 등 패널의 모든 섹션에 접근할 수 있다. 승인/반려 결과는 요청자 + 원본 작성자에게 알림.

*[설계 변경 (v5): 기존에는 유형별로 기본 뷰가 크게 달랐으나, 관리자가 판단에 필요한 전체 맥락(메타 정보, 파일 구조, 사용 현황 등)을 동일하게 확인할 수 있도록 패널 프레임을 통일. 차이는 콘텐츠 영역의 기본 뷰뿐.]*

#### 관리자 전용 스킬 테이블 액션

| 액션 | 설명 |
|------|------|
| 삭제 | 스킬을 팀에서 영구 삭제. 활성화 중인 팀원에게 알림 |
| 폐기(Deprecate) | 스킬을 "폐기됨" 상태로 변경. 기존 사용자에게 경고 표시, 신규 활성화 불가 |
| 상태 변경 | Active ↔ Deprecated |
| 카테고리 변경 | 스킬의 카테고리 재분류 |

## 4. 스킬 추가 경로

스킬을 팀에 등록하는 경로는 2가지이다. 등록 즉시 팀에 공유되며("미검토" 뱃지 부착, 관리자에게 알림), 생성자는 자동 활성화된다.

| 경로 | 진입점 | 설명 | 근거 |
|------|--------|------|------|
| 채팅에서 만들기 | [+ 추가] → "채팅에서 만들기" | AI 채팅으로 이동. 스킬 생성 프롬프트가 자동 입력되어 대화형으로 스킬을 설계 | Anthropic skill-creator (Intent Capture → Interview → SKILL.md 생성), Manus conversation-to-skill, Relevance AI "Invent" |
| 파일에서 가져오기 | [+ 추가] → "파일에서 가져오기" | 파일 업로드 모달에서 SKILL.md 또는 .zip 패키지 업로드 | Manus .skill 업로드, Claude.ai Settings > Skills ZIP upload, Gemini CLI `skills install` |

### 4.1 진입점 — [+ 추가] 버튼

팀 스킬 테이블 상단의 **[+ 추가]** 버튼을 클릭하면 드롭다운이 열리며 2개 옵션을 표시한다.

```
┌──────────────────────────┐
│  + 추가 ▼                │
├──────────────────────────┤
│  💬 채팅에서 만들기       │
│  📁 파일에서 가져오기     │
└──────────────────────────┘
```

- **채팅에서 만들기**: AI 채팅 뷰로 이동하며 스킬 생성 프롬프트가 자동 입력됨
- **파일에서 가져오기**: 현재 화면 위에 모달이 열림

### 4.2 채팅에서 만들기

#### 진입 흐름

```
[+ 추가] → "채팅에서 만들기"
    │
    ▼
AI 채팅 뷰 (새 세션)
    │
    ├─ 시스템: 스킬 생성 모드 컨텍스트 로드
    ├─ 입력창: 프롬프트 템플릿 자동 입력 (사용자 편집 가능, 전송 전 상태)
    │
    ▼
사용자가 프롬프트 확인/편집 후 전송
    │
    ▼
에이전트: Intent Capture → Interview → SKILL.md 초안 생성 → 확인 요청
    │
    ▼
사용자: 검토·수정 → 승인
    │
    ▼
스킬 등록 (팀에 공유, "미검토" 뱃지, 생성자 자동 활성화)
```

#### 자동 입력 프롬프트

채팅 입력창에 아래 템플릿이 미리 채워진 상태로 표시된다. 사용자는 `{ }` 부분을 자신의 내용으로 교체한 후 전송한다. 전송 전까지는 일반 입력 텍스트와 동일하게 편집할 수 있다.

```
새로운 스킬을 만들고 싶습니다.

**목적**: {이 스킬이 무엇을 하는지 설명해주세요}
**트리거 상황**: {언제 이 스킬이 사용되어야 하는지 — 사용자가 어떤 요청을 했을 때?}
**결과물 형식**: {스킬 실행 결과의 형태 — 파일, 텍스트, 데이터 등}
```

*[설계 근거: Anthropic skill-creator의 Intent Capture 4가지 핵심 질문 (기능적 목표, 트리거 조건, 결과물 형식, 테스트 필요성)을 사용자가 직접 채울 수 있는 구조화된 프롬프트로 변환. 빈 채팅으로 보내는 것보다 출발점을 제공하여 사용자 부담을 줄이되, 자유 형식 입력도 허용.]*

#### 에이전트의 대화형 생성 프로세스

프롬프트를 수신한 에이전트는 아래 단계를 순서대로 진행한다. 각 단계에서 사용자 확인을 받은 후 다음 단계로 넘어간다.

**Phase 1 — Intent 확인 & 상세화 (Interview)**

에이전트가 사용자의 프롬프트를 분석한 후 부족한 정보를 추가 질문한다.

| 확인 항목 | 설명 | 예시 질문 |
|-----------|------|----------|
| 엣지 케이스 | 비정상 입력, 예외 상황 | "입력 데이터가 빈 경우 어떻게 처리할까요?" |
| 입출력 형식 | 정확한 파일 형식, 데이터 구조 | "결과물이 .xlsx인가요, .csv인가요?" |
| 성공 기준 | 스킬이 잘 동작했다고 판단할 조건 | "어떤 결과가 나오면 성공으로 볼 수 있을까요?" |
| 의존성 | 필요한 외부 도구, 데이터 소스 | "특정 API나 데이터 소스 연동이 필요한가요?" |

*[설계 근거: Anthropic skill-creator의 Interview & Research Phase 패턴. 엣지 케이스, 입출력 형식, 성공 기준, 의존성을 사전에 확인하여 SKILL.md 품질을 높임.]*

**Phase 2 — SKILL.md 초안 생성**

에이전트가 수집한 정보를 바탕으로 SKILL.md 초안을 생성하고, 채팅 내에서 미리보기로 제시한다.

```
에이전트: "스킬 초안을 작성했습니다. 검토해주세요."

┌─────────────────────────────────────────┐
│  📄 SKILL.md 미리보기                    │
│                                         │
│  ---                                    │
│  name: monthly-sales-report             │
│  description: 월별 매출 데이터를 분석하여 │
│    트렌드 차트와 요약 리포트를 자동 생성.  │
│    매출 분석, 월간 보고서 요청 시 사용.    │
│  ---                                    │
│                                         │
│  ## 지시사항                             │
│  1. 입력 데이터 검증...                   │
│  2. 월별 트렌드 분석...                   │
│  ...                                    │
│                                         │
│  [전체 보기]                              │
└─────────────────────────────────────────┘

"수정할 부분이 있으면 말씀해주세요. 만족하시면 '등록'이라고 답해주세요."
```

사용자는 채팅으로 수정 요청을 보내거나(예: "트리거 조건에 '분기 보고서'도 추가해줘"), 만족하면 등록을 승인한다.

**Phase 3 — 스킬 등록**

사용자가 승인하면 에이전트가 스킬을 팀에 등록한다.

| 등록 시 동작 | 설명 |
|-------------|------|
| SKILL.md 저장 | 에이전트가 생성한 최종 SKILL.md를 서버에 저장 |
| 팀 공유 | 팀 스킬 테이블에 즉시 추가 + "미검토" 뱃지 |
| 관리자 알림 | 관리자에게 신규 스킬 알림 발송 |
| 생성자 자동 활성화 | 생성자의 채팅에서 즉시 사용 가능 |
| 메타데이터 설정 | 작성자, 생성일, 출처("채팅 생성"), 버전 1.0 |

등록 완료 후 에이전트가 확인 메시지와 함께 스킬 상세 패널로의 링크를 제공한다.

```
에이전트: "✅ 'monthly-sales-report' 스킬이 등록되었습니다.
팀에 공유되었으며, 관리자 검토 전까지 '미검토' 상태입니다.
내 채팅에서 바로 사용할 수 있습니다.

[스킬 상세 보기 →]"
```

#### 보조 스크립트·리소스 추가

SKILL.md만으로 충분하지 않은 복잡한 스킬의 경우, 에이전트가 보조 파일을 함께 생성할 수 있다.

| 파일 유형 | 에이전트 동작 | 예시 |
|-----------|-------------|------|
| scripts/ | Interview 단계에서 스크립트 필요성 판단 → 자동 생성 | `scripts/extract_data.py` |
| references/ | 참조 문서가 필요하면 에이전트가 작성 제안 | `references/report-format.md` |
| assets/ | 사용자가 템플릿 파일을 채팅에 업로드하면 assets/에 포함 | `assets/template.xlsx` |

에이전트가 생성한 모든 파일은 등록 전에 사용자에게 목록으로 제시하고, 사용자가 확인한 후 패키지로 등록한다.

*[설계 근거: Anthropic의 Progressive Disclosure 아키텍처 — SKILL.md (Level 2) + scripts/references/assets (Level 3) 구조. 단순한 스킬은 SKILL.md 하나로 충분하고, 복잡한 스킬은 보조 파일을 포함하는 패키지로 구성.]*

### 4.3 파일에서 가져오기

#### 진입 흐름

```
[+ 추가] → "파일에서 가져오기"
    │
    ▼
파일 업로드 모달 (현재 화면 위에 오버레이)
    │
    ├─ 파일 선택/드래그앤드롭
    ├─ 검증 (구조·필수 필드)
    ├─ 미리보기
    │
    ▼
[등록] 버튼 클릭
    │
    ▼
스킬 등록 (팀에 공유, "미검토" 뱃지, 생성자 자동 활성화)
```

#### 파일 업로드 모달

```
┌───────────────────────────────────────────────────────┐
│  파일에서 가져오기                                [✕]  │
├───────────────────────────────────────────────────────┤
│                                                       │
│  ┌ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┐ │
│  │                                                 │ │
│  │   📁 파일을 드래그하거나 클릭하여 선택하세요     │ │
│  │                                                 │ │
│  │   지원 형식: SKILL.md (단일 파일), .zip (패키지)  │ │
│  │                                                 │ │
│  └ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┘ │
│                                                       │
│                                                       │
│                                     [취소]  [등록]     │
└───────────────────────────────────────────────────────┘
```

#### 지원 파일 형식

| 형식 | 내용 | 처리 |
|------|------|------|
| **SKILL.md** (단일 파일) | YAML 프론트매터 + Markdown 본문 | 파일을 직접 파싱하여 등록 |
| **.zip** (패키지) | SKILL.md + scripts/ + references/ + assets/ | 압축 해제 후 SKILL.md 존재 여부 확인 → 전체 패키지 등록 |

#### 검증 규칙

파일 업로드 시 즉시 검증을 수행한다. 검증 결과는 모달 내에 인라인으로 표시된다.

**필수 검증 (통과 못하면 등록 불가):**

| 규칙 | 검증 내용 | 실패 시 메시지 |
|------|----------|---------------|
| SKILL.md 존재 | .zip일 경우 루트 또는 단일 하위 폴더에 SKILL.md가 있는지 | "SKILL.md 파일을 찾을 수 없습니다" |
| 프론트매터 존재 | YAML 프론트매터(`---` ... `---`) 파싱 가능 여부 | "YAML 프론트매터를 파싱할 수 없습니다" |
| name 필드 | 프론트매터에 `name` 필드 존재 + 비어있지 않음 | "`name` 필드가 필요합니다" |
| description 필드 | 프론트매터에 `description` 필드 존재 + 비어있지 않음 | "`description` 필드가 필요합니다" |
| 이름 중복 | 팀 내 기존 스킬과 `name` 중복 여부 | "'{name}' 이름의 스킬이 이미 존재합니다" |

**경고 검증 (경고 표시, 등록은 가능):**

| 규칙 | 검증 내용 | 경고 메시지 |
|------|----------|-----------|
| description 길이 | 1024자 초과 | "설명이 권장 길이(1024자)를 초과합니다" |
| 본문 길이 | SKILL.md 본문 500줄 초과 | "본문이 500줄을 초과합니다. 보조 파일(references/)로 분리를 권장합니다" |
| 스크립트 참조 | SKILL.md에서 scripts/ 파일을 참조하는데 해당 파일이 패키지에 없음 | "참조된 파일 '{filename}'이 패키지에 포함되지 않았습니다" |

*[설계 근거: agentskills.io 표준의 필수 필드(name, description)를 준수하면서, Anthropic SKILL.md 권장 사항(본문 500줄 미만, description 1024자 이내)을 경고로 안내.]*

#### 미리보기

검증을 통과하면 모달 하단이 미리보기로 확장된다.

```
┌───────────────────────────────────────────────────────┐
│  파일에서 가져오기                                [✕]  │
├───────────────────────────────────────────────────────┤
│                                                       │
│  ✅ monthly-sales-report.zip                  [변경]   │
│                                                       │
│  ──────────────────────────────────────────────────── │
│                                                       │
│  이름:  monthly-sales-report                          │
│  설명:  월별 매출 데이터를 분석하여 트렌드 차트와...     │
│                                                       │
│  포함 파일:                                            │
│    ● SKILL.md                                         │
│    scripts/extract_data.py                            │
│    references/report-format.md                        │
│    assets/template.xlsx                               │
│                                                       │
│  ⚠️ 본문이 500줄을 초과합니다 (623줄).                  │
│     보조 파일로 분리를 권장합니다.                       │
│                                                       │
│                                     [취소]  [등록]     │
└───────────────────────────────────────────────────────┘
```

미리보기에 표시되는 정보:

| 항목 | 출처 |
|------|------|
| 이름 | 프론트매터 `name` 필드 |
| 설명 | 프론트매터 `description` 필드 (길면 말줄임) |
| 포함 파일 | 패키지 내 파일 목록 (SKILL.md 강조) |
| 경고 | 경고 검증 결과 (있을 경우) |

#### 등록 후 동작

[등록] 클릭 시 "채팅에서 만들기"와 동일한 등록 프로세스가 실행된다.

| 등록 시 동작 | 설명 |
|-------------|------|
| 파일 저장 | 업로드된 파일(패키지)을 서버에 저장 |
| 팀 공유 | 팀 스킬 테이블에 즉시 추가 + "미검토" 뱃지 |
| 관리자 알림 | 관리자에게 신규 스킬 알림 발송 |
| 생성자 자동 활성화 | 생성자의 채팅에서 즉시 사용 가능 |
| 메타데이터 설정 | 작성자, 생성일, 출처("파일 가져오기"), 버전 1.0 |

모달이 닫히고 테이블에 새 스킬이 추가된 상태를 보여준다. 토스트 알림: "'{name}' 스킬이 등록되었습니다."

### 4.4 두 경로 비교

| 비교 항목 | 채팅에서 만들기 | 파일에서 가져오기 |
|-----------|---------------|-----------------|
| **대상 사용자** | 스킬 작성 경험이 없거나 AI 도움이 필요한 사용자 | SKILL.md를 직접 작성했거나 외부에서 가져온 사용자 |
| **진입 비용** | 낮음 — 자연어로 목적만 설명하면 됨 | 중간 — SKILL.md 형식을 알아야 함 |
| **생성 품질** | 에이전트가 엣지 케이스·트리거 조건을 상세화하여 품질 보장 | 업로드한 파일 품질에 의존 |
| **소요 시간** | 2-5분 (대화 왕복) | 1분 미만 (파일 준비가 되어 있다면) |
| **보조 파일** | 에이전트가 필요 시 자동 생성 | 사용자가 .zip에 직접 포함 |
| **출처 메타데이터** | "채팅 생성" | "파일 가져오기" |

*[설계 근거: Anthropic은 대화형 생성(skill-creator)을, Manus는 conversation-to-skill + .skill 업로드 양 경로를 제공한다. KonaI-Agent는 엔터프라이즈 환경에서 두 유형의 사용자를 모두 지원하기 위해 양 경로를 병행. 채팅 생성은 Anthropic의 Intent Capture → Interview → Write 패턴을 웹 기반으로 적응한 것이고, 파일 가져오기는 agentskills.io 표준의 이식성(파일 복사만으로 이식)을 활용한 것이다.]*

## 5. 네비게이션 플로우

### 5.1 기본 탐색 플로우

```
[GNB: 스킬 클릭]
    │
    ▼
팀 스킬 테이블 (전체 폭)
    │
    ├─ [활성화 토글] ────────► 활성화/비활성 그룹 간 행 이동 (테이블 내)
    │
    ├─ [행 클릭] ────────────► 슬라이드 패널 열림 (테이블 축약)
    │                            │
    │                            ├─ [다른 행 클릭] ──► 패널 교체
    │                            ├─ [전체 확장] ──► 전체 페이지 상세
    │                            ├─ [채팅에서 편집] ──► AI 채팅 (스킬 컨텍스트 로드) ← 주 편집 경로
    │                            ├─ "..." → [직접 편집] ──► 수정본 생성 → 편집 모드 ← 보조 경로
    │                            └─ [패널 닫기] ──► 전체 폭 테이블 복원
    │
    ├─ [+ 추가] ─────────────► 드롭다운 (추가 방법 선택)
    │                            ├─ 채팅에서 만들기 ──► AI 채팅 (새 세션, 프롬프트 자동 입력)
    │                            │       └─ 대화형 생성: Intent 확인 → Interview → SKILL.md 초안 → 등록
    │                            └─ 파일에서 가져오기 ──► 파일 업로드 모달
    │                                    └─ 파일 선택 → 검증 → 미리보기 → [등록]
    │
    └─ [검색/필터] ──────────► 테이블 필터링
```

### 5.2 편집·제안 플로우

```
슬라이드 패널 (상세 뷰 — 내 현재 버전 표시)
    │
    ├─ [채팅에서 편집] ──► AI 채팅 (스킬 컨텍스트 로드, 대화형 편집)
    │       │
    │       └─ 채팅에서 수정 완료 → 수정본 자동 생성/갱신 → 패널로 돌아오면 수정본 표시
    │
    └─ "..." → [직접 편집] (보조 경로)
        │
        ▼
    수정본 없으면 자동 생성 / 있으면 기존 수정본 열기 → 편집 모드 전환
        │
        ├─ 파일 목록에서 파일 선택 → 콘텐츠 영역에서 인라인 편집
        ├─ [diff 보기] 버튼으로 원본 대비 변경점 side-by-side 확인
        │
        ├─ [저장] → 내 채팅에 즉시 적용 → 편집 모드 종료 → 수정본 읽기 전용 뷰로 복귀
        ├─ [취소] → (미저장 시 확인 모달) → 읽기 모드 복귀
        │
        └─ 저장 후 흐름:
                ├─ 채팅에서 수정본 확인 (자동 적용 상태)
                │       ├─ 불만족 → [채팅에서 편집] 또는 "..." → [직접 편집] → 추가 편집 (반복)
                │       └─ 만족 → [개선 제안 제출]
                │
                ├─ [개선 제안 제출] → 관리자에게 전달 + 원본 작성자에게 알림
                │       ├─ (원본 작성자가 코멘트를 남길 수 있음)
                │       ├─ 승인 → 원본에 병합 (새 버전), 수정본 제거, 제안자+작성자에게 알림
                │       └─ 반려 → 코멘트와 함께 반환, 제안자+작성자에게 알림 (수정 후 재제안 가능)
                │
                └─ "..." → [원본 복구] → 수정본 폐기, 원본으로 복귀 (내 채팅도 원본으로 자동 전환)
```

### 5.3 관리자 플로우

```
[관리 탭 클릭] (관리자만 표시)
    │
    ▼
통합 대기열 (유형 필터: 전체 / 신규 / 제안 / 폐기)
    │
    └─ [검토] 클릭 ──► 팀 스킬 상세와 동일 구조의 패널 열림 (관리자 액션 바 추가)
                         │  (모든 유형: 헤더 + 파일 목록 + 콘텐츠 영역 + 버전/제안 이력)
                         │
                         ├─ [신규] 콘텐츠 기본 뷰: 스킬 전체 내용
                         │    ├─ 확인 → "미검토" 뱃지 제거
                         │    └─ 삭제 → 스킬 제거 (생성자에게 알림)
                         │
                         ├─ [제안] 콘텐츠 기본 뷰: 원본 대비 side-by-side diff + 작성자 코멘트
                         │    ├─ 승인 → 원본에 병합, 새 버전, 요청자+작성자에게 알림
                         │    └─ 반려 → 코멘트(필수), 요청자+작성자에게 알림
                         │
                         └─ [폐기] 콘텐츠 기본 뷰: 스킬 전체 내용 + 사용 현황
                              ├─ 승인 → 폐기 처리 (사용자에게 경고)
                              └─ 반려 → 코멘트(필수), 요청자에게 알림

전체 스킬 관리: 별도 테이블에서 삭제, 폐기, 카테고리 변경 가능
```

### 5.4 외부에서의 진입 경로

| 출발점 | 도착 | 시나리오 |
|--------|------|---------|
| AI 채팅 → 스킬 생성 완료 | 아티팩트 패널에서 스킬 내용 확인 | 채팅에서 바로 확인. 팀 테이블에 자동 등록. "스킬 관리에서 보기" 링크는 선택적 |
| AI 채팅 우측 사이드바 → 사용 중 스킬 클릭 | 스킬 상세 패널 | 현재 세션에서 활성화된 스킬의 상세로 이동 |
| 알림 → "개선 제안이 승인됨" | 스킬 상세 (새 버전) | 제안자 + 원본 작성자에게 결과 알림 |
| 알림 → "내 스킬에 개선 제안이 등록됨" | 제안 상세 | 원본 작성자가 코멘트 기회를 얻음 |
| 알림 → "스킬이 폐기됨" | 스킬 상세 | 해당 스킬을 활성화 중인 팀원에게 안내 |

## 6. 주요 인터랙션 패턴

### 6.1 활성화 토글

활성화 토글은 **테이블에서만** 제공. 슬라이드 패널에서는 현재 상태 텍스트만 표시.

| 상태 | 동작 | 영향 범위 |
|------|------|----------|
| 활성 → 비활성 | 에이전트가 해당 스킬을 호출하지 않음 | 해당 사용자의 채팅 세션만 |
| 비활성 → 활성 | 에이전트가 다시 호출 가능 | 해당 사용자의 채팅 세션만 |

토글 시 행이 활성화/비활성 그룹 간 이동하며, 이동 자체가 시각적 피드백이 된다.

### 6.2 편집 모드 (수정본에서)

원본은 읽기 전용. "..." 메뉴의 [직접 편집]을 누르면 **패널 전체가 편집 모드로 전환**된다. 주 편집 경로는 [채팅에서 편집]이며, 직접 편집은 오타 수정 등 경미한 변경용 보조 경로이다.

파일 목록 + 콘텐츠 뷰 구조가 유지되며, 선택한 파일의 콘텐츠 영역이 편집 가능 상태가 된다:

| 파일 목록에서 선택 | 콘텐츠 영역 편집 동작 |
|-------------------|---------------------|
| SKILL.md (기본) | 콘텐츠 영역에서 바로 인라인 편집 (다른 텍스트 파일과 동일) |
| 텍스트 (.md, .txt, .csv) | 콘텐츠 영역에서 바로 인라인 편집 |
| 스크립트 (.py, .js, .sh) | 콘텐츠 영역 상단에 [채팅에서 수정] 버튼 표시 |
| 바이너리 (.png, .pdf 등) | 콘텐츠 영역 상단에 [파일 교체] 버튼 표시 |

파일 간 이동: 편집 모드에서 파일 목록의 다른 파일을 클릭하면, 현재 파일의 편집 내용이 유지된 채 선택 파일로 전환된다. 각 파일의 편집 상태는 독립적으로 관리.

**[diff 보기] 버튼** — 콘텐츠 영역 상단에 위치. 클릭하면 원본 대비 현재 편집 내용을 side-by-side diff로 표시 (읽기 전용). 다시 클릭하면 편집 뷰로 복귀. side-by-side diff에서 원본이 이미 보이므로 별도 [원본] 뷰는 제공하지 않는다. 패널 폭이 좁으면 unified diff로 폴백.

**액션**: [취소]와 [저장]을 직접 노출. "..." 메뉴 없음. [취소] 시 미저장 변경이 있으면 확인 모달 표시 후 읽기 모드로 복귀. 수정본 폐기(원본 복구)는 읽기 모드의 "..." 메뉴에서 접근.

### 6.3 검색·필터

| 위치 | 검색 범위 | 동작 |
|------|----------|------|
| 팀 스킬 테이블 | 팀 전체 스킬 | 이름, 설명, 작성자, 카테고리 기준 실시간 필터링 |

### 6.4 개선 제안 워크플로우

| 단계 | 주체 | 동작 |
|------|------|------|
| 수정본 생성 | 제안자 | [편집] 클릭 → 개인 수정본 자동 생성 |
| 편집·저장 | 제안자 | 수정본을 편집하고 [저장] → 내 채팅에 즉시 적용되어 확인 |
| 제안 제출 | 제안자 | [개선 제안 제출] → 변경 요약 입력 → 관리자에게 전달, 원본 작성자에게 알림 |
| 작성자 코멘트 (선택) | 원본 작성자 | 제안에 대한 의견을 코멘트로 남김 (승인 권한은 없음) |
| 검토 | 관리자 | 제안 대기열에서 diff + 작성자 코멘트 확인 |
| 승인/반려 | 관리자 | 승인 → 원본 병합 (새 버전) / 반려 → 코멘트(필수)와 함께 반환 (수정 후 재제안 가능) |
| 결과 알림 | 시스템 | 제안자 + 원본 작성자에게 결과 알림 |

### 6.5 삭제·폐기

삭제는 원본 작성자에게만 노출된다. 비작성자의 패널 "..." 메뉴에는 삭제가 표시되지 않는다.

| 동작 | 조건 | 프로세스 |
|------|------|---------|
| 즉시 삭제 | 작성자 본인 + 다른 활성화 사용자 0명 | 확인 모달 → 삭제 (수정본이 있으면 함께 삭제됨을 안내) |
| 폐기 요청 | 작성자 본인 + 다른 활성화 사용자 있음 | 요청 → 관리자 승인 대기 |
| 관리자 삭제 | 관리자 | 확인 모달 → 삭제 (활성화 중인 팀원에게 알림) |
| 관리자 폐기 | 관리자 | Deprecated 상태로 변경 (기존 사용자 경고, 신규 활성화 불가) |

## 7. 상태별 화면 변화

### 7.1 팀 스킬 테이블 — 빈 상태

스킬이 0개인 신규 팀에 표시.

```
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│          아직 팀에 등록된 스킬이 없습니다                      │
│                                                             │
│     [채팅에서 만들기]         [파일에서 가져오기]               │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 7.2 패널 미선택 상태

테이블에서 아직 스킬을 클릭하지 않았을 때. 테이블이 전체 폭으로 표시된다.

### 7.3 수정본 존재 시 테이블 표시

수정본이 있는 스킬은 테이블에서 상태 뱃지로 표시. 해당 행 클릭 시 패널에서 [수정본으로 전환] 버튼 제공.

### 7.4 관리 탭 — 빈 상태

대기 중인 제안이 없을 때: "대기 중인 제안이 없습니다."

| 설계 결정 | 채택 근거 | 참조 |

| 활성화 모델 (사본 아님) | 원본 참조로 관리 부담 최소화. 전체 스킬 중 필요한 것만 선택 | 자체 설계 |
| 편집 시 수정본 자동 생성 | "포크" 개념 없이 편집 행위가 자연스럽게 수정본 생성. 테스트 후 제안 | Git branch에서 착안, 명시적 포크 제거 |
| 저장과 제안 제출 분리 | 편집 → 저장 → 테스트 → (반복) → 제안 제출. 저장 없이 제안 제출이 바로 보이면 UX가 어색함. 중간 저장으로 며칠에 걸친 작업도 지원 | 자체 설계 (자연스러운 편집 흐름) |
| 파일 탐색기 + 콘텐츠 뷰 구조 | 스킬은 파일 패키지. "본문 vs 첨부"로 분리하면 파일 간 이동 시 스크롤 왕복 필요. 파일 목록 → 클릭 → 콘텐츠 전환 방식으로 탐색 비용 제거. 단일 파일 스킬에서도 자연스러움 | Claude web skill UI, VS Code explorer |

| 패널 전체 편집 모드 전환 | [편집] 1회로 패널 전체가 편집 모드. 파일 목록에서 파일 전환 시에도 편집 상태 유지. 각 파일 편집 상태 독립 관리 | 자체 설계 (편집 진입 비용 최소화) |
| 테스트 시 자동 저장 | 최신 편집 내용으로 테스트해야 의미 있음. [저장]은 "테스트 없이 중간 저장" 용도로 분리 | 자체 설계 |
| 테이블 + 슬라이드 패널 | 전체 폭 테이블로 정보 밀도 확보 + 패널로 상세 확인. 화면 전환 없음 | Jira, Linear, Notion 데이터베이스 |
| 패널 전체 확장 옵션 | 편집 작업 시 넓은 공간 필요 | 자체 설계 |
| 활성화/비활성 그룹 분리 | 내가 사용하는 스킬과 팀 전체 스킬을 한 화면에서 관리 | 자체 설계 |
| 활성화 토글: 테이블에서만 | 빠른 켜고 끄기가 주 용도. 패널에서는 불필요 | v3 설계 유지 |
| 작성자 기반 삭제 | 삭제 권한을 작성자로 한정. 수정본 유무와 무관. 비작성자에게는 삭제 노출 안 함 | 자체 설계 (v5 변경) |
| 관리자 뷰: 스킬 메뉴 내 탭 | 스킬 맥락에서 벗어나지 않고 관리 | 자체 설계 |
| 관리자 통합 대기열 | 신규/제안/폐기를 유형별로 나누면 관리자가 여러 탭을 오가야 함. 통합 테이블 + 유형 필터로 단순화 | 자체 설계 |
| 검토 시 상세 패널 연동 | 관리자가 승인/반려 판단을 위해 스킬 전체 내용 또는 diff를 확인할 수 있어야 함 | 자체 설계 |
| 개선 제안: 승인/반려 2가지 | "수정 요청"과 "반려"의 실질적 차이가 없음. 코멘트 내용으로 의도 전달 가능. 관리자 판단 부담 최소화 | Git PR 패턴 단순화 |
| 제안 시 원본 작성자 알림 | 관리자가 모든 도메인 지식을 갖기 어려움. 작성자 코멘트로 판단 보조 (승인 권한은 관리자만) | GitHub PR reviewer 패턴 |
| 채팅 편집 주 경로 + 직접 편집 보조 | [채팅에서 편집]이 주 편집 경로. 직접 편집(인라인)은 "..." 메뉴에 배치하여 오타 수정 등 경미한 변경용으로 제공. 구조적 변경은 채팅으로 유도 | 자체 설계 (v5 변경) |
| 파일 타입별 편집 경계 | 텍스트는 인라인 편집, 스크립트는 채팅에서. 경미한 편집/구조적 변경 분리 | Copilot Studio Configure vs Topics |
| 패널 "내 현재 버전" 표시 | 원본 뷰/수정본 뷰를 구분하지 않음. 수정본이 없으면 원본, 있으면 수정본을 동일한 패널에 표시. 사용자 관점에서 "내가 보는 스킬 = 내가 쓰는 스킬" | 자체 설계 |
| 저장 후 편집 모드 종료 | 저장 → 읽기 전용 복귀. 편집 모드에 갇히지 않고 테스트/제안 제출로 자연스럽게 이어짐 | 일반적 문서 편집 패턴 |
| 주요 액션 직접 노출 + "..." 메뉴 (작성자별 분기) | 패널을 여는 주 목적은 내용 확인. 자주 쓰는 액션만 직접 노출하고 나머지는 "..." 메뉴에 배치. 작성자/비작성자에 따라 "..." 메뉴 구성이 달라짐. 편집 모드에서는 "..." 메뉴 없이 [취소]와 [저장]만 직접 노출 | 자체 설계 (v5 변경) |
| [diff 보기] 버튼 (토글 대체) | 기존 [편집\|원본\|diff] 3개 토글을 [diff 보기] 버튼으로 단순화. side-by-side diff에서 원본이 이미 보이므로 [원본] 뷰 불필요. 읽기 모드(수정본 있음)와 편집 모드 모두에서 동일하게 제공 | 자체 설계 (v5 변경) |
| side-by-side diff 기본, unified 폴백 | diff 표시는 side-by-side를 기본으로 하되, 패널 폭이 좁으면 unified diff로 자동 전환. 버전 이력 비교, 편집 모드 diff, 관리자 제안 검토 모두 동일 규칙 적용 | GitHub PR diff 참조 (v5 변경) |
| 관리자 검토 패널 통일 | 모든 검토 유형(신규/제안/폐기)에서 팀 스킬 상세와 동일한 패널 프레임 사용. 차이는 콘텐츠 영역의 기본 뷰만 유형별로 다름. 관리자가 전체 맥락을 확인한 후 판단할 수 있도록 함 | 자체 설계 (v5 변경) |
| SKILL.md 파라미터 별도 UI 제거 | 파라미터는 SKILL.md 본문에 자연어로 정의. 별도 키-값 폼 불필요. Claude/GPTs 등 주요 서비스도 본문 내 정의 | Claude skills, OpenAI GPTs |
| 업무 기능 기준 카테고리 | 사용자가 업무 목적으로 탐색 | ChatGPT GPT Store 카테고리에서 착안 |
| 스킬 생성 2경로 병행 | 채팅 생성(AI 가이드)과 파일 가져오기(직접 업로드)를 병행하여 경험 수준이 다른 사용자 모두 지원 | Anthropic skill-creator + Manus .skill upload (v5 추가) |
