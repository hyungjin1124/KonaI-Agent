# 홈/대시보드 메뉴 — IA 상세 설계

**최종 생성 일자**: 2026-03-21
**버전**: 1.0
**상태**: 프로토타입 설계 문서

---

## 1. 메뉴 목적

**홈/대시보드 메뉴는 전사 직원의 의사결정 진입점**으로서, 조직 전체의 데이터 기반 AI 인사이트를 한눈에 보여주고, 데이터 탐색/분석으로의 빠른 진입을 제공한다.

---

## 2. 하위 구조: "홈"과 "대시보드" 통합 여부 결정

### 리서치 기반 분석

경쟁사 분석 결과, "홈"과 "대시보드"의 관계는 두 가지 패턴을 보인다:

| 제품 | 홈/대시보드 구조 | 특징 |
|------|-----------------|------|
| **Datadog** | 분리 | Home(시작점/요약) ↔ Dashboards List(별도 메뉴) |
| **ThoughtSpot** | 분리 | Home(콘텐츠 허브, KPI Watchlist) ↔ Liveboards(메인 분석 도구) |
| **Databricks** | 분리 | Home(최근 활동 리스트) ↔ Dashboards(별도 메뉴) |
| **Snowflake** | 분리 | Projects/Home(요약) ↔ Dashboards(별도) |
| **Dify** | 없음 | 앱별 Overview 대시보드로 분산(글로벌 홈 대시보드 미존재) |
| **ServiceNow** | 통합 | AI Control Tower 자체가 중앙 대시보드(별도 "홈" 없음) |
| **Salesforce** | 분리 | CRM Home ↔ Agentforce Analytics(별도) |

### KonaI-Agent 결정: **홈과 대시보드를 통합**

**근거:**
1. **사용자 의도의 유사성**: 두 화면 모두 "조직 전체의 상황 파악"을 목표로 함. 분리 시 중복 네비게이션 비용 증가
2. **AI 인사이트 일원화**: 자동 생성된 인사이트(Watchdog, SpotIQ 유형)를 한 곳에 표시하는 것이 UX상 효율적
3. **채팅→대시보드 경로 단순화**: AI 채팅에서 생성한 분석을 "홈/대시보드"로 바로 저장 가능
4. **ServiceNow AI Control Tower 사례**: 단일 "중앙 관제 대시보드" 패턴이 엔터프라이즈 AI 플랫폼에 적합

**구현 방식**: 단일 "홈/대시보드" 페이지 → 탭/섹션으로 내용 구분

## 3. 하위 구조: 탭/섹션 구성

### 3.1 최상위 레이아웃

```
홈/대시보드 (/dashboard 또는 /)
├─ [상단 네비게이션 바]
│  ├─ 기간 선택 (Date Range Picker)
│  ├─ 글로벌 필터 (조직/부서/팀)
│  └─ 새 대시보드 생성 버튼
│
├─ [좌측 사이드바 또는 탭]
│  ├─ 📊 AI 인사이트 (기본 탭)
│  ├─ 📈 KPI 대시보드
│  ├─ 🎯 부서별 성과
│  └─ ⚙️ 커스텀 대시보드
│
└─ [메인 영역]
   └─ 선택한 탭의 위젯 그리드
```

### 3.2 각 탭의 역할

#### 탭 1: AI 인사이트 (기본 진입점)

**목적**: AI가 자동으로 발견한 비즈니스 기회/이상 신호를 우선순위 순으로 표시

**구성 요소**:
- **AI Highlight Card** (상단 고정)
  - 자연어로 작성된 2-3개 줄 요약: "최근 7일간 매출은 전주 대비 12% 증가. 주요 성장 동인은 아래 제품군입니다."
  - 출처: AI 분석 엔진 (리서치에서 ThoughtSpot AI Highlights, Datadog Watchdog 패턴)
  - 상호작용: 요약 텍스트 클릭 → 해당 분석의 상세 대시보드/채팅 결과로 드릴다운

- **변화 감지 (Unexpected Changes)**
  - 위젯: 시각화 모음 (차트 + 설명)
  - 예시: "사용자 가입 수가 예상보다 20% 낮음 (vs. 예측)" → 원인 분석 링크
  - 상호작용: 개별 변화 카드 클릭 → AI 채팅으로 "왜 이런 일이 일어났나?"라는 자동 질의 실행

- **인사이트 피드**
  - 스크롤 가능한 리스트: 시간순 또는 중요도순 정렬 가능
  - 각 항목: 제목 + 설명 + 액션 버튼 (자세히 보기, 핀, 대시보드로 추가)

#### 탭 2: KPI 대시보드

**목적**: 조직 전체의 핵심 성과 지표 (KPI) 모니터링

**구성 요소**:
- **KPI 카드 행**
  - 예시: 활성 사용자, 데이터 처리량(GB), 쿼리 성공률, AI 비용(monthly)
  - 표시: 현재값 + 비교 기간 대비 변화율(%) + 트렌드 미니 차트
  - 색상 코드: 정상(녹색), 경고(노란색), 위험(빨간색)

- **주요 메트릭 시각화 (2-3개)**
  - 시계열 차트: 예측 대역(prediction band)과 함께 과거 실적 표시
  - 분포 차트 또는 히트맵: 시간대별, 부서별 성과 분포

- **드릴다운 지점**: KPI 카드 클릭 → 해당 지표의 상세 분석 대시보드로 이동

#### 탭 3: 부서별 성과

**목적**: 역할/부서별로 관련된 대시보드를 빠르게 접근

**구성 요소**:
- **부서별 카드 레이아웃**
  - 각 카드: 부서명 + 대표 지표 3개(요약) + 상세 보기 버튼
  - 부서: 영업, 마케팅, CS, 개발, 운영 등

- **실제 대시보드 임베드 (선택 사항)**
  - 부서 카드 클릭 → 해당 부서 전용 대시보드로 전환 또는 모달로 확대

#### 탭 4: 커스텀 대시보드

**목적**: 사용자/팀이 만든 일회용 또는 저장된 대시보드 리스트

**구성 요소**:
- **대시보드 리스트/그리드 보기**
  - 각 항목: 대시보드 썸네일 + 제목 + 마지막 업데이트 시간 + 즐겨찾기 토글
  - 필터: 내가 만든 것 / 공유받은 것 / 즐겨찾기
  - 검색바: 대시보드명으로 검색

- **빠른 생성 버튼** ("+ 새 대시보드")
  - AI 어시스턴트로 생성 (자연어 프롬프트)
  - 또는 빈 캔버스에서 시작

## 4. AI 인사이트 통합 방식 (리서치 패턴 기반)

### 4.1 자동 인사이트 생성 경로

```
데이터 소스
  ↓
AI 분석 엔진 (Watchdog / SpotIQ 유형)
  ├─ 이상 탐지 (Anomaly Detection)
  ├─ 추세 분석 (Trend Analysis)
  ├─ 원인 분석 (Root Cause Analysis)
  └─ 예측 (Forecasting)
  ↓
AI 인사이트 카드 → 홈/대시보드 "AI 인사이트" 탭
  ├─ 신뢰도 순 또는 영향도 순 정렬
  ├─ 3-5개만 표시 (나머지는 "모두 보기")
  └─ 자연어 요약 + 상호작용 버튼
```

### 4.2 리서치에서 관찰된 4가지 통합 수준

| 수준 | 패턴 | 예시 | KonaI-Agent 채택 |
|------|------|------|-----------------|
| **Level 1: 위젯화** | AI 인사이트를 "Watchdog Alerts" 같은 별도 위젯으로 대시보드에 추가 | Datadog Watchdog Alerts Widget | ✅ 기본 구현 |
| **Level 2: 자동 인라인** | AI가 자동으로 대시보드에 인사이트 카드를 "푸시" | ThoughtSpot AI Highlights (버튼 클릭) | ✅ "AI 인사이트" 탭으로 제공 |
| **Level 3: 채팅 통합** | AI 채팅에서 생성한 분석이 대시보드로 직접 저장됨 | Databricks "Ask Genie" 결과 → 대시보드 | ✅ 아래 섹션 참조 |
| **Level 4: 중앙 관제** | AI 거버넌스/리스크/성과가 단일 대시보드에서 모니터링됨 | ServiceNow AI Control Tower | 🔄 Phase 2 (관리자 메뉴) |

### 4.3 인사이트 상호작용 설계

**Level 2 구현 (AI Highlights 유사)**:

```
AI 인사이트 카드
├─ 자연어 요약 텍스트 (클릭 가능)
│  └─ 클릭 → "AI 채팅"으로 이동 (해당 분석 컨텍스트 전달)
├─ "자세히 보기" 버튼
│  └─ 클릭 → 하위 인사이트 리스트 (예: SpotIQ Change Analysis)
├─ "대시보드에 추가" 버튼
│  └─ 클릭 → 커스텀 대시보드에 이 인사이트를 위젯으로 저장
└─ "닫기" 또는 "이 인사이트는 도움이 되지 않음" (피드백)
   └─ 클릭 → AI 모델 재학습 데이터로 수집
```

## 5. 다른 메뉴와의 연결점

### 5.1 홈/대시보드 → AI 채팅

**연결 경로**:
- **"AI 인사이트" 탭의 자연어 요약 클릭** → AI 채팅 시작 (프롬프트 자동 입력)
  - 예: "사용자 가입 수 감소의 원인을 분석해줘"
- **KPI 카드 클릭 → 상세 보기** → "이 데이터에 대해 질문하기" 버튼 → 채팅으로 이동
- **위젯 우측 상단 "⋮" 메뉴** → "AI로 분석하기" → 채팅 오픈

**채팅 상태 유지**: 채팅에서 생성된 분석 결과가 "대시보드로 저장" 버튼을 통해 홈/대시보드로 돌아옴 (5.3 참조)

### 5.2 AI 채팅 → 홈/대시보드

**연결 경로**:
- **채팅 결과 아래 "대시보드에 저장" 버튼**
  - 클릭 → 모달: "어느 대시보드에 추가하시겠어요?" (기존 또는 신규)
  - 신규 선택 시 → 대시보드 이름 입력 → "커스텀 대시보드" 탭에 추가

- **채팅 결과 "핀" 버튼**
  - 클릭 → 홈/대시보드의 "AI 인사이트" 탭에 임시 추가 (세션 동안만 유지, 또는 별도 저장)

**설계 원칙**: 채팅과 대시보드를 "느슨하게 연결" → 사용자가 원할 때만 저장하도록 (Databricks Genie 패턴)

### 5.3 스킬 → 홈/대시보드

**연결 경로**:
- **스킬 실행 결과 "대시보드에 추가" 버튼**
  - 스킬 결과(테이블, 차트, 텍스트)를 새 대시보드 위젯으로 생성
  - 예: "고객 세분화 스킬" 실행 → 결과 테이블 → "커스텀 대시보드"에 저장

- **스킬 메뉴에서 최근 실행 결과 리스트**
  - 사용자가 최근 스킬 실행 내역을 홈/대시보드에서도 볼 수 있도록 (선택 사항)

### 5.4 데이터 메뉴 → 홈/대시보드

**연결 경로**:
- **데이터 탐색(Data Explorer) 결과 "대시보드 위젯으로 추가"**
  - 데이터 필터링/정렬 후 결과를 홈/대시보드의 커스텀 대시보드에 위젯으로 저장

- **홈/대시보드의 위젯 "데이터 소스 보기"**
  - 위젯 우측 상단 "⋮" 메뉴 → "데이터 소스" → 데이터 메뉴로 이동하여 원본 테이블 확인

**데이터 거버넌스**: 데이터 담당자는 홈/대시보드에서 모든 대시보드의 데이터 혈통(lineage) 확인 가능 (Role-based, 아래 섹션 참조)

### 5.5 관리자 메뉴 → 홈/대시보드

**연결 경로**:
- **관리자 메뉴의 "사용량 모니터링" → 대시보드**
  - 사용자별/대시보드별 조회 수, 저장 횟수, 공유 빈도 등을 홈/대시보드에서 조회 가능 (관리자 전용)

- **관리자 메뉴의 "감사 로그"**
  - 대시보드 변경, 사용자 추가/삭제 등의 감사 기록을 별도 섹션에서 확인

**홈/대시보드 공개 설정** (관리자):
- 특정 대시보드를 전사 공개/비공개 설정
- 역할별 가시성 제어: "이 대시보드는 [영업팀]에만 표시"

## 6. 역할별 차이 (Role-Based Differentiation)

### 6.1 일반 직원 (General User)

**보유 권한**:
- 홈/대시보드의 4개 탭 모두 조회
- "AI 인사이트", "KPI 대시보드" 탭은 조직 기본값 (수정 불가)
- "커스텀 대시보드" 탭에서 **자신이 만든 대시보드만 수정/삭제**
- **공유받은 대시보드는 조회만** (수정 불가)

**특화 콘텐츠**:
- "부서별 성과" 탭: 자신의 부서 관련 대시보드만 표시
- 채팅에서 생성한 분석 → "내 분석" 폴더로 자동 저장 (선택 사항)

### 6.2 데이터 담당자 (Data Steward)

**추가 권한**:
- 모든 대시보드의 **데이터 혈통(lineage) 확인**
  - 위젯 우측 "데이터 소스" 클릭 → 테이블/뷰 메타데이터 + 업스트림 ETL 정보 표시
- 데이터 품질 문제 발견 시 **알림 표시** (예: "이 테이블의 마지막 업데이트는 2시간 전입니다")
- **"데이터 관리" 탭** (5번째 탭, 데이터 담당자만 표시)
  - 사용 중인 테이블 목록, 스키마 변경 이력, 데이터 품질 점수

**UI 차이**:
- 각 위젯 우측 상단에 "데이터 출처" 아이콘 표시 (클릭 가능)
- 데이터 이상 감지 시 상단 배너: "경고: 매출_일별 테이블의 데이터 정합성 문제" 링크

### 6.3 관리자 (Platform Admin + Customer Admin)

#### 플랫폼 관리자 (Platform Admin)
- 모든 사용자의 모든 대시보드 조회/감사
- **"관리" 탭** (6번째 탭)
  - 사용량 대시보드: 누가 언제 뭘 조회했는가
  - 감사 로그: 대시보드 생성/수정/공유 이력
  - 비용 모니터링: AI 분석, 데이터 처리 비용 추적

#### 고객사 관리자 (Customer Admin)
- 자신의 조직 내 사용자/대시보드 관리만
- 같은 "관리" 탭이지만 필터링된 범위(자신의 조직만)

**UI 차이**:
- 각 대시보드/사용자에 **"비용" 메타데이터 표시** (월간 크레딧 소비 등)
- 대시보드 목록 우측에 "사용자 수", "마지막 조회일" 표시
- "대시보드 삭제" 버튼 활성화 (일반 사용자는 비활성)

## 7. 프로토타입 구현 범위 vs 추후 확장

### 7.1 프로토타입 (Phase 1, MVP)에 반드시 포함

| 항목 | 이유 | 세부사항 |
|------|------|---------|
| **AI 인사이트 탭** | 핵심 차별화 기능 | 자동 생성된 인사이트 3-5개 표시 (목 데이터) |
| **KPI 대시보드** | 의사결정 진입점 | 4-6개 KPI 카드 + 1개 시계열 차트 |
| **커스텀 대시보드** | 사용자 주도 분석 | 대시보드 리스트 조회 + 생성 버튼 |
| **기간 필터** | 기본 상호작용 | 홈/대시보드 상단의 Date Range Picker |
| **위젯 드릴다운** | 탐색 UX | KPI 카드 클릭 → 상세 분석 페이지 |
| **채팅 연결** | 한 탭 상호작용 | "AI로 분석하기" 버튼 → 우측 채팅 패널 오픈 |
| **일반 사용자 역할** | 기본 UX | 읽기 + 커스텀 대시보드 작성만 |

**구현 우선순위**: AI 인사이트 → KPI 대시보드 → 채팅 연결

### 7.2 Phase 2 (확장 기능)에 포함

| 항목 | 이유 | 예상 타임라인 |
|------|------|--------------|
| **부서별 성과 탭** | 역할 기반 콘텐츠 | 3개월 후 (사용자 피드백 수집 후) |
| **데이터 담당자 권한** | 데이터 거버넌스 | 데이터 메뉴가 완성된 후 |
| **관리자 "관리" 탭** | 운영/감시 | 사용량 집계 시스템 구축 후 |
| **스킬 결과 통합** | 크로스 기능 | 스킬 메뉴 완성 후 |
| **대시보드 공유 고급 기능** | 협업 | 사용자 피드백 기반 |
| **AI가 자동으로 대시보드 생성** | 에이전트 기능 | LLM 기반 "Dashboard Agent" 구현 후 |

### 7.3 포기하거나 미연기 기능

| 항목 | 사유 |
|------|------|
| **Dify 패턴: 앱별 내장 대시보드** | KonaI-Agent는 "앱" 개념이 없음 (스킬/채팅만 존재) |
| **Snowflake 패턴: 타일 한 개당 하나의 SQL 쿼리** | 프로토타입은 더 강력한 위젯 라이브러리 필요 |

## 10. 인터랙션 디자인 (Key Flows)

### Flow 1: 일반 사용자가 AI 인사이트 발견

```
1. 사용자가 홈/대시보드 방문
   ↓
2. "AI 인사이트" 탭 기본 선택 (또는 클릭)
   ↓
3. 상단 AI Highlight: "최근 데이터 변화 요약"
   ↓
4. 사용자가 "자세히 보기" 클릭
   ↓
5. 우측 패널에 AI 채팅 자동 오픈 (프롬프트 전달)
   → "이 변화의 원인이 뭐예요?"
   ↓
6. 채팅이 상세 분석 결과 표시
   ↓
7. 사용자 선택:
   a) "대시보드에 저장" → 커스텀 대시보드 추가
   b) "이 분석 복사" → 공유 링크 생성
   c) "닫기" → 대시보드로 복귀
```

### Flow 2: 커스텀 대시보드 생성 및 저장

```
1. "커스텀 대시보드" 탭 클릭
   ↓
2. "+ 새 대시보드" 버튼 클릭
   ↓
3. 선택:
   a) "AI 어시스턴트로 생성" → 자연어 프롬프트 입력
      → AI가 위젯 자동 제안
      → 사용자 승인 → 저장
   b) "빈 캔버스 시작" → 수동으로 위젯 추가
      ↓
4. 위젯 추가 (+ 버튼)
   → 데이터 소스 선택
   → 차트 유형 선택
   → 레이아웃에 배치
   ↓
5. 대시보드 저장 (Ctrl+S)
   → 이름 입력: "2026년 3월 매출 분석"
   → 공유 설정: 비공개 / 팀 공개 / 전사 공개
   → 저장
   ↓
6. "공유" 버튼으로 동료에게 링크 전달 (선택)
```

### Flow 3: KPI 드릴다운 (대시보드 → 채팅)

```
1. KPI 대시보드의 "활성 사용자" 카드 클릭
   ↓
2. 모달 또는 풀스크린: 해당 KPI의 상세 분석
   - 지난 30일 트렌드
   - 부서/지역별 분포
   - 예측 추세
   ↓
3. 사용자가 "왜 이 주에 사용자가 감소했어?" 물어봄
   ↓
4. "질문하기" 버튼 클릭 → 우측 채팅 열림
   (자동 프롬프트: "2026-03-15 주간 활성 사용자 감소의 원인을 분석해주세요")
   ↓
5. AI 채팅이 분석 결과 제시
```

## 12. 검증 기준 (Acceptance Criteria)

### 프로토타입이 완성되었다고 판단하는 기준

- [ ] "AI 인사이트" 탭: 목 데이터로 3-5개 인사이트 카드 표시
- [ ] "KPI 대시보드" 탭: 4개 KPI 카드 + 1개 시계열 차트 렌더링
- [ ] "커스텀 대시보드" 탭: 사용자가 새 대시보드 생성 → 위젯 추가 → 저장 가능
- [ ] 기간 필터: 날짜 범위 선택 시 모든 위젯이 필터링됨
- [ ] 채팅 연결: "AI로 분석하기" 버튼 클릭 시 우측 채팅 패널 오픈 (프롬프트 전달)
- [ ] 드릴다운: KPI 카드 클릭 시 상세 분석 화면으로 이동
- [ ] 역할 기반 UI: 일반 사용자는 "커스텀 대시보드" 수정/삭제만 가능, 관리자 탭은 미표시
- [ ] 반응형 디자인: 데스크톱(1920x1080), 태블릿(768px) 이상에서 정상 렌더링
- [ ] 성능: 초기 로딩 < 2초, 위젯 상호작용 반응성 < 500ms

## 최종 설계 결론

KonaI-Agent의 홈/대시보드 메뉴는:

1. **통합 대시보드 패턴** (ServiceNow 사례)을 채택하되, **탭 기반 콘텐츠 분화**로 단순함과 깊이의 균형
2. **AI 인사이트 중심**의 진입점으로, 자동 생성된 인사이트를 우선 노출
3. **느슨한 연결(loose coupling)**로 채팅, 스킬, 데이터 메뉴와 상호작용 (Databricks 패턴)
4. **역할 기반 차등화**로 일반 사용자/데이터 담당자/관리자의 다른 필요를 수용
5. **반복적 확장**을 고려하여 Phase 1에서는 핵심 기능만 (AI 인사이트 + KPI + 커스텀) 구현
