## 1. 사이트맵

```
관리자 (GNB 5번째, 관리자 역할에게만 노출, 3탭 플랫 구조)
├─ [사용자 관리] ────────── 테이블 + 인라인 액션
├─ [운영 현황] ──────────── 단일 스크롤 페이지 (3개 섹션) + 모델 설정 팝업
│   ├─ 에이전트 상태
│   ├─ 비용/사용량
│   ├─ 활동 리포트
│   └─ [⚙ 모델 설정] ─────── 우상단 버튼 → 팝업
└─ [대화 이력] ──────────── 전체 폭 테이블 + 슬라이드 패널
```

*[설계 변경 (v4 vs v3): (1) 2화면(사용자 관리 + 모니터링) → 3탭 플랫 구조(사용자 관리 + 운영 현황 + 대화 이력)로 변경. 대화 이력은 테이블+패널 구조로 독립 화면급 복잡도를 가지므로, 대시보드형 운영 현황과 분리. (2) "모니터링" → "운영 현황"으로 명칭 변경 — 에이전트 상태·비용·활동 리포트를 포괄하는 명칭. (3) 에이전트 상태의 오류 전용 패널 제거 → 오류 테이블 컬럼을 확장하여 테이블만으로 트리아지 가능하도록 설계. (4) 비용/사용량 차트에 토큰 사용량 뷰 토글 추가.]*

*[설계 변경 (v3 vs v2): (1) 비용/사용량: 이중 Y축(토큰 스택 바 + 누적 비용 라인) → 단일 Y축 모델별 일별 비용 스택 바. 비용이 1차 관심사, 토큰은 툴팁. (2) 모델별 비용 비율 수평 바 차트 제거 — 스택 바 범례에 금액 병기로 대체. (3) 오류 행 클릭 시 "대화 이력과 동일한 패널" → "오류 전용 패널" 신설. 판단 가이드(유사 오류·영향 범위·추정 원인) 포함. (4) 대화 이력 패널의 에러 표시 최소화 — 한 줄 요약만, 상세는 오류 전용 패널 담당. (5) 활동 리포트에 팀 드롭다운 필터 추가 — 팀별 도입 현황·스킬 활용·성과 비교 가능.]*

*[설계 변경 (v2 vs v1): (1) 모델 프로바이더를 스크롤 섹션에서 우상단 버튼+팝업으로 분리 — 접근성 개선, 스크롤 길이 축소. (2) 사용자 초대 → 사용자 추가로 변경, 멤버 디렉토리 기반 선택 방식 채택. (3) 비용/사용량 차트를 이중 Y축으로 통합. (4) 오류 목록 "더 보기"를 섹션 내 확장으로 변경 (대화 이력으로 점프하지 않음). (5) 사용자 테이블에 팀명 컬럼 추가. (6) 스킬 활용의 "공유된 스킬 수" 제거 — 생성 즉시 팀 전체에 공유되므로 구분 무의미. (7) 스킬별 사용 현황에 작성자 팀 컬럼 추가.]*

## 2. 설계 원칙

서비스 기획서 3.5절에서 정의한 세 가지 원칙을 IA 설계에 그대로 적용한다.

| 원칙 | IA 적용 |
|------|---------|
| **최소 기능 원칙** | 단일 테넌트·소수 사용자 환경에서 실제 필요한 기능만 포함. 3개 탭으로 한정 |
| **목적 기반 모니터링** | 모든 지표에 "이걸 보고 무엇을 판단/대처하는가"를 명시. 목적 없는 지표 배제 |
| **화면 최소화** | 기능이 적을 때 탭·메뉴를 세분화하지 않음. 운영 현황은 단일 스크롤 페이지에 섹션으로 구분. 대화 이력은 탐색형 UI(테이블+패널)이므로 독립 탭으로 분리 |

## 3. 역할 모델

2역할 체계를 사용한다. 별도의 권한 관리 화면 없이 사용자 관리에서 역할을 직접 변경한다.

| 역할 | 설명 | GNB 가시성 |
|------|------|-----------|
| **일반 사용자** | 채팅, 스킬 사용, 대시보드 | 홈/대시보드, AI 채팅, 스킬 |
| **관리자** | 일반 사용자 권한 + 데이터 관리 + 서비스 운영 | 전체 5개 메뉴 |

관리자 역할은 AI사업팀(서비스 제공자)과 코나아이 경영진(CEO, 임원진, 조직장)에게 부여한다. 권한이 없는 메뉴는 GNB에서 숨김 처리한다. *[근거: Snowflake, Dify, ChatGPT Enterprise — 업계 표준 숨김 패턴. service-plan.md GNB 구조]*

## 4. 화면별 정보 구성

### 4.1 사용자 관리

사용자 계정의 조회·역할 할당을 **단일 화면**에서 처리한다. 사용자 목록은 ERP에서 자동 동기화되며, 퇴사·휴직 등 상태 변경도 ERP 원천 데이터를 따른다(Single Source of Truth). 별도의 수동 비활성화 기능은 제공하지 않는다.

#### 화면 레이아웃

```
┌──────────────────────────────────────────────────────────────────────────────────────────┐
│  사용자 관리                                                                              │
│  검색 [___________]   팀▼   역할▼                                                          │
├──────────────────────────────────────────────────────────────────────────────────────────┤
│  │ 이름    │ 팀        │ 이메일            │ 권한 그룹          │ 역할 ▼  │ 최근 활동일 │
│  │ 김영수  │ 생산기술팀 │ kim@kona.com      │ 생산관리, 기본권한  │ [일반 ▼]│ 2026.03.24 │
│  │ 박지은  │ 회계팀    │ park@kona.com     │ 기본권한           │ [일반 ▼]│ 2026.03.20 │
│  │ 이대표  │ 대표실    │ lee@kona.com      │ 임원(사장단)       │ [관리자▼]│ 2026.03.25 │
│  │ 최민호  │ 영업1팀   │ choi@kona.com     │ —                 │ [일반 ▼]│ 2026.03.28 │
│  │ 정수진  │ 구매팀    │ jung@kona.com     │ 기본권한, 구매관리  │ [일반 ▼]│ 2026.03.22 │
│  ...                                                                                      │
└──────────────────────────────────────────────────────────────────────────────────────────┘
```

*[설계 변경 (v5): 권한 그룹 컬럼 추가. "팀" 컬럼이 이미 부서(부서 기반 접근의 한 축)를 보여주므로, 테이블에서 보이지 않는 정보인 ERP 그룹 소속을 추가하여 관리자가 패널을 열지 않아도 "이 사람이 어떤 경로로 데이터 접근 권한을 갖는가"를 파악할 수 있게 함. 상세: data-ia.md 4.2절]*

#### 테이블 컬럼

| 컬럼 | 설명 | 정렬 |
|------|------|------|
| 이름 | 사용자 이름 | 가나다순 |
| 팀 | 소속 팀명. 조직 데이터에서 가져옴 | — |
| 이메일 | 사용자 이메일 주소 | — |
| 권한 그룹 | ERP 그룹(`_tcagroupsecu`) 소속 목록. 최대 2개 표시, 초과 시 `+N` truncation. 그룹 없으면 `—` | — |
| 역할 | 인라인 드롭다운 (일반/관리자). 즉시 변경 가능 | — |
| 최근 활동일 | 마지막 로그인 또는 활동 날짜 (yyyy.mm.dd) | 최근순 (기본) |

기본 정렬: 최근 활동일 순.

#### 필터

| 필터 | 옵션 |
|------|------|
| 검색 | 이름, 이메일 기준 실시간 필터링 |
| 팀 | 전체, 팀 목록 (조직 데이터 기반) |
| 역할 | 전체, 일반, 관리자 |

#### 주요 액션

| 액션 | 위치 | 설명 |
|------|------|------|
| 역할 변경 | 테이블 인라인 드롭다운 | 클릭 즉시 변경. 확인 모달 없음 (Dify Members 패턴) |

#### 사용자 행 클릭 → 슬라이드 패널

사용자 행 클릭 시 우측에 슬라이드 패널이 열린다. 패널 헤더에 이름·팀·역할을 항상 표시하고, 본문은 **사용자 정보(기본 접힘)** + **뷰테이블 접근 현황(기본 펼침)** 순서로 배치한다. 사용자 정보를 상단에 두되 접힘 상태로 유지하여, 뷰테이블 접근 현황이 길어져도 사용자 정보가 밀려 내려가지 않도록 한다. 관리자가 패널을 여는 주된 이유는 데이터 접근 상태 확인이므로 접근 현황이 바로 펼쳐진다. 패널의 상세 구성은 `data-ia.md` 4.3절을 참조한다.

*[설계 변경 (v6): 패널 배치 순서 변경 — 사용자 정보(접힘)를 상단, 뷰테이블 접근 현황(펼침)을 하단으로. v5에서는 접근 현황을 먼저 배치했으나, 접근 현황 목록이 길어질 경우 사용자 정보가 패널 하단으로 밀려 접근하기 어려워지는 문제. 사용자 정보를 접힘 상태로 상단에 고정하면 필요할 때 즉시 펼칠 수 있고, 접근 현황은 그 아래에서 자유롭게 늘어나도 무방.]*

*[설계 변경 (v5): 패널 정보 위계 변경 — 뷰테이블 접근 현황을 기본 펼침으로 승격, 사용자 정보를 기본 접힘으로 하강. 스킬 메뉴 패널에서 품질 테스트를 기본 펼침으로 둔 것과 동일한 "가장 필요한 정보를 먼저" 패턴.]*

### 4.2 운영 현황

에이전트 운영 상태, 비용/사용량, 활동 리포트를 **단일 스크롤 페이지**에서 관리한다. 대화 이력은 독립 탭(4.3절)으로 분리한다. 모델 설정은 우상단 버튼으로 분리한다. 화면 자체가 리포트처럼 읽히도록 설계하여, 경영진이 직접 열람해도 서비스 현황을 파악할 수 있게 한다.

#### 섹션 배치 순서와 근거

| 순서 | 섹션 | 읽는 질문 | 배치 근거 |
|------|------|----------|----------|
| 1 | 에이전트 상태 | 시스템이 정상 작동하는가? | **운영 건강성이 최우선**. 오류가 있으면 나머지 지표는 의미가 없음 |
| 2 | 비용/사용량 | 얼마나 쓰고 있는가? | 경영진의 1차 관심사. 에이전트가 정상이라면 다음은 비용 |
| 3 | 활동 리포트 | 서비스가 효과를 내고 있는가? | 장기적 도입 효과. 가장 전략적이지만 긴급하지 않음 |

위에서 아래로 **긴급도(운영→재무→상세→전략)** 순으로 배치하여, 스크롤할수록 시야가 넓어지는 리포트 구조를 형성한다.

#### 4.2.1 에이전트 상태

**알 수 있는 것**: 에이전트 실행 성공/실패율, 최근 오류 목록
**가능한 판단/대처**: 오류 급증 감지 → 개발팀에 정보 전달, 문제 있는 모델 교체 판단

| 요소 | 설명 |
|------|------|
| KPI 카드 | 성공률(%), 실패율(%), 총 실행 건수. 전 기간 대비 변화율 표시 |
| 최근 오류 목록 | 기본 10건 표시. 시간, 사용자, 에러 타입(Timeout/Model Error/Tool Error), 실패 단계, 요약 |
| [더 보기 ▼] | 클릭 시 섹션 내에서 10건씩 추가 로드 (인플레이스 페이지네이션). 대화 이력으로 점프하지 않음 |
| 오류 행 클릭 | 행 하이라이트만 표시. 트리아지에 필요한 정보는 테이블 컬럼에서 직접 확인 |

**오류 목록의 "더 보기" 설계:**

오류 목록은 에이전트 상태 섹션 내부에서 독립적으로 확장된다. 대화 이력 조회 섹션으로 스크롤하거나 점프하지 않는다. 이는 오류 목록의 컬럼 구성(시간, 에러 타입, 실패 단계)과 대화 이력의 컬럼 구성(사용자, 대화 요약, 스킬, 모델)이 다르기 때문이다. 컬럼이 갑자기 바뀌면 "같은 건을 보고 있는데 맥락이 전환되는" 어색함이 발생한다.

| 동작 | 설명 |
|------|------|
| 기본 | 최근 10건 표시 |
| [더 보기 ▼] 1회 | 10건 추가 로드 (총 20건). 오류가 더 있으면 [더 보기 ▼] 유지 |
| 오류 행 클릭 | 행 하이라이트 표시 (패널 없음) |
| 최대 표시 | 50건까지 로드. 이후 "전체 오류를 보려면 대화 이력 탭에서 상태=오류로 필터하세요" 안내 |

**오류 테이블 확장 컬럼:**

오류 전용 패널 대신, 오류 테이블 컬럼을 확장하여 테이블만으로 트리아지가 가능하도록 설계한다. 관리자가 내려야 하는 세 가지 판단(반복인가, 범위가 넓은가, 내부/외부 문제인가)이 모두 테이블 컬럼에서 답이 나온다.

| 컬럼 | 설명 | 트리아지 판단 |
|------|------|-------------|
| 시간 | 발생 시간 (mm.dd HH:mm) | — |
| 사용자 | 사용자 이름 (팀) | — |
| 요청 요약 | 사용자 첫 메시지 요약 (최대 20자) | 무엇을 하려다 실패했는가 |
| 스킬 | 사용된 스킬. 미사용 시 "—" | 특정 스킬의 반복 실패 식별 |
| 모델 | 사용된 AI 모델 | 모델 교체 판단 |
| 에러 타입 | Timeout / Model Error / Tool Error | 내부 vs 외부 문제 추정 |
| 실패 단계 | 데이터 조회 / 응답 생성 / 스킬 실행 | 내부 vs 외부 문제 추정 |
| 유사(24h) | 최근 24시간 동일 에러 타입 건수 | 일회성인가, 반복인가 |
| 영향 | 동일 오류를 겪은 사용자 수 | 범위가 넓은가 |
| 🔗 | LangFuse 트레이스 링크 (아이콘 버튼) | 심층 분석 필요 시 |

```
시간         │ 사용자 │ 요청 요약       │ 스킬     │ 모델        │ 에러 타입    │ 실패 단계   │ 유사 │ 영향 │    │
03.25 14:32 │ 김철수  │ 3월 매출 분석.. │ 매출 분석 │ Claude 3.5 │ Timeout     │ 데이터 조회 │ 4건  │ 3명  │ 🔗 │
03.25 11:15 │ 박영희  │ PPT 생성..    │ PPT 생성 │ GPT-4o     │ Model Error │ 응답 생성   │ 1건  │ 1명  │ 🔗 │
03.25 09:40 │ 홍길동  │ 고객 리스트..  │ 매출 분석 │ Claude 3.5 │ Timeout     │ 데이터 조회 │ 4건  │ 3명  │ 🔗 │
```

**이전 설계(오류 전용 패널)와의 차이:**

(1) 오류 전용 슬라이드 패널 제거 — 패널에서 보여주던 판단 가이드(유사 오류, 영향 범위)를 테이블 컬럼으로 승격. 여러 오류를 스캔하며 패턴을 비교하는 것이 가능해짐.
(2) 에러 메시지 원문, 재시도 횟수 등 개발자 레벨 정보는 LangFuse에서 확인. 관리자 트리아지에 불필요한 중간 레이어 제거.
(3) 대화 이력 패널과의 정보 중복 해소 — 오류 정보가 테이블에만 존재하고, 대화 내용은 대화 이력 탭에서만 확인.

*[설계 변경 (v4): (1) 오류 전용 슬라이드 패널 제거 → 테이블 컬럼 확장. 관리자 트리아지 판단(반복 여부, 영향 범위, 내부/외부)이 테이블만으로 가능. (2) 에러 메시지 원문·재시도 횟수 등 개발자 레벨 상세는 LangFuse 담당. 관리자 화면에 불필요한 중간 레이어를 제거. (3) 오류 패널과 대화 이력 패널 간 정보 중복 문제 근본 해소.]*

*[설계 변경 (v3): (1) 오류 행 클릭 시 "대화 이력과 동일한 패널" → "오류 전용 패널"로 변경. 운영 트리아지(무엇이 왜 실패했는가, 일회성인가 반복인가)에 최적화. (2) 판단 가이드 영역 신설 — 유사 오류 건수, 영향 범위, 추정 원인. LangFuse 없이도 1차 트리아지 가능. (3) 대화 이력 패널의 에러 표시 최소화 — 에러 타입+실패 단계 한 줄 요약만 표시, 상세는 에이전트 상태 쪽 담당. 정보 계층 분리로 중복 혼란 해소.]*

*[근거: (1) LangSmith 트레이스 목록 — 에러 상세를 트레이스 컨텍스트 내에서 보여주는 패턴. (2) Datadog Error Tracking — 유사 에러 그루핑 + 영향 범위 표시 패턴. (3) ai-platform-admin-dashboard-patterns.md — 에이전트 실행의 투명성(Trace-First) 원칙. (4) 목적 기반 모니터링 원칙 — "이걸 보고 무엇을 판단하는가"가 명확해야 함.]*

#### 4.2.2 비용/사용량

**알 수 있는 것**: 모델별 일별 비용 추이, 비용 급증 시점과 원인 모델
**가능한 판단/대처**: 예산 초과 위험 감지 → 모델 다운그레이드 또는 사용 제한 판단

| 요소 | 설명 |
|------|------|
| KPI 카드 | 이번 달 비용(전월 대비 변화율), 총 토큰 소비량, 일평균 비용 |
| 모델별 일별 차트 | **모델별 스택 바 (단일 Y축)** + 뷰 토글 [비용 ▼ / 토큰]. 기본 뷰는 비용(관리자 1차 관심사), 토글로 토큰 뷰 전환. 바 호버 시 상세 툴팁(비용 뷰에서는 토큰 수·단가, 토큰 뷰에서는 비용·단가) 표시 |

**모델별 일별 차트 상세 (비용 뷰 / 토큰 뷰):**

```
비용(₩)
80K ┤ ▓▓▓░░
60K ┤ ▓▓▓▓░░▒
40K ┤ ▓▓▓▓▓░▒▒
20K ┤ ▓▓▓▓▓▓░▒▒
    ├────────────────────────────────────────────────
    3/20   3/21    3/22    3/23    3/24
  ▓ Claude 3.5 Sonnet (₩816K)  ░ GPT-4o (₩288K)  ▒ 기타 (₩96K)
```

- Y축: 비용 뷰에서는 일별 총 비용(₩), 토큰 뷰에서는 일별 총 토큰 수. 뷰 토글로 전환
- 스택 구성(모델별): 어떤 모델이 비용을 많이 차지하는지 시각적으로 파악
- 범례: 모델명 + 선택 기간 내 누적 금액 표시. 별도 비용 비율 차트 불필요
- 바 호버 툴팁: 비용 뷰에서는 해당 일자의 모델별 토큰 수·단가, 토큰 뷰에서는 비용·단가 표시. 교차 확인으로 "비용은 높은데 토큰은 적다 = 고비용 모델" 판단 가능

**이전 설계(이중 Y축 + 비용 비율 바)와의 차이:**
(1) 이중 Y축 제거 — 두 축의 스케일 관계가 자의적이라 시각적 오독 가능성 있음. 단일 Y축 + 뷰 토글로 단순화. 비용과 토큰을 같은 차트 공간에서 토글로 전환하여 각각 명확하게 읽을 수 있음.
(2) 누적 비용 → 일별 비용 — 누적 비용은 항상 우상향하여 일별 변동을 읽기 어려움. KPI 카드의 "이번 달 비용 ▲12%"가 이미 예산 소진 속도를 답하므로, 차트는 일별 패턴에 집중.
(3) 모델별 비용 비율 바 제거 — 스택 바가 이미 모델별 비중을 시각적으로 보여줌. 범례에 금액을 병기하면 동일 정보 제공. 정보 중복 제거.

*[설계 변경 (v3): (1) 이중 Y축(토큰 스택 바 + 누적 비용 라인) → 단일 Y축 비용 스택 바로 변경. 비용이 관리자의 1차 관심사이므로 비용을 기본축으로 설정. 토큰 수는 툴팁으로 제공. (2) 모델별 비용 비율 수평 바 차트 제거 — 스택 바 범례에 금액 병기로 대체.]*

*[설계 변경 (v4): 비용 전용 차트 → 비용/토큰 뷰 토글 추가. 토큰 사용량 추이도 차트에서 직접 확인 가능하도록 변경. 기본 뷰는 비용(관리자 1차 관심사), 토큰 뷰에서는 사용량 증감 패턴 확인.]*

*[근거: OpenAI Usage — 모델별 스택 바 차트. Anthropic Console — 모델별 비용 분리. ai-platform-admin-dashboard-patterns.md P1 — 비용이 운영자의 1차 의사결정 기준. 목적 기반 모니터링 원칙에 따라 "어떤 날에 비용이 튀었는가? 원인 모델은?" 질문에 직접 답하는 구조.]*

### 4.3 대화 이력

관리자 메뉴의 세 번째 탭. 전체 대화를 검색·조회하고 상세 내용을 확인하는 독립 화면이다.

|------|------|
| 검색 | 대화 내용, 사용자 이름 기준 |
| 사용자 | 팀원 목록 |
| 날짜 | 기간 선택 (오늘, 최근 7일, 최근 30일, 커스텀) |
| 상태 | 전체, 완료, 오류 |

##### 슬라이드 패널 구성

| 영역 | 설명 |
|------|------|
| 헤더 | 사용자 이름, 대화 요약, 날짜/시간, 사용 스킬, 사용 모델, 상태, 턴 수 |
| 대화 내용 | 사용자 메시지(👤)와 에이전트 응답(🤖)을 시간순으로 표시. 스킬 호출은 인라인 뱃지로 표시 |
| 에러 요약 | 에러 발생 시 접힘 상태로 한 줄 요약 표시 (에러 타입 + 실패 단계). 에러 없으면 "(없음)". 상세 분석은 에이전트 상태의 오류 전용 패널에서 수행 |
| LangFuse 링크 | 패널 하단. 해당 대화의 trace ID로 LangFuse 상세 화면 직접 이동 |

> **운영 현황 탭과의 관계**: 운영 현황의 에이전트 상태 오류 테이블은 트리아지용 확장 컬럼(에러 타입, 실패 단계, 유사 건수, 영향 범위)을 가지며, 오류의 1차 판단은 해당 테이블에서 완결된다. 대화 이력 탭은 "사용자가 뭘 했는가"를 확인하는 대화 검토 목적이며, 오류 대화의 에러 정보는 한 줄 요약(에러 타입 + 실패 단계)만 표시한다. 50건 초과 오류를 확인해야 할 때, 운영 현황의 안내 문구에서 대화 이력 탭의 상태=오류 필터로 연결된다.

*[설계 근거: (1) 스킬 메뉴와 동일한 "테이블 + 슬라이드 패널" 패턴으로 서비스 전체 일관성 확보. (2) ChatGPT Enterprise Usage — 사용자별 대화 리포트 패턴. (3) 2-tier 관찰 패턴 — 관리자 화면(Tier 1)은 집계 지표와 에러 요약까지, 상세 트레이스(Tier 2)는 LangFuse에서. OpenAI/Anthropic의 플랫폼 콘솔은 집계만, 상세는 전용 도구(LangSmith/LangFuse)에서 처리하는 업계 표준. ai-platform-admin-dashboard-patterns.md Section 2.1]*

#### 4.2.3 활동 리포트

**알 수 있는 것**: 서비스 도입 효과와 활용 패턴
**가능한 판단/대처**: 도입 효과 추적, 미사용자 온보딩, 스킬 개선 방향 도출, 서비스 성과 근거

세 개의 하위 그룹으로 구성하며, 각 그룹은 접힘/펼침이 가능하다 (기본 모두 펼침).

##### 팀 필터

활동 리포트 섹션 헤더에 **팀 드롭다운 필터**를 제공한다. 기본값 "전체"에서는 전사 집계를, 특정 팀 선택 시 해당 팀의 도입 현황·스킬 활용·서비스 성과만 표시한다.

```
━━ 활동 리포트 ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━  팀: [전체 ▼]
```

| 항목 | 설명 |
|------|------|
| 위치 | 활동 리포트 섹션 제목 우측 |
| 옵션 | 전체, 팀 목록 (조직 데이터 기반. 사용자 관리의 팀 필터와 동일 소스) |
| 영향 범위 | 도입 현황·스킬 활용·서비스 성과 3개 그룹 모두에 적용 |
| 다른 섹션 | 에이전트 상태·비용/사용량·대화 이력 조회에는 미적용. 이들은 시스템 차원 지표이므로 팀별 분리의 의미가 약함 |

팀별 필터 적용 시 변화:

| 그룹 | 전체 | 팀 선택 시 |
|------|------|-----------|
| 도입 현황 | 전사 활성 사용자 수, 전체 사용자별 현황 | 해당 팀 활성 사용자 수, 팀원별 현황 |
| 스킬 활용 | 전사 스킬 생성/수정 수, 전체 스킬 사용 현황 | 해당 팀원이 생성한 스킬, 해당 팀원의 스킬 사용 현황 |
| 서비스 성과 | 전사 정기 사용 비율, 산출물 수, 스킬 실행 수 | 해당 팀의 정기 사용 비율, 산출물 수, 스킬 실행 수 |

**활용 시나리오**: "사업1팀은 정기 사용 비율 85%인데 마케팅팀은 30%다 → 마케팅팀에 타겟 온보딩 필요", "AI사업팀이 스킬 생성을 주도하고 있는데, 사업1팀에서도 자생적 생성이 시작됐다 → 서비스 침투 확산 신호"

*[설계 변경 (v3): 전사 집계 전용 → 팀 드롭다운 필터 추가. 어느 조직에서 잘 사용하고 있는지 파악하기 위해 팀별 뷰 필요. 필터 범위는 활동 리포트에만 한정 — 에이전트 상태·비용은 시스템 차원 지표.]*

#### 4.2.4 모델 설정 (팝업)

**알 수 있는 것**: 현재 사용 가능한 모델 목록, API 키 상태
**가능한 판단/대처**: API 키 만료 시 즉시 교체, 비용 절감을 위한 모델 전환, 신규 모델 추가

모니터링 페이지 우상단의 **[⚙ 모델 설정]** 버튼을 클릭하면 팝업(모달)이 열린다. 모니터링의 스크롤 섹션과 분리하여 접근성을 높인다.

```
┌─ 모델 설정 ─────────────────────────────────────────────────┐
│                                                              │
│  ┌────────────────────────────────────────────────────────┐ │
│  │ 프로바이더  │ 모델              │ API 키 상태 │ 활성 │ 액션│ │
│  │ Anthropic  │ Claude 3.5 Sonnet │ ✅ 정상     │ [ON]│ [⚙]│ │
│  │ Anthropic  │ Claude 3 Opus     │ ✅ 정상     │ [OFF]│ [⚙]│ │
│  │ OpenAI     │ GPT-4o            │ ✅ 정상     │ [ON]│ [⚙]│ │
│  │ OpenAI     │ GPT-4o mini       │ ⚠️ 만료 임박│ [ON]│ [⚙]│ │
│  └────────────────────────────────────────────────────────┘ │
│                                                              │
│  [+ 모델 추가]                                    [닫기]      │
└──────────────────────────────────────────────────────────────┘
```

| 요소 | 설명 |
|------|------|
| 모델 테이블 | 프로바이더, 모델명, API 키 상태(정상/만료 임박/만료), 활성화 토글 |
| API 키 상태 | ✅ 정상, ⚠️ 만료 임박 (30일 이내), ❌ 만료. 만료 임박/만료 시 행 강조 |
| 활성화 토글 | 에이전트가 사용 가능한 모델 제어 |
| [⚙] 설정 | 팝오버. API 키 변경, 모델 별칭 설정 |
| [+ 모델 추가] | 프로바이더 선택 → API 키 입력 → 모델 선택 → 추가 |

**비용 확인 → 모델 변경 흐름**: 비용/사용량 섹션에서 특정 모델의 비용이 높다고 판단되면, 우상단의 [⚙ 모델 설정]을 클릭하여 팝업에서 해당 모델을 비활성화하고 저비용 모델을 활성화할 수 있다. 팝업이므로 현재 보고 있던 비용 섹션의 맥락을 잃지 않는다.

*[설계 변경 (v2): 모니터링 하단 스크롤 섹션 → 우상단 버튼 + 팝업으로 분리. (1) 접근성 개선 — 페이지 어디서든 버튼 하나로 접근 가능. 하단까지 스크롤할 필요 없음. (2) 비용 섹션 맥락 유지 — 팝업이므로 비용 차트를 보면서 모델을 변경할 수 있음. (3) 스크롤 길이 축소 — 모니터링 페이지가 4개 섹션으로 줄어 가독성 향상.]*

*[근거: Dify Model Providers — 프로바이더별 모델 목록 + API 키 관리. OpenAI Models — 모델 활성화/비활성화.]*

```
    │                                   ├─ [⚙ 설정] ──► API 키 변경
    │                                   └─ [+ 모델 추가] ──► 추가 폼
    │
    └─ [대화 이력] ────────► 전체 폭 테이블
                              │
                              ├─ [더 보기 ▼] ──► 테이블 내 확장
                              └─ [행 클릭] ──► 대화 패널 (메시지 흐름 중심)
                                   ├─ [다른 행 클릭] ──► 패널 교체
                                   ├─ [LangFuse 링크] ──► 외부 LangFuse (새 탭)
                                   └─ [패널 닫기] ──► 전체 폭 테이블 복원
```

### 5.2 사용자 관리 → 운영 현황·대화 이력 연결 플로우

```
사용자 관리에서 특정 사용자의 활동이 궁금할 때
    │
    └─ [운영 현황] 또는 [대화 이력] 탭 이동
         │
         ├─ [운영 현황] → 활동 리포트 → 사용자별 활용 현황에서 해당 사용자 확인
         │
         └─ [대화 이력] → 사용자 필터 적용 → 해당 사용자의 대화 목록 확인
              └─ [행 클릭] → 패널에서 대화 내용·에이전트 응답 확인
```

### 5.3 운영 현황 내부 및 탭 간 연결 플로우

```
비용/사용량에서 특정 모델 비용이 높다고 판단
    │
    └─ [⚙ 모델 설정] 클릭 → 팝업에서 해당 모델 비활성화 + 저비용 모델 활성화
         └─ 팝업 닫으면 비용 섹션이 그대로 보임 (맥락 유지)

에이전트 상태에서 오류 발견
    │
    ├─ 오류 테이블 컬럼(에러 타입, 실패 단계, 유사, 영향)에서 1차 트리아지
    │
    ├─ [더 보기 ▼] → 섹션 내에서 오류 목록 확장
    │
    ├─ [🔗 LangFuse] → 외부 LangFuse (새 탭)에서 심층 분석
    │
    └─ 50건 초과 시 → 대화 이력 탭에서 상태=오류 필터로 확인
```

### 5.4 외부에서의 진입 경로

| 출발점 | 도착 | 시나리오 |
|--------|------|---------|
| GNB → 관리자 | 사용자 관리 (기본 탭) | 관리자 메뉴 첫 진입 시 기본 화면 |
| 알림 (오류 급증) | 운영 현황 → 에이전트 상태 섹션 | 오류 관련 알림 클릭 시 해당 섹션으로 앵커 이동 |
| 스킬 메뉴 → 호출 수 클릭 | 운영 현황 → 활동 리포트 → 스킬 활용 | 스킬 상세에서 조직 전체 사용 현황이 궁금할 때 |

### 7.2 모니터링 — 데이터 부족 상태

```
── 에이전트 상태 ──────────────────────────────
  아직 에이전트 실행 이력이 없습니다.
  AI 채팅에서 대화를 시작하면 여기에 실행 현황이 표시됩니다.

── 비용/사용량 ───────────────────────────────
  아직 사용량 데이터가 없습니다.

── 활동 리포트 ───────────────────────────────
  [활성 사용자 1명 / 전체 1명]
  사용자를 추가하고 서비스 활용을 시작해보세요.
```

### 7.3 모델 설정 — API 키 만료 상태

API 키가 만료 임박하거나 만료된 경우.

```
  │ OpenAI  │ GPT-4o mini  │ ⚠️ 만료 임박 (D-7) │ [ON] │ [키 교체] │
  │ OpenAI  │ GPT-3.5      │ ❌ 만료              │ [OFF]│ [키 교체] │
```

만료 임박 행은 주황색 배경, 만료 행은 빨간색 배경으로 강조. 만료된 모델은 자동으로 비활성화. 모니터링 페이지의 [⚙ 모델 설정] 버튼에도 경고 뱃지 표시.
