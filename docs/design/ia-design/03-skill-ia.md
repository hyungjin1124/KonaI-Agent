## 2. 스코프 모델

### 팀 공유 드라이브

스킬 화면은 **팀이 공유하는 드라이브**와 같다. 누군가 스킬을 만들면(채팅에서) 자동으로 팀 드라이브에 올라가고, 팀원 모두가 볼 수 있다.

| 항목 | 내용 |
|------|------|
| **공유 범위** | 팀 단위. 생성·복사한 스킬은 즉시 팀 전체에 보임. 승인 절차 없음 |
| **탐색 범위** | 내 팀 스킬만 열람 가능. 다른 팀 스킬은 볼 수 없음 |
| **팀 소속** | 1인 1팀. 다중 팀 소속 없음 |

### 활성화 모델

팀 드라이브에 있는 스킬 중 **내가 사용할 스킬만 활성화**한다. 누구의 스킬이든 활성화할 수 있고, 복사 없이 바로 사용 가능하다.

| 동작 | 설명 | 결과 |
|------|------|------|
| **활성화** | 팀 스킬을 내 채팅에서 사용하겠다고 선택 | 에이전트가 해당 스킬을 호출 가능 |
| **비활성화** | 내 채팅에서 더 이상 사용하지 않음 | 에이전트가 호출하지 않음. 팀에서 사라지지 않음 |

### 복사

스킬을 기반으로 변형을 만들고 싶으면 **복사**한다. 내 스킬이든 남의 스킬이든 복사할 수 있다. 복사하면 내 이름으로 된 독립적인 스킬이 팀 드라이브에 새로 올라간다. 공유 드라이브에서 파일을 복사하는 것과 같다.

```
어떤 스킬이든 [복사] 가능:

A의 "매출 분석" (v3)
    └─ B가 [복사] ──► B의 "매출 분석" (v1) → 자유롭게 커스텀

A의 "월간 보고서" (v2)
    └─ A가 [복사] ──► A의 "주간 보고서" (v1) → 변형 생성
```

**핵심 원칙:**
- **모든 스킬에서 복사 가능** — 내 스킬을 복사해서 변형을 만들 수도 있음
- 복사본은 원본과 **독립적**이다 — 원본이 바뀌어도 복사본에 영향 없음
- 복사본은 팀 전체에 보인다 — 공유 드라이브에 파일이 하나 더 생기는 것
- 복사 시 원본의 현재 버전을 기반으로 v1이 생성됨
- 출처(원본 스킬·작성자) 정보가 메타데이터에 기록됨

### 버전 관리

모든 스킬은 편집할 때마다 새 버전이 생긴다. 버전 이력에서 이전 버전으로 복구할 수 있다.

| 동작 | 설명 |
|------|------|
| **편집 (채팅)** | 채팅에서 스킬을 수정하면 새 버전(v1→v2→v3...)이 생김 |
| **버전 복구** | 버전 이력에서 이전 버전을 선택하여 복구. 복구 자체도 새 버전으로 기록됨 |
| **AI 변경 요약** | 버전마다 에이전트가 "무엇이 어떻게 바뀌었는지" 한국어로 요약 |

*[설계 변경 (v7): (1) "개인 수정본" 개념을 "복사"로 전환 — 남의 스킬을 포크하는 것이 아니라 독립적인 복사본 생성. (2) 원본 복구 제거 → 버전 이력에서 아무 버전이나 복구 가능으로 일반화. (3) 편집은 채팅에서만 가능하므로 수동 편집 관련 상태(편집 중, 수정본 적용 중 등) 불필요.]*

## 3. 화면별 정보 구성

### 3.1 팀 스킬 — 테이블

팀 내 모든 스킬을 한 화면에서 보는 테이블. **활성화 그룹과 비활성 그룹**으로 나뉜다.

#### 전체 폭 레이아웃 (패널 닫힌 상태)

```
┌──────────────────────────────────────────────────────────────────────────────────────┐
│  팀 스킬                                    검색 [___________]                        │
│  카테고리▼  작성자▼  활성 멤버▼                                                       │
├──────────────────────────────────────────────────────────────────────────────────────┤
│  ── 활성화 (3) ────────────────────────────────────────────────────────────────────   │
│  │ 이름       │ 한 줄 설명     │ 카테고리  │ 작성자│ 수정일     │ 버전│호출 수│활성 멤버  │⚡│
│  │ 매출 분석   │ 월별 매출 추이 │ 데이터    │ 홍길동│ 2026.03.20│ v3 │   47│[홍][김]+3│ON│
│  │ 보고서 생성 │ 주간 보고서... │ 문서 생성 │ 김철수│ 2026.03.18│ v1 │   23│[김][박]  │ON│
│  │ 분기 매출   │ 분기별 트렌드  │ 데이터    │ 나    │ 2026.03.22│ v2 │    3│[나]      │ON│
│                                                                                      │
│  ── 비활성 (10) ───────────────────────────────────────────────────────────────────   │
│  │ 회의록 정리 │ 회의 녹취를... │ 커뮤니케… │ 박영희│ 2026.03.15│ v1 │   12│[박][홍]+1│  │
│  │ 데이터 정제 │ ERP 원시...    │ 데이터    │ 이민수│ 2026.03.10│ v2 │   58│[이][김]+4│  │
│  │ 이메일 초안 │ 회신 이메일... │ 커뮤니케… │ 최수진│ 2026.03.24│ v1 │    0│—         │  │
│  ...                                                                                 │
└──────────────────────────────────────────────────────────────────────────────────────┘
```

위 예시에서 "분기 매출"은 내가 홍길동의 "매출 분석"을 복사한 뒤 이름을 변경한 스킬이다. 활성 멤버 컬럼의 이니셜 아바타는 최대 2개까지 표시하고, 초과 시 "+N"을 표시한다. "+N" 클릭 시 전체 활성 멤버 리스트가 팝오버로 열린다. 활성 멤버가 없으면 "—"으로 표시.

#### 패널 열린 상태 (축약 테이블 + 슬라이드 패널)

```
┌──────────────────────────────────┬──────────────────────────────────────┐
│ 검색  카테고리▼  작성자▼          │                                      │
├──────────────────────────────────┤  매출 분석                            │
│ ── 활성화 (3) ──                  │  카테고리: 데이터 분석                 │
│  이름       │ 작성자│호출 수│⚡   │  작성자: 홍길동  v3  호출 47회         │
│▸매출 분석   │ 홍길동│    47│ON   │  활성 멤버: 홍길동, 김철수 외 3명      │
│  보고서 생성│ 김철수│    23│ON   │  ──────────────────────               │
│  분기 매출  │ 나    │     3│ON   │  [복사]                               │
│ ── 비활성 (10) ──                │  ──────────────────────               │
│  회의록 정리│ 박영희│    12│     │  ▼ 버전 이력 (3)                      │

│  ...                             │  v3 — 2026.03.20 홍길동               │
│                                  │  ┌─ 🤖 AI 변경 요약 ──────────────┐ │
│                                  │  │ [추가] 데이터 검증 단계          │ │
│                                  │  │        → 빈 셀 기본값(0) 자동   │ │
│                                  │  │ [변경] 출력 형식: 표 → 차트      │ │
│                                  │  │        → 월별 추이 시각적 비교   │ │
│                                  │  │ [추가] 트리거: '분기 보고서'     │ │
│                                  │  │ [원문 비교 →]                    │ │
│                                  │  └────────────────────────────────┘ │
│                                  │                                      │
│                                  │  v2 — 2026.03.15 홍길동               │
│                                  │  🤖 [추가] 증감률 컬럼 외 1건   [▶]  │
│                                  │                                      │
│                                  │  v1 — 2026.03.01 홍길동 (최초 생성)   │
│                                  │  ──────────────────────               │
│                                  │  ▶ 스킬 콘텐츠                       │
```

패널이 열리면 테이블 컬럼이 축약된다 (이름 + 작성자 + 호출 수 + 활성화 상태). 패널을 닫으면 전체 폭 테이블로 복원.

#### 테이블 컬럼

| 컬럼 | 설명 | 정렬 | 패널 열림 시 |
|------|------|------|------------|
| 이름 | 스킬 이름 | 가나다순 | 유지 |
| 한 줄 설명 | 스킬 용도 요약 | — | 숨김 |
| 카테고리 | 데이터 분석, 문서 생성, 업무 자동화, 커뮤니케이션 | — | 숨김 |
| 작성자 | 스킬 생성자 이름 | — | 유지 |
| 최종 수정일 | 마지막 수정 날짜 (yyyy.mm.dd) | 최근순 | 숨김 |
| 버전 | 현재 버전 번호 | — | 숨김 |
| 호출 수 | 이 스킬이 채팅에서 실제로 실행된 총 횟수 | 많은순 | 유지 |
| 활성 멤버 | 현재 이 스킬을 활성화한 팀원. 이니셜 아바타 최대 2개 + "+N" 오버플로. "+N" 클릭 시 전체 리스트 팝오버 | 많은순 | 숨김 |
| 활성화 토글 | 내 채팅에서 사용 여부 | — | 유지 |

기본 정렬: 활성화 그룹 내에서 호출 수 많은 순, 비활성 그룹 내에서 최근 수정일 순.

#### 필터

| 필터 | 옵션 |
|------|------|
| 카테고리 | 데이터 분석, 문서 생성, 업무 자동화, 커뮤니케이션 |
| 작성자 | 팀원 목록 |
| 활성 멤버 | 팀원 목록. "이 사람이 활성화한 스킬만 보기" |

### 3.2 스킬 상세 — 슬라이드 패널

테이블 행 클릭 시 우측에서 슬라이드로 열리는 상세 패널. **버전 이력이 가장 먼저** 보이고, 스킬 콘텐츠는 그 아래에 배치된다.

#### 헤더

| 요소 | 설명 |
|------|------|
| 스킬 이름 | 제목 |
| 설명 (Description) | 스킬이 무엇을 하는지 한 줄 설명 |
| 카테고리 | 태그 |
| 메타 정보 | 작성자, 버전, 호출 수, 활성 멤버(텍스트 리스트 — "홍길동, 김철수 외 3명". "외 N명" 클릭 시 팝오버), 출처(직접 생성/복사 — 복사 시 원본 스킬·작성자 표시), 생성일, 최종 수정일(yyyy.mm.dd) |
| 상태 표시 | "활성화 중" 또는 "비활성" (텍스트만, 토글은 테이블에서) |
| 액션 버튼 | 아래 참조 |
| 전체 확장 | [↗] 버튼 → 전체 페이지로 전환 |

#### 패널 액션

모든 스킬에서 [복사]가 가능하다. 내 스킬이면 [채팅에서 편집]이 추가로 노출된다. 활성화/비활성화는 테이블 토글에서만 제공하고, 패널에서는 현재 상태 텍스트만 표시한다.

| 직접 노출 | 조건 | 설명 |
|----------|------|------|
| [복사] | 모든 스킬 | 이 스킬을 복사하여 새 스킬로 생성 |
| [채팅에서 편집] | 내 스킬만 | 채팅으로 이동하여 스킬 수정. 저장 시 새 버전 생성 |

**[복사] 동작:**

[복사] 클릭 시 별도 모달 없이 즉시 복사된다. 이름은 자동 넘버링으로 생성된다.

| 단계 | 동작 |
|------|------|
| 1. 이름 생성 | 동일 작성자의 기존 스킬과 겹치지 않도록 자동 넘버링. 첫 복사: `{원본 이름} (2)`, 이후: `(3)`, `(4)`... |
| 2. 스킬 생성 | 현재 스킬의 최신 버전을 기반으로 내 이름의 새 스킬이 v1으로 생성됨 |
| 3. 팀 표시 | 팀 드라이브에 새 행으로 추가 |
| 4. 자동 활성화 | 내 채팅에서 자동 활성화 |
| 5. 알림 | 토스트: "'{이름}' 스킬이 생성되었습니다" |

이름은 복사 후 패널 헤더에서 언제든 수정할 수 있다 (아래 "이름 수정" 참조).

*[설계 변경 (v7): (1) 수동 편집(직접 편집) 제거 — "..." 메뉴 자체가 불필요해짐. (2) 원본 복구 제거 — 버전 이력에서 복구. (3) [복사]를 모든 스킬에서 제공 — 내 스킬이든 남의 스킬이든 복사 가능. (4) 복사 시 모달 없이 자동 넘버링으로 즉시 생성 — 마찰 최소화. 이름 수정은 패널 헤더에서. (5) 패널에서 활성화/비활성화 버튼 제거 — 테이블 토글에서만 제공.]*

#### 이름 수정

패널 헤더의 스킬 이름을 클릭하면 **인라인 편집** 상태로 전환된다. 내 스킬에서만 가능.

```
┌──────────────────────────────────────┐
│  [매출 분석 (2)                    ]  │  ← 클릭 시 텍스트 입력으로 전환
│  카테고리: 데이터 분석                 │     Enter 또는 포커스 아웃으로 저장
│  작성자: 나  v1  호출 3회             │     Esc로 취소
│  ...                                  │
└──────────────────────────────────────┘
```

| 항목 | 설명 |
|------|------|
| 진입 | 패널 헤더에서 스킬 이름 클릭 (내 스킬만. 남의 스킬은 클릭 불가) |
| 편집 | 인라인 텍스트 입력으로 전환. Enter 또는 포커스 아웃으로 저장, Esc로 취소 |
| 중복 검증 | 팀 내 동일 작성자의 스킬과 이름이 겹치면 인라인 에러 |
| 버전 영향 | 이름 변경은 새 버전을 생성하지 않음 (메타데이터 수정) |

#### 본문 — 버전 이력 (최상단)

패널 본문의 **가장 첫 번째 영역**. 버전별 변경 사항을 추적하는 것이 스킬 파일을 읽는 것보다 중요하다는 판단에 따라 최상단에 배치한다.

각 버전의 AI 변경 요약은 **변경 유형 태그 + 설명** 리스트로 구성된다. 산문 대신 스캔 가능한 구조화된 리스트를 사용하여, 빠르게 훑어도 핵심 변경을 파악할 수 있도록 한다.

**변경 유형 태그:**

| 태그 | 의미 | 사용 기준 |
|------|------|----------|
| `추가` | 이전 버전에 없던 기능·로직·조건이 새로 생김 | 새 섹션, 새 트리거, 새 파라미터 등 |
| `변경` | 기존 기능·로직·값이 다른 것으로 바뀜 | 출력 형식 전환, 기본값 변경, 로직 수정 등 |
| `삭제` | 기존 기능·로직·조건이 제거됨 | 사용하지 않는 파라미터 삭제 등 |
| `개선` | 기존 기능의 품질·성능·정확도가 향상됨 | 에러 처리 보강, 설명 명확화 등 |

**각 항목의 구성:**

```
[태그] 변경 대상 — 무엇이 어떻게 바뀌었는지 (한 줄)
      → 왜 바뀌었는지 또는 사용자에게 미치는 영향 (한 줄)
```

태그로 변경의 종류를, 첫 줄로 사실을, 둘째 줄(→)로 맥락/영향을 전달한다. 둘째 줄은 AI가 판단하여 필요할 때만 표시한다 (의도가 명확한 단순 변경은 첫 줄만).

**패널 목업 — 최신 버전 펼침:**

```
▼ 버전 이력 (3)

  v3 — 2026.03.20 홍길동                            ← 최신: 펼침
  ┌─ 🤖 AI 변경 요약 ─────────────────────────────┐
  │                                                 │
  │  [추가] 데이터 검증 단계                         │
  │         → 빈 셀 발견 시 기본값(0)으로 자동 채움.  │
  │           입력 누락으로 인한 분석 오류 방지        │
  │                                                 │
  │  [변경] 출력 형식: 표 → 차트                      │
  │         → 월별 추이를 시각적으로 비교 가능         │
  │                                                 │
  │  [추가] 트리거 조건에 '분기 보고서' 추가           │
  │                                                 │
  │  [원문 비교 →]                                   │
  └─────────────────────────────────────────────────┘
  [이 버전으로 복구]

  v2 — 2026.03.15 홍길동                            ← 이전: 접힘
  🤖 [추가] 전월 대비 증감률 컬럼 외 1건              [▶]

  v1 — 2026.03.01 홍길동 (최초 생성)
```

**접힘 상태의 한 줄 요약:** 이전 버전은 첫 번째 태그 항목만 표시하고, 나머지 항목 수를 "외 N건"으로 안내한다. [▶] 클릭 시 전체 요약 블록이 펼쳐진다.

| 항목 | 설명 |
|------|------|
| 버전 목록 | 수정일, 수정자, AI 변경 요약. 최신 버전이 맨 위 |
| AI 변경 요약 | 변경 유형 태그 리스트. 한국어. 스킬 저장 시 자동 생성 |
| 요약 블록 시각 구분 | 연한 배경색 + 좌측 accent 보더 + "🤖 AI 변경 요약" 레이블로 AI 콘텐츠임을 명시 (Distill 패턴) |
| [원문 비교 →] | 요약 블록 하단. 클릭 시 해당 버전과 이전 버전 간 side-by-side diff 표시. 패널 폭이 좁으면 unified diff로 폴백 |
| [이 버전으로 복구] | 내 스킬에서만 표시. 해당 버전의 내용으로 새 버전을 생성 (예: v2로 복구 → v4가 됨). 확인 모달 표시 |

**펼침/접힘 규칙:**
- **최신 버전**: 요약 블록이 항상 펼침 상태
- **이전 버전**: 한 줄 요약(첫 번째 태그 항목 + "외 N건")으로 접힘. 클릭 시 펼침
- **버전 5개 이상**: 최근 3개만 목록에 표시, "이전 버전 더 보기" 링크로 나머지 접근

*[설계 변경 (v7): (1) 버전 이력을 패널 최하단(접힘)에서 최상단(펼침)으로 이동. "어떤 부분이 바뀌었는지 파악"이 "스킬 파일 읽기"보다 우선. (2) raw diff 대신 AI 변경 요약이 기본. "사람들이 영어 + 장문 diff를 읽지 않을 것"이라는 리더 피드백 반영. (3) 산문 대신 변경 유형 태그 리스트 채택 — 스캔 가능성 확보. 태그(추가/변경/삭제/개선)로 종류를, 첫 줄로 사실을, 둘째 줄(→)로 맥락을 전달. (4) 최신 버전만 펼침, 이전은 접힘 — 패널 길이 관리 (Slack 스레드 요약 패턴). (5) AI 블록 시각 구분 — 배경색 + 좌측 보더 + 레이블 (Distill 패턴). (6) 원본 복구 대신 버전별 [이 버전으로 복구] 제공 — 더 유연한 복구.]*

## 5. 주요 인터랙션 패턴

### 5.1 활성화 토글

활성화 토글은 **테이블에서만** 제공. 슬라이드 패널에서는 현재 상태 텍스트("활성화 중" / "비활성")만 표시.

| 상태 | 동작 | 영향 범위 |
|------|------|----------|
| 활성 → 비활성 | 에이전트가 해당 스킬을 호출하지 않음 | 해당 사용자의 채팅 세션만 |
| 비활성 → 활성 | 에이전트가 다시 호출 가능 | 해당 사용자의 채팅 세션만 |

토글 시 행이 활성화/비활성 그룹 간 이동하며, 이동 자체가 시각적 피드백이 된다.

### 5.2 복사

| 항목 | 설명 |
|------|------|
| 진입점 | 슬라이드 패널의 [복사] 버튼 (모든 스킬에서 표시) |
| 이름 | 자동 넘버링: `{원본 이름} (2)`, `(3)`... 복사 후 패널 헤더에서 수정 가능 |
| 결과 | 현재 스킬의 최신 버전을 기반으로 내 이름의 새 스킬 생성 (v1) |
| 팀 표시 | 테이블에 새 행으로 추가 |
| 자동 활성화 | 복사본이 내 채팅에서 자동 활성화 |
| 원본과의 관계 | 독립적. 메타데이터에 출처(원본 스킬·작성자)만 기록 |

### 5.3 이름 수정

| 항목 | 설명 |
|------|------|
| 진입점 | 패널 헤더에서 스킬 이름 클릭 (내 스킬만) |
| 동작 | 인라인 텍스트 입력. Enter/포커스 아웃으로 저장, Esc로 취소 |
| 중복 검증 | 팀 내 동일 작성자의 스킬과 이름이 겹치면 인라인 에러 |
| 버전 영향 | 이름 변경은 새 버전을 생성하지 않음 (메타데이터 수정) |

### 5.4 버전 복구

| 항목 | 설명 |
|------|------|
| 진입점 | 버전 이력에서 [이 버전으로 복구] (내 스킬에서만) |
| 동작 | 선택한 버전의 내용으로 새 버전을 생성. 예: v2로 복구하면 v4(내용=v2)가 됨 |
| 확인 | "v2의 내용으로 새 버전을 생성합니다" 확인 모달 |
| AI 요약 | 복구 시에도 AI 변경 요약이 생성됨 ("v2로 복구되었습니다. 변경 내용: ...") |

### 5.5 검색·필터

| 위치 | 검색 범위 | 동작 |
|------|----------|------|
| 팀 스킬 테이블 | 팀 전체 스킬 | 이름, 설명, 작성자, 카테고리, 활성 멤버 기준 실시간 필터링 |

### 5.6 버전 비교 — AI 변경 요약

| 항목 | 설명 |
|------|------|
| 생성 시점 | 스킬 저장 시 자동으로 이전 버전과 비교하여 생성 |
| 언어 | 한국어 (사용자 설정 언어를 따름) |
| 출력 형식 | 변경 유형 태그(`추가`/`변경`/`삭제`/`개선`) + 설명 리스트 |
| 항목 구성 | **첫 줄**: 태그 + 변경 대상 + 무엇이 어떻게 바뀌었는지. **둘째 줄(→)**: 왜 바뀌었는지 또는 사용자에게 미치는 영향 (AI가 필요하다고 판단할 때만) |
| 접힘 요약 | 이전 버전은 첫 번째 태그 항목 + "외 N건"으로 한 줄 표시 |
| 시각 구분 | 연한 배경색 + 좌측 accent 보더 + "🤖 AI 변경 요약" 레이블 (Distill 패턴) |
| 원문 비교 | 요약 블록 하단 [원문 비교 →] 링크. side-by-side diff. 패널 폭 좁으면 unified diff 폴백 |

**좋은 요약 vs 빈약한 요약:**

```
❌ 빈약한 예시:
   [추가] 데이터 검증
   [변경] 출력 형식

✅ 충분한 예시:
   [추가] 데이터 검증 단계
          → 빈 셀 발견 시 기본값(0)으로 자동 채움. 입력 누락으로 인한 분석 오류 방지
   [변경] 출력 형식: 표 → 차트
          → 월별 추이를 시각적으로 비교 가능
```

태그만으로는 "무엇이"만 알 수 있다. 첫 줄의 구체적 설명으로 "어떻게"를, 둘째 줄(→)로 "왜/영향"을 전달해야 스킬 원문을 읽지 않아도 핵심을 파악할 수 있다. 둘째 줄은 AI가 맥락이 불명확하거나 영향이 큰 변경에만 붙이고, 의도가 자명한 단순 변경(예: 트리거 조건 추가)에는 생략한다.

*[설계 근거: (1) 리더 피드백 — "diff 방식으로 보여줘도 사람들이 읽지 않을 것 (영어 + 장문)". (2) 산문 요약도 길어지면 읽히지 않음 → 태그 리스트로 스캔 가능성 확보 (gpt-commit-summarizer 계층 패턴). (3) "사실 + 맥락" 2단 구조로 빈약하지 않으면서도 간결하게. (4) 둘째 줄(→)의 선택적 표시로 불필요한 장황함 방지.]*

## 6. 상태별 화면 변화

### 6.1 팀 스킬 테이블 — 빈 상태

스킬이 0개인 신규 팀에 표시.

```
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│          아직 팀에 등록된 스킬이 없습니다                      │
│          채팅에서 스킬을 만들어보세요                          │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 6.2 패널 미선택 상태

테이블에서 아직 스킬을 클릭하지 않았을 때. 테이블이 전체 폭으로 표시된다.

### 6.3 복사본 표시

복사본은 복사 시 지정한 이름으로 테이블에 표시된다. 패널에서는 메타 정보에 "복사 출처: 홍길동의 '매출 분석'"이 표시되어 어디서 파생된 스킬인지 알 수 있다.

## 7. 설계 근거 요약

| 설계 결정 | 채택 근거 | 참조 |
|-----------|----------|------|
| 공유 드라이브 컨셉 | 스킬 화면을 팀 공유 폴더처럼 접근. 올라간 것은 모두에게 보이고, 별도 승인 없이 즉시 공유 | 리더 피드백 (v6) |
| 복사 모델 (수정본 대체) | 모든 스킬(내 것이든 남의 것이든)을 복사해서 변형 생성. 공유 드라이브에서 파일 복사하는 것과 동일. 원본과 독립적으로 관리 | 리더 피드백 (v7) |
| 수동 편집 제거 | 편집은 채팅에서만 가능. 인라인 편집 UI, 편집 모드 전환, 저장/취소 등 모든 편집 UI 제거로 화면 단순화 | v7 변경 |
| 원본 복구 → 버전별 복구 | "원본으로 돌아가기" 대신 아무 버전으로나 복구 가능. 더 유연하고, 복사 모델에서 "원본"이라는 개념이 불필요 | v7 변경 |
| 스킬 추가 UI 제거 | [+ 추가] 버튼, 채팅에서 만들기, 파일에서 가져오기 모두 제거. 스킬 생성은 채팅에서. 스킬 화면은 보기·활성화·복사에 집중 | v7 변경 |
| 버전 이력 최상단 배치 | "어떤 부분이 바뀌었는지"가 "스킬 파일 읽기"보다 중요. 패널을 열면 버전 이력이 먼저 보임 | 리더 피드백 (v7) |
| AI 변경 요약 (diff 대체) | raw diff는 영어 + 장문이라 사람들이 읽지 않음. 변경 유형 태그 리스트(추가/변경/삭제/개선 + 사실 + 맥락)로 스캔 가능하면서 핵심 파악 가능한 구조. 최신만 펼침, 이전은 접힘 | 리더 피드백 + Distill·gpt-commit-summarizer·Slack 스레드 요약 패턴 |
| 관리자 탭·워크플로우 제거 | 관리 기능은 사용자 피로도와 부담을 늘림. 문제가 생기면 나중에 디벨롭 | 리더 피드백 (v6) |
| 삭제·폐기 제거 | 공유 드라이브에서 올라간 것은 그냥 둠. 삭제 권한 관리의 복잡도 제거 | 리더 피드백 (v6) |
| 활성화 토글: 테이블에서만 | 빠른 켜고 끄기가 주 용도. 패널에서는 상태 텍스트만 표시 | v3부터 유지 |
| 복사 시 자동 넘버링 | 모달 없이 즉시 복사. `{이름} (2)`, `(3)` 자동 생성으로 마찰 최소화. 이름 수정은 패널 헤더에서 | v7 변경 |
| 호출 수 / 활성 멤버 컬럼 분리 | "실행 횟수"와 "누가 쓰는지"는 별개 정보. 기존 "사용" 컬럼이 두 의미를 혼용하고 있어 분리. 활성 멤버는 이니셜 아바타 스택으로 컴팩트 표시 | v7 변경 |
| 수정일 yyyy.mm.dd 포맷 | 연도 포함으로 시점 모호성 제거. 점(.) 구분자로 가독성 확보 | v7 변경 |
| 파일 탐색기 + 콘텐츠 뷰 구조 | 스킬은 파일 패키지. 파일 목록 → 클릭 → 콘텐츠 전환 방식 | Claude web skill UI |
| 테이블 + 슬라이드 패널 | 전체 폭 테이블로 정보 밀도 확보 + 패널로 상세 확인. 화면 전환 없음 | Jira, Linear, Notion |
| side-by-side diff 기본, unified 폴백 | 버전 비교 시 동일 규칙. 패널 폭이 좁으면 자동 전환 | GitHub PR diff |
| 콘텐츠 영역 읽기 전용 | 수동 편집이 없으므로 편집 모드, 저장/취소, diff 보기 토글 등 제거. 읽기에만 집중 | v7 변경 |
| 액션 분기 단순화 | [복사]는 모든 스킬, [채팅에서 편집]은 내 스킬에서만. 삭제·폐기·개선 제안 없으므로 복잡한 권한 분기 불필요 | v7 변경 |
