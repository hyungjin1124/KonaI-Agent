## 1. 사이트맵

```
스킬 (GNB 3번째)
├─ 팀 스킬 (기본 탭) ──── 단일 테이블 + 슬라이드 패널
│   ├─ 테이블 (활성화 그룹 / 비활성 그룹, 마켓플레이스 참조 스킬 포함)
│   └─ 슬라이드 패널 (품질 테스트 → 버전 이력 → 스킬 콘텐츠)
└─ 마켓플레이스 (두 번째 탭) ── 전사 스킬 허브
    ├─ 테이블 (인기 배지·검색·카테고리·정렬)
    └─ 슬라이드 패널 (스킬 상세)
```

팀 스킬과 마켓플레이스는 스킬 메뉴 내 **탭 네비게이션**으로 전환한다. 팀 스킬이 기본 탭이다.

```
┌─────────────────────────────────────────────────┐
│  스킬                                            │
│  [팀 스킬]  [마켓플레이스]                         │
│   ─────     ──────────────                       │
│  (현재 탭에 따라 하위 화면 전환)                    │
└─────────────────────────────────────────────────┘
```

## 2. 스코프 모델

### 팀 공유 드라이브

스킬 화면은 **팀이 공유하는 드라이브**와 같다. 누군가 스킬을 만들면(채팅에서) 자동으로 팀 드라이브에 올라가고, 팀원 모두가 볼 수 있다.

| 항목 | 내용 |
|------|------|
| **공유 범위** | 팀 단위. 생성·복사한 스킬은 즉시 팀 전체에 보임. 승인 절차 없음 |
| **탐색 범위** | 팀 스킬 탭에서는 내 팀 스킬만 열람 가능. 다른 팀 스킬은 **마켓플레이스 탭**에서 탐색 (→ 3.3절) |
| **팀 소속** | 1인 1팀. 다중 팀 소속 없음 |

### 활성화 모델

팀 드라이브에 있는 스킬 중 **내가 사용할 스킬만 활성화**한다. 누구의 스킬이든 활성화할 수 있고, 복사 없이 바로 사용 가능하다.

| 동작 | 설명 | 결과 |
|------|------|------|
| **활성화** | 팀 스킬을 내 채팅에서 사용하겠다고 선택 | 에이전트가 해당 스킬을 호출 가능 |
| **비활성화** | 내 채팅에서 더 이상 사용하지 않음 | 에이전트가 호출하지 않음. 팀에서 사라지지 않음 |

**마켓플레이스 참조 스킬의 활성화**: 마켓플레이스에서 스킬을 활성화하면, 팀 드라이브에 **참조 행**이 자동 생성되어 팀원 전체가 볼 수 있다. 같은 스킬을 여러 팀원이 활성화하면 참조 행의 "활성 멤버"에 추가된다 (행 중복 없음). 참조 스킬은 읽기 전용이며, 편집하려면 복사해야 한다. 상세: → 3.3–3.4절

### 복사

스킬을 기반으로 변형을 만들고 싶으면 **복사**한다. 내 스킬이든 남의 스킬이든 복사할 수 있다. 복사하면 내 이름으로 된 독립적인 스킬이 팀 드라이브에 새로 올라간다. 공유 드라이브에서 파일을 복사하는 것과 같다.

```
어떤 스킬이든 [복사] 가능:

A의 "매출 분석" (v3)
    └─ B가 [복사] ──► B의 "매출 분석" (v1) → 자유롭게 커스텀

A의 "월간 보고서" (v2)
    └─ A가 [복사] ──► A의 "주간 보고서" (v1) → 변형 생성
```

**핵심 원칙:**
- **모든 스킬에서 복사 가능** — 내 스킬을 복사해서 변형을 만들 수도 있음
- 복사본은 원본과 **독립적**이다 — 원본이 바뀌어도 복사본에 영향 없음
- 복사본은 팀 전체에 보인다 — 공유 드라이브에 파일이 하나 더 생기는 것
- 복사 시 기본은 최신 버전 기반으로 v1 생성. 버전 이력에서 특정 버전을 선택하여 복사할 수도 있음
- 출처(원본 스킬·작성자·기반 버전) 정보가 메타데이터에 기록됨

### 버전 관리

모든 스킬은 편집할 때마다 새 버전이 생긴다. 버전 이력에서 이전 버전으로 복구할 수 있다.

| 동작 | 설명 |
|------|------|
| **편집 (채팅)** | 채팅에서 스킬을 수정하면 새 버전(v1→v2→v3...)이 생김 |
| **버전 복구** | 버전 이력에서 이전 버전을 선택하여 복구. 복구 자체도 새 버전으로 기록됨 |
| **AI 변경 요약** | 버전마다 에이전트가 "무엇이 어떻게 바뀌었는지" 한국어로 요약 |

*[설계 변경 (v7): (1) "개인 수정본" 개념을 "복사"로 전환 — 남의 스킬을 포크하는 것이 아니라 독립적인 복사본 생성. (2) 원본 복구 제거 → 버전 이력에서 아무 버전이나 복구 가능으로 일반화. (3) 편집은 채팅에서만 가능하므로 수동 편집 관련 상태(편집 중, 수정본 적용 중 등) 불필요.]*

### 마켓플레이스 — 전사 공개

팀 드라이브의 스킬을 전사에 공개하여 다른 팀이 탐색·활성화·복사할 수 있게 하는 모델이다.

#### 전사 공개

| 항목 | 내용 |
|------|------|
| **공개 주체** | 스킬 작성자 본인 |
| **공개 대상** | 전사 전체 (모든 팀) |
| **공개 방식** | 팀 스킬 상세 패널 헤더의 "전사 공개" 토글 (내 스킬만) |
| **승인 절차** | 없음. 팀 드라이브 철학("올라간 것은 바로 보인다")을 전사로 확장 |
| **비공개 전환** | 작성자가 언제든 비공개로 전환 가능. 이미 활성화한 팀에서는 계속 사용 가능 (비공개 시점의 버전에 고정). 신규 활성화만 불가 |

#### 마켓플레이스 → 팀 드라이브 연결

마켓플레이스에서 스킬을 활성화하면 **팀 드라이브에 참조 행(reference row)이 자동 생성**된다. 이를 통해 팀원 전체가 "우리 팀이 마켓플레이스에서 가져온 스킬"을 볼 수 있다.

| 상황 | 동작 |
|------|------|
| 팀에서 최초 활성화 | 팀 드라이브에 참조 행 생성. 🏪 뱃지 표시 |
| 같은 스킬을 다른 팀원이 활성화 | 기존 참조 행의 "활성 멤버"에 추가 (행이 중복 생성되지 않음) |
| 모든 팀원이 비활성화 | 참조 행이 비활성 그룹으로 이동. 팀 드라이브에서 사라지지 않음 |

**참조 스킬의 권한:**

| 동작 | 가능 여부 | 설명 |
|------|----------|------|
| 활성화/비활성화 | ✅ | 테이블 토글에서 개인 단위로 조작 |
| 복사 | ✅ | 복사하면 내 이름의 독립 스킬로 팀 드라이브에 생성 |
| 편집 | ❌ | 원본은 다른 팀 소속이므로 편집 불가. 편집하려면 복사 |

#### 원본 업데이트 전파

마켓플레이스 참조 스킬은 원본을 직접 참조하므로, **원본이 업데이트되면 자동 반영**된다. 특정 버전에 고정하고 싶으면 복사하여 독립 관리한다.

| 항목 | 설명 |
|------|------|
| 자동 반영 | 원본 작성자가 스킬을 편집하면, 참조하는 모든 팀의 스킬도 업데이트 |
| 변경 알림 | 팀 드라이브 참조 행에 "업데이트됨" 뱃지 표시. 패널에서 AI 변경 요약 확인 가능 |
| 버전 고정 없음 | 항상 최신 버전을 참조. 버전 고정이 필요하면 복사 |

*[설계 근거 (v10): (1) 팀 드라이브의 "승인 없이 자유 공유" 철학을 전사로 확장. 초기에는 진입 장벽을 낮추고, 품질 문제 발생 시 관리자 승인 프로세스를 후순위에서 도입. (2) 팀 스킬의 핵심 목적이 "우리 팀이 뭘 쓰는지 파악"이므로, 마켓플레이스 출처 스킬도 팀 드라이브에 반드시 표시. (3) 참조 모델의 장점은 원본 개선이 자동 전파되는 것. 독립이 필요하면 복사.]*

#### 보상 체계: 행동 기반 지표

star/like 같은 명시적 투표 체계를 사용하지 않는다. 조직 내에서는 참여자 수가 적고 관계가 고정되어 있어 투표 기반 시그널의 조작 리스크가 높다 (부서 밀어주기, 상사 스킬 의무 star 등). 대신 **실제 사용 행동에서 자동 수집되는 지표**를 사용한다.

| 지표 | 설명 | 조작 난이도 |
|------|------|-----------|
| 전사 호출 수 | 모든 팀에서 이 스킬이 채팅에서 실행된 총 횟수 | 높음 (실제 실행 필요) |
| 활성 팀 수 | 이 스킬을 활성화한 팀의 수 | 높음 (다른 팀이 채택해야 함) |
| 복사 횟수 | 이 스킬을 복사해서 변형을 만든 횟수 | 중간 |
| 리텐션 | 활성화 후 30일 뒤에도 활성 상태인 비율 | 높음 |

**보상 경로:**

| 단계 | 방식 | 시점 |
|------|------|------|
| 1단계 (MVP) | **가시성 보상** — 인기 스킬 테이블 상단 고정 + 🔥 "인기" 배지 부여 (최근 30일 전사 호출 수 상위 N%) | 초기 |
| 2단계 | **관리자 리포트** — 관리자 > 모니터링에 "스킬 기여도 리포트" 추가. 인사 평가·인센티브 연결은 관리자 재량 | 데이터 축적 후 |

## 3. 화면별 정보 구성

### 3.1 팀 스킬 — 테이블

팀 내 모든 스킬을 한 화면에서 보는 테이블. **활성화 그룹과 비활성 그룹**으로 나뉜다. 마켓플레이스에서 활성화한 참조 스킬도 이 테이블에 표시된다 (🏪 뱃지로 구분).

#### 전체 폭 레이아웃 (패널 닫힌 상태)

```
┌────────────────────────────────────────────────────────────────────────────────────────────┐
│  팀 스킬                                         검색 [___________]                        │
│  카테고리▼  작성자▼  활성 멤버▼                                                             │
├────────────────────────────────────────────────────────────────────────────────────────────┤
│  ── 활성화 (3) ──────────────────────────────────────────────────────────────────────────   │
│  │ 이름       │ 한 줄 설명     │ 카테고리  │ 작성자│ 수정일     │ 버전│호출 수│활성 멤버  │⚡│
│  │ 매출 분석   │ 월별 매출 추이 │ 데이터    │ 홍길동│ 2026.03.20│ v3 │   47│[홍][김]+3│ON│
│  │ 보고서 생성 │ 주간 보고서... │ 문서 생성 │ 김철수│ 2026.03.18│ v1 │   23│[김][박]  │ON│
│  │ 분기 매출   │ 분기별 트렌드  │ 데이터    │ 나    │ 2026.03.22│ v2 │    3│[나]      │ON│
│                                                                                            │
│  ── 비활성 (10) ─────────────────────────────────────────────────────────────────────────   │
│  │ 회의록 정리 │ 회의 녹취를... │ 커뮤니케… │ 박영희│ 2026.03.15│ v1 │   12│[박][홍]+1│  │
│  │ 데이터 정제 │ ERP 원시...    │ 데이터    │ 이민수│ 2026.03.10│ v2 │   58│[이][김]+4│  │
│  │ 이메일 초안 │ 회신 이메일... │ 커뮤니케… │ 최수진│ 2026.03.24│ v1 │    0│—         │  │
│  ...                                                                                       │
└────────────────────────────────────────────────────────────────────────────────────────────┘
```

위 예시에서 "분기 매출"은 내가 홍길동의 "매출 분석"을 복사한 뒤 이름을 변경한 스킬이다. 활성 멤버 컬럼의 이니셜 아바타는 최대 2개까지 표시하고, 초과 시 "+N"을 표시한다. "+N" 클릭 시 전체 활성 멤버 리스트가 팝오버로 열린다. 활성 멤버가 없으면 "—"으로 표시.

### 3.2 스킬 상세 — 슬라이드 패널

테이블 행 클릭 시 우측에서 슬라이드로 열리는 상세 패널. **헤더 → 품질 테스트 → 버전 이력(접힘) → 스킬 콘텐츠(접힘)** 순서로 구성된다.

#### 헤더

| 요소 | 설명 |
|------|------|
| 스킬 이름 | 제목 |
| 설명 (Description) | AI가 SKILL.md를 분석하여 자동 생성한 2~3줄 요약. 스킬이 어떤 입력을 받아 어떤 결과를 내놓는지를 자연어로 서술 |
| 카테고리 | 태그 |
| 메타 정보 | 작성자, 버전, 호출 수, 활성 멤버(텍스트 리스트 — "홍길동, 김철수 외 3명". "외 N명" 클릭 시 팝오버), 출처(직접 생성/복사 — 복사 시 원본 스킬·작성자 표시), 생성일, 최종 수정일(yyyy.mm.dd) |
| 최신 변경 인라인 | 메타 정보 하단. "v3 · 3일 전 · [변경] 출력 형식: 표→차트 외 2건" 형태로 최신 버전의 AI 변경 요약 첫 항목을 한 줄로 표시. 버전 이력을 펼치지 않아도 최근 변경을 즉시 파악 가능 |
| 상태 표시 | "활성화 중" 또는 "비활성" (텍스트만, 토글은 테이블에서) |
| 액션 버튼 | 아래 참조 |
| 전체 확장 | [↗] 버튼 → 전체 페이지로 전환 |

**설명(Description) 자동 생성:** 스킬 생성·편집 시 AI가 SKILL.md의 지시사항을 분석하여 사용자 관점의 요약을 자동 생성한다. 기존의 한 줄 설명을 대체하며, "이 스킬이 무엇을 입력받아 무엇을 결과로 내놓는지"를 2~3줄로 서술한다. 테이블의 "한 줄 설명" 컬럼에는 이 요약의 첫 문장이 표시된다.

*[설계 변경 (v8): (1) 한 줄 설명을 AI 자동 생성 2~3줄 요약으로 확장 — SKILL.md 원문(영어 장문)을 읽지 않아도 스킬의 입력·결과·용도를 파악 가능. (2) 최신 변경 인라인 추가 — 버전 이력을 펼치지 않아도 최근 변경을 헤더에서 즉시 확인. 버전 이력 기본 접힘 전환에 따른 보완.]*

#### 패널 액션

모든 스킬에서 [복사]가 가능하다. 내 스킬이면 [채팅에서 편집]이 추가로 노출된다. 활성화/비활성화는 테이블 토글에서만 제공하고, 패널에서는 현재 상태 텍스트만 표시한다.

| 직접 노출 | 조건 | 설명 |
|----------|------|------|
| [복사] | 모든 스킬 | 이 스킬을 복사하여 새 스킬로 생성 |
| [채팅에서 편집] | 내 스킬만 | 채팅으로 이동하여 스킬 수정. 저장 시 새 버전 생성 |

**[복사] 동작:**

[복사] 클릭 시 별도 모달 없이 즉시 복사된다. 이름은 자동 넘버링으로 생성된다.

| 단계 | 동작 |
|------|------|
| 1. 이름 생성 | 동일 작성자의 기존 스킬과 겹치지 않도록 자동 넘버링. 첫 복사: `{원본 이름} (2)`, 이후: `(3)`, `(4)`... |
| 2. 스킬 생성 | 현재 스킬의 최신 버전을 기반으로 내 이름의 새 스킬이 v1으로 생성됨 |
| 3. 팀 표시 | 팀 드라이브에 새 행으로 추가 |
| 4. 자동 활성화 | 내 채팅에서 자동 활성화 |
| 5. 알림 | 토스트: "'{이름}' 스킬이 생성되었습니다" |

이름은 복사 후 패널 헤더에서 언제든 수정할 수 있다 (아래 "이름 수정" 참조).

*[설계 변경 (v7): (1) 수동 편집(직접 편집) 제거 — "..." 메뉴 자체가 불필요해짐. (2) 원본 복구 제거 — 버전 이력에서 복구. (3) [복사]를 모든 스킬에서 제공 — 내 스킬이든 남의 스킬이든 복사 가능. (4) 복사 시 모달 없이 자동 넘버링으로 즉시 생성 — 마찰 최소화. 이름 수정은 패널 헤더에서. (5) 패널에서 활성화/비활성화 버튼 제거 — 테이블 토글에서만 제공.]*

#### 본문 — 품질 테스트 (첫 번째 영역, 기본 펼침)

패널 본문의 **가장 첫 번째 영역**. 스킬 생성·편집 시 AI가 자동으로 실행한 테스트 결과를 보여준다. 테스트 프롬프트가 **활용 예시** 역할을 하고, 각 프롬프트에 붙은 **검증 항목(expectations)**과 **근거(evidence)**가 "이 스킬이 무엇을 보장하는가"를 구체적으로 전달한다.

**테스트 자동 생성 원칙:** 채팅에서 스킬을 생성·편집하면, AI가 SKILL.md의 지시사항을 분석하여 3~5개의 테스트 프롬프트와 프롬프트별 검증 항목(expectations)을 자동으로 생성하고 실행한다. 테스트 프롬프트는 실제 사용자가 채팅에서 입력할 법한 자연어 문장이며, 스킬의 핵심 기능과 경계 조건을 포괄한다. 검증 항목은 "좋은 출력이란 무엇인가"를 항목별로 정의한 것이며, Grader 서브에이전트가 각 항목에 대해 PASS/FAIL + evidence를 판정한다. *[참조: Anthropic skill-creator Eval 모드(2026.03) — 테스트 프롬프트 + expectations 기반 자동 평가, Executor/Grader 서브에이전트 병렬 실행]*

**실제 eval 구조:**

하나의 테스트 프롬프트 안에 여러 개의 검증 항목(expectations)이 있고, 각 항목마다 판정(✓/✗)과 근거(evidence)가 붙는다. 실제 Anthropic eval 산출물의 구조:

```
프롬프트: "어제 AI 관련 뉴스 좀 정리해줘"
  ✓ has_markdown_structure   → "# AI Daily Briefing, ## Highlights 등 적절한 헤더 존재"
  ✓ has_news_items_5plus     → "6개 섹션에 걸쳐 20개 이상 뉴스 항목 발견"
  ✓ has_source_urls          → "20개 이상 뉴스에 [Label](URL) 형식 출처 포함"
  ✓ has_categories           → "6개 카테고리로 분류됨"
  ✓ has_date_in_report       → "헤더에 날짜 '2026-03-26' 포함"
  ✓ has_summaries            → "20개 중 19개에 2-3줄 요약 포함"
  ✓ correct_language         → "전체 보고서 한국어로 작성됨"
```

**UI 표시 방식 (B안: 모든 항목에 검증 상세 접힘 제공):**

| 요소 | 설명 |
|------|------|
| 검증 일시 | 마지막 Eval 실행 시점 (yyyy.mm.dd). 스킬 편집마다 자동 갱신 |
| 테스트 프롬프트 | ✓/✗ + 프롬프트 (자연어) + [▸ 검증] 접힘 토글. 프롬프트 수준의 ✓/✗는 해당 프롬프트의 모든 expectations가 통과하면 ✓, 하나라도 실패하면 ✗ |
| 검증 상세 (접힘) | [▸ 검증] 클릭 시 펼쳐짐. 해당 프롬프트의 expectations 목록: 각 항목별 ✓/✗ + 항목명 + evidence |
| 실패 evidence (인라인) | ✗ 프롬프트는 접지 않아도 실패한 expectations의 evidence가 프롬프트 하단에 즉시 노출 |
| 💡 참고 (조건부) | AI가 테스트 결과와 스킬 분석을 종합하여 도출한 사용 시 주의사항. 유의미한 참고가 있을 때만 표시 |

통과한 프롬프트는 프롬프트 자체가 "이 스킬로 이런 걸 할 수 있다"는 활용 예시 역할을 하고, 관심 있는 사용자는 [▸ 검증]을 펼쳐 "정확히 무엇을 검증해서 통과한 것인지" 확인할 수 있다. 실패한 프롬프트는 **어떤 expectation이 왜 실패했는지**가 즉시 보여서 스킬의 한계를 명확히 전달한다.

**좋은 테스트 프롬프트 vs 빈약한 테스트 프롬프트:**

빈약한 예시는 expectations도 당연한 것만 검증하므로 "굳이 테스트할 필요가 있나?"라는 인상을 준다. 구체적인 예시는 실제 업무 맥락을 반영한 프롬프트에 의미 있는 expectations가 붙어서, 테스트 항목 자체가 "이 스킬이 이 상황에서 이것까지 보장한다"는 활용 가이드 역할을 한다.

```
❌ 빈약한 예시:
   ✓ "매출 분석해줘"                                           ▸ 검증
     [펼치면]
     ✓ has_output → "출력이 생성됨"
     ✓ has_numbers → "숫자가 포함됨"
     — expectations가 당연한 것만 검증하여 테스트의 가치가 느껴지지 않음

✅ 구체적인 예시:
   ✓ "지난 6개월간 월별 매출 추이를 꺾은선 차트로 분석해줘"     ▸ 검증
     [펼치면]
     ✓ 차트 형식 — "꺾은선 차트 형태로 출력됨"
     ✓ 기간 정확성 — "최근 6개월(2025.10~2026.03) 데이터 포함"
     ✓ 데이터 레이블 — "월별 수치 레이블 표시됨"
     ✓ 추세 설명 — "전월 대비 증감 추세에 대한 해석 포함"
     — expectations가 구체적이어서 "이 스킬이 여기까지 보장한다"가 드러남

   ✓ "매출 데이터에 3월이 비어있는데 그래도 분석 가능해?"       ▸ 검증
     [펼치면]
     ✓ 결측 감지 — "3월 데이터 누락을 감지하고 사용자에게 알림"
     ✓ 결측 처리 — "누락 월을 보간 처리하여 차트 생성"
     ✓ 주의사항 명시 — "보간 데이터임을 범례에 표시"
     — 경계 조건(결측 데이터)에서 스킬이 어떻게 반응하는지 전달

   ✗ "Export the quarterly revenue report in English"          ▸ 검증
     → 다국어 출력: 영어 요청이나 한국어로 생성됨
     → 언어 감지: 입력 언어에 따른 출력 언어 전환 실패
     [펼치면]
     ✓ 데이터 조회 — "분기 매출 데이터 정상 조회"
     ✓ 보고서 구조 — "분기별 섹션으로 구성됨"
     ✗ 다국어 출력 — "영어 요청이나 한국어로 생성됨"
     ✗ 언어 감지 — "입력 언어에 따른 출력 언어 전환 실패"
     — 실패 evidence가 인라인으로 노출되어 스킬의 한계가 즉시 보임
```

**💡 참고 (Analysis Note):**

#### 본문 — 버전 이력 (두 번째 영역, 기본 접힘)

품질 테스트 아래에 배치. **기본 접힘 상태**이며, 접힘 상태에서 최신 버전의 한 줄 미리보기를 표시한다. 버전 이력의 주 용도는 **스킬이 의도대로 작동하지 않을 때** 원인을 추적하고 이전 버전으로 복구하는 것이므로, 평상시에는 접혀 있되 필요할 때 빠르게 접근 가능한 구조가 적합하다.

각 버전의 AI 변경 요약은 **변경 유형 태그 + 설명** 리스트로 구성된다. 산문 대신 스캔 가능한 구조화된 리스트를 사용하여, 빠르게 훑어도 핵심 변경을 파악할 수 있도록 한다.

**변경 유형 태그:**

| 태그 | 의미 | 사용 기준 |
|------|------|----------|
| `추가` | 이전 버전에 없던 기능·로직·조건이 새로 생김 | 새 섹션, 새 트리거, 새 파라미터 등 |
| `변경` | 기존 기능·로직·값이 다른 것으로 바뀜 | 출력 형식 전환, 기본값 변경, 로직 수정 등 |
| `삭제` | 기존 기능·로직·조건이 제거됨 | 사용하지 않는 파라미터 삭제 등 |
| `개선` | 기존 기능의 품질·성능·정확도가 향상됨 | 에러 처리 보강, 설명 명확화 등 |

**각 항목의 구성:**

```
[태그] 변경 대상 — 무엇이 어떻게 바뀌었는지 (한 줄)
      → 왜 바뀌었는지 또는 사용자에게 미치는 영향 (한 줄)
```

태그로 변경의 종류를, 첫 줄로 사실을, 둘째 줄(→)로 맥락/영향을 전달한다. 둘째 줄은 AI가 판단하여 필요할 때만 표시한다 (의도가 명확한 단순 변경은 첫 줄만).

**접힘 상태 목업:**

```
▶ 버전 이력 (3)
  v3 · 2026.03.20 · [변경] 출력 형식: 표→차트 외 2건
```

**펼침 상태 목업:**

```
▼ 버전 이력 (3)

  v3 — 2026.03.20 홍길동
  ┌─ 🤖 AI 변경 요약 ─────────────────────────────┐
  │                                                 │
  │  [추가] 데이터 검증 단계                         │
  │         → 빈 셀 발견 시 기본값(0)으로 자동 채움.  │
  │           입력 누락으로 인한 분석 오류 방지        │
  │                                                 │
  │  [변경] 출력 형식: 표 → 차트                      │
  │         → 월별 추이를 시각적으로 비교 가능         │
  │                                                 │
  │  [추가] 트리거 조건에 '분기 보고서' 추가           │
  │                                                 │
  │  [원문 비교 →]  [다른 버전과 비교 ▼]              │
  └─────────────────────────────────────────────────┘
  [이 버전으로 복구]  [이 버전으로 복사]

  v2 — 2026.03.15 홍길동
  🤖 [추가] 전월 대비 증감률 컬럼 외 1건              [▶]

  v1 — 2026.03.01 홍길동 (최초 생성)
```

| 항목 | 설명 |
|------|------|
| 접힘 미리보기 | 최신 버전의 첫 번째 태그 항목 + "외 N건"을 한 줄로 표시 |
| 버전 목록 | 수정일, 수정자, AI 변경 요약. 최신 버전이 맨 위 |
| AI 변경 요약 | 변경 유형 태그 리스트. 한국어. 스킬 저장 시 자동 생성 |
| 요약 블록 시각 구분 | 연한 배경색 + 좌측 accent 보더 + "🤖 AI 변경 요약" 레이블로 AI 콘텐츠임을 명시 (Distill 패턴) |
| [원문 비교 →] | 요약 블록 하단. 클릭 시 해당 버전과 직전 버전 간 side-by-side diff 표시. 패널 폭이 좁으면 unified diff로 폴백 |
| [다른 버전과 비교 ▼] | 요약 블록 하단. 클릭 시 비교 대상 버전 리스트 드롭다운. 선택 시 AI가 두 버전 간 차이를 동적으로 분석 (아래 5.7절 상세) |
| [이 버전으로 복구] | 내 스킬에서만 표시. 해당 버전의 내용으로 새 버전을 생성 (예: v2로 복구 → v4가 됨). 확인 모달 표시 |
| [이 버전으로 복사] | 모든 스킬에서 표시. 해당 버전의 스냅샷을 기반으로 내 이름의 새 스킬 v1 생성. 상세: → 5.2절 |

**펼침/접힘 규칙:**
- **버전 이력 전체**: 기본 접힘. 접힘 상태에서 최신 버전 한 줄 미리보기 표시
- **펼침 시 최신 버전**: 요약 블록이 펼침 상태
- **펼침 시 이전 버전**: 한 줄 요약(첫 번째 태그 항목 + "외 N건")으로 접힘. 클릭 시 펼침
- **버전 5개 이상**: 최근 3개만 목록에 표시, "이전 버전 더 보기" 링크로 나머지 접근

*[설계 변경 (v8): (1) 버전 이력을 패널 최상단 펼침에서 기본 접힘으로 전환. 패널을 여는 주 목적이 "스킬 파악"(품질 테스트에서 커버)이므로, 버전 이력은 필요할 때 펼쳐보는 구조가 적합. (2) 접힘 상태에서 최신 버전 한 줄 미리보기 + 헤더의 최신 변경 인라인으로 접힘 상태에서도 최근 변경 정보 유실 없음. (3) [다른 버전과 비교 ▼] 추가 — 비연속 버전 동적 비교 지원 (5.7절).]*

### 3.4 마켓플레이스 — 스킬 상세 패널

테이블 행 클릭 시 우측에서 슬라이드로 열리는 상세 패널. 3.2절의 팀 스킬 상세 패널과 **동일한 정보 구조**를 따르되, 액션과 메타 정보에 차이가 있다.

**[활성화] 동작:**

| 단계 | 동작 |

| 1. 팀 드라이브 확인 | 팀 드라이브에 이 스킬의 참조 행이 이미 있는지 확인 |

**[복사] 동작:** 5.2절과 동일. 출처 메타데이터에 "마켓플레이스 > 원본 스킬 > 원본 작성자 · 소속 팀" 기록.

## 5. 주요 인터랙션 패턴

### 5.1 활성화 토글

활성화 토글은 **테이블에서만** 제공. 슬라이드 패널에서는 현재 상태 텍스트("활성화 중" / "비활성")만 표시.

| 상태 | 동작 | 영향 범위 |
|------|------|----------|
| 활성 → 비활성 | 에이전트가 해당 스킬을 호출하지 않음 | 해당 사용자의 채팅 세션만 |
| 비활성 → 활성 | 에이전트가 다시 호출 가능 | 해당 사용자의 채팅 세션만 |

토글 시 행이 활성화/비활성 그룹 간 이동하며, 이동 자체가 시각적 피드백이 된다.

### 5.2 복사

#### 패널 헤더 [복사] — 최신 버전 복사

| 항목 | 설명 |
|------|------|
| 진입점 | 슬라이드 패널의 [복사] 버튼 (모든 스킬에서 표시) |
| 이름 | 자동 넘버링: `{원본 이름} (2)`, `(3)`... 복사 후 패널 헤더에서 수정 가능 |
| 결과 | 현재 스킬의 **최신 버전**을 기반으로 내 이름의 새 스킬 생성 (v1) |
| 팀 표시 | 테이블에 새 행으로 추가 |
| 자동 활성화 | 복사본이 내 채팅에서 자동 활성화 |
| 원본과의 관계 | 독립적. 메타데이터에 출처(원본 스킬·작성자·기반 버전)만 기록 |

#### 버전 이력 [이 버전으로 복사] — 특정 버전 복사

| 항목 | 설명 |
|------|------|
| 진입점 | 버전 이력에서 각 버전의 [이 버전으로 복사] (모든 스킬에서 표시) |
| 이름 | 자동 넘버링: 패널 헤더 [복사]와 동일 |
| 결과 | **선택한 버전의 스냅샷**을 기반으로 내 이름의 새 스킬 생성 (v1) |
| 팀 표시 | 테이블에 새 행으로 추가 |
| 자동 활성화 | 복사본이 내 채팅에서 자동 활성화 |
| 원본과의 관계 | 독립적. 메타데이터에 출처(원본 스킬·작성자·**기반 버전**)가 기록됨 |
| 메타 표시 | 패널 메타 정보에 "복사 출처: 홍길동의 '매출 분석' **v2** 기반" 형태로 버전 명시 |

*[설계 변경 (v11): 특정 버전 복사 기능 추가. "v3까지는 잘 돌았는데 v4에서 프롬프트가 바뀌어서 예전 버전을 쓰고 싶다"는 케이스 대응. 패널 헤더 [복사]는 기존대로 최신 버전 복사, 버전 이력의 [이 버전으로 복사]는 선택한 버전 복사. 두 진입점 모두 결과는 동일(내 이름의 v1 독립 스킬).]*

### 5.3 이름 수정

| 항목 | 설명 |
|------|------|
| 진입점 | 패널 헤더에서 스킬 이름 클릭 (내 스킬만) |
| 동작 | 인라인 텍스트 입력. Enter/포커스 아웃으로 저장, Esc로 취소 |
| 중복 검증 | 팀 내 동일 작성자의 스킬과 이름이 겹치면 인라인 에러 |
| 버전 영향 | 이름 변경은 새 버전을 생성하지 않음 (메타데이터 수정) |

### 5.4 버전 복구

| 항목 | 설명 |
|------|------|
| 진입점 | 버전 이력에서 [이 버전으로 복구] (내 스킬에서만) |
| 동작 | 선택한 버전의 내용으로 새 버전을 생성. 예: v2로 복구하면 v4(내용=v2)가 됨 |
| 확인 | "v2의 내용으로 새 버전을 생성합니다" 확인 모달 |
| AI 요약 | 복구 시에도 AI 변경 요약이 생성됨 ("v2로 복구되었습니다. 변경 내용: ...") |

### 5.5 검색·필터

| 위치 | 검색 범위 | 동작 |
|------|----------|------|
| 팀 스킬 테이블 | 팀 전체 스킬 | 이름, 설명, 작성자, 카테고리, 활성 멤버 기준 실시간 필터링 |
| 마켓플레이스 | 전사 공개 스킬 전체 | 이름, AI 설명, 작성자, 카테고리 기준 실시간 필터링 |

### 5.6 버전 비교 — AI 변경 요약 (사전 생성)

| 항목 | 설명 |
|------|------|
| 생성 시점 | 스킬 저장 시 자동으로 이전 버전과 비교하여 생성 |
| 언어 | 한국어 (사용자 설정 언어를 따름) |
| 출력 형식 | 변경 유형 태그(`추가`/`변경`/`삭제`/`개선`) + 설명 리스트 |
| 항목 구성 | **첫 줄**: 태그 + 변경 대상 + 무엇이 어떻게 바뀌었는지. **둘째 줄(→)**: 왜 바뀌었는지 또는 사용자에게 미치는 영향 (AI가 필요하다고 판단할 때만) |
| 접힘 요약 | 이전 버전은 첫 번째 태그 항목 + "외 N건"으로 한 줄 표시 |
| 시각 구분 | 연한 배경색 + 좌측 accent 보더 + "🤖 AI 변경 요약" 레이블 (Distill 패턴) |
| 원문 비교 | 요약 블록 하단 [원문 비교 →] 링크. side-by-side diff. 패널 폭 좁으면 unified diff 폴백 |

**좋은 요약 vs 빈약한 요약:**

```
❌ 빈약한 예시:
   [추가] 데이터 검증
   [변경] 출력 형식

✅ 충분한 예시:
   [추가] 데이터 검증 단계
          → 빈 셀 발견 시 기본값(0)으로 자동 채움. 입력 누락으로 인한 분석 오류 방지
   [변경] 출력 형식: 표 → 차트
          → 월별 추이를 시각적으로 비교 가능
```

태그만으로는 "무엇이"만 알 수 있다. 첫 줄의 구체적 설명으로 "어떻게"를, 둘째 줄(→)로 "왜/영향"을 전달해야 스킬 원문을 읽지 않아도 핵심을 파악할 수 있다. 둘째 줄은 AI가 맥락이 불명확하거나 영향이 큰 변경에만 붙이고, 의도가 자명한 단순 변경(예: 트리거 조건 추가)에는 생략한다.

*[설계 근거: (1) 리더 피드백 — "diff 방식으로 보여줘도 사람들이 읽지 않을 것 (영어 + 장문)". (2) 산문 요약도 길어지면 읽히지 않음 → 태그 리스트로 스캔 가능성 확보 (gpt-commit-summarizer 계층 패턴). (3) "사실 + 맥락" 2단 구조로 빈약하지 않으면서도 간결하게. (4) 둘째 줄(→)의 선택적 표시로 불필요한 장황함 방지.]*

### 5.7 비연속 버전 동적 비교

사전 생성 요약(5.6절)은 항상 **직전 버전 대비** 변경만 보여준다. 비연속 버전 간 차이(예: v2↔v5)를 파악하려면, 기준 버전에서 비교 대상을 선택하여 AI가 동적으로 분석하는 기능이 필요하다.

#### 인터랙션 — 패턴 C (기준 버전에서 비교 대상 선택)

사용자는 항상 **기준점**을 가지고 비교를 시작한다. "v5(현재)가 이상한데, v2 때는 괜찮았으니 v5 기준으로 v2와 뭐가 달라졌는지 보고 싶다"는 식이다. 이 멘탈 모델에 맞춰, 특정 버전의 요약 블록 하단에서 비교 대상을 선택하는 방식을 사용한다.

```
  v5 — 2026.03.25 홍길동
  ┌─ 🤖 AI 변경 요약 ─────────────────────────────┐
  │  [변경] 출력 대시보드에 부서별 필터 추가          │
  │  ...                                            │
  │                                                 │
  │  [원문 비교 →]  [다른 버전과 비교 ▼]              │
  │                  ├─ v4와 비교                    │
  │                  ├─ v3와 비교                    │
  │                  ├─ v2와 비교  ◄── 클릭          │
  │                  └─ v1과 비교                    │
  └─────────────────────────────────────────────────┘
```

| 항목 | 설명 |
|------|------|
| 진입점 | 버전 요약 블록 하단의 [다른 버전과 비교 ▼] |
| 비교 대상 | 해당 버전을 제외한 모든 버전이 리스트로 표시. 직전 버전은 이미 사전 생성 요약이 있으므로 리스트에서 제외 가능 |
| 처리 방식 | AI가 두 버전의 원문 diff를 분석하여 변경 요약 생성. 중간 버전들의 사전 생성 요약을 입력으로 활용하여 토큰 비용 절감 |
| 로딩 | AI 분석 중 로딩 인디케이터 표시. 응답 시간은 스킬 복잡도에 따라 3~10초 예상 |

#### 비교 결과 표시

선택 시 해당 버전 아래에 AI 비교 분석 블록이 인라인으로 삽입된다.

```
  ┌─ 🤖 v5 ↔ v2 AI 비교 분석 ────────────────────────────────┐
  │                                                            │
  │  v2 이후 3개 버전에 걸쳐 다음이 변경되었습니다:              │
  │                                                            │
  │  [추가] 데이터 검증 단계 (v3에서 추가)                      │
  │         → ERP에서 가져온 매출 데이터에 빈 셀이 있을 경우     │
  │           기본값(0)으로 채워 분석 오류를 방지.               │
  │           v2에서는 빈 셀이 있으면 해당 월이 누락됨           │
  │                                                            │
  │  [변경] 출력 형식: 표 → 차트 → 대시보드 (v3, v5에서 변경)   │
  │         → v2의 텍스트 표 형식에서 인터랙티브 대시보드로 전환. │
  │           부서별 필터, 기간 슬라이더 추가됨                  │
  │                                                            │
  │  [추가] 트리거 조건 '분기 보고서', '반기 실적' (v3, v4에서)  │
  │         → v2에서는 '매출 분석', '매출 추이'로만 트리거됨.    │
  │           v5에서는 7개 트리거 패턴 지원                     │
  │                                                            │
  │  [추가] 필터 파라미터: 기간, 부서, 제품군 (v4에서 추가)      │
  │         → "마케팅팀 3분기 매출만 보여줘" 같은 조건부 분석 가능│
  │                                                            │
  │  [원문 비교 보기]                                [닫기]     │
  └────────────────────────────────────────────────────────────┘
```

비연속 비교에서는 **각 변경이 어느 버전에서 발생했는지**를 명시한다. 이를 통해 "v3에서 추가된 검증 단계가 문제의 원인일 수 있다"와 같은 추적이 가능하다. 또한 v2 시점의 동작("v2에서는 빈 셀이 있으면 해당 월이 누락됨")을 함께 기술하여, 단순 변경 나열이 아닌 **전후 동작 차이**를 전달한다.

*[설계 변경 (v8): 비연속 버전 동적 비교 신설. (1) 사전 생성 요약(5.6절)은 직전 버전 대비만 커버. 비연속 비교(v2↔v5 등)는 AI가 동적으로 분석. (2) 패턴 C(기준 버전에서 비교 대상 선택) 채택 — 사용자가 "이 버전 기준으로 저 버전과 비교"하는 멘탈 모델에 부합. (3) 중간 버전의 사전 생성 요약을 입력으로 활용하여 토큰 비용 절감. (4) 각 변경의 발생 버전을 명시하여 문제 추적 가능.]*

### 6.2 패널 미선택 상태

테이블에서 아직 스킬을 클릭하지 않았을 때. 테이블이 전체 폭으로 표시된다.

### 6.3 복사본 표시

복사본은 복사 시 지정한 이름으로 테이블에 표시된다. 패널에서는 메타 정보에 "복사 출처: 홍길동의 '매출 분석' v3 기반"이 표시되어 어디서, 어떤 버전에서 파생된 스킬인지 알 수 있다. 최신 버전 복사의 경우 버전 표시 생략.

### 6.4 마켓플레이스 — 빈 상태

전사 공개 스킬이 0개일 때.

```
┌─────────────────────────────────────────────────────────────────┐
│                                                                  │
│         아직 전사에 공개된 스킬이 없습니다                          │
│         팀 스킬에서 만든 스킬을 전사에 공개해보세요                  │
│                                                                  │
│                    [팀 스킬로 이동]                               │
└─────────────────────────────────────────────────────────────────┘
```

### 6.5 팀 스킬 테이블 — 마켓플레이스 참조 스킬 혼재

참조 스킬과 팀 내 생성 스킬이 같은 테이블에 있으므로, 출처 구분이 명확해야 한다.

| 구분 | 표시 | 편집 가능 |
|------|------|----------|
| 팀 내 생성 | (뱃지 없음) | 내 스킬이면 ✅ |
| 마켓플레이스 참조 | 🏪 뱃지 + 작성자에 소속 팀 표시 | ❌ (복사해야 편집 가능) |
| 복사본 (마켓플레이스 출처) | (뱃지 없음, 패널 메타에 출처 기록) | ✅ |

### 6.6 비공개 전환 시

작성자가 마켓플레이스에서 비공개로 전환하면:

| 영향 받는 곳 | 동작 |
|-------------|------|
| 마켓플레이스 | 카드 제거. 신규 활성화 불가 |
| 이미 활성화한 팀 | 참조 행 유지. 계속 사용 가능. 단, 향후 업데이트는 반영되지 않음 (비공개 시점의 버전에 고정) |
| 이미 복사한 스킬 | 영향 없음 (독립) |
