# UX Review Report — 2026-03-19

## Target
`src/components/AdminView.tsx` + `src/app/admin/`

## Summary
관리자 대시보드는 사용자 관리, 권한 설정, 사용량 모니터링, 감사 로그 등 4개 주요 기능을 담은 엔터프라이즈 관리 화면이다. 전반적으로 UI 일관성과 기본 접근성이 잘 구현되어 있으나, 권한 설정 탭의 복잡도가 높고 사용자 관리 플로우에서 몇 가지 마찰이 발견된다.

## Personas
| 페르소나 | 기술 수준 | 사용 빈도 | 주요 목표 |
|---------|---------|---------|---------|
| IT관리자 | 중상 | 주 2-3회 | 신규 사용자 등록, 권한 변경, 접근 제어 관리 |
| 보안담당자 | 중상 | 주 1회 | 감사 로그 검토, 권한 충돌 점검, 정책 관리 |
| 경영진/부서장 | 중 | 월 1-2회 | 사용량 모니터링, 팀별 비용 추적 |

## Part 1: UX Checklist Findings

### Flow Analysis

#### Users Tab (사용자 관리)
- Entry: 기본 탭. 검색, 필터, 뷰 전환 가능
- Actions: 사용자 추가, 수정, 삭제, 상태 활성화/비활성화, 일괄 임포트, 접근권한 뷰
- Exits: 수정 완료 시 토스트 표시 후 리스트로 복귀
- Issues:
  1. 삭제 확인 다이얼로그 있지만, 일괄 삭제 기능 없음
  2. 조직도 뷰에서 사용자 검색 불가 (리스트 모드에서만 가능)

#### Permissions Tab (권한 설정)
- Entry: 6개 중첩 탭 (역할 정의 → 조직-역할 매핑 → 테이블 접근 매트릭스 → RLS → 마스킹 → 미리보기)
- Actions: 역할 생성/수정/삭제, 접근 수준 토글, RLS 규칙 추가/삭제, 마스킹 정책 설정, 통합 미리보기
- Exits: 저장 버튼 클릭 후 토스트 표시
- Issues:
  1. 6개 탭이 한 줄에 나열되어 화면 폭이 좁으면 스크롤 필요
  2. 테이블 접근 매트릭스 (15역할 × 43 카테고리)는 수평 스크롤이 많음
  3. "저장되지 않은 변경사항" 경고가 좋으나, 탭 이동 시 상태 보존 여부가 불명확

#### Usage Tab (사용량)
- Entry: 기간 필터 (7d/30d/90d)
- Actions: 기간 선택, KPI 카드 확인, 테이블 정렬/페이지네이션
- Issues: 없음 (스트레이트포워드)

#### Audit Tab (감사 로그)
- Entry: 타임 레인지, 액터 타입, 액션 카테고리, 심각도 필터
- Actions: 로그 검색, 필터, 행 클릭하여 상세 정보 조회
- Issues:
  1. 복수 필터 조합 후 리셋 시 한 번에 초기화되지 않음 (개별 X 버튼만 있음)

## Part 2: Scenario-Based Product Review

### S1: 신규 사용자 등록 (이름, 이메일, 조직, 직급만 필요)
- **페르소나**: IT관리자, 주 2-3회 사용, 신규 입사자 온보딩 중
- **현재 경로**:
  1. 사용자 관리 탭 → "사용자 추가" 버튼
  2. UserFormModal 오픈 → Step 1 (기본정보 입력)
  3. 이름, 이메일 입력 → 조직 선택 (OrgTreeSelector) → 직급 선택 (3개 버튼)
  4. "다음" 버튼 → Step 2 (역할 확인)
  5. 자동 매핑된 역할 확인 → "등록하기" 버튼
  6. 토스트 메시지 "사용자가 추가되었습니다"
- **마찰점**:
  1. [필드 시각화 부재] Step 1에서 "이름, 이메일, 조직, 직급"이 필수인데 별표(*) 또는 "필수" 라벨이 없음
     - 위치: UserFormModal.tsx:224-277
     - 현재: `<Label>이름</Label>` (색상만 회색)
     - 문제: 사용자가 필수 여부를 명확히 인식하지 못함
  2. [자동 역할 할당 불투명] Step 2에서 "조직-직급 매핑 기반으로 역할이 자동 할당되었습니다"라는 배너는 있으나, 어디서 이 매핑이 정의되었는지 사용자가 알 수 없음
     - 위치: UserFormModal.tsx:286-296
     - 현재: 성공 배너만 표시
     - 문제: 관리자가 역할 매핑을 확인/변경해야 할 때 권한 설정 탭으로 가야 하는데 가는 방법이 명시되지 않음
  3. [역할 매핑 부재 케이스 경고] 매핑이 없으면 Step 2에서 "이 조직+직급 조합에 대한 역할 매핑이 없습니다"와 "권한 설정 > 조직-역할 매핑에서..." 링크가 있음 (좋음) 하지만 링크가 실제 동작하지 않음 (텍스트만)
     - 위치: UserFormModal.tsx:354-355
     - 현재: `<p className="text-xs text-amber-700 mt-1.5">권한 설정 &gt; 조직-역할 매핑에서...</p>`
     - 개선: 클릭 가능한 버튼 또는 href 링크로 변경
  4. [Step 2 저장 비활성화 조건] 역할 수가 0이면 "등록하기" 버튼이 비활성화됨 (canSave = roles.length > 0)
     - 위치: UserFormModal.tsx:156
     - 문제: 사용자가 왜 버튼이 비활성화되었는지 알 수 없음 (온스크린 메시지 없음)
- **개선안**:
  1. Step 1 필수 필드에 "*" 또는 Badge "필수" 추가
     - 대상 파일: `src/components/features/user-management/components/UserFormModal.tsx`
     - effort: Low (< 1h)
  2. Step 2에서 "조직-역할 매핑 보기" 또는 "매핑 설정하기" 버튼 추가 (권한 설정 탭으로 네비게이션)
     - 대상 파일: `src/components/features/user-management/components/UserFormModal.tsx`
     - effort: Medium (1-2h, 네비게이션 로직 필요)
  3. Step 2 저장 불가 상태일 때 "역할이 할당되지 않았습니다" 인라인 메시지 추가
     - 대상 파일: `src/components/features/user-management/components/UserFormModal.tsx`
     - effort: Low (< 1h)
- **빠진 기능**:
  - 사용자 선택적 필드 (예: 부서, 전화번호, 자동 할당 역할 수정) — 현재 역할은 읽기 전용
  - 사용자 일괄 선택 후 상태 일괄 변경 (활성화/비활성화)

### S2: 권한 설정 (조직-역할 매핑 구성)
- **페르소나**: IT관리자, 월 1회, 신규 부서 추가 후 역할 매핑 필요
- **현재 경로**:
  1. 권한 설정 탭 → "조직-역할 매핑" 탭 (6개 탭 중 2번째)
  2. 표: 조직 + 직급 조합 → 주 역할 + 추가 역할 선택
  3. "+ 추가" 버튼 → 새 행 추가 또는 기존 행 편집
  4. 저장 → 하단 "저장" 버튼
  5. 토스트: "모든 권한 설정이 저장되었습니다"
- **마찰점**:
  1. [내비게이션 복잡도] 권한 설정이 6개 탭으로 분리됨. 사용자가 어디서부터 시작해야 할지 불명확
     - 위치: PermissionSettingsView.tsx:358-373 (onboarding 가이드 배너)
     - 현재: 가이드 배너 있음 ("1. 역할 정의 → 2. 조직-역할 매핑 → ...")
     - 문제: 배너를 닫으면 다시 볼 수 없음. 탭을 이동할 때마다 현재 위치 표시가 약함
  2. [저장 상태 불명확] isDirty 플래그로 "저장 안 됨" 표시는 있으나, 각 탭에서 변경 후 저장하지 않고 다른 탭으로 이동할 수 있음
     - 위치: PermissionSettingsView.tsx:176-196
     - 현재: beforeunload 경고만 있음
     - 문제: 탭 간 이동 시 저장 여부 확인 없음
  3. [테이블 접근 매트릭스 스케일] 15 역할 × 43 카테고리 = 645개 셀. 수평 스크롤 많음
     - 위치: TableAccessLayer (불러온 파일에 전체 내용 없음)
     - 문제: 모바일/태블릿에서 사용 불가. 데스크톱도 불편
- **개선안**:
  1. 권한 설정 진입 시 필수 체크리스트 표시 (Step 1-6 진행도)
     - 대상 파일: `src/components/features/permission-settings/PermissionSettingsView.tsx`
     - effort: Medium (1-2h)
  2. 탭 간 이동 시 "저장되지 않은 변경사항" 확인 다이얼로그 추가 (선택적)
     - 대상 파일: `src/components/features/permission-settings/PermissionSettingsView.tsx`
     - effort: Medium (1-2h)
  3. 테이블 접근 매트릭스: 가상 스크롤 + 역할별 필터 추가
     - 대상 파일: `src/components/features/permission-settings/components/TableAccessLayer.tsx`
     - effort: High (3-4h)

## Part 3: 서비스 기획 관점 구조 리뷰

### 정보 구조 적합성
- **현재 탭/섹션 구조**:
  - 메인: 6개 탭 (사용자 관리, 권한 설정, 사용량, 감사 로그, 시스템 프롬프트, 피드백 품질)

  - **IT관리자**: 사용자 관리 → 권한 설정이 주 업무. 현재 구조가 이를 반영함 (일치)

  - **경영진**: 사용량 모니터링만 필요. 사용량 탭 있음 (일치)

- **제안**:
  - 현재 구조 유지. 다만 권한 설정의 6개 중첩 탭은 사용 순서 강제 필요 (Step 1-6)
  - 메인 탭 순서 제안: 사용자 관리 → 권한 설정 → 사용량 → 감사 로그 (사용 빈도순)

### 기능 존폐 판단
| 기능/컴포넌트 | 판단 | 근거 |
|-------------|------|------|
| 사용자 관리 (Create/Edit/Delete) | 유지 | 핵심 기능. 대부분의 관리자가 주 1회 이상 사용 |
| 사용자 CSV 일괄 임포트 | 유지 | 온보딩 시 필수. 분기별 신입 때 유용 |

| 사용량 모니터링 | 유지 | 경영진, 부서장용. 비용 추적 중요 |
| 감사 로그 | 유지 | 보안 규정 준수 (컴플라이언스) 필수 |
| 시스템 프롬프트 | 유지 | AI 응답 품질 제어. 관리자 필수 |
| 피드백 품질 | 유지 | 모델 개선용. 분석가용 |

- **현재 한 화면에 노출되는 개념 수**:
  - 사용자 관리: 5 (사용자 목록, 검색, 조직도, 추가/수정/삭제, 일괄 임포트)

  2. 테이블 접근 매트릭스: 기본값 축소. 사용자가 "세부 조정" 탭을 명시적으로 열어야 함
