## Summary

스킬 관리 v4는 기존 `/settings/skills`에서 독립 라우트 `/skills`로 승격되었으며, 테이블+슬라이드 패널 레이아웃, 활성화 그룹 분리, 개선 제안 워크플로우 등 체계적으로 설계되어 있다. 전반적인 UX 품질은 양호하나, **파괴적 동작(삭제)에 확인 다이얼로그 부재, 초안 편집 모드의 실제 편집 불가 상태, AdminTab 내 중복 인라인 컴포넌트 vs 미사용 별도 파일, 그리고 스킬 관리/카테고리 관리의 미구현 "준비 중" 상태**가 가장 시급한 문제이다.

## Part 1: UX Checklist Findings

### Flow Analysis

#### 팀 스킬 탭 (Team Skills Tab)
- **Entry**: Sidebar에서 Cpu 아이콘 클릭 → `/skills` → 기본 탭 "팀 스킬"
- **Actions**: 검색, 카테고리/상태/작성자 필터, 활성화 토글, 행 클릭 → 상세 패널 열기, 패널 내 편집/삭제/개선 제안, 스킬 추가 (준비 중)
- **Exits**: 다른 네비게이션으로 이동, 관리 탭으로 전환
- **Issues**: 스킬 추가 기능("채팅에서 만들기", "파일에서 가져오기") 모두 "준비 중" 토스트만 표시

#### 관리 탭 (Admin Tab)
- **Entry**: "팀 스킬" → "관리" 탭 전환 (관리자만 보임)
- **Actions**: 개선 제안 검토/승인/거절/수정 요청, 폐기 요청 승인/거절, 스킬 관리(준비 중), 카테고리 관리(준비 중)
- **Exits**: 팀 스킬 탭으로 돌아가기, 다른 네비게이션
- **Issues**: 스킬 관리, 카테고리 관리 2개 섹션이 "준비 중" 플레이스홀더

## Part 2: Scenario-Based Product Review

### S1: 필요한 스킬을 찾아서 활성화하기
- **페르소나**: 일반 사용자, 월 1-2회, 새 프로젝트 시작 시
- **현재 경로**:
  1. Sidebar에서 스킬 아이콘 클릭 → `/skills` 진입
  2. 검색창에 키워드 입력 또는 카테고리 드롭다운에서 필터 선택
  3. 비활성 그룹에서 원하는 스킬 행 확인
  4. Switch 토글을 클릭하여 활성화
  5. "활성화되었습니다" 토스트 확인
- **마찰점**:
  1. [위치 비직관] 활성화 토글과 행 클릭의 혼동
     - 위치: `SkillTableRow.tsx:256`
     - 현재: Switch 클릭 시 `stopPropagation()`으로 행 선택 방지
     - 문제: 사용자가 스킬 이름을 클릭하면 패널이 열리고, Switch만 클릭해야 활성화. Switch 영역이 작아서 모바일/터치에서 실수 가능
  2. [피드백 부재] 활성화 후 행이 비활성 그룹에서 활성화 그룹으로 이동하는데, 이동 애니메이션이 없어 사용자가 "사라졌다"고 인식할 수 있음
     - 위치: `SkillTable.tsx:157-171`
     - 현재: useMemo로 그룹 재분류 → 즉시 리렌더
     - 문제: 스킬이 비활성 목록에서 사라지고 활성 목록 상단에 갑자기 나타남
- **개선안**:
  1. 활성화 토글 영역을 더 넓게 (패딩 확대) 또는 행 클릭 시 활성화/패널 열기 선택 가이드 제공
     - 현재: Switch만 토글 트리거
     - 제안: Switch 셀 전체를 클릭 영역으로 확장 (현재도 div로 감싸져 있으나 패딩이 좁음)
     - 대상 파일: `SkillTableRow.tsx:256`
     - effort: Low
  2. 그룹 이동 시 짧은 하이라이트 애니메이션 추가
     - 현재: 즉시 리렌더
     - 제안: 활성화 직후 해당 행에 2초간 하이라이트 배경 적용
     - 대상 파일: `SkillTableRow.tsx`, `TeamSkillsTab.tsx`
     - effort: Medium
- **빠진 기능**: 없음

### S2: 스킬 상세 정보 확인 후 개선 제안 작성/제출
- **페르소나**: 에이전트 개발자, 주 1회, 기존 스킬을 개선하고 싶을 때
- **현재 경로**:
  1. 팀 스킬 탭에서 대상 스킬 행 클릭 → 슬라이드 패널 열림
  2. 개요/본문/첨부/버전 이력/개선 제안 탭 순회하며 현재 상태 확인
  3. 헤더의 "편집" 버튼 클릭 → `handleStartDraft()` → 초안 생성
  4. 패널이 DraftEditMode로 전환
  5. 초안 편집 (현재 플레이스홀더)
  6. "개선 제안 제출" 클릭 → changeSummary 입력 → "제출" 클릭
  7. "개선 제안이 제출되었습니다" 토스트 확인
- **마찰점**:
  1. [기능 부재] 초안 편집 모드가 **플레이스홀더**임 — 실제 인스트럭션 본문 편집 불가
     - 위치: `SkillSlidePanel.tsx:141-155` (DraftEditContent)
     - 현재: "수정본 편집 영역" 텍스트와 아이콘만 표시
     - 문제: 사용자가 "편집" 버튼을 누르면 편집을 기대하지만, 편집 인터페이스가 없음
  2. [실수 복구 불가] "초안 폐기" 버튼에 확인 다이얼로그 없음
     - 위치: `SkillSlidePanel.tsx:96-100`
     - 현재: 클릭 즉시 `onDiscard()` → 초안이 null로 설정
     - 문제: 작성 중인 초안이 한 번의 실수 클릭으로 영구 삭제
  3. [자동 채움 불투명] 초안 생성 시 현재 스킬의 본문/파라미터가 자동 복사되지만, 사용자에게 "현재 버전을 기반으로 초안이 생성되었습니다" 안내 없음
     - 위치: `TeamSkillsTab.tsx:24-35` (makePersonalDraft)
     - 현재: 스킬의 instructionBody, parameters, attachments를 깊은 복사
     - 문제: 사용자가 초안이 빈 것인지 현재 버전 복사인지 모름
  4. [피드백 부재] 제안 제출 후 관리 탭의 제안 큐에 반영되었다는 안내가 없음
     - 위치: `TeamSkillsTab.tsx:141-158`
     - 현재: 토스트만 표시. 실제로 mockPendingSuggestions에 추가되지 않음 (state가 분리)
     - 문제: 상태가 탭 간 공유되지 않아 관리 탭에 실제 반영 안 됨
- **개선안**:
  1. 초안 편집 인터페이스 구현 (최소: textarea로 instructionBody 편집)
     - 현재: 플레이스홀더
     - 제안: DraftEditContent에 마크다운 에디터 또는 최소한 textarea 배치
     - 대상 파일: `SkillSlidePanel.tsx:141-155`
     - effort: High
  2. ConfirmDialog를 "초안 폐기"에 적용
     - 현재: 즉시 폐기
     - 제안: `<ConfirmDialog destructive title="초안 폐기" description="작성 중인 수정본을 삭제합니다. 이 작업은 되돌릴 수 없습니다." />`
     - 대상 파일: `SkillSlidePanel.tsx`
     - effort: Low
  3. 초안 생성 시 "현재 버전(v2)을 기반으로 수정본이 생성되었습니다" 토스트 변경
     - 대상 파일: `TeamSkillsTab.tsx:128`
     - effort: Low
- **빠진 기능**: 초안 실제 편집 인터페이스 (인스트럭션 본문, 파라미터, 첨부 편집)

## Part 3: 서비스 기획 관점 구조 리뷰

### 정보 구조 적합성
- **현재 탭/섹션 구조**:
  - 1단계: 팀 스킬 / 관리 (SkillsPageView 탭)
  - 2단계 (관리 내): 개선 제안 / 폐기 요청 / 스킬 관리 / 카테고리 관리 (서브 네비게이션)
  - 상세 패널 내: 개요 / 본문 / 첨부 / 버전 이력 / 개선 제안 (5개 탭)

- **사용자 업무 모델과의 일치도**: 대체로 일치. "팀 스킬"은 조회/활성화/수정 중심, "관리"는 승인/폐기/설정 중심으로 역할 기반 분리가 명확함.

- **불일치 사항**:
  - 관리 탭의 "스킬 관리" 서브섹션과 "팀 스킬" 탭의 역할이 겹칠 가능성이 높음. "스킬 관리"에서 "강제 비활성화, 소유권 이전" 등을 제공한다면, 이는 팀 스킬 테이블에 관리자 전용 컬럼/액션으로 통합하는 것이 더 자연스러울 수 있음.
  - 상세 패널의 "개선 제안" 탭(해당 스킬의 제안 이력)과 관리 탭의 "개선 제안" 서브섹션(전체 대기 큐)이 이름은 같지만 맥락이 다름 — 혼란 가능.

- **제안**:
  - 상세 패널의 "개선 제안" 탭 이름을 "제안 이력"으로 변경하여 관리 탭의 "개선 제안"(큐)과 구분
  - 관리 탭의 "스킬 관리" 서브섹션은 "팀 스킬" 탭에 관리자 모드 토글로 통합 검토

### 기능 존폐 판단

| 기능/컴포넌트 | 판단 | 근거 |
|-------------|------|------|

| 슬라이드 패널 (상세) | 유지 | 모달 대비 컨텍스트 유지 우수. 테이블과 상세를 동시에 볼 수 있음 |
| 활성화 그룹 분리 | 유지 | 내 활성화 스킬과 미활성 스킬의 시각적 구분이 명확하고 유용 |
| 초안 편집 모드 (DraftEditMode) | 신규 추가 (완성 필요) | 현재 플레이스홀더. 개선 제안 워크플로우의 핵심 단계 |
| 관리 > 개선 제안 큐 | 유지 | 승인 프로세스의 핵심. side-by-side diff 모달 잘 설계됨 |
| 관리 > 폐기 요청 큐 | 유지 | 필요한 기능이나, 현재 인라인 버전과 별도 파일 버전 정리 필요 |

| DeprecationQueue.tsx (별도 파일) | 이동 — AdminTab에서 사용 | 인라인 버전보다 기능이 풍부하고 접근성도 나음 |
| CategoryManager.tsx (별도 파일) | 이동 — AdminTab에서 사용 | 이미 완성된 컴포넌트. 즉시 연결 가능 |

### 복잡도 관리
- **현재 한 화면에 노출되는 개념 수**: 팀 스킬 탭 약 6개 (검색, 4종 필터, 활성화 그룹, 상세 패널 5탭), 관리 탭 약 4개 (4종 서브섹션)
- **Progressive Disclosure 적용이 필요한 영역**: 현재 잘 적용되어 있음. 상세 패널이 클릭 시에만 열리고, 관리 탭은 권한 기반 숨김.
- **사용자 수준별 뷰 분리**: `IS_ADMIN` 환경변수로 관리 탭 숨김 처리됨. 추후 auth context 기반으로 전환 필요.

### 화면 간 관계
- **선후 관계**: 채팅에서 스킬 생성(미구현) → 스킬 목록에서 확인/편집 → 활성화 → AI 채팅에서 사용
- **설정값 영향 범위 가시성**:
  - 활성화 토글 변경 → AI 채팅에서 해당 스킬 사용 가능/불가 변경 → 이 연결이 UI에서 안내되지 않음
  - 폐기 승인 → 팀 전체 스킬 목록에서 제거 → 영향받는 사용자 수는 표시되지만 실제 영향 미반영
  - 제안 승인 → 스킬 버전 업데이트 → 팀 스킬 탭과 상태 동기화 없음 (서로 다른 state)

### 구조 변경 제안 (요약)
1. **AdminTab 내 인라인 컴포넌트를 별도 파일로 교체**: DeprecationQueue.tsx, CategoryManager.tsx를 AdminTab에서 import하여 사용. 인라인 버전 제거. — 영향 범위: `AdminTab.tsx`
2. **상세 패널 "개선 제안" 탭 이름 변경**: "제안 이력"으로 변경하여 관리 탭의 "개선 제안"(큐)과 구분 — 영향 범위: `SkillSlidePanel.tsx`
3. **"팀 스킬" ↔ "관리" 탭 간 상태 동기화**: 현재 TeamSkillsTab의 skills state와 AdminTab의 suggestions state가 완전히 분리되어 있음. 공유 context 또는 상위 리프트 필요 — 영향 범위: `SkillsPageView.tsx`, `TeamSkillsTab.tsx`, `AdminTab.tsx`
