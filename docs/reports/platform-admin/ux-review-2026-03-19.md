# UX Review Report -- 2026-03-19

## Target
`src/components/features/platform-admin/` + `src/app/platform-admin/`

## Summary
플랫폼 관리자 화면은 테넌트 관리, 활동 모니터링, 비용 관리, 알림, 과금/빌링, 감사 로그의 6개 탭을 갖춘 종합 운영 콘솔이다. 전반적으로 시각적 완성도와 정보 밀도의 균형이 잘 잡혀 있으나, (1) `UsageAlertTab`과 `ActivityMonitoringTab`/`AlertManagementTab` 간 기능 중복, (2) 테넌트 생성 위저드에서 수집한 `industry`/`adminEmail`/`enableSso`/`deployDemoAgent` 등 다수 필드가 생성 후 어디에도 표시되지 않는 유령 필드 문제, (3) 프로덕션 수준의 인증/권한 검증 부재가 가장 시급한 해결 대상이다.

## Personas
| 페르소나 | 기술 수준 | 사용 빈도 | 주요 목표 |
|---------|---------|---------|---------|
| P1. 플랫폼 운영자 (SRE/DevOps) | 높음 — 시스템 아키텍처 이해 | 매일 | 테넌트 헬스 모니터링, 장애 트레이스 분석, 알림 규칙 관리 |
| P2. 재무/사업 담당자 | 중간 — 기술보다 비즈니스 지표 중심 | 주 1-2회 | 비용 관리, 과금 현황 확인, 매출 리포트, 미수금 추적 |
| P3. 고객 온보딩 담당자 | 중간 | 필요 시 (월 수 회) | 신규 테넌트 생성, API 키 발급, 리소스 제한 설정, 계약 관리 |

### Flow Analysis

#### 테넌트 관리 탭
- Entry: 사이드바 "Platform Administration" 클릭 -> 기본 탭
- Actions: 카드/테이블 뷰 전환, 헬스 필터, 검색, 테넌트 상세 패널, 테넌트 생성 위저드
- Exits: 상세 패널 닫기, 다른 탭 이동
- Issues: 필터/검색 상태가 탭 전환 시 유실; 상세 패널 열린 상태에서 다른 테넌트 클릭 시 부자연스러운 전환

#### 활동 모니터링 탭
- Entry: "활동 모니터링" 탭 클릭 (lazy load)
- Actions: 테넌트/기간 필터, CSV 내보내기, 에이전트 트레이스 상세 워터폴, 스킬 사용 분석
- Exits: 다른 탭 이동
- Issues: 필터 변경이 차트 데이터에 실제 반영되지 않음 (mock 데이터 한계)

#### 비용 관리 탭
- Entry: "비용 관리" 탭 클릭
- Actions: CSV 내보내기, 예산 초과 시 알림 규칙 이동 링크
- Exits: 알림 관리 탭으로 교차 이동 가능
- Issues: 비용 데이터가 달러($)인데 빌링 탭은 원화(KRW) -- 통화 불일치

#### 알림 관리 탭
- Entry: "알림 관리" 탭 클릭
- Actions: 규칙 토글, 규칙 추가/편집, 이상 감지 규칙 토글
- Exits: 없음 (알림 이력 "전체 이력" 버튼은 아직 미구현)
- Issues: 알림 규칙 삭제 기능 없음

#### 과금/빌링 탭
- Entry: "과금/빌링" 탭 클릭
- Actions: 월 선택, 청구서 일괄 발행
- Exits: 없음
- Issues: "청구서 일괄 발행" 버튼이 아무 동작 없음

#### 감사 로그 탭
- Entry: "감사 로그" 탭 클릭
- Actions: 4중 필터, 검색, 타임라인/테이블 뷰 전환, CSV/JSON 내보내기, 새로고침
- Exits: 없음
- Issues: 가장 완성도 높은 탭. 페이지네이션, 자동 폴링, 내보내기 모두 구현

## Part 2: Scenario-Based Product Review

### S1: 새 고객 테넌트 온보딩 (생성 위저드)

- **페르소나**: P3. 고객 온보딩 담당자, 월 수 회, 영업팀 요청 시
- **현재 경로**:
  1. `TenantManagementTab` -> "테넌트 추가" 버튼 클릭
  2. `TenantCreateWizard` Step 1: 회사명, 도메인, 산업군, 담당자 정보 입력
  3. Step 2: 요금제 선택(카드 UI), 계약 시작일/종료일 입력
  4. Step 3: 관리자 이메일, 초대 링크/SSO 토글
  5. Step 4: 태그, 메모, 샘플 에이전트 배포 토글
  6. "생성 완료" 클릭 -> 목록에 추가, 위저드 닫힘
- **마찰점**:
  1. [유령 필드] `industry` 필드 수집 후 어디에도 표시되지 않음
     - 위치: `TenantCreateWizard.tsx:137-143`
     - 현재: `TenantCreateInput.industry`로 수집하나 `handleCreate`에서 `Tenant` 객체 생성 시 `industry` 필드가 `Tenant` 타입에 존재하지 않아 무시됨
     - 문제: 사용자가 산업군을 선택하는 수고를 하지만 이 데이터는 버려짐
  2. [유령 필드] `adminEmail`, `useInviteLink`, `enableSso`, `deployDemoAgent` 필드도 동일
     - 위치: `TenantManagementTab.tsx:42-77` `handleCreate` 함수
     - 현재: `TenantCreateInput`에는 있지만 `Tenant` 타입에 매핑되는 필드 없음
     - 문제: Step 3, Step 4의 핵심 설정값이 모두 저장 후 유실됨
  3. [피드백 부재] 생성 완료 후 성공 메시지/토스트 없음
     - 위치: `TenantManagementTab.tsx:76-78`
     - 현재: `setWizardOpen(false)`만 호출
     - 문제: 위저드가 닫히면서 목록 상단에 새 테넌트가 추가되지만, 사용자가 성공 여부를 확인하기 어려움
  4. [입력 방식 부적합] `contactPhone` 필드에 전화번호 포맷 제약 없음

### 복잡도 관리

- **현재 한 화면에 노출되는 개념 수**: 탭별로 상이
  - 테넌트 관리: 4 KPI + 필터 3종 + 뷰 전환 + 카드/테이블 + 상세 패널(3 서브탭) = 중간
  - 활동 모니터링: 4 KPI + 필터 2종 + 차트 2개 + 사용량 테이블 + 트레이스(메트릭 4개 + 도넛 + 테이블) + 스킬 테이블 = **높음**
  - 비용 관리: 4 KPI + 경고 배너 + 차트 3개 + 테이블 = 중간~높음
- **Progressive Disclosure 적용 필요 영역**:
  - `ActivityMonitoringTab`: 에이전트 트레이스/스킬 분석을 접기/펼치기 또는 독립 탭으로 분리
  - `TenantDetailPanel`: 리소스 제한의 고급 설정(dataRetentionMonths 등)을 "고급 설정" 접기 영역으로
- **사용자 수준별 뷰 분리 필요성**: 현재 불필요. 이 화면은 플랫폼 관리자 전용이므로 모든 사용자가 동일 수준의 전문성을 가짐

### 화면 간 관계

- **선후 관계**: 테넌트 관리(생성) -> 활동 모니터링(운영 중) -> 비용/빌링(정산) -> 감사 로그(감사)
- **설정값 영향 범위 가시성**:
  - 테넌트 리소스 제한 변경이 활동 모니터링의 "한도 대비" 표시에 영향 -- 연결 안 보임
  - 테넌트 상태 변경(Suspended)이 빌링 탭의 결제 상태에 영향 -- 연결 안 보임
  - 알림 규칙 변경이 알림 이력에 영향 -- 동일 탭 내이므로 부분 가시
  - 비용 관리 -> 알림 관리 탭 링크만 유일한 교차 탭 참조 (`CostManagementTab.tsx:75`)
- **왕복 줄이기**: 테넌트별 비용/사용량을 테넌트 상세 패널에서 바로 볼 수 있도록 서브탭 추가 고려

- **데이터 출처/갱신 시점 표시 여부**: `PlatformAuditLogTab`만 `lastUpdated` 시간 표시 + 30초 자동 폴링 구현. 나머지 5개 탭은 갱신 시점 미표시
- **실시간 vs 집계 데이터 구분 여부**: 미구분. 활동 모니터링의 "활성 에이전트 세션"(실시간)과 "총 API 호출"(이번 달 누계)이 같은 KPI 행에 있으나 갱신 주기 차이 미표시
- **0과 "데이터 없음" 구분**: 부분 처리. `TenantHealthCard`에서 `errorRate > 0`이면 표시, 아니면 `-` 표시하여 구분. 그러나 "한도 0%"가 "사용하지 않음"인지 "토큰 제한 없음"인지 모호
- **KPI 수치 정합성**: `TENANT_KPI.total.value` = "24"이지만 `MOCK_TENANTS` 배열은 6건 -- 하드코딩된 mock 값과 실제 데이터 간 불일치

### 보안/접근 제어

- **민감 데이터 마스킹**: API 키가 `keyPrefix` (`sk-prod-****-a3f2`)로 마스킹됨 -- 적절. 그러나 담당자 이메일, 전화번호, IP 주소가 평문 노출
- **라우트 가드**: `useAdminGuard`가 존재하나 demo 모드로 항상 `true` 반환 (`useAdminGuard.ts:27 setIsAllowed(true)`). 프로덕션에서는 실제 인증/인가 로직으로 교체 필요
- **API 레벨 권한 검증**: 프론트엔드만으로 확인 불가. 현재 mock 데이터 사용으로 API 호출 자체가 없음
- **민감 동작 2차 인증**: 테넌트 정지에 사유 입력 필수화는 되어 있으나, 관리자 비밀번호 재입력이나 2FA는 없음
- **CSV 내보내기 보안**: `PlatformAuditLogTab.tsx:95-98`에 CSV 인젝션 방지 (`=+@` prefix 이스케이프) 구현됨 -- 양호

### 운영 가시성

- **감사 로그 기록**: 감사 로그 탭이 존재하나 현재 UI에서 발생하는 동작(상태 변경, 리소스 수정 등)이 자동으로 감사 로그에 기록되는 메커니즘 없음. mock 데이터만 표시
- **분석 이벤트**: 코드에 analytics 이벤트 발송 로직 없음
- **변경 이력 추적**: 리소스 제한 변경, 상태 변경에 대한 변경 이력(who, when, what, from-to)이 `Tenant` 타입에 없음

### 성능 관련

- **초기 로딩**: `PlatformAdminView`가 lazy import + Suspense로 코드 분할 적용. 각 탭도 lazy load. 양호
- **탭 전환**: lazy 탭은 첫 진입 시 `TabFallback` 표시 후 로드. 2회차부터 캐시됨. 양호
- **차트 렌더링**: `ActivityMonitoringTab`과 `CostManagementTab`에 Recharts 차트 3-4개 동시 렌더. 30일 데이터는 문제 없으나 장기간 시 주의 필요
- **캐싱**: 자주 바뀌지 않는 데이터(테넌트 목록, 요금제 종류)에 대한 캐싱 전략 부재. SWR/React Query 등 미사용
