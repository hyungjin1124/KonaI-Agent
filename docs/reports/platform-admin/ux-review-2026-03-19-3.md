## PART 3: 서비스 기획 관점

### 3.1 IA 적합성: 10개 탭의 타당성

**현재 구조**:
```
Operations (5개)
  ├─ 테넌트 관리 (tenant CRUD, 헬스 체크)
  ├─ 대화 모니터링 (conversation 트래킹)
  ├─ 에러 대시보드 (error aggregation)
  ├─ 활동 모니터링 (API call, token consumption)
  └─ 알림 관리 (threshold-based rules)

BI (3개)
  ├─ 비용 관리 (cost breakdown, forecasting)
  ├─ 과금/빌링 (billing, revenue)
  └─ 감사 로그 (audit trail)

Quality (2개)
  ├─ 피드백 모니터링 (user feedback)
  └─ AI 품질 관리 (accuracy, hallucination)
```

**평가**:
- ✅ **Operations**: 5개는 명확한 카테고리. "대화" "에러" "활동"이 모두 운영에 필수적.
- ⚠️ **BI**: 3개 탭이 맞는지 의문. "비용 관리"와 "과금/빌링"의 구분이 모호.
  - 비용 관리: 모델별 비용, 예측, 최적화 (operational cost intelligence)
  - 과금/빌링: 테넌트별 청구, 결제 상태 (revenue & AR management)
  - 구분 타당성: ✅ 실제로 다른 목적이므로 분리 가치 있음
- ✅ **Quality**: 2개는 짜임새 있음. 고객 만족도와 AI 품질은 모두 quality assurance.

**결론**: IA 구조는 견고. 추가 탭 필요성 낮음.


옵션 B: 모바일에서 아코디언 또는 드롭다운 메뉴
```tsx
// 768px 이하에서는 그룹만 보이고, 탭을 드롭다운으로 표시
@media (max-width: 768px) {

    </DropdownMenuContent>
  </DropdownMenu>
}
```

**권장**: 옵션 A (가로 스크롤)로 구현 → 사용자가 모든 탭명 한눈에 볼 수 있음.
