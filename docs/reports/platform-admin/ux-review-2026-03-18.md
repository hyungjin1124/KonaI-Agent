# UX 리뷰 — platform-admin — 2026-03-18

## 요약

총 이슈: 47개 (Critical: 5, High: 14, Medium: 19, Low: 9)
검토 컴포넌트: 19개

platform-admin은 정보 밀도와 기능 커버리지 측면에서 잘 설계된 운영 콘솔이다.
그러나 **프로덕션 준비도** 관점에서 여러 즉시 위험 항목이 발견되었다:
접근 제어 가드 부재, 파괴적 작업(테넌트 정지·API 키 폐기)에 대한 확인 다이얼로그 없음,
데이터 갱신 시점 불투명, 상태 변경 후 피드백 부재가 핵심 위험이다.
Part 3 구조 관점에서는 `UsageAlertTab.tsx`가 렌더링되지 않는 사용되지 않는 컴포넌트로 남아있고,
비용 관리와 빌링이 사용자 멘탈 모델과 맞지 않게 두 탭으로 분리된 문제도 발견되었다.

## Part 1: UX Checklist Findings

### Flow Analysis

#### 테넌트 관리 탭 (TenantManagementTab)

- Entry: 사이드바 "Platform Admin" → 기본값 테넌트 관리 탭
- Actions: 헬스카드/테이블 뷰 전환, 상태 필터, 검색, 테넌트 추가, 헬스카드 클릭 → 상세 패널, 상태 변경
- Exits: 없음 (단일 페이지 내 패널 확장)
- Issues: 상세 패널이 아래에 렌더링되어 카드 목록과 동시에 보이며, 닫기 버튼 없음

#### 활동 모니터링 탭 (ActivityMonitoringTab)

- Entry: "활동 모니터링" 탭 클릭
- Actions: 테넌트/기간 필터, CSV 내보내기, 트레이스 행 클릭 → 워터폴 패널
- Exits: 워터폴 패널 닫기(오버레이 클릭 또는 X)
- Issues: 필터가 상태에 연결되지 않음 (select onChange 핸들러 없음)

#### 비용 관리 탭 (CostManagementTab)

- Entry: "비용 관리" 탭 클릭
- Actions: CSV 내보내기, 차트 호버 툴팁
- Exits: 없음
- Issues: 완전히 읽기 전용. 기간 필터 없음. 예산 초과 경고 배너의 링크("알림 규칙을 확인하세요")가 클릭 불가 텍스트로만 구현됨

#### 알림 관리 탭 (AlertManagementTab)

- Entry: "알림 관리" 탭 클릭
- Actions: 규칙 토글, 규칙 추가/편집(모달), 이상감지 토글, "전체 이력 →" 버튼
- Exits: 편집 모달 닫기
- Issues: AlertRuleCard의 "편집" 버튼과 AlertManagementTab의 group-hover 편집 버튼이 중복. "전체 이력" 버튼이 미구현(핸들러 없음)

#### 과금/빌링 탭 (BillingTab)

- Entry: "과금/빌링" 탭 클릭
- Actions: 월 필터, 청구서 일괄 발행
- Exits: 없음
- Issues: 청구서 일괄 발행 버튼에 onClick 핸들러 없음

#### 감사 로그 탭 (PlatformAuditLogTab)

- Entry: "감사 로그" 탭 클릭
- Actions: 4개 필터 + 검색, 타임라인/테이블 토글, 페이지네이션, CSV/JSON 내보내기
- Exits: 없음
- Issues: 기간 필터(PERIOD_OPTIONS)가 상태에 바인딩되지 않음(value/onChange 없음). 이벤트 행 클릭 시 상세보기 없음

## Part 2: Scenario-Based Product Review

### S1: 새벽 2시 긴급 — B Corp 테넌트가 미결제로 API 남용 중

- **페르소나**: 플랫폼 운영자, 온콜 당직, 긴급 상황
- **현재 경로**:
  1. 사이드바 "Platform Admin" 클릭 → 테넌트 관리 탭 자동 로드
  2. 헬스카드에서 B Corp 카드 찾기 (6개 카드 중 시각적 탐색)
  3. B Corp 카드 클릭 → TenantDetailPanel이 카드 목록 아래에 렌더링
  4. 스크롤 다운 → 상세 패널 확인
  5. 상태 변경 버튼 클릭 → StatusChangeModal
  6. "정지" 선택 → 사유 선택 → "상태 변경 확인"
  7. 모달 닫힘 → 패널에서 상태 업데이트 확인
- **마찰점**:
  1. [위치 비직관] B Corp이 위험 상태임에도 헬스카드 그리드에서 특별한 정렬 우선순위 없이 5번째에 위치
    - 위치: `TenantManagementTab.tsx:154` — `filteredTenants.map`
    - 현재: 원본 배열 순서 그대로 렌더링
    - 문제: 위험/주의 테넌트가 맨 앞에 와야 긴급 대응 시간을 줄일 수 있음
  2. [화면 과밀] 카드 클릭 후 상세 패널이 카드 그리드 아래에 인라인으로 추가 렌더링
    - 위치: `TenantManagementTab.tsx:167`
    - 현재: `{selectedTenant && <TenantDetailPanel ... />}`가 카드 그리드 아래 단순 append
    - 문제: 카드 3열 × n행이 있을 때 패널까지 스크롤이 길어짐. 어떤 카드가 선택됐는지 시각적 연결 없음
  3. [피드백 부재] StatusChangeModal에서 확인 후 성공 토스트가 없음
    - 위치: `TenantDetailPanel.tsx:96-110`, `handleStatusConfirm`
    - 현재: `setStatusModalOpen(false)` 후 패널 상태만 업데이트
    - 문제: 운영자가 정지 처리가 실제로 적용됐는지 확인 불가. API 연동 환경에서 더 치명적
  4. [실수 복구 불가] 상태 변경 확인 버튼을 누르면 되돌리기 메커니즘 없음
    - 위치: `StatusChangeModal.tsx:159-170`
    - 현재: 확인 시 즉시 상태 변경
    - 문제: 실수로 Active 테넌트를 Suspended로 변경하면 즉시 서비스 중단
- **개선안**:
  1. 헬스 레벨 기준 정렬 (danger → warning → healthy)
    - 현재: 원본 순서 유지
    - 제안: `filterTenants` 함수에 기본 정렬 추가 또는 TenantManagementTab에서 useMemo 정렬
    - 대상 파일: `src/components/features/platform-admin/data/tenantData.ts` 또는 `TenantManagementTab.tsx`
    - effort: Low
  2. 선택된 테넌트 카드에 선택 표시 + 상세 패널을 오른쪽 슬라이드 패널로 변경
    - 제안: `fixed inset-y-0 right-0 w-[420px]` 슬라이드 패널 + 오버레이
    - 대상 파일: `TenantDetailPanel.tsx`, `TenantManagementTab.tsx`
    - effort: Medium
  3. StatusChangeModal onConfirm 후 toast 알림 추가
    - 대상 파일: `TenantManagementTab.tsx:handleUpdate`
    - effort: Low
- **빠진 기능**: 상태 변경 이력 표시 (언제, 누가, 왜 변경했는지 TenantDetailPanel에서 확인 불가)

### S2: 신규 테넌트 30개 계약 후 일괄 온보딩

- **페르소나**: 영업 담당자, 계약 완료 직후 온보딩, 긴급하지 않으나 실수 여유도 낮음
- **현재 경로**:
  1. "테넌트 추가" 버튼 클릭 → TenantCreateWizard 모달

  5. "다음" → Step 4: 태그, 메모, 샘플 에이전트
  6. "생성 완료" → 모달 닫힘
- **마찰점**:
  1. [피드백 부재] "생성 완료" 클릭 후 성공 toast나 생성된 테넌트로의 이동이 없음
    - 위치: `TenantManagementTab.tsx:39-76`, `handleCreate`
    - 현재: `setWizardOpen(false)` 후 배열 앞에 추가
    - 문제: 운영자가 실제로 생성됐는지 확인하려면 카드 목록에서 직접 찾아야 함
  2. [입력 유형 부적합] 계약 종료일 이전에 시작일을 설정할 수 있고 (역순 날짜), 검증 없음
    - 위치: `TenantCreateWizard.tsx:184-187`
