# UX Review Report — 2026-03-19

## Target

`src/components/features/skill-management/` 및 관련 라우트/타입 파일 전체

## Summary

스킬 관리 화면은 전체적으로 시각적 완성도가 높고, 카탈로그-활성 스킬-관리의 3탭 구조가 업무 모델에 부합한다. 그러나 **피드백 부재(토글/승인/정책 저장 시 성공 알림 없음)**, **스킬 삭제 기능 부재**, **관리 탭 내 승인 대기 건수가 대기 외 탭에서 비가시**, **업로드 위저드 파일 검증 미구현** 등 프로덕션 운영 시 반복적으로 마찰을 일으킬 이슈들이 발견됨. 특히 모든 상태 변경(토글, 승인, 정책 저장, 롤백)이 React 로컬 state에만 반영되고 API 연동/에러 처리/감사 로그가 전무하여, 실 운영 환경 배포 전 구조적 보완이 필수적이다.

## Part 1: UX Checklist Findings

### Flow Analysis

#### 카탈로그 탭 (Catalog)

- **Entry**: `/settings/skills` 직접 진입 또는 Sidebar Settings 드롭다운 > "Skill 관리" 클릭
- **Actions**: 검색, 카테고리 필터, 스킬 카드 클릭(상세 패널), 스킬 토글, 스킬 추가 버튼
- **Exits**: 상세 패널(Sheet) 오픈, 업로드 위저드(Dialog) 오픈
- **Issues**: 검색 초기화 버튼 없음, 카테고리 필터 + 검색어 조합 시 결과 건수 미표시

#### 활성 스킬 탭 (Active)

- **Entry**: 메인 탭 "활성 스킬" 클릭
- **Actions**: 토글 on/off, 업데이트 적용, 상세 패널 이동
- **Exits**: 상세 패널 오픈
- **Issues**: 비활성화 그룹 전체가 `opacity-60`으로 dimmed되어 있어 해당 그룹 내 인터랙션이 가능한지 시각적으로 불분명

#### 관리 > 조직 스킬 목록 (Admin > org-skills)

- **Entry**: "관리" 탭 > 서브탭 "조직 스킬 목록"
- **Actions**: 검색, 배포 정책 드롭다운 변경, 토글
- **Exits**: 없음 (스킬 카드 클릭으로 상세 이동 불가)
- **Issues**: 조직 스킬 목록에서 스킬 상세 패널로 이동하는 경로가 없음

#### 관리 > 정책 설정 (Admin > policy)

- **Entry**: "관리" 탭 > 서브탭 "정책 설정"
- **Actions**: 기본 정책 라디오 선택, 토글 설정 3종, 평가 통과율 숫자 입력, 저장
- **Exits**: 없음 (독립 설정 화면)
- **Issues**: 저장 성공 시 피드백 없음 (console.log만), 취소/초기화 버튼 없음

#### 관리 > 승인 요청 (Admin > approvals)

- **Entry**: "관리" 탭 > 서브탭 "승인 요청"
- **Actions**: 필터(전체/대기/승인/반려), 승인/반려 버튼, 검토 의견 입력
- **Exits**: 없음
- **Issues**: 승인/반려 후 피드백 없음, 확인 다이얼로그 없음

#### 스킬 상세 패널 (Detail Panel)

- **Entry**: 카탈로그 카드 클릭 또는 활성 스킬 리스트에서 ChevronRight 클릭
- **Actions**: 토글, 탭 전환(개요/평가/버전), 업데이트 적용, 롤백
- **Exits**: Sheet 닫기(X 또는 오버레이 클릭)
- **Issues**: 패널 재진입 시 이전 탭 상태(activeTab) 유지되지 않고 항상 'overview'로 초기화

## Part 2: Scenario-Based Product Review

### S1: 신규 입사자가 처음으로 필요한 스킬을 찾아 활성화한다

- **페르소나**: 신규 입사자 (기술 수준 낮음), 최초 1회 사용
- **현재 경로**:
  1. Sidebar > Settings 아이콘 클릭 > 드롭다운에서 "Skill 관리" 클릭
  2. 카탈로그 탭 진입 (기본값)
  3. 12개 카드가 3열 그리드로 표시됨
  4. 카테고리 필터 또는 검색으로 원하는 스킬 찾기
  5. 카드 우하단 Switch 토글
- **마찰점**:
  1. [위치 비직관] Settings 아이콘이 어떤 기능인지 모름. 아이콘만 있고 라벨이 없는 수평 네비게이션에서 톱니바퀴가 스킬 관리를 포함한다는 것을 신규 사용자가 인지하기 어려움
    - 위치: `Sidebar.tsx:100`
    - 현재: 아이콘만 표시, hover 시에도 tooltip은 "Settings" (영문)
    - 문제: 스킬 관리가 Settings 하위에 있다는 IA가 직관적이지 않음
  2. [용어 난해] 카테고리 필터("문서 작성", "데이터 분석" 등)와 소스 배지("플랫폼", "조직", "내가 추가")의 차이를 신규 사용자가 바로 이해하기 어려움
    - 위치: `CategoryFilterBar.tsx`, `SkillSourceBadge.tsx`
    - 현재: 두 분류 체계가 설명 없이 병존
    - 문제: "플랫폼 스킬"과 "조직 스킬"의 차이를 모르는 사람이 대다수
  3. [피드백 부재] 스킬을 토글 ON 한 후 아무런 피드백이 없음. Switch 색상만 바뀜
    - 위치: `SkillManagementView.tsx:53-59` (handleToggle)
    - 현재: state만 업데이트, UI 피드백 없음
    - 문제: "정말 활성화된 건가?" 의문
- **개선안**:
  1. 토글 성공 시 toast 메시지: `"{스킬명}" 활성화되었습니다`
    - 현재: state 변경만
    - 제안: `NotificationContext` 또는 sonner toast 연동
    - 대상 파일: `SkillManagementView.tsx`
    - effort: Low
  2. 카탈로그 상단에 "AI 에이전트가 사용할 수 있는 스킬을 선택하세요. 활성화하면 채팅에서 바로 사용됩니다." 같은 온보딩 안내 문구 추가
    - 현재: 헤더에 "에이전트가 사용할 수 있는 스킬을 관리하고 설정합니다." 한 줄만 존재
    - 제안: 최초 방문 시 배너 또는 카드 형태 가이드
    - 대상 파일: `SkillManagementView.tsx`
    - effort: Medium
- **빠진 기능**: 추천 스킬 (신규 사용자용 "시작하기" 큐레이션)

### S2: 팀 리더가 팀원에게 필수 스킬을 배포하려 한다

- **페르소나**: 팀 리더 (기술 수준 중간), 월 1~2회
- **현재 경로**:
  1. 관리 탭 > 조직 스킬 목록 서브탭
  2. 배포 정책 드롭다운에서 "필수"로 변경
  3. 끝 (저장 없이 즉시 반영)
- **마찰점**:
  1. [피드백 부재] 정책을 "필수"로 변경해도 피드백 없음. 잘 변경되었는지 확인할 방법 없음
    - 위치: `OrgSkillManagementPanel.tsx:98-108`
    - 현재: select 변경 > `onPolicyChange` 호출 > state 업데이트만
    - 문제: 비즈니스 임팩트가 큰 변경(필수 배포)인데 확인 단계가 없음
  2. [실수 복구 불가] "필수" → "차단"으로 실수로 변경해도 undo 없음
    - 위치: `OrgSkillManagementPanel.tsx:100`
    - 현재: 즉시 반영
    - 문제: 전사 사용 중인 스킬이 순간적으로 차단될 위험
  3. [탭 간 단절] "조직 스킬 목록"에서 변경한 정책이 "카탈로그" 탭의 정책 배지에 반영되지만, 사용자는 탭을 전환해야 확인 가능
    - 위치: `SkillCard.tsx:23` (POLICY_LABEL), `OrgSkillManagementPanel.tsx:98-108`
    - 현재: 같은 skills state를 공유하므로 데이터는 동기화됨
    - 문제: 변경의 영향 범위(예: "42명이 사용 중인 스킬을 차단합니다")가 안 보임
- **개선안**:
  1. "필수" 또는 "차단"으로 변경 시 확인 다이얼로그: "이 스킬은 현재 {n}명이 사용 중입니다. 정말 [필수/차단]으로 변경하시겠습니까?"
    - 현재: 즉시 반영
    - 제안: `confirm-dialog.tsx` 활용
    - 대상 파일: `OrgSkillManagementPanel.tsx`
    - effort: Medium
  2. 영향 받는 사용자 수를 드롭다운 옆에 표시
    - 현재: 사용자 수가 데이터에 있지만(`activeUserCount`) 조직 스킬 목록에서 미표시
    - 제안: 스킬 정보 영역에 `{n}명 사용 중` 추가
    - 대상 파일: `OrgSkillManagementPanel.tsx:78-88`
    - effort: Low
- **빠진 기능**: 정책 변경 이력(감사 로그), 변경 전 영향 범위 미리보기

### S3: 관리자가 긴급하게 승인 요청을 처리한다

- **페르소나**: 플랫폼 관리자 (기술 수준 높음), 긴급 상황
- **현재 경로**:

  5. 대기 중인 카드 확인 > 검토 의견 입력 > 승인 또는 반려 클릭
- **마찰점**:

- **현재 탭/섹션 구조**:
  - L1 탭: 카탈로그 | 활성 스킬 | 관리
  - L2 서브탭 (관리 내): 조직 스킬 목록 | 정책 설정 | 승인 요청
  - 별도 패널: 스킬 상세(Sheet), 업로드 위저드(Dialog)
- **사용자 업무 모델과의 일치도**:
  - **일치하는 부분**: "카탈로그에서 골라서 활성화한다"는 앱스토어 패러다임이 잘 반영됨
  - **불일치 1**: "활성 스킬" 탭이 카탈로그의 필터 뷰(`isEnabled === true`)와 기능적으로 거의 동일. 사용자 입장에서는 "내가 켠 스킬"을 카탈로그 안에서 필터로 볼 수도 있음. 별도 탭의 존재 이유가 약함
  - **불일치 2**: "관리" 탭 내 "조직 스킬 목록"과 카탈로그의 차이가 불명확. 조직 스킬 목록은 카탈로그 + 정책 관리가 합쳐진 뷰인데, 같은 스킬 데이터를 다른 방식으로 보여주는 것이 혼란을 줄 수 있음
  - **불일치 3**: 상세 패널에서 "평가 결과 확인 -> 정책 변경 결정"이 하나의 흐름인데, 두 화면(상세 패널 vs 관리 탭)으로 분산됨
- **제안**:
  - "활성 스킬" 탭을 카탈로그 내 "활성만 보기" 필터로 흡수 검토 (탭 수 축소)
  - 또는 "활성 스킬" 탭을 "내 스킬"로 리네이밍하여 사용자의 개인화된 스킬 설정 공간으로 차별화
  - 상세 패널에 관리자용 정책 변경 드롭다운 추가 (S9 개선안 참조)

### 복잡도 관리

- **현재 한 화면에 노출되는 개념 수**: 약 12개 (스킬, 카테고리, 소스, 배포 정책, 평가 통과율, 변동성, 기준 대비, 버전, 업데이트, MCP, 대상 범위, 태그)
- **Progressive Disclosure 적용이 필요한 영역**:
  - 상세 패널: 이미 탭으로 분리되어 있어 적절함
  - 조직 스킬 목록: 정렬/필터 옵션을 "고급 필터" 접기/펼치기로 분리
  - 정책 설정: "평가 통과율 기준"은 고급 설정으로 분리 가능
- **사용자 수준별 뷰 분리**: 현재 `IS_ADMIN` 하드코딩으로 "관리" 탭 전체를 보이거나 숨기는 방식. 적절한 접근이나, 실제로는 동적 권한 체크 필요

### 화면 간 관계

- **선후 관계**:
  - 에이전트 설정(`/settings/agent-config`)에서 어떤 에이전트를 설정 -> 스킬 관리에서 해당 에이전트가 사용할 스킬 활성화 -> 채팅(`/chat`)에서 실제 사용
  - 현재 이 연결 고리가 UI에서 전혀 보이지 않음
- **설정값 영향 범위 가시성**:
  - 정책 설정에서 "개인 스킬 업로드 허용"을 끄면, 카탈로그의 "스킬 추가" 버튼이 영향 받아야 하지만, 현재 두 기능이 연동되지 않음
  - 배포 정책 "차단"으로 변경 시 영향 받는 사용자 수가 안 보임

### 구조 변경 제안 (요약)

1. **활성 스킬 탭 차별화**: "내 스킬 + 업데이트 센터"로 리포지셔닝. 단순 on/off 리스트에서 벗어나, 업데이트 알림/변경 이력/개인 설정의 허브로 발전 — 영향 범위: `ActiveSkillList.tsx`, `SkillManagementView.tsx` 탭 구조
2. **상세 패널에 관리자 액션 통합**: 평가 확인 -> 정책 변경 -> 차단의 워크플로를 하나의 패널에서 완결 — 영향 범위: `SkillDetailPanel.tsx`
3. **관리 탭 뱃지 클릭 시 승인 서브탭 자동 선택**: 긴급 대응 경로 단축 — 영향 범위: `SkillManagementView.tsx`

## 긍정적 관찰

1. **시각적 완성도 높음**: 카드 UI, 배지 시스템(EvalQualityBadge, SkillSourceBadge), 색상 체계가 일관되고 세련됨. 특히 평가 통과율에 따른 4단계 색상 구분(green > blue > amber > red)이 직관적
2. **컴포넌트 분리 적절**: 12개 컴포넌트가 각각 단일 책임을 가지며, props 인터페이스가 명확. 재사용성이 높음
3. **타입 안전성 확보**: `skill-management.types.ts`에 모든 도메인 타입이 엄격하게 정의됨. union type 활용 우수
4. **롤백 확인 다이얼로그**: 유일하게 확인 단계가 있는 위험 동작. 현재-대상 버전 비교, 안심 문구("기록은 유지됩니다") 포함
5. **드래그앤드롭 업로드**: 업로드 위저드의 DnD 인터랙션이 자연스러움. 드래그 시 시각 피드백(border color 변경, 아이콘 교체)
6. **카테고리 필터 카운트**: 필터 버튼에 건수가 표시되어 데이터 분포를 즉시 파악 가능
7. **업데이트 알림 시스템**: pendingUpdate의 Bell 아이콘 + 상세 패널 배너 + 활성 목록 뱃지 등 다층적 알림 구조
8. **정책 설정 조건부 표시**: `allowPersonalUpload` 토글에 따라 "관리자 승인 필요" 옵션이 조건부로 노출되는 Progressive Disclosure 패턴
9. **lazy loading 적용**: 페이지 레벨에서 `React.lazy` + `Suspense` 적용으로 초기 번들 크기 최적화
10. **Mock 데이터 현실감**: 12개 스킬의 메타데이터가 실제 업무 시나리오를 반영하여 데모/프로토타이핑에 충분한 수준
