## Part 1: UX Checklist Findings

### Flow Analysis

#### 카탈로그 탭 (Catalog) — 개선됨

- Entry: `/settings/skills` 접근 시 기본 탭
- Actions: 검색, 정렬 + **정렬 방향 토글**(신규), 카테고리 필터, Source 필터, 페이지네이션(신규), 카드 클릭 → 상세 패널, 토글 활성화/비활성화
- Exits: 상세 패널(Sheet) 열기, 활성 스킬 탭 이동, 관리 탭 이동
- **Phase 1 이슈 해소**: ✅ P1-8(정렬 방향 토글) 구현됨, ✅ ST-6(페이지네이션) 추가됨

#### 평가 결과 탭 (Eval) — 신규 서브탭 추가

- Entry: 상세 패널 > "평가 결과" 탭
- Actions: **Outputs 서브탭** (평가 케이스별 상세) ← **NEW**, **Benchmark 서브탭** (성능 비교 시각화) ← **NEW**
- Exits: 다른 메인 탭, 상세 패널 닫기
- Issues: 평가 케이스(currentIdx) 네비게이션 중 서브탭 전환 시 상태가 유지되나, 메인 탭 복귀 후 재진입 시 **Outputs 기본값으로 리셋**됨 (경미)

#### 활성 스킬 탭 (Active) — 미변경

- Entry: 메인 탭에서 "활성 스킬" 클릭
- Actions: 활성/비활성 그룹 확인, 토글 변경, 업데이트 적용, 상세 패널 열기
- Exits: 카탈로그로 이동 CTA (빈 상태일 때), 상세 패널
- **Phase 1 이슈 유지**: ⚠️ 검색/필터 기능 없음 (원안 유지, 우선순위 낮음)

## Part 2: Scenario-Based Product Review

### S1: 비개발자 직원이 업무에 필요한 스킬을 찾아서 활성화

**페르소나**: 일반 직원(기획자, 마케터), 비개발 직군, 월 1-2회, 여유롭게

**현재 경로** (Phase 1과 동일):
  1. Sidebar > Settings > Skill 관리 클릭 → `/settings/skills` 진입
  2. 카탈로그 탭(기본 선택됨)에서 카테고리 필터 클릭 (예: "콘텐츠 제작")
  3. 그리드에서 원하는 카드 발견, 카드 클릭
  4. SkillDetailPanel(Sheet) 개요 탭에서 설명, 평가 통과율, 태그 확인
  5. Switch 토글 ON 클릭 → toast "활성화되었습니다"
  6. Sheet 닫기 → 카탈로그에서 카드의 Switch가 ON으로 변경됨

**마찰점**:
  1. [용어 난해] EvalQualityBadge의 "85%" — 비개발자에게 불명확한 상태 유지
     - 위치: `src/components/features/skill-management/components/EvalQualityBadge.tsx`
     - 현재: 숫자만 표시, ± 기호는 있으나 tooltip 메시지 불명확
     - 문제: "평가 통과율"이라는 라벨이 전무; "±" 기호도 비개발자에겐 혼동
     - **Phase 1 이슈 유지**: ⚠️
  2. [위치 비직관] `mandatory` 정책 스킬의 Switch disabled 이유 불명확
     - 현재: `disabled={isMandatory || isBlocked}` → 회색 처리, "필수" 배지만 표시
     - 문제: "왜 토글을 끌 수 없는지" 설명 부재
     - **Phase 1 이슈 유지**: ⚠️
  3. [신규 마찰점] "평가 통과율 기준" 정책의 영향이 사용자 입장에선 불명확
     - 위치: SkillPolicyPanel(관리 탭) → 설정 후 카탈로그 복귀 시 아무 피드백 없음
     - 현재: 정책 저장 시 toast "정책 설정이 저장되었습니다" (일반 사용자는 관리 탭 접근 불가)
     - 문제: 개발자가 스킬 업로드 후 비활성화 상태인데, 그 이유(평가 기준 미달)를 알 수 없음
     - 예: evalMinPassRate=70%로 설정 후, 평가 통과율 60%인 스킬을 활성화하려 하면 경고만 표시되고, **실제 차단되지 않음**

**개선안**:
  1. EvalQualityBadge에 라벨 추가 ("평가 통과율") + tooltip 개선
     - 현재: 숫자만, tooltip = "불안정 (변동성 높음)"
     - 제안: 숫자 좌측에 "평가:" 라벨 + tooltip = "이 스킬의 평가 통과율입니다. 70% 이상이 권장됩니다."
     - 대상 파일: `src/components/features/skill-management/components/EvalQualityBadge.tsx`
     - effort: Low
  2. Mandatory/Blocked 스킬의 Switch 근처에 설명 추가
     - 현재: "필수" / "차단됨" 라벨만
     - 제안: Tooltip "이 정책은 관리자가 설정했습니다." + 클릭 불가 시각화 강화
     - 대상 파일: `src/components/features/skill-management/components/SkillCard.tsx:96-97`
     - effort: Low
  3. **정책-동작 연동**: 활성화 시 evalMinPassRate 위반 시 **차단** (현재는 경고만)
     - 현재: `handleToggle`에서 경고만 표시 (`toast.warning`)
     - 제안: `if (evalMinPassRate 미달) { toast.warning + return; }` → 상태 변경 안 함
     - 대상 파일: `src/components/features/skill-management/SkillManagementView.tsx:102-120`
     - effort: Low

**빠진 기능**:
  - 정책 기준 미달 스킬의 **사용자 대면 경고 또는 차단** (현재 toast 경고도 약함)
  - 정책 변경 후 **영향받는 스킬 자동 비활성화** (현재 무시)

**필드 감사** (업로드 시 생성되는 스킬):

### S2: 에이전트 개발자가 업로드한 스킬의 평가 결과를 상세 검토

**페르소나**: 에이전트 개발자 / 팀 리더, 상-중 기술 수준, 주 1-2회, 긴박한 디버깅 상황

**현재 경로** (Sprint 1 신규):
  1. 카탈로그에서 개인 스킬 찾아 카드 클릭
  2. SkillDetailPanel 열림 → "평가 결과" 탭 클릭
  3. **"Outputs" 서브탭** (기본): 평가 케이스 커서(1/n) + 프롬프트 + With/Without 비교 + 등급 확인
  4. 이전/다음 버튼으로 케이스 네비게이션
  5. "Benchmark" 서브탭 클릭: 성능 비교 차트 + 통과율/응답시간/토큰 비교
  6. 성능 분석 노트 확인 후 결론 도출

**마찰점**:
  1. [데이터 탐색 단절] Outputs 케이스 탐색 중 Benchmark로 이동 후 복귀하면 **케이스 인덱스가 첫 번째로 리셋**
     - 위치: `src/components/features/skill-management/components/SkillDetailPanel.tsx:56`, `OutputsTab.tsx:12`
     - 현재: OutputsTab에서 로컬 state `currentIdx`를 관리하되, 서브탭 전환 시 마운트/언마운트되어 리셋
     - 문제: "5번째 케이스를 확인하던 중 Benchmark를 보고 돌아오니 1번째가 되어 있음" → UX 좌절감
     - 개발자가 케이스 간 비교 패턴을 분석하는 중인데 흐름 단절
  2. [시각화 밀도] BenchmarkTab의 도넛 차트(2개) + StatBar(3개) → 한눈에 비교 어려움
     - 위치: `src/components/features/skill-management/components/BenchmarkTab.tsx`
     - 현재: With/Without 도넛 나란히, 하단에 성능 바 3개 → 세로 스크롤 필요
     - 문제: 통과율/응답시간 상충(response time 증가하면서 통과율은 향상?)을 한눈에 파악 어려움
     - 제안: 도넛 차트 하단에 "주요 발견" 요약 (예: "+15%p 통과율, -2.3s 응답") 추가

**개선안**:
  1. OutputsTab의 `currentIdx` 상태를 부모(SkillDetailPanel)로 올리기
     - 현재: OutputsTab 내부 state → 서브탭 전환 시 리셋
     - 제안: `evalSubTab` 상태와 함께 `currentEvalIdx` 상태 추가 → SkillDetailPanel에서 관리
     - 대상 파일:
       - `src/components/features/skill-management/components/SkillDetailPanel.tsx` (상태 추가)
       - `src/components/features/skill-management/components/OutputsTab.tsx` (prop으로 전환)
     - effort: Medium
  2. BenchmarkTab에 "주요 발견" 요약 섹션 추가
     - 현재: 도넛 + 바 시각화만
     - 제안:
       ```

       + 통과율: +15%p (With: 85% → Without: 70%)
       − 응답 시간: +1.5s (With: 3.2s → Without: 1.7s)  [성능 트레이드오프]
       ```
     - 대상 파일: `src/components/features/skill-management/components/BenchmarkTab.tsx:130-180`
     - effort: Low
  3. 형식화 등급(FormalGradesAccordion) 펼침 상태 유지
     - 현재: 각 Accordion은 독립적으로 열고 닫힘 (상태 유지됨 ✅)
     - 제안: 현 상태 유지 (문제 없음)

| 항목 | 현 상태 | 평가 |
|------|--------|------|
| 데이터 출처 | mock 데이터, 출처 미표시 | ⚠️ API 전환 시 "출처: platform" 등 필요 |
| 마지막 갱신 시점 | `lastUpdated` 필드는 있으나 UI에 미표시 | ⚠️ 상세 패널에 "마지막 업데이트: YYYY-MM-DD" 표시 필요 |
| 실시간 vs 집계 데이터 | 구분 없음 (mock) | ⚠️ API 전환 시 "집계 데이터 (마지막 갱신: 1시간 전)" 명시 필요 |
| 숫자가 0일 때 | "평가 미실행" vs "실제 0" 구분됨 (null 사용) | ✅ 좋음 |

**권장**:
- evalLastRun 필드를 상세 패널 평가 요약에 표시
- mock → API 전환 시 데이터 신뢰도 배지 추가

### 관점 2: 규모 확장 대응 (Scalability)

| UI 요소 | 현재 규모 | 예상 운영 규모 | 문제점 | 대응 |
|---------|---------|-------------|--------|------|
| 카탈로그 그리드 | ~15개 (mock) | 100+ | 페이지네이션 필요 | ✅ 추가됨 (12개/page) |
| 평가 결과 네비게이션 | ~5개 케이스 | 50+ | 선택기 또는 검색 필요 | ⚠️ 미구현 (커서만 제공) |
| 조직 스킬 테이블 | ~10개 | 100+ | 정렬/페이지네이션/검색 필요 | ⚠️ 미구현 |
| 활성 스킬 목록 | ~10개 | 100+ | 검색 필요 | ⚠️ 미구현 |
| 정책 영향도 계산 | 스킬 100개 | 1000개+ | O(n) 복잡도 → 성능 저하 | ⚠️ 계산 최적화 필요 |

**권장**:
- 평가 케이스 50+일 때 **드롭다운 또는 검색** 추가
- 조직 스킬 테이블에 **서버 사이드 정렬/페이지네이션** 구현

### 관점 3: 오류/엣지 케이스 대응

| 상황 | 현 처리 | 위험도 | 권장 |
|------|--------|--------|------|
| 파일 업로드 실패 | 검증 에러만 표시 (네트워크 에러 미처리) | 중 | API 전환 시 재시도 버튼 추가 |
| 정책 저장 중 네트워크 끊김 | 처리 없음 (mock이라 불필요) | 중 | loading state + 타임아웃 처리 필요 |

| 평가 데이터 로딩 중 탭 전환 | 상태 유지, 로딩 표시 없음 (mock) | 낮음 | skeleton 로딩 추가 |

### 관점 5: 보안과 접근 제어

| 항목 | 현 상태 | 위험도 | 권장 |
|------|--------|--------|------|
| 프론트엔드 관리자 가드 | IS_ADMIN = process.env.NEXT_PUBLIC_SKILL_ADMIN | 🔴 **높음** | 백엔드 인증 토큰 기반으로 전환 필수 |
