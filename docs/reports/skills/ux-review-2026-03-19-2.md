## Target

`src/components/features/skill-management/` 및 `src/app/settings/skills/page.tsx`
(총 14개 파일: SkillManagementView.tsx, SkillCard.tsx, SkillDetailPanel.tsx, ActiveSkillList.tsx, SkillUploadWizard.tsx, SkillApprovalQueue.tsx, SkillPolicyPanel.tsx, OrgSkillManagementPanel.tsx, EvalQualityBadge.tsx, SkillSourceBadge.tsx, VersionHistoryTable.tsx, RollbackConfirmModal.tsx, CategoryFilterBar.tsx, skillMockData.ts)

## Summary

스킬 관리 화면은 전반적으로 잘 구조화된 Phase 1 구현이다. 3계층 탭(카탈로그/활성/관리), 카드 기반 카탈로그, Sheet 상세 패널, 업로드 위자드 등 핵심 플로우가 갖춰져 있다. 가장 큰 우려는 **(1) 환경 변수 기반 관리자 권한 구현(프로덕션 보안 위험)**, **(2) 폼 필드의 유령 필드 문제(tags, teamIds 등 미수집 또는 미표시)**, **(3) 정책 설정(SkillPolicyPanel)이 실제 스킬 동작에 연결되지 않는 단절** 세 가지이다.

## Part 1: UX Checklist Findings

### Flow Analysis

#### 카탈로그 탭 (Catalog)

- Entry: `/settings/skills` 접근 시 기본 탭
- Actions: 스킬 검색, 카테고리 필터, 정렬, 카드 클릭 -> 상세 패널, 토글 활성화/비활성화, "스킬 추가" 버튼
- Exits: 상세 패널(Sheet) 열기, 활성 스킬 탭 이동, 관리 탭 이동
- Issues: 카드 클릭과 ChevronRight 아이콘 클릭이 동일 동작으로 중복; 정렬 방향(오름차순/내림차순) 제어 불가

#### 활성 스킬 탭 (Active)

- Entry: 메인 탭에서 "활성 스킬" 클릭
- Actions: 활성/비활성 그룹 확인, 토글 변경, 업데이트 적용, 상세 패널 열기
- Exits: 카탈로그로 이동 CTA (빈 상태일 때), 상세 패널
- Issues: 활성 스킬 탭에 검색/필터 기능 없음 — 활성 스킬이 20개 이상이면 원하는 스킬 찾기 어려움

#### 관리 탭 (Admin)

- Entry: 메인 탭에서 "관리" 클릭 (관리자만 표시)
- Actions: 조직 스킬 관리, 정책 설정, 승인 요청 처리
- Exits: 상세 패널, 각 서브탭 간 이동
- Issues: 정책 설정 저장 후 피드백은 toast로 제공되지만, 실제 스킬 동작에 반영되지 않음(SkillPolicyPanel.onSave 콜백이 설정값을 skills 상태에 적용하지 않음)

## Part 2: Scenario-Based Product Review

### S1: 비개발자 직원이 업무에 필요한 스킬을 찾아서 활성화

- **페르소나**: 일반 직원(기획자, 마케터), 비개발 직군, 월 1-2회, 여유롭게
- **현재 경로**:
  1. Sidebar > Settings > Skill 관리 클릭 -> `/settings/skills` 진입
  2. 카탈로그 탭(기본 선택됨)에서 카테고리 필터 탭 클릭 (예: "콘텐츠 제작")
  3. 그리드에서 원하는 카드 발견, 카드 클릭
  4. SkillDetailPanel(Sheet)에서 설명, 평가 통과율, 태그 확인
  5. Switch 토글 ON 클릭 -> toast "활성화되었습니다"
  6. Sheet 닫기 -> 카탈로그에서 카드의 Switch가 ON으로 변경됨
- **마찰점**:
  1. [용어 난해] EvalQualityBadge의 "85%"가 무엇을 의미하는지 비개발자에겐 불명확
    - 위치: `src/components/features/skill-management/components/EvalQualityBadge.tsx:46-48`
    - 현재: 숫자만 표시 (예: "85%"), `±` 기호 있으나 tooltip이 "불안정 (변동성 높음)"만 표시
    - 문제: "평가 통과율"이라는 라벨 없이 숫자만 보면 "무엇의 85%"인지 알 수 없음
  2. [위치 비직관] `mandatory` 정책의 스킬은 Switch가 disabled인데, 그 이유가 "필수" 배지를 읽어야만 이해됨
    - 위치: `src/components/features/skill-management/components/SkillCard.tsx:96-97`
    - 현재: `disabled={isMandatory || isBlocked}` — 시각적으로 회색 처리만 됨
    - 문제: 왜 토글을 끌 수 없는지 설명 없음
  3. [기능 부재] 스킬 활성화 후 "활성 스킬" 탭으로 자동 이동하지 않음 — 사용자가 활성화된 것을 확인하려면 직접 탭 전환 필요
    - 위치: `src/components/features/skill-management/SkillManagementView.tsx:81-90`
    - 현재: handleToggle은 toast만 표시
    - 문제: 활성화 확인 경로가 불명확
- **개선안**:
  1. EvalQualityBadge에 tooltip 추가: "평가 통과율 85% — 테스트 시나리오의 85%를 통과했습니다"
    - 현재: 숫자만 렌더링
    - 제안: `<Tooltip>` 래핑하여 설명 텍스트 추가
    - 대상 파일: `src/components/features/skill-management/components/EvalQualityBadge.tsx`
    - effort: Low
  2. 비활성화된 Switch 아래 또는 옆에 "필수 스킬 (해제 불가)" 또는 "차단됨" 미니 라벨 추가
    - 현재: disabled 스타일만 적용
    - 제안: `{isMandatory && <span className="text-xs text-gray-400">필수 — 해제 불가</span>}`
    - 대상 파일: `src/components/features/skill-management/components/SkillCard.tsx:93-99`
    - effort: Low
  3. 카탈로그 카드에서 토글 활성화 시 "활성 스킬 탭에서 확인" 안내 또는 토글 옆 체크 아이콘 추가
    - 대상 파일: `src/components/features/skill-management/SkillManagementView.tsx`
    - effort: Low
- **빠진 기능**: "추천 스킬" 섹션 (design 문서에 명시되어 있으나 미구현)

### S2: 에이전트 개발자가 직접 만든 스킬을 업로드

- **페르소나**: 에이전트 개발자, 기술 수준 상, 주 1회, 프로젝트 진행 중
- **현재 경로**:
  1. 헤더의 "스킬 추가" 버튼 클릭
  2. SkillUploadWizard 다이얼로그 열림 (step: 'upload')
  3. .zip 또는 .skill 파일 드래그앤드롭 또는 클릭 업로드
  4. 파일 검증 (유형, 크기) -> 성공 시 step: 'confirm'
  5. 스킬 이름(파일명에서 자동 추출), 설명(선택), 카테고리 입력
  6. "스킬 추가" 클릭 -> 스킬 생성, 카탈로그 탭으로 이동, toast 표시
- **마찰점**:
  1. [유령 필드/역방향] 업로드 위자드에서 `tags` 입력 필드가 없음 — 생성된 스킬의 tags는 `[]`로 설정됨. 카탈로그 카드에 태그 영역이 있으나 빈 상태
    - 위치: `src/components/features/skill-management/SkillManagementView.tsx:130`
    - 현재: `tags: []` 하드코딩
    - 문제: 태그 없는 스킬은 태그 기반 검색에서 발견 불가
  2. [자동 채움 불투명] `source`가 자동으로 `'personal'`로 설정되는데, 사용자에게 이 정보가 업로드 폼에서 보이지 않음
    - 위치: `src/components/features/skill-management/SkillManagementView.tsx:128`
    - 현재: 자동 설정, 업로드 위자드에 표시 없음
    - 문제: 조직 스킬로 등록하고 싶은 관리자도 같은 위자드를 사용할 수밖에 없으며, 등록 후 source 변경 불가
  3. [기능 부재] 업로드 후 스킬이 `isEnabled: false`로 생성되는데, 바로 활성화하는 옵션 없음
    - 위치: `src/components/features/skill-management/SkillManagementView.tsx:127`
    - 현재: 항상 비활성 상태로 생성
    - 문제: 업로드 직후 테스트하려면 카탈로그에서 찾아서 토글해야 함
  4. [피드백 부재] 파일의 SKILL.md 존재 여부와 YAML frontmatter 유효성이 실제로 검증되지 않음 — UI에 "요구사항"으로 안내하지만 실제 검증 로직 없음
    - 위치: `src/components/features/skill-management/components/SkillUploadWizard.tsx:156-166`
    - 현재: 안내 텍스트만 존재, validateFile()은 확장자와 크기만 검증
    - 문제: 잘못된 구조의 파일이 그대로 등록될 수 있음
- **개선안**:
  1. 업로드 위자드 confirm 단계에 태그 입력 필드 추가 (comma-separated 또는 chip input)

## Part 3: 서비스 기획 관점 구조 리뷰

### 정보 구조 적합성

- **현재 탭/섹션 구조**:
  - 메인 탭 3개: 카탈로그 | 활성 스킬 | 관리(관리자 전용)
  - 관리 서브탭 3개: 조직 스킬 목록 | 정책 설정 | 승인 요청
  - 상세 패널 탭 3개: 개요 | 평가 결과 | 버전 이력
- **사용자 업무 모델과의 일치도**: 대체로 일치함
  - "스킬을 찾아서 켜기" (카탈로그 + 활성 스킬) — 일반 사용자의 핵심 플로우에 맞음
  - "스킬을 관리하기" (관리 탭) — 관리자의 역할에 맞음
  - **불일치 1**: "활성 스킬" 탭이 독립적으로 존재하는 가치가 모호함. 카탈로그에서 이미 토글로 활성/비활성을 관리할 수 있고, 활성 스킬 탭은 "활성화된 것만 모아 보기"인데, 카탈로그에 "활성 스킬만 보기" 필터를 추가하면 같은 기능을 할 수 있음. 다만, 활성 스킬 탭은 리스트 뷰로 밀도 높은 관리에 적합하므로 현재 구조도 합리적
  - **불일치 2**: "조직 스킬 목록"(관리 서브탭)과 "카탈로그"(메인 탭)가 같은 스킬 데이터를 다른 뷰로 보여줌 — 관리자가 두 곳을 오가며 혼란을 느낄 수 있음
- **제안**: 현재 3탭 구조 유지하되, 카탈로그에 "활성 스킬만 보기" 필터를 추가하여 활성 탭의 핵심 기능을 카탈로그에서도 수행 가능하게 하면 점진적으로 활성 탭을 카탈로그의 프리셋 필터로 흡수 가능

### 복잡도 관리

- **현재 한 화면에 노출되는 개념 수**: 메인 탭 3개 + 관리 서브탭 3개 + 상세 패널 탭 3개 = 최대 9개 네비게이션 포인트. 카탈로그에서 동시 노출되는 정보: 검색, 정렬, 카테고리 필터, 카드 그리드(카드당 6개 정보: 제목, 설명, 출처, 정책, 태그, 평가, 토글), 페이지네이션 = **적정 수준**
- **Progressive Disclosure 적용이 필요한 영역**:
  - 관리 탭: 현재 3개 서브탭으로 잘 분리됨 — 적정
  - 상세 패널: 3탭(개요/평가/버전)으로 잘 분리됨 — 적정
  - **개선 필요**: 카탈로그 카드에서 태그가 3개까지만 표시되는 것은 좋은 Progressive Disclosure
- **사용자 수준별 뷰 분리가 필요한가**: 현재 IS_ADMIN 환경 변수로 "관리" 탭 전체를 숨기는 방식. 이는 적절한 접근이나, 상세 패널 내 정책 변경 드롭다운도 isAdmin prop으로 제어되므로 두 레벨에서 동시 제어 — **적정**

### 화면 간 관계

- **선후 관계**: 이 화면은 독립적으로 동작 — 선후 의존성 낮음. 다만 정책 설정이 스킬 활성화에 영향을 미치는 구조여야 하는데 현재 단절됨
- **설정값 영향 범위 가시성**:
  - SkillPolicyPanel에서 설정한 `defaultPolicy`가 신규 스킬 생성 시 적용되어야 하나 **연결 안 됨**
  - SkillPolicyPanel에서 설정한 `evalMinPassRate`가 스킬 활성화 시 검증에 사용되어야 하나 **연결 안 됨**
  - OrgSkillManagementPanel에서 변경한 개별 정책은 카탈로그 카드의 정책 배지에 **즉시 반영됨** (동일 skills 상태 공유)
- **이 화면의 데이터를 외부로 내보내야 하는가**: 관리자는 감사 목적으로 스킬 목록/정책/승인 이력을 CSV 등으로 내보내야 할 수 있음 — 현재 **내보내기 기능 없음**
