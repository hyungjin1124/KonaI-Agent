## 요약

스킬 관리 화면은 **두 개의 독립적인 뷰 시스템**(레거시 `SkillManagementView` + 신규 `SkillsPageView`)이 공존하며, 신규 시스템(`/skills` 라우트)이 기획 문서(v4)를 정확히 반영하고 있다. 사용자 보고 이슈(여백 과다, 패널 깨짐, 활성화 토글 문제) 모두 확인되었으며, 핵심 원인은 (1) 패널 열림 시 테이블 컬럼 collapse 로직의 `w-0 + opacity-0` 처리가 레이아웃 잔상을 남기는 점, (2) Switch 토글의 이벤트 핸들링 이중 바인딩, (3) `TeamSkillsTab`의 전체 뷰포트 높이 강제(`calc(100vh - 64px)`)로 인한 여백 문제이다.

총 **47건** 이슈 발견: 체크리스트 15건, 시나리오 20건, 구조 리뷰 5건, 프로덕션 7건. 프로덕션 즉시 위험 3건, Quick Win 12건.

## Part 1: UX 체크리스트

### Flow Analysis

#### 팀 스킬 탭 (TeamSkillsTab)
- **Entry**: GNB "스킬" 클릭 -> `/skills` -> `SkillsPageView` -> 기본 "팀 스킬" 탭
- **Actions**: 검색, 필터(카테고리/상태/작성자), 테이블 행 클릭(패널 열기), 활성화 토글, 추가(채팅/파일)
- **Exits**: 패널 닫기(테이블 복원), 관리 탭 전환, 사이드바 네비게이션
- **Issues**: `style={{ height: 'calc(100vh - 64px)' }}`가 탭 컨텐츠 높이를 강제하여, 탭 헤더가 이 영역 바깥에 있으면 전체 레이아웃에서 빈 공간 발생

#### 관리 탭 (AdminTab)
- **Entry**: "관리" 탭 클릭 (관리자만 표시)
- **Actions**: 신규 스킬 검토(확인/삭제), 개선 제안 검토(승인/반려), 폐기 요청 처리, 스킬 관리(삭제/폐기/카테고리 변경), 카테고리 설명 편집
- **Exits**: 팀 스킬 탭 전환, 사이드바
- **Issues**: 관리 탭은 자체 높이를 `minHeight: calc(100vh - 56px)`으로 설정하여 탭 간 높이 불일치

## Part 2: 시나리오 기반 리뷰

### S1: 팀 스킬 탐색 및 활성화

- **페르소나**: 일반 팀원, 주 1-3회, 새 스킬이 팀에 추가되었다는 알림을 받고 확인하러 옴
- **현재 경로**:
  1. GNB "스킬" 클릭 -> `/skills` 진입
  2. "팀 스킬" 탭 (기본 선택) -> `TeamSkillsTab` 렌더
  3. 테이블에서 비활성 그룹의 스킬 확인
  4. 원하는 스킬 행의 Switch 토글 클릭 -> 활성화
  5. 행이 활성화 그룹으로 이동, toast 알림 표시
- **마찰점**:
  1. [활성화 토글 이벤트 이중 바인딩] Switch 토글 클릭 시, `SkillTableRow`에서 `handleToggleClick`(e.stopPropagation)으로 행 클릭 방지 + `Switch.onCheckedChange`에서 다시 `onToggle()` 호출. 그런데 `handleToggleCheckedChange`는 `e.stopPropagation()`만 하고 `onCheckedChange`를 막지 않는다. 따라서 **클릭 한 번에 `onToggle()`이 두 번 호출**될 수 있다: (1) `handleToggleClick`의 부모 div onClick은 `e.stopPropagation()`만 하고 toggle을 호출하지 않지만, (2) `Switch.onCheckedChange={() => onToggle()}`이 실행된다. 실제로는 `div.onClick={handleToggleClick}`은 `e.stopPropagation()`만 하므로 toggle을 호출하지 않고, `Switch.onCheckedChange`만 호출되어 정상 작동하는 것으로 보인다. 그러나 코드 의도가 불명확하고, `handleToggleCheckedChange`가 `onMouseDown`에 바인딩되어 있는데 이는 Switch의 기본 마우스 이벤트를 방해할 수 있다.
     - 위치: `SkillTableRow.tsx:261-269`
     - 현재: `<div onClick={handleToggleClick} onMouseDown={handleToggleCheckedChange}><Switch onCheckedChange={() => onToggle()} />`
     - 문제: `onMouseDown`의 `e.stopPropagation()`이 Radix Switch의 내부 마우스 이벤트 전파를 방해하여, 일부 환경에서 토글이 반응하지 않을 수 있음. 사용자 보고("활성화/비활성화가 정상 작동하지 않음")의 직접 원인
  2. [피드백 불충분] 활성화 시 행이 그룹 간 이동하지만, 애니메이션이 없어 어디로 갔는지 사용자가 인지하기 어려움
     - 위치: `SkillTable.tsx:157-171`
     - 현재: useMemo로 activated/deactivated 그룹 즉시 재분류
     - 문제: 행이 사라졌다가 다른 그룹에서 나타나는데, 시각적 연결고리 없음
  3. [자체 toast vs sonner] `TeamSkillsTab`은 자체 구현 toast(`useState<ToastState>`)를 사용하고, 레거시 `SkillManagementView`는 `sonner`의 `toast.success()`를 사용. 프로젝트 내 toast 구현 이중화
     - 위치: `TeamSkillsTab.tsx:96-100`
     - 현재: 수동 `setTimeout` + 상태 기반 토스트
     - 문제: sonner에 비해 큐잉, 스택, 접근성 지원 부족
- **개선안**:
  1. Switch 이벤트 핸들링 단순화
     - 현재: div로 감싸서 stopPropagation + Switch.onCheckedChange 별도 호출
     - 제안: div.onClick만으로 `e.stopPropagation(); onToggle();` 처리하고, `Switch`의 `onCheckedChange`를 제거하며 `checked`만 사용 (제어 컴포넌트)
     - 대상 파일: `src/components/features/skill-management/components/SkillTableRow.tsx`
     - effort: Low
  2. 자체 toast를 sonner로 교체
     - 현재: 수동 useState 기반 toast
     - 제안: `import { toast } from 'sonner'` 사용으로 통일
     - 대상 파일: `src/components/features/skill-management/components/TeamSkillsTab.tsx`
     - effort: Low
  3. 행 이동 시 애니메이션 추가
     - 현재: 즉시 그룹 재분류
     - 제안: `layoutId` (framer-motion) 또는 CSS transition으로 행 이동 애니메이션
     - 대상 파일: `SkillTable.tsx`
     - effort: High
- **빠진 기능**: 없음

### S2: 스킬 상세 확인 및 패널 인터랙션

- **페르소나**: 일반 팀원, 새 스킬의 지시사항/파라미터를 확인하려는 상황
- **현재 경로**:
  1. 테이블 행 클릭 -> `handleRowClick` -> `isPanelOpen=true`, `selectedSkillId` 설정
  2. `SkillSlidePanel` 우측에서 열림 (w-[45%])
  3. 테이블이 w-[55%]로 축소, collapsible 컬럼 숨김
  4. 패널 내 탭(개요/본문/첨부/버전이력/개선제안) 탐색
  5. [전체 확장] 클릭 -> 테이블 w-0, 패널 w-full
- **마찰점**:
  1. [패널 열림 시 레이아웃 잔상] 사용자 보고 이슈 "우측 패널이 열렸을 때 UI가 깨져보임"의 원인. 테이블 컬럼 숨김이 `opacity-0 w-0 overflow-hidden p-0`으로 처리되는데, `<TableHead>`와 `<TableCell>`에 `transition-all duration-200`이 적용되어 있어, w-0으로 가는 과정에서 **테이블 셀이 잠시 뭉개지면서** 보임
     - 위치: `SkillTableRow.tsx:198-209`, `SkillTable.tsx:195-209`
     - 현재: 개별 셀에 `opacity-0 w-0 overflow-hidden p-0` + `transition-all duration-200`
     - 문제: `transition-all`이 width, padding, margin 모두에 적용되어 중간 프레임에서 레이아웃이 깨져 보임
  2. [패널 열림 시 과도한 여백] 사용자 보고 이슈 "화면에 불필요한 여백이 너무 많음"의 원인 중 하나. `TeamSkillsTab`에서 `style={{ height: 'calc(100vh - 64px)' }}`로 전체 높이를 강제하는데, 실제 뷰포트에서 사이드바 상단, 탭 헤더 등을 고려하면 64px이 부정확하여 하단에 빈 공간이 생김
     - 위치: `TeamSkillsTab.tsx:248`
     - 현재: `style={{ height: 'calc(100vh - 64px)' }}`
     - 문제: 하드코딩된 offset이 실제 레이아웃과 불일치
  3. [패널-테이블 비율] 패널 45%, 테이블 55%로 고정인데, 작은 화면(1280px 이하)에서 테이블이 너무 좁아져 '이름' 컬럼도 truncate됨
     - 위치: `TeamSkillsTab.tsx:250-256`
     - 현재: 고정 비율 `w-[55%]` / `w-[45%]`
     - 문제: 반응형 미대응
  4. [패널 닫기 후 포커스] 패널을 닫아도 이전에 선택했던 행의 배경색(`bg-red-50/40`)이 유지됨. `selectedSkillId`가 null로 초기화되지 않기 때문
     - 위치: `TeamSkillsTab.tsx:113-116`
     - 현재: `handleClosePanel`에서 `setIsPanelOpen(false); setIsExpanded(false);`만 수행. `setSelectedSkillId(null)` 없음
     - 문제: 패널 닫힌 후에도 이전 선택 행이 하이라이트되어 있어 혼란
- **개선안**:
  1. 컬럼 숨김 방식 변경
     - 현재: 개별 셀 `transition-all` + `w-0 opacity-0`
     - 제안: `display: none` 또는 `visibility: collapse`로 즉시 숨김, transition은 테이블 영역 width에만 적용
     - 대상 파일: `SkillTableRow.tsx`, `SkillTable.tsx`
     - effort: Medium
  2. 하드코딩 높이 제거
     - 현재: `calc(100vh - 64px)`
     - 제안: 부모에서 `flex flex-col h-full`로 자연스럽게 채우기, `style` 속성 제거
     - 대상 파일: `TeamSkillsTab.tsx:248`
     - effort: Low
  3. 패널 닫기 시 선택 해제
     - 현재: `selectedSkillId` 유지
     - 제안: `handleClosePanel`에 `setSelectedSkillId(null)` 추가

## Part 3: 서비스 기획 관점 구조 리뷰

### 정보 구조 적합성

- **현재 탭/섹션 구조**:
  - 최상위: "팀 스킬" | "관리" (2탭)
  - 관리 탭 내: "신규 스킬 검토" | "개선 제안" | "폐기 요청" | "스킬 관리" | "카테고리 관리" (5서브섹션)

- **사용자 업무 모델과의 일치도**: **대체로 일치**. 일반 사용자는 "팀 스킬" 탭만 사용하고, 관리자는 "관리" 탭에서 큐레이션 업무를 수행. 기획 의도와 정확히 부합.

- **문제점**: 관리 탭의 5개 서브섹션 중 "신규 스킬 검토"와 "스킬 관리"는 같은 엔티티(스킬)를 다른 관점에서 보여주는데, 미검토 스킬을 "확인"한 후 "스킬 관리"에서 확인하면 여전히 "미검토" 상태로 보임. **데이터 분리로 인한 교차 시나리오 단절**.

- **제안**: "신규 스킬 검토"를 독립 섹션이 아닌, "스킬 관리" 테이블의 필터(`미검토만 보기`)로 통합하면 데이터 동기화 문제가 해소되고 관리 포인트가 줄어듦.

### 기능 존폐 판단

| 기능/컴포넌트 | 판단 | 근거 |
|-------------|------|------|
| 팀 스킬 테이블 + 슬라이드 패널 | **유지 (핵심)** | 기획의 중심 구조. 정보 밀도와 상세 확인의 균형 |
| 활성화/비활성 그룹 분리 | **유지** | 사용자가 "내가 쓰는 것"과 "팀에 있는 것"을 한눈에 구분 |
| 수정본 편집 모드 | **유지 (핵심)** | 개선 제안 워크플로우의 핵심 입구. 다만 테스트 기능 미구현으로 절반만 작동 |
| CategoryManager | **축소** | 설명 수정만 지원하여 전용 카드 UI가 과도. 테이블 인라인 편집으로 축소 가능 |
| DeprecationQueue 자체 헤더/설명 | **제거** | SectionHeader와 중복 |
| 레거시 SkillManagementView | **제거** | v4 SkillsPageView가 대체. mock 데이터도 빈 배열로 export. 사용자 혼란만 유발 |
| 스킬 추가 (채팅/파일) | **신규 추가 필수** | 팀에 스킬을 등록하는 유일한 경로인데 미구현 |
| 수정본 테스트 기능 | **신규 추가 필요** | 기획서 핵심 플로우이나 UI 미구현 |
| 알림 연동 | **신규 추가 필요** | 제안 결과, 신규 스킬, 폐기 결과 알림이 전체 워크플로우의 피드백 루프 |

### 복잡도 관리

- **현재 한 화면에 노출되는 개념 수**: 팀 스킬 탭에서 6개(테이블, 필터, 패널, 수정본, 제안, 활성화), 관리 탭에서 5개 서브섹션
- **Progressive Disclosure 적용이 필요한 영역**:
  - 관리 탭의 "카테고리 관리"는 사용 빈도가 매우 낮으므로, 기본으로 접기(collapse) 또는 설정 하위 메뉴로 이동
- **사용자 수준별 뷰 분리**: 이미 관리자/일반 사용자 분리가 `IS_ADMIN` 환경변수로 구현됨. 적절한 수준.

### 화면 간 관계

- **선후 관계**: AI 채팅에서 스킬 생성 -> 팀 스킬 테이블에 등록 -> 관리 탭에서 검토. 이 흐름에서 "채팅 -> 스킬 테이블" 연결이 미구현.
- **설정값 영향 범위 가시성**: 관리 탭에서 변경한 사항(스킬 삭제, 폐기, 카테고리 변경)이 팀 스킬 탭에 즉시 반영되지 않음. **탭 간 state 분리로 인한 문제**.
- **왕복 패턴**: 관리자가 "개선 제안 검토" -> "팀 스킬 탭에서 원본 확인" -> "다시 관리 탭"을 자주 오가야 하는데, 탭 전환 시 필터/스크롤이 초기화됨.

### 구조 변경 제안 (요약)

1. **레거시 라우트 제거**: `/settings/skills` -> `/skills` 리다이렉트. 영향 범위: `src/app/settings/skills/page.tsx`
2. **탭 간 상태 공유**: `TeamSkillsTab`과 `AdminTab`이 같은 skills 배열을 참조하도록 Context 또는 상위 컴포넌트에서 state 관리. 영향 범위: `SkillsPageView.tsx`, `TeamSkillsTab.tsx`, `AdminTab.tsx`
3. **"신규 스킬 검토" -> "스킬 관리" 통합**: 미검토 필터로 통합. 영향 범위: `AdminTab.tsx`, `AdminSkillTable.tsx`
