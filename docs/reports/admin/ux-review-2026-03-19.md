# UX Review Report -- 2026-03-19

## Target

`src/components/AdminView.tsx` + `src/app/admin/page.tsx` 및 하위 전체 컴포넌트

## Summary

관리자 대시보드는 6개 탭(사용자 관리, 권한 설정, 사용량, 감사 로그, 시스템 프롬프트, 피드백 품질)으로 구성되어 있으며, 각 탭은 비교적 높은 완성도로 구현되어 있다. 그러나 **사용자 관리와 권한 설정이 별도 탭으로 분리되어 있으면서도 업무상 강하게 결합되어 있어 탭 간 왕복이 빈번하게 발생하는 구조적 문제**가 가장 큰 마찰점이다. 또한 사용자 테이블에 페이지네이션이 없고, 상태/부서별 필터가 부재하며, 모든 데이터가 클라이언트 사이드 mock으로 운영되어 프로덕션 전환 시 상당한 작업이 필요하다.

## Part 1: UX Checklist Findings

### Flow Analysis

#### 사용자 관리 탭

- Entry: `/admin` 진입 시 기본 탭 (`defaultValue="users"`)
- Actions: 사용자 검색, 추가, 편집, 삭제, 상태 토글, 접근 뷰 보기, CSV 임포트, 조직도 뷰 전환
- Exits: 모달 닫기로 복귀, 탭 전환
- Issues: 검색만 가능하고 상태/부서/역할별 필터 없음. 페이지네이션 없음.

#### 권한 설정 탭

- Entry: "권한 설정" 탭 클릭
- Actions: 역할 정의 CRUD, 조직-역할 매핑 CRUD, 테이블 접근 매트릭스 편집, RLS/마스킹 관리, 통합 미리보기, 감사 로그 확인, 전체 저장
- Exits: 저장 후 동일 탭 유지, 다른 탭 전환 (미저장 경고 있음)
- Issues: 7개 서브탭으로 복잡도가 높음. 탭 내 탭 구조(중첩 탭).

#### 사용량 탭

- Entry: "사용량" 탭 클릭
- Actions: 기간 필터, KPI 확인, 차트 분석, 에이전트 비용 테이블, 팀 예산/사용자 사용량 확인
- Exits: 탭 전환
- Issues: 데이터 내보내기 기능 없음.

#### 감사 로그 탭

- Entry: "감사 로그" 탭 클릭
- Actions: 다중 필터 (시간, 액터, 카테고리, 심각도, PII), 검색, CSV 내보내기, 상세 드로어
- Exits: 탭 전환, CSV 다운로드
- Issues: 양호한 구현. 필터 조합이 잘 동작.

#### 시스템 프롬프트 탭

- Entry: "시스템 프롬프트" 탭 클릭
- Actions: 프롬프트 CRUD, 버전 관리, 비교(diff), 인라인 테스트, 배포 라벨 관리
- Exits: 탭 전환, Sheet 닫기
- Issues: 모드 기반 카테고리 필터링(`mode="admin"`) 적용됨.

#### 피드백 품질 탭

- Entry: "피드백 품질" 탭 클릭
- Actions: 기간 필터, 피드백 유형/에이전트 필터, 검색, 상태 변경(인라인), 상세 드로어
- Exits: 탭 전환, 드로어 닫기
- Issues: 페이지네이션 없음.

## Part 2: Scenario-Based Product Review

### S1: 신규 사용자 1명 등록

- **페르소나**: IT관리자, 매일, 입사 시마다 수행
- **현재 경로**:
  1. `/admin` 진입 → 사용자 관리 탭 (기본)
  2. "사용자 추가" 버튼 클릭 → `UserFormModal` 오픈
  3. Step 1: 이름, 이메일, 소속 조직(OrgTreeSelector), 직급 선택
  4. "다음" 클릭 → Step 2: 역할 자동 매핑 결과 확인 (읽기 전용)
  5. "등록하기" 클릭 → 모달 닫힘 + Toast "사용자가 추가되었습니다."
- **마찰점**:
  1. [파생값 불투명] 역할이 자동 매핑되지만, 매핑 로직의 근거가 Step 2에서 충분히 설명되지 않음
    - 위치: `UserFormModal.tsx:87-108` (`matchOrgRoles`)
    - 현재: "조직-직급 매핑 기반으로 N개 역할이 자동 할당되었습니다" 메시지만 표시
    - 문제: 어떤 매핑 규칙(OrgRoleMapping)에 의해 이 역할이 할당되었는지 알 수 없음. 잘못된 역할이 할당되어도 원인을 찾기 어려움
  2. [기능 부재] 역할을 수동으로 추가/제거할 수 없음 (읽기 전용)
    - 위치: `UserFormModal.tsx:282-365`
    - 현재: Step 2는 완전히 읽기 전용. `RoleChipSelector` 컴포넌트가 코드에 있지만 사용되지 않음
    - 문제: 매핑에 없는 예외적 역할 할당이 불가능. 예: 경영기획실 팀원에게 임시로 재무 뷰어 역할 추가
  3. [기능 부재] 매핑이 없을 때 이 화면에서 직접 해결할 수 없음
    - 위치: `UserFormModal.tsx:347-362`
    - 현재: "권한 설정 > 조직-역할 매핑에서 매핑을 추가해 주세요" 안내만 표시. 매핑 화면으로의 직접 링크 없음
    - 문제: 사용자는 모달을 닫고 → 권한 설정 탭 → 조직-역할 매핑 서브탭으로 이동 → 매핑 추가 → 다시 사용자 추가 플로우를 처음부터 반복해야 함
  4. [입력 유형 부적합] `position` 필드가 `EnhancedUser.position`에 자유 텍스트로 저장되지만, 실제로는 `positionLevel` 값이 그대로 들어감
    - 위치: `UserFormModal.tsx:142`
    - 현재: `position: positionLevel || ''` — positionLevel 값을 position에 복제
    - 문제: `position`과 `positionLevel`이 항상 동일값이므로 두 필드의 존재 이유가 불명확
- **개선안**:
  1. Step 2에 "이 역할이 할당된 근거" 섹션 추가 — 매칭된 `OrgRoleMapping`의 요약 표시
    - 대상 파일: `UserFormModal.tsx`
    - effort: Medium
  2. Step 2에 수동 역할 추가/제거 토글 추가 (기존 `RoleChipSelector` 활용)
    - 대상 파일: `UserFormModal.tsx`
    - effort: Medium
  3. 매핑 없음 경고에 권한 설정 탭으로의 직접 네비게이션 링크 추가
    - 대상 파일: `UserFormModal.tsx:355`
    - effort: Low
- **빠진 기능**: 수동 역할 오버라이드, 매핑 근거 표시, 이메일 중복 체크
- **필드 감사**:

### S2: 신규 입사자 50명 CSV 일괄 등록

- **페르소나**: IT관리자, 분기 1회, 대규모 채용 후
- **현재 경로**:
  1. "CSV 임포트" 버튼 클릭 → `BulkUserImportModal` 오픈
  2. CSV 파일 드래그 앤 드롭 또는 파일 선택
  3. 헤더 검증 → 미리보기 테이블에 검증 결과 표시
  4. "N명 임포트" 클릭 → 완료
- **마찰점**:
  1. [기능 부재] CSV 임포트 시 역할은 문자열(`ROLE_FIN_USER`)로 직접 입력해야 하는데, 단건 등록에서는 조직-직급 기반 자동 매핑이 적용됨
    - 위치: `BulkUserImportModal.tsx:83-84`
    - 현재: CSV에서 roles 컬럼에 `ROLE_`* 코드를 세미콜론으로 구분하여 직접 입력
    - 문제: 단건 등록은 자동 매핑인데 일괄 등록은 수동 입력. 일관성 결여. 역할 코드를 모르면 사용할 수 없음

  - **합쳐야 할 탭**: "시스템 프롬프트" + "피드백 품질" → "AI 품질 관리" 탭 (내부 서브탭)

### 복잡도 관리

- **현재 한 화면에 노출되는 개념 수**: 권한 설정 탭 기준 7개 서브탭, 각 서브탭에 CRUD + 필터 + 테이블. 총 ~15개 이상의 관리 대상 개념
- **Progressive Disclosure 적용이 필요한 영역**:
  - 권한 설정의 "자동 설정 & 비고" 섹션은 이미 접기/펼치기 적용됨 (좋은 패턴)
  - 그러나 7개 서브탭 자체가 과다. 추천 순서 배너가 있지만 강제력 없음
  - **제안**: 초기 설정 시에는 위저드 형태로 1→2→3→4→5 순서를 안내하고, 이후에는 자유 탭 이동 허용
- **사용자 수준별 뷰 분리가 필요한가**: 필요. 현재 IT관리자/보안담당자/경영진이 동일 화면을 봄. 경영진은 사용량+피드백만 필요하고 권한 설정은 불필요.

### 화면 간 관계

- **선후 관계**: 역할 정의 → 조직-역할 매핑 → 테이블 접근 매트릭스 → RLS/마스킹 → 사용자 등록 (이 순서가 온보딩 배너에 안내됨)
- **설정값 영향 범위 가시성**: **안 보임**
  - 역할 삭제 시 연쇄 정리는 코드에서 수행되지만(`handleRoleDeleted`), 사용자에게 "이 역할을 삭제하면 N명의 사용자와 M개의 매핑이 영향받습니다"라는 영향 범위 미리보기가 없음
  - 접근 매트릭스 변경 시 몇 명의 사용자에게 영향이 가는지 표시되지 않음

### 구조 변경 제안 (요약)

1. **탭 통합**: "시스템 프롬프트" + "피드백 품질" → "AI 품질 관리" 서브탭으로 통합 — 영향 범위: `AdminView.tsx` TabsTrigger 2개 → 1개, 내부 서브탭 추가
