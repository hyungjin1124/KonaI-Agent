# UX 리뷰 리포트 — Admin
날짜: 2026-03-18

## 요약
- 총 이슈: 31개
- 중요: 4개 | 높음: 10개 | 중간: 11개 | 낮음: 6개

관리자 콘솔은 매우 넓은 영역(사용자, RBAC, RLS, 마스킹, 조직 매핑, 플랫폼 운영)을 다루고 있으며, 접을 수 있는 모듈과 카드 레이아웃으로 데이터 밀도를 잘 관리하고 있습니다. 주요 문제점은: (1) 아이콘만 있는 액션 버튼에 `aria-label` 대신 `title` 속성이 광범위하게 사용되어 많은 브라우저에서 화면 읽기 프로그램이 제대로 작동하지 않음; (2) 모든 파괴적 작업에 `window.confirm()`을 사용하여 AT 사용자가 접근할 수 없고 스타일링도 불가능; (3) 접근 매트릭스 테이블이 WCAG 규격의 테이블 구조(`<table>`, `<th scope>`, `<caption>`)가 완전히 없음; (4) 권한 설정 레이어 어디에도 로딩, 저장, 오류 상태가 없어서 사용자가 변경 후 피드백을 전혀 받지 못함.

## Issues

### [중요] 아이콘만 있는 액션 버튼이 `aria-label` 대신 `title`을 사용
**파일**: `src/components/AdminView.tsx:191,201,209,219` and `src/components/features/permission-settings/components/RowSecurityLayer.tsx:188,197` and `src/components/features/permission-settings/components/ColumnMaskingLayer.tsx:154,159` and `src/components/features/permission-settings/components/RoleDefinitionManager.tsx:344,351` and `src/components/features/permission-settings/components/OrgRoleMappingManager.tsx:500,507`
**WCAG**: 1.1.1 Non-text Content (Level A), 4.1.2 Name, Role, Value (Level A)
**문제**: 모든 아이콘만 있는 버튼(Eye, Power, Edit2, Trash2)이 접근 가능한 이름으로 `title="편집"` / `title="삭제"`를 사용합니다. `title` 속성은 키보드 포커스가 요소에 도달할 때 화면 읽기 프로그램(VoiceOver, NVDA)에 의해 안정적으로 표시되지 않습니다. 또한 터치 디바이스에서도 보이지 않습니다. `Button` 컴포넌트는 `<button>` 요소를 래핑하므로 `aria-label`이 올바른 접근입니다.
**수정 방법**: `title="편집"`을 `aria-label="편집"`으로 바꿉니다(보조 호버 툴팁으로 `title` 유지). 패턴: `<Button aria-label="삭제" title="삭제" ...>`. 버튼당 한 줄의 변경으로 모든 인스턴스를 수정할 수 있습니다.

### [중요] 파괴적 작업에 `window.confirm()` 사용 — 접근 불가능하고 커스터마이징 불가
**파일**: `src/components/AdminView.tsx:100`, `src/components/features/permission-settings/components/RowSecurityLayer.tsx:343`, `src/components/features/permission-settings/components/ColumnMaskingLayer.tsx:349`, `src/components/features/permission-settings/components/RoleDefinitionManager.tsx:236`, `src/components/features/permission-settings/components/OrgRoleMappingManager.tsx:319`
**WCAG**: 3.2.5 Change on Request (Level AAA); 브라우저 기본 `confirm()` 대화 상자가 모든 화면 읽기 프로그램 + 브라우저 조합에서 제대로 표시되지 않고 커스텀 포커스 관리를 준수하지 않으므로 실제로는 AA 수준에서 AT 사용자에게 장애가 됨.
**문제**: 모든 삭제 흐름에서 `if (!confirm(...)) return;`을 사용합니다. 이것은 Radix UI 포커스 트랩 동작을 우회하며 예측 가능한 순서로 키보드 포커스를 받을 수 없습니다. `RoleDefinitionManager.tsx:233`의 경고 텍스트에는 confirm 문자열 안에 이모지(`⚠`)가 포함되어 있으며, 이는 접근 가능한 경고에 부적절합니다.
**수정 방법**: 모든 `confirm()` 호출을 Radix `<AlertDialog>`로 바꿉니다(`src/components/ui/`에 이미 래핑되어 있을 가능성 높음). AlertDialog는 `role="alertdialog"`를 사용하고 명확한 파괴적 `Button variant="destructive"` 확인 작업을 포함해야 합니다. 이것은 다섯 개의 모든 호출자에게 공유되는 재사용 가능한 `<ConfirmDeleteDialog>` 컴포넌트 패턴입니다.

### [중요] 접근 매트릭스가 진정한 접근 가능한 테이블이 아님
**파일**: `src/components/features/permission-settings/components/TableAccessLayer.tsx:338-556`
**WCAG**: 1.3.1 Info and Relationships (Level A)
**문제**: 접근 매트릭스는 CSS `flex` `div` 행으로만 구축되어 있습니다. 시각적으로 테이블(열 헤더, 행, 셀)을 모방하지만 의미론적 구조를 제공하지 않습니다. 화면 읽기 프로그램은 `<table>/<th>/<td>`에서처럼 "row 3, column 5: 전체접근"을 표시할 수 없습니다. 378-392 줄의 열 역할 헤더는 일반 `<div>` 요소입니다. 358 줄의 고정된 헤더 행에는 `<thead>` 등가물이나 `scope` 속성이 없습니다. 또한 테이블 용도를 설명하는 캡션도 없습니다.
**수정 방법**: `<table>`과 `<caption>`, `<thead>/<th scope="col">`, 고정된 왼쪽 열의 `<tbody>/<th scope="row">`, 그리고 셀의 `<td>`를 사용하도록 리팩토링합니다. 모듈 아코디언 행은 `<tr>`과 `colspan`을 사용할 수 있습니다. 수평 스크롤이 필요하므로, `role="region" aria-label="접근 매트릭스"` 래핑과 키보드 스크롤 가능성을 위해 `tabindex="0"`을 사용합니다.

### [중요] 알림 벨 버튼에 접근 가능한 이름이 없음
**파일**: `src/components/Sidebar.tsx:211-222`
**WCAG**: 4.1.2 Name, Role, Value (Level A)
**문제**: 211 줄의 알림 벨 `<Button>`에는 `<Bell size={20} />`과 빨간 점 배지 `<span>`만 포함되어 있습니다. `aria-label`도, `title`도 없으며, 읽지 않은 개수 배지(`<span className="absolute...">`)는 순수하게 시각적입니다 — AT 사용자에게 새 알림 개수를 표시하기 위한 `aria-label`이나 `aria-live` 영역이 없습니다.
**수정 방법**: `aria-label={unreadCount > 0 ? \`알림 ${unreadCount}건 읽지 않음\` : '알림'}`을 버튼에 추가합니다. 빨간 점 배지 span은 개수가 버튼 레이블에 표현되므로 `aria-hidden="true"`여야 합니다.
