## Summary

Admin 패널은 사용자 관리 + 데이터 접근 제어(3-Layer 보안) + 사용량 모니터링의 세 축이 단일 탭 인터페이스에 통합되어 있으며, 기능 완성도는 높다. 그러나 **권한 설정 탭의 6-Layer 중첩 탭 구조**와 **저장 버튼 부재**가 가장 심각한 UX 결함이다. 사용자는 복잡한 권한 매트릭스를 수십 번 수정하고도 그것이 실제로 저장되었는지 알 수 없으며, 페이지 새로고침 시 모든 변경이 사라진다.

## Part 1: UX Checklist Findings

### Flow Analysis

#### 관리자 대시보드 (AdminView)
- **Entry**: `/admin` 라우트 직접 접근, 또는 사이드바 UserCog 아이콘 클릭
- **Actions**: 사용자 추가/편집/삭제, 권한 설정 (6개 서브탭), 사용량 조회, 감사로그, 시스템 프롬프트, 피드백 품질
- **Exits**: 다른 글로벌 네비게이션으로 이동
- **Issues**: 6개 최상위 탭이 화면 상단 헤더에 가로 배치 → 좁은 뷰포트에서 줄바꿈 발생 가능. 각 탭 전환 시 스크롤 위치, 검색어 등 상태 초기화됨.

#### 권한 설정 (PermissionSettingsView)
- **Entry**: AdminView "권한 설정" 탭 클릭
- **Actions**: 역할 정의 CRUD, 조직-역할 매핑 CRUD, 매트릭스 셀 클릭, RLS 규칙 CRUD, 마스킹 정책 CRUD, 통합 미리보기
- **Exits**: 다른 어드민 탭 클릭
- **Issues**: **저장 버튼 없음** — 매트릭스 변경사항이 언제 실제 반영되는지 명확하지 않음. 6개 서브탭 내 상태가 독립적으로 관리되어 탭 간 상호 영향이 사용자에게 불투명함.

#### Platform Admin (PlatformAdminView)
- **Entry**: 사이드바 Building2 아이콘 클릭 (`/platform-admin`)
- **Actions**: 테넌트 관리, 사용량/알림, 빌링, 감사 로그
- **Exits**: 다른 글로벌 네비게이션
- **Issues**: "테넌트 추가" 버튼이 기능 없음 (onClick 미구현). TenantDetailPanel이 페이지 맨 아래에 append되어 클릭 후 스크롤이 필요함.

## Part 2: Scenario-Based Product Review

### S1: 신규 입사자 50명 등록 — 일괄 처리
- **페르소나**: IT 관리자, 월말 인사이동 후 신규 입사자 온보딩, 시간 압박 있음
- **현재 경로**:
  1. `/admin` 진입 → "사용자 관리" 탭 (기본값)
  2. "사용자 추가" 버튼 클릭 → `UserFormModal` 열림
  3. 3단계 위저드에서 개인 정보, 부서, 역할 입력
  4. 저장 → 모달 닫힘, 목록에 추가됨
  5. 50번 반복
- **마찰점**:
  1. [기능 부재] 일괄 사용자 추가(CSV import) 기능 없음
     - 위치: `AdminView.tsx:309-316`
     - 현재: 단건 추가 버튼만 존재
     - 문제: 50명을 한 명씩 수작업으로 입력해야 함. 실무에서 가장 높은 빈도의 onboarding 시나리오
  2. [피드백 부재] 저장 성공 시 toast가 없어 "저장됐나?" 불확실
     - 위치: `AdminView.tsx:95-103` (handleSaveUser)
     - 현재: 목록에 행이 추가되지만 별도 알림 없음
     - 문제: 관리자가 목록을 시각적으로 확인해야 함
- **개선안**:
  1. CSV 임포트 기능 추가
     - 현재: 없음
     - 제안: "사용자 추가" 옆에 "일괄 추가 (CSV)" 버튼, 파일 업로드 → 미리보기 → 확인 플로우
     - 대상 파일: `AdminView.tsx`, 새 `BulkUserImportModal.tsx`
     - effort: High
  2. 성공 toast 추가
     - 현재: 없음
     - 제안: `handleSaveUser` 완료 후 `{user.name} 사용자가 추가되었습니다.` toast
     - 대상 파일: `AdminView.tsx:95-103`
     - effort: Low
- **빠진 기능**: CSV 일괄 임포트, 성공 피드백 toast

## Part 3: 서비스 기획 관점 구조 리뷰

### 정보 구조 적합성

**현재 탭/섹션 구조:**
- AdminView: [사용자 관리] [권한 설정] [사용량] [감사 로그] [시스템 프롬프트] [피드백 품질]
- PermissionSettingsView: [역할 정의] [조직-역할 매핑] [테이블 접근 매트릭스] [행 수준 보안] [컬럼 마스킹] [통합 권한 미리보기]

**사용자 업무 모델과의 일치도:**

IT 관리자의 정신 모델은 "사람 관리"와 "데이터 보안 정책" 두 가지로 나뉜다. 현재 구조는 이를 잘 분리했다. 그러나 권한 설정 내 6개 서브탭은 "3-Layer 보안 정책의 순서"를 반영하는데, 일반 IT 관리자의 사고 순서(역할 → 사람 → 데이터 범위 → 마스킹)와 완벽히 일치하지는 않는다.

**문제 지점:**
- "시스템 프롬프트"와 "피드백 품질"이 사용자 관리 탭들과 같은 AdminView 탭에 있는데, 이 두 기능은 IT 관리자가 아닌 **AI 운영 담당**이 사용한다. 다른 사용자를 위한 기능이 같은 화면에 혼재.
- "사용량 모니터링"이 Admin에도 있고(`AdminView.usage`) Platform Admin에도 있다(`UsageAlertTab`). 두 화면의 차이가 명확하지 않음 — Admin의 사용량은 테넌트 내부용, Platform Admin의 사용량은 전체 플랫폼용이지만 UI 레벨에서 구분이 안 됨.

**제안:**
- "시스템 프롬프트"와 "피드백 품질"은 `/settings/prompt-management` 또는 별도 AI 운영 탭으로 이동
- AdminView의 사용량 탭 헤더에 "이 테넌트의 사용량" 명시

### 복잡도 관리

현재 한 화면에 노출되는 개념 수:
- AdminView: 6개 탭 × 다양한 도메인 개념
- PermissionSettingsView: 6개 서브탭 × (345뷰, 15역할, 43서브카테고리, RLS, 마스킹 등)

**Progressive Disclosure 적용 필요 영역:**
1. 테이블 접근 매트릭스 — 15개 역할 전체를 초기에 표시 → 선택한 역할(2~5개)만 표시
2. 권한 설정 서브탭 — "기본 설정"(역할 정의 + 조직 매핑)과 "고급 설정"(RLS + 컬럼 마스킹) 분리
3. OrgRoleMappingManager 폼 — "자동 설정 & 비고" 섹션이 기본 접힘 처리된 것 좋음. 계속 유지.

**사용자 수준별 뷰 분리 필요 여부:** 필요함
- 기본 관리자: 사용자 관리 + 기본 권한(역할 정의 + 조직 매핑 + 매트릭스)

**선후 관계:**
역할 정의 → 조직-역할 매핑 → 테이블 접근 매트릭스 → RLS → 컬럼 마스킹 → 미리보기 (순서 중요하지만 강제되지 않음)

**설정값 영향 범위 가시성:**
- `역할 정의 탭`에서 새 역할 추가 → `조직-역할 매핑 탭`에 즉시 선택 가능 (연결됨)

### 구조 변경 제안 (요약)

1. **권한 설정 탭에 저장 버튼 추가**: 모든 변경은 "저장" 클릭 전까지 임시 상태. 하단 고정 바 형태로 구현 — 영향 범위: `PermissionSettingsView.tsx`, 전체 하위 컴포넌트의 state lifting 필요

4. **관리자 Admin(테넌트 내부용) vs Platform Admin(플랫폼 전체용) 시각적 차별화**: 같은 탭 구성(사용량, 감사 로그)이 두 화면에 있어 혼동 — 영향 범위: `Sidebar.tsx`, 헤더 디자인
