[2026-04-07] 문제: IA 설계 단계에서 결정 사항이 많아질 때 결정 간 의존성을 추적하지 않으면 나중에 어떤 결정이 어떤 결정에서 파생됐는지 놓침 → 해결: IA 설계 문서에 "확정된 결정" 표를 D1~DN 식으로 ID 부여하여 나열하고, 각 결정 항목 옆에 "번복 조건"과 "의존하는 하위 결정"을 함께 기록할 것. skill-ia-creation-flow.md §1.2에 적용.

[2026-04-07] 문제: 프로토콜(무엇을)과 IA(어떻게 surface로 표현)를 같은 문서에 섞으면 양쪽이 업데이트될 때마다 충돌 위험 → 해결: 프로토콜 단일 출처(skill-creation-protocol.md)와 IA 단일 출처(skill-ia-creation-flow.md)를 분리하고, 각 문서 메타데이터에 "연계 문서"를 명시하여 단일 출처(single source of truth) 원칙을 문서 자체에 박아둘 것.

[2026-04-07] 문제: 기존 큰 문서(skill-ia.md 1100줄+)에 surgical edit을 적용할 때 한 번에 읽지 말고 섹션별 offset/limit로 정확한 청크만 읽으면 실수가 줄어듦 → 해결: 편집 대상 섹션별 offset 범위를 미리 메모한 뒤 각 Edit 직전에 필요한 청크만 Read로 확보, 편집 직후 Grep으로 키워드 기반 검증. 이 세션에서 v13 8건 편집에 적용하여 모든 편집이 1회 시도에 성공.

[2026-04-07] 문제: 결정 사이의 순환 파생(예: B2 단일 드래프트 + B1 느슨 lifecycle → "이미 드래프트 있는 채팅에서 새 스킬 요청 시 어떻게" 질문)이 종종 숨어있음 → 해결: 각 결정이 확정된 직후 "이 결정과 이전 결정의 조합으로 자동으로 결정되는 것은?"을 1회 체크하여 파생 결정을 놓치지 않을 것. 이 세션에서 이 습관이 "귀결 3건"을 추가 확정하게 해주었음.
