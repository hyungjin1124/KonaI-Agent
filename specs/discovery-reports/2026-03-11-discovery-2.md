### 상세

#### NEW-1: Agent Registry (에이전트 레지스트리)

- **발견 출처**: [Microsoft Agent 365](https://blog.admindroid.com/microsoft-agent-365-unified-control-plane-to-manage-ai-agents/) (2026년 5월 1일 GA 예정, $15/user)
- **경쟁사 현황**:
  - **Microsoft Agent 365**: 5가지 핵심 관리 기능 제공 — Registry(에이전트 인벤토리), Access Control(최소 권한), Visualization(통합 대시보드), Interoperability(Work IQ 통합), Security(심층 방어)
  - 에이전트를 고유 Agent ID를 가진 **1급 ID(first-class identity)** 로 취급
  - Microsoft Entra Conditional Access로 에이전트별 조건부 접근 제어 (위험, 그룹 멤버십, 역할, 상태, 커스텀 속성 기반)
  - Agent Policy Templates로 표준화된 보안 정책 적용
  - 섀도우 에이전트(비인가 에이전트) 탐지 및 격리 기능
  - 에이전트-사용자-리소스 연결을 매핑하는 통합 대시보드
- **KonaI-Agent 관련성**: 현재 카탈로그에 에이전트 레지스트리/인벤토리 개념이 없음. multi_agent_orchestration_ui와 결합하면 에이전트 관리 허브를 구성할 수 있음. 단, 현재 KonaI-Agent는 프론트엔드 데모이므로 mock 기반으로 UI 패턴만 구현하는 것이 적절

#### NEW-2: Admin Configuration Profiles

- **발견 출처**: [LibreChat 2026 Roadmap](https://www.librechat.ai/blog/2026-02-18_2026_roadmap) (2026 Q1)
- **경쟁사 현황**:
  - **LibreChat**: 역할별 차등 설정 프로파일 도입 — 비즈니스 사용자용 간소화 vs 파워 유저용 전체 개방
  - GUI 기반 설정 관리 (기존 YAML 수동 편집 대체)
  - 그룹별 설정 적용 가능
  - Embedded Access Controls (사후 추가가 아닌 설정 패널 내장)
  - **Open WebUI**: Group-Based Access Control로 모델/지식/프롬프트/도구를 그룹별 제한
  - **ChatGPT Enterprise**: Workspace 내 Projects로 팀별 협업 공간 + 역할별 사용 한도(spend controls) 설정
- **KonaI-Agent 관련성**: 현재 permission_matrix가 역할-리소스 매트릭스만 제공. 역할별 차등 UI 경험이나 설정 프로파일 개념은 없음. agent_config과 연계하여 관리자가 역할별로 다른 에이전트 설정을 적용할 수 있는 패턴

#### NEW-3: Knowledge Base Management (지식 베이스 관리)

- **발견 출처**: [MS Copilot Studio](https://learn.microsoft.com/en-us/microsoft-copilot-studio/whats-new), [Open WebUI](https://docs.openwebui.com/features/), ChatGPT Enterprise
- **경쟁사 현황**:
  - **MS Copilot Studio**: SharePoint 지식 연동 + 파일 그룹(GA, Aug 2025) + 메타데이터 필터(파일명, 소유자, 수정일). 테넌트 그래프 그라운딩으로 시맨틱 검색 정밀도 향상
  - **Open WebUI**: 문서 스토어 + 벡터 검색 + RAG 통합. 그룹별 지식 접근 제어
  - **ChatGPT Enterprise**: 워크스페이스 파일 관리 + 프로젝트별 공유 대화 + 영속 컨텍스트
  - **Composio**: 시맨틱 거버넌스로 도구 호출 전 의도·신뢰도 기반 인터셉트
- **KonaI-Agent 관련성**: 카탈로그에 지식 베이스/RAG 소스 관리 컴포넌트가 없음. 에이전트가 참조하는 문서 소스를 관리자가 CRUD하고, 그룹별로 접근을 제어하는 UI 필요

  - **Open WebUI**: 메시지 볼륨, 사용자 활동, 모델 성능 메트릭 분석
- **KonaI-Agent 관련성**: 현재 피드백 수집/품질 추적 메커니즘이 없음. 에이전트 응답에 대한 사용자 피드백을 수집하고, 미답변·불만족 패턴을 분석하는 관리자 뷰 필요
