## 1. data-ia.md 변경 상세

### 1.1 섹션 1 (사이트맵) — 그룹 탭 제거

**현재:**
```
관리자 > 사용자 관리 (2탭으로 확장)
├─ 사용자 (기본 탭) ── 기존 + 패널에 "뷰테이블 접근 현황" 추가
└─ 그룹 (신규 탭) ─── 그룹 목록 + 슬라이드 패널 (소속 사용자, 접근 가능 뷰테이블)
```

**변경:**
```
관리자 > 사용자 관리
└─ 사용자 목록 + 슬라이드 패널 (사용자 정보 + 뷰테이블 접근 현황)
```

- "2탭으로 확장" 표현 제거, 단일 화면으로 복원
- 그룹 탭 라인 삭제

### 1.2 섹션 2.3 (좌측 뷰테이블 목록) — 소스 컬럼 추가 + 등록 변경

**변경 내용:**

(a) **테이블 컬럼 추가**: 기존 `뷰테이블 이름, 도메인, auth_type, 접근 가능 그룹 수` → `뷰테이블 이름, 소스, 도메인, 접근 대상 수`
- "소스" 컬럼: ERP / Jira / Excel 등 데이터 소스 유형 표시
- "auth_type" 컬럼 제거 (소스 컬럼으로 대체, auth_type은 내부 개념)
- "접근 가능 그룹 수" → "접근 대상 수" (부서+그룹+사용자 합산)

(b) **필터 추가**: 기존 도메인 필터 + **소스 유형 필터** 드롭다운 (전체 / ERP / Jira / Excel / ...)

(c) **[+ 등록] 버튼**: ERP 뷰테이블 등록 제거. 비ERP 소스 등록 전용으로 변경
- 버튼 클릭 → 비ERP 소스 등록 다이얼로그 열림 (3절에서 재설계)
- ERP 뷰테이블은 백엔드/마이그레이션으로만 등록됨을 안내 문구로 명시

(d) **와이어프레임 업데이트**: 테이블 헤더를 변경된 컬럼으로 수정

### 1.3 섹션 2.5 ([개요] 탭) — ERP 뷰 편집 제거 + 소스별 분기

**변경 내용:**

- ERP 뷰: [편집] 버튼 제거. "모든 필드는 읽기 전용이다. ERP에서 관리되는 데이터이므로 이 화면에서 수정할 수 없다." 문구 추가
- 비ERP 뷰: [편집] 버튼 유지. 메타데이터 수정 가능
- 비ERP 뷰의 [개요] 탭 표시 필드:
  - 뷰테이블 ID, 표시명, 설명, 소스 유형, 도메인, 활성 여부
  - (ERP 전용인 auth_type, pgmseq, 원천 ERP 화면 등은 비ERP에서 미표시)
- "하단 액션" 섹션을 조건부로 기술:
  - ERP 뷰: 액션 없음
  - 비ERP 뷰: [편집] — 수정 다이얼로그 열기

### 1.4 섹션 2.8 ([접근 권한] 탭) — 부서 추가 + 소스별 분기

**변경 내용:**

(a) **제목 변경**: "접근 가능 그룹/사용자" → **"접근 가능 부서/그룹/사용자"**

(b) **ERP 뷰의 접근 권한 표시** — 부서 행 추가:
- `_TCAOrgDeptSecu`에서 해당 pgmseq에 secu='1'인 부서 목록 표시
- 표시 순서: **부서 → 그룹 → 사용자 오버라이드** (넓은 범위부터)
- 부서 행도 ▸ 펼침으로 소속 사용자 인라인 표시 가능

**테이블 예시 업데이트:**
```
▸ 생산기술팀 (150)                  부서   18명   _TCAOrgDeptSecu secu='1'
▸ 품질관리팀 (170)                  부서   10명   _TCAOrgDeptSecu secu='1'
▸ 생산관리                          그룹   12명   _tcagroupsecu secu='1'
▸ 임원(사장단)                      그룹    5명   _tcagroupsecu secu='1'
  박지은                            사용자   —    _tcausersecu secu='1' (오버라이드)
```

- 하단 안내 문구에 `_TCAOrgDeptSecu` 추가:
  "ⓘ ERP 연동 뷰의 접근 권한은 ERP 부서별권한등록·그룹별권한등록·사용자별권한등록에서 관리됩니다."
- **[편집] 버튼 제거** (ERP 뷰이므로)
- **[그룹 상세 보기 →] 링크 제거** (그룹 탭이 없으므로 이동 대상 없음)

(c) **비ERP 뷰의 접근 권한 표시 + 편집** (신규):
- 비ERP 뷰는 부서 + 사용자 단위로만 접근 권한 표시
- **[편집] 버튼 활성화** → 접근 권한 편집 다이얼로그에서 부서/사용자 추가·제거 가능
- 그룹 개념 미사용 (ERP 그룹은 ERP 전용 개념이므로)

**비ERP 뷰 접근 권한 표시 예시:**
```
접근 가능 부서/사용자

  생산기술팀 (150)                  부서   18명   관리자 직접 설정
  품질관리팀 (170)                  부서   10명   관리자 직접 설정
  박지은                            사용자   —    관리자 직접 설정

ⓘ 이 데이터 소스의 접근 권한은 KonaI-Agent에서 직접 관리됩니다.

[편집]
```

- 편집 다이얼로그: 부서 검색/추가, 사용자 검색/추가, 제거 기능
- 하단 안내 문구: "ⓘ 이 데이터 소스의 접근 권한은 KonaI-Agent에서 직접 관리됩니다."

(d) **RLS 설정 영역**: ERP/비ERP 공통. 비ERP 뷰는 rls_type이 확장될 수 있음 (향후)

### 1.5 섹션 3 (등록/수정 다이얼로그) — 비ERP 전용으로 재설계

**현재:** ERP 뷰테이블 등록/수정 전용 (auth_type, pgmseq 매핑, rls_type/rls_config)

**변경:** 비ERP 데이터 소스 등록/수정 전용으로 재설계

**3.1 폼 필드 (비ERP 소스 등록):**

| 필드 | 타입 | 필수 | 설명 |
|------|------|------|------|
| view_id | text input | ✓ | 뷰테이블 식별자 |
| view_name | text input | ✓ | 표시명 |
| description | textarea | | 뷰테이블 설명 |
| source_type | select | ✓ | 소스 유형 (Jira / Excel / API / 기타) |
| source_config | 동적 폼 | | source_type에 따라 연결 정보 입력 (향후 소스별 설계) |
| domain | select | ✓ | 도메인 분류 |
| is_active | toggle | ✓ | 활성 여부 |

- ERP 전용 필드 제거: auth_type, pgmseq 매핑, rls_type, rls_config
- auth_type은 source_type에서 자동 결정됨 (예: source_type='jira' → auth_type='jira')
- rls_type/rls_config는 비ERP 소스의 RLS 방식이 확정되면 추가

**3.2 rls_config 동적 폼:** 비ERP 소스용으로 간소화 또는 향후 확장으로 이동

**3.3 등록 플로우:**
```
[+ 등록] 클릭
  → 다이얼로그 열림
  → 소스 유형 선택 → 연결 정보 입력 → 메타데이터 입력
  → [저장]
  → 유효성 검증 (view_id 중복, 필수 필드)
  → 성공 시: agent_view_registry 저장 (auth_type은 source_type 기반 자동 결정)
            기본 접근 권한 없음 (관리자가 별도 설정 필요)
```

**3.4 접근 권한 검증 미리보기:** 제거 (ERP pgmseq 기반 미리보기였으므로 비ERP에서는 불필요)
- 비ERP 소스는 등록 후 [접근 권한] 탭에서 부서/사용자를 직접 설정

### 1.6 섹션 4 (관리자 > 사용자 관리 확장) — 그룹 탭 제거 + 사용자 추가 제거

## 3. data-access-policy.md 변경 상세

### 3.1 섹션 1 (기본 원칙) — 비ERP 소스 원칙 추가

- 현재 "ERP 권한 우선" 원칙 유지
- **추가 원칙**: "비ERP 소스 자체 관리: ERP 외 데이터 소스(Jira, Excel 등)의 접근 권한은 KonaI-Agent에서 부서/사용자 단위로 직접 관리한다. ERP 그룹 개념은 적용하지 않는다."

### 3.2 섹션 2 (용어 정의) — 비ERP 관련 용어 추가

- **auth_type 설명 수정**: "현재: erp_pgm, erp_derived. **비ERP 소스 연동 시 소스별 auth_type 자동 생성 (예: jira, excel)**"
- 비ERP 전용 접근 권한 테이블 개념 추가 (아래 4절에서 상세)

### 3.3 섹션 4 (데이터 모델) — 비ERP 접근 권한 테이블 추가

**신규 테이블: `agent_view_access` — 비ERP 뷰 접근 권한**

| Column | Type | Description |
|--------|------|-------------|
| view_id | varchar (PK, FK) | 뷰테이블 식별자 (agent_view_registry 참조) |
| grant_type | varchar (PK) | `'dept'` \| `'user'` |
| grant_target | int (PK) | grant_type='dept'이면 deptseq, 'user'이면 userseq |
| created_at | timestamp | 등록일시 |
| created_by | int | 설정한 관리자 userseq |

- ERP 뷰(erp_pgm, erp_derived)에는 이 테이블을 사용하지 않음 (ERP 권한 테이블에서 자동 계산)
- 비ERP 뷰만 이 테이블로 접근 권한 관리
- 그룹(group) grant_type 미지원 — 부서와 사용자만으로 운영

**ER Diagram 업데이트:**
- 기존 ERP 테이블 다이어그램 하단에 `agent_view_access` 추가
- 비ERP 뷰 → `agent_view_access` → `_tcauser` (userseq), 부서 (deptseq) 관계 표시

### 3.4 섹션 5 (권한 판단 로직) — 비ERP resolve 함수 패턴 추가

**5.1 공통 인터페이스:** 유지 (비ERP도 동일한 boolean + WHERE절 반환)

**비ERP 공통 resolve 패턴 추가:**
```
resolve_custom(userseq, view_id):
  [접근 허용 판단]
  1. agent_view_access에서 view_id의 grant 목록 조회
  2. grant_type='user', grant_target=userseq인 레코드 존재 → ✅ 허용
  3. grant_type='dept', grant_target=사용자의 deptseq인 레코드 존재 → ✅ 허용
  4. 둘 다 없음 → ❌ 차단

  [데이터 범위 판단]
  5. rls_type에 따라 처리 (비ERP 소스는 초기에 rls_type=NULL로 시작, 향후 확장)
```

### 3.5 섹션 6 (비ERP 데이터 소스 확장 가이드) — 접근 권한 모델 구체화

**현재:** 소스별 auth_type 정의 가이드 (추상적)

**변경:** 공통 접근 권한 모델 명시
- 모든 비ERP 소스는 `agent_view_access` 테이블 공유
- 부서/사용자 단위 권한 설정은 소스 무관하게 동일
- 소스별로 달라지는 것은 데이터 연결 방식과 RLS 로직뿐
- Jira/e2max 예시를 위 구조에 맞게 업데이트

### 3.6 섹션 8 (접근 권한 관리 화면) — 부서 추가 + 비ERP 편집

**8.1 데이터 메뉴 — [접근 권한] 탭:**
- "접근 가능 그룹/사용자" → **"접근 가능 부서/그룹/사용자"**
- `_TCAOrgDeptSecu` 참조 추가
- ERP 뷰: 읽기 전용 현황 (부서/그룹/사용자 합집합)
- 비ERP 뷰: **편집 가능** (부서/사용자 단위 직접 설정, `agent_view_access` 기반)

**8.3 핵심 관리 포인트:**
- ERP 연동 뷰: "접근 권한은 ERP의 **부서별권한등록(`_TCAOrgDeptSecu`)**, 그룹별권한등록, 사용자별권한등록에서 관리" (부서 추가)
- 비ERP 뷰: "`agent_view_access` 테이블 기반, 부서/사용자 단위로 관리자가 직접 설정"

## 4. admin-ia.md 변경 상세

### 4.1 사용자 추가 버튼 제거 (피드백 5)

admin-ia.md에는 `[+ 사용자 추가]` 버튼이 깊이 설계되어 있다. 다음 위치를 모두 수정한다.

**(a) 사용자 관리 와이어프레임 (67행 부근):**
- `[+ 사용자 추가]` 버튼을 와이어프레임에서 제거

**(b) 액션 테이블 (103~107행 부근):**
- "사용자 추가 | 우상단 [+ 사용자 추가] 버튼 | 멤버 디렉토리에서 선택" 행 삭제

**(c) "사용자 추가 — 멤버 디렉토리 기반 선택" 전용 섹션 (109~153행 부근):**
- 섹션 전체 삭제 (모달 와이어프레임, 팀 단위 선택 플로우, 전제 조건 포함)

**(d) 사이트맵 / 화면 흐름도 (566~570행 부근):**
- `├─ [+ 사용자 추가] ──► 멤버 디렉토리 모달` 라인 삭제

**(e) 인터랙션 패턴 6.1절 (642~648행 부근):**
- "6.1 사용자 추가" 섹션 전체 삭제

**(f) 온보딩 시나리오 (714~721행 부근):**
- 빈 상태에서 `[+ 사용자 추가]` 유도 와이어프레임의 버튼 제거
- 온보딩 문구를 "ERP 사용자가 자동으로 동기화됩니다" 등으로 변경 검토

**(g) 설계 근거 테이블 (760행 부근):**
- "멤버 디렉토리 기반 사용자 추가" 행 삭제

**(h) 문서 상단 버전 이력 (7행):**
- v2 변경 내용에서 "멤버 디렉토리 기반 사용자 추가" 기술을 "(v4에서 제거됨)" 등으로 주석 처리
